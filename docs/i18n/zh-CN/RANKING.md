# 排名方法论

> 🌐 [English](../../RANKING.md) · [Português (Brasil)](../pt-BR/RANKING.md) · **中文（简体）**

排名是对已合并公开目录条目的透明视图。它们绝不会使用隐藏的综合评分,也绝不会将来自更大的父项目的
星标视为插件本身的热度。

## “按星标排名的热门插件”判定规则

一个条目只有在以下所有条件都成立时才符合资格:

```text
kind == plugin (规范的原生 DSH 插件包判别符)
repositoryScope == dedicated
verification.status in [eligible, verified]
仓库处于活跃状态且未被归档
星标确实属于该确切的插件仓库
条目已合并入公开目录
```

符合资格的条目使用 `popularity.starsPolicy: exact-repository`,以及 `popularity.stars` 中的一个非
负整数。出现并列时,使用不区分大小写的插件 ID 作为确定性的显示顺序;这种并列打破规则并不意味着质
量上的差异。

`kind` 是唯一的制品类型判别符。模式在设计上不存储可能与之矛盾的第二个 DSH 集成类型字段。

## 明确排除的情形

位于更大单体仓库(monorepo)中的插件仍然可以被收录进目录,但其父项目的星标对于插件排名而言是未定
义的。它必须使用 `repositoryScope: monorepo`、`popularity.starsPolicy:
undefined-parent-repository` 和 `popularity.stars: null`。它会出现在功能性板块中,但会被排除在所
有基于星标的排名之外。

插件家族、主题、皮肤、技能、预设、客户端、界面、桥接程序以及更广泛的生态系统项目不会出现在“按星
标排名的热门插件”中。在存在可比数据的情况下,它们会获得各自单独的板块。聚合网站、市场、安装器目
录和列表不是目录条目,也不会获得任何目录板块。

## 排名视图

本项目可能会发布针对星标数、24 小时增长、7 天增长、近期更新、已验证安装、插件家族、主题和皮肤、
客户端和界面,以及生态系统集成的不同视图。每个视图都必须公开其自身的纳入规则和快照时间。

当符合资格的条目数为零时,不会渲染“热门插件”视图。第一个符合资格的合并条目会创建一个“热门插
件”视图;只有当符合条件的条目达到十个后,标签才会变为“十大”(Top 10)。不允许使用占位或虚构的排
名。

## 验证不代表官方背书

`eligible` 表示公开结构和 DSH 集成已通过校验。`verified` 在此基础上还表示针对固定源代码或软件包
的安装冒烟测试已经通过。这两种状态都不代表官方背书、保证或绝对的安全认证。
