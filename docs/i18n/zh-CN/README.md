本仓库是该目录的公开真实来源。每一条记录都是 `catalog/plugins/` 下的一个 YAML 文件,依据已发布的 JSON Schema 校验,通过一次单独评审的拉取请求添加,并始终署名插件的原始创作者。目录中的任何内容都不是从其他目录或列表生成的:每个条目都是根据创作者原始仓库在固定提交处重新构建而成。

网站和 CLI 均维护于私有代码库;本仓库承载它们所使用的公开目录数据、模式定义和政策。

## 🚀 安装 CLI

```bash
npx @diegosouza.pw/dsh-plugins --help
```

该带作用域的包以 `@diegosouza.pw/dsh-plugins@0.1.0` 发布,上面的命令是目前的标准调用方式;本仓库不托管任何安装脚本。

### 立即使用 CLI

0.1.0 版本提供只读的发现与校验命令,以及需要征得同意才能执行的安装命令。完整的命令参考(包括参数、退出码和代码执行同意机制)见 [docs/CLI.md](../../docs/CLI.md)。

| 命令                        | 功能说明                                                        | 是否会改动你的系统?                    |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | 校验目录 YAML、模式和本地语义                   | 否——只读                          |
| `search <query...>`            | 在本地搜索公开目录字段                                | 否——只读                          |
| `info <id>`                    | 显示一个公开目录条目                                       | 否——只读                          |
| `list`                         | 列出由目录管理的已安装项,不修改配置文件            | 否——只读                          |
| `doctor`                       | 对 Node、DSH、原生 Windows 策略和目录进行只读诊断  | 否——只读                          |
| `add <id> --profile <name> --dry-run` | 显示经过校验的安装计划,不写入文件也不启动子进程 | 否——演练模式                            |
| `add <id> --profile <name> --allow-code-execution` | 通过官方 DSH 委托机制安装        | 是——仅在显式传入同意参数时   |

```bash
# Validate the catalog in this repository (what CI runs):
npx @diegosouza.pw/dsh-plugins@0.1.0 catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx @diegosouza.pw/dsh-plugins@0.1.0 search memory --catalog .
npx @diegosouza.pw/dsh-plugins@0.1.0 info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx @diegosouza.pw/dsh-plugins@0.1.0 add <plugin-id> --profile default --dry-run
```

变更类命令(`add`、`update`、`remove`)在未传入 `--allow-code-execution` 时绝不会执行插件生命周期代码。在原生 Windows 上,v0.1.0 中这些变更操作已被禁用;请改用 WSL。只读和演练模式命令在任何环境下都可用。

## 🔍 插件如何进入目录

```mermaid
flowchart LR
    A["创作者仓库<br/>(固定提交)"] --> B["一个分支,<br/>一个 PR,<br/>一个 YAML 条目"]
    B --> C["catalog-validation CI<br/>(模式 + 本地语义)"]
    C --> D["维护者关卡<br/>(身份、创作者绑定,<br/>固定证据)"]
    D --> E["catalog/plugins/*.yaml<br/>已合并"]
    E --> F["网站"]
    E --> G["CLI"]
    E --> H["catalog.json 订阅源"]
```

1. **一个插件,一个分支,一个拉取请求。** 该 PR 只新增或修改 `catalog/plugins/` 下的一个 YAML 文件。
2. **创作者优先。** 由插件创作者本人或所属组织发起的 PR,针对同一插件始终优先于社区整理或自动化提交——参见
   [docs/CREDIT.md](../../docs/CREDIT.md)。
3. **证据来自原始来源。** 每个字段都是根据创作者仓库在固定的 40 位提交哈希处重新构建而成:描述、许可证、DSH 集成方式、
   安装描述符、星标数。
4. **本地校验。** `catalog validate` 会检查结构和本地语义;这与 `catalog-validation` CI 任务在 PR 上运行的检查
   完全相同。
5. **维护者关卡。** 合并前,维护者会单独核实仓库身份、创作者绑定和固定证据。本地校验通过是必要条件,但绝非充分条件。

完整的贡献约定——所需证据、YAML 规则、星标政策、冲突处理和评审关卡——见 [CONTRIBUTING.md](../../CONTRIBUTING.md)。决策如何制定、由谁制定,见
[docs/GOVERNANCE.md](../../docs/GOVERNANCE.md)。

## 📄 条目结构剖析

每个条目都是以其 ID 命名的一个 YAML 文件。下面的示例可通过当前模式的校验(逐字段参考见 [docs/SCHEMA.md](../../docs/SCHEMA.md)):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

模式强制要求的关键不变量:

- `unofficial: true` 和 `schemaVersion: 1` 是固定常量。
- 位于 monorepo 中的插件必须使用 `stars: null`——绝不继承父项目的星标。
- 安装描述符只能是精确版本的 npm 包,或固定的源代码本身;它是数据,绝非 shell 命令。
- `verified` 状态需要可供评审的冒烟测试证据;否则条目状态为 `eligible`,且 `smokeTest: null`。

## 🗂 本仓库收录什么

本仓库收录为 DeepSeek Harness(DSH)独立发布的各类集成,包括原生插件、插件家族、主题、技能、客户端和桥接程序。制品类型、
能力分类和界面标签定义见 [docs/CATEGORIES.md](../../docs/CATEGORIES.md)。

每条公开记录都是 `catalog/plugins/` 下的一个 YAML 文件,且必须通过 `schemas/plugin.schema.yaml` 的校验。收录意味着
已完成文档规定的资格或验证检查;这不是安全认证,也不代表 DeepSeek 的认可。

## 🏅 排名与验证

只有专属的、原生的、符合资格或已验证的插件仓库,且星标确实属于该仓库本身,才能进入星标排名。存放在更大 monorepo 中的
集成仍可被发现,但使用 `stars: null`,绝不继承父项目的星标。完整判定规则见
[docs/RANKING.md](../../docs/RANKING.md)。

公开的验证状态用于区分结构性资格与安装冒烟测试。任何状态都不代表绝对安全。使用前请自行审查插件的仓库、固定提交、许可证和
安装行为。

## 🤝 贡献或认领条目

在发起拉取请求之前,请先阅读 [CONTRIBUTING.md](../../CONTRIBUTING.md)。一个拉取请求只能新增或修改一个插件条目,且必须引用原始创作者
仓库,而非其他目录。由创作者本人提交的拉取请求优先于自动化目录提交。

创作者认领、更正和移除均可通过结构化的 issue 表单提交。切勿提交凭据、私人联系方式或其他敏感信息。
