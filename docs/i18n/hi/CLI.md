# CLI संदर्भ — `omni-dsh-plugins@1.0.1`

> 🌐 [English](../../docs/CLI.md) · [Português (Brasil)](../pt-BR/CLI.md) · [中文（简体）](../zh-CN/CLI.md) · [中文（繁體）](../zh-TW/CLI.md) · [Español](../es/CLI.md) · [Français](../fr/CLI.md) · [Italiano](../it/CLI.md) · [Deutsch](../de/CLI.md) · [Русский](../ru/CLI.md) · [Polski](../pl/CLI.md) · [Čeština](../cs/CLI.md) · [Magyar](../hu/CLI.md) · [Български](../bg/CLI.md) · [Dansk](../da/CLI.md) · [한국어](../ko/CLI.md) · [العربية](../ar/CLI.md) · **हिन्दी**

> **गैर-आधिकारिक सामुदायिक परियोजना। DeepSeek से संबद्ध, अनुमोदित या प्रायोजित नहीं है।**
> DeepSeek नाम और चिह्न अपने संबंधित स्वामी के हैं।

यह पेज प्रकाशित CLI का दस्तावेज़ीकरण ठीक वैसे ही करता है जैसे वह वर्ज़न `1.0.1` में व्यवहार करता है। नीचे दिया गया हर
सिनॉप्सिस और फ्लैग प्रकाशित कमांड के अपने `--help` आउटपुट से आता है; यहां कुछ भी अप्रकाशित व्यवहार का वर्णन नहीं करता।
CLI इस रिपॉज़िटरी में [`cli/`](../../cli) के अंतर्गत विकसित किया जाता है और npm पर
[`omni-dsh-plugins`](https://www.npmjs.com/package/omni-dsh-plugins) के रूप में रिलीज़ किया जाता है, जिसके साथ एक
प्रोवेनेंस अटेस्टेशन होता है जो हर बिल्ड को उस कमिट और वर्कफ़्लो रन से जोड़ता है जिसने उसे बनाया।

```bash
npx omni-dsh-plugins --help
```

## v1.0.1 में डिज़ाइन सिद्धांत

- **डिफ़ॉल्ट रूप से रीड-ओनली।** `catalog`, `search`, `info`, `list` और `doctor` कभी भी प्रोफाइल में बदलाव नहीं करते,
  फ़ाइलें नहीं लिखते या प्लगइन कोड को स्पॉन नहीं करते।
- **कोड एग्ज़ीक्यूशन के लिए सहमति गेट।** `add`, `update` और `remove` तब तक DSH/pnpm लाइफ़साइकल कोड चलाने से इनकार
  करते हैं जब तक आप `--allow-code-execution` पास न करें। इसके बिना, सत्यापित योजना देखने के लिए `--dry-run` का
  उपयोग करें।
- **नेटिव Windows नीति।** कोड एग्ज़ीक्यूशन के साथ नेटिव Windows `add`/`update`/`remove` v1.0.1 में अक्षम हैं; WSL का
  उपयोग करें। ड्राई-रन और रीड-ओनली कमांड उपलब्ध रहते हैं, और नेटिव Windows रिकवरी मार्कर के लिए दस्तावेज़ीकृत मैनुअल
  रिकवरी आवश्यक है।
- **पिन किए गए इनपुट।** कैटलॉग इनपुट एक स्थानीय डायरेक्टरी, एक स्नैपशॉट फ़ाइल, या एक पिन किया गया सार्वजनिक स्नैपशॉट
  URL हो सकता है, वैकल्पिक रूप से एक सटीक 40-वर्ण रिविज़न पर लॉक किया गया।

## सामान्य विकल्प

ये विकल्प कैटलॉग-उपभोग करने वाले कमांड पर दिखाई देते हैं (`catalog validate`, `search`, `info`, `add`, `update`,
`remove`, `doctor`):

| विकल्प                    | अर्थ                                                            |
| ------------------------- | ------------------------------------------------------------------ |
| `--catalog <path-or-url>` | स्थानीय कैटलॉग डायरेक्टरी, स्नैपशॉट फ़ाइल, या पिन किया गया सार्वजनिक स्नैपशॉट URL |
| `--revision <sha>`        | सटीक 40-वर्ण स्नैपशॉट रिविज़न                               |
| `--json`                  | स्थिर JSON आउटपुट देता है                                            |

ग्लोबल विकल्प: `-V, --version` CLI वर्ज़न प्रिंट करता है; `-h, --help` किसी भी कमांड के लिए सहायता प्रिंट करता है
(`dsh-plugins help [command]` भी काम करता है)।

## एग्ज़िट कोड

CLI परंपरागत प्रोसेस एग्ज़िट कोड का उपयोग करता है:

| एग्ज़िट कोड | अर्थ                                                                    |
| --------: | -------------------------------------------------------------------------- |
| `0`       | सफलता (जिसमें "खाली लेकिन मान्य" परिणाम शामिल हैं, जैसे एक खाली कैटलॉग)     |
| `1`       | विफलता: वैलिडेशन एरर, एंट्री नहीं मिली, आवश्यक विकल्प गुम है, या कोई डायग्नोस्टिक जांच जो एरर की रिपोर्ट करती है |

v1.0.1 के साथ देखे गए उदाहरण: एक मान्य खाली कैटलॉग पर `catalog validate` `0 entries valid; catalog is empty` के
साथ `0` पर एग्ज़िट होता है; `info <unknown-id>` `Plugin not found` के साथ `1` पर एग्ज़िट होता है; जब कोई भी जांच (जैसे
गुम `dsh` एक्ज़ीक्यूटेबल) एरर की रिपोर्ट करती है तो `doctor` `1` पर एग्ज़िट होता है।

## कमांड

### `catalog` — सार्वजनिक कैटलॉग सतहों को मान्य करें

```text
dsh-plugins catalog validate [--catalog <path-or-url>] [--revision <sha>] [--json]
dsh-plugins catalog docs-check [root]
dsh-plugins catalog github-forms-check [root]
```

- **`catalog validate`** — कैटलॉग YAML और सिमेंटिक्स को मान्य करता है: सुरक्षित YAML पार्सिंग, सार्वजनिक स्कीमा, SPDX
  एक्सप्रेशन पार्सिंग, सटीक SemVer, SHA-512 SRI, और डुप्लिकेट ID / repository-node-plus-subpath अस्वीकृति। यह
  स्थानीय और रीड-ओनली है: यह GitHub से संपर्क नहीं करता, रिपॉज़िटरी पहचान हल नहीं करता या पिन की गई कमिट पर प्रमाण
  का निरीक्षण नहीं करता। यह ठीक वही कमांड है जिसे `catalog-validation` CI जॉब हर कैटलॉग पुल रिक्वेस्ट पर चलाता है।
- **`catalog docs-check [root]`** — जांचता है कि आवश्यक सार्वजनिक कैटलॉग दस्तावेज़ीकरण मौजूद है और Markdown fence
  संतुलित हैं।
- **`catalog github-forms-check [root]`** — संरचित सार्वजनिक GitHub इश्यू फ़ॉर्म (claim, correction, removal) की
  जांच करता है।

```bash
# रिपॉज़िटरी रूट से:
npx omni-dsh-plugins catalog validate --catalog .
npx omni-dsh-plugins catalog docs-check .
npx omni-dsh-plugins catalog github-forms-check .
```

### `search` — सार्वजनिक कैटलॉग फ़ील्ड को स्थानीय रूप से खोजें

```text
dsh-plugins search [options] <query...>
```

चुने गए कैटलॉग इनपुट के विरुद्ध स्थानीय रूप से सार्वजनिक कैटलॉग फ़ील्ड को खोजता है। मेल खाने वाली एंट्रीज़ प्रिंट
करता है, या जब कुछ मेल न खाए तो `No plugins found.` (एग्ज़िट `0`) प्रिंट करता है।

```bash
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins search notes markdown --catalog . --json
```

### `discover` — कैटलॉग से परे प्लगइन खोजें

```text
dsh-plugins discover [options] <query...>
```

> `discover` `1.0.0` में शिप होता है, इस पैकेज नाम के तहत पहली रिलीज़।

पहले क्यूरेटेड कैटलॉग खोजता है, फिर — जब तक `--offline` न दिया जाए — लाइव GitHub `dsh-plugin` टॉपिक, ताकि जो प्लगइन
अभी तक सबमिट नहीं किया गया है वह भी खोजा जा सके। कैटलॉग परिणाम वह प्रमाण रखते हैं जो कैटलॉग में मौजूद है (पिन की गई
कमिट, निर्माता, लाइसेंस); सामुदायिक परिणाम इनमें से कुछ भी नहीं रखते और उसी रूप में लेबल किए जाते हैं, क्योंकि उनके
बारे में कुछ भी समीक्षित नहीं किया गया है।

`--limit <n>` प्रति स्तर परिणामों को सीमित करता है (डिफ़ॉल्ट `8`)। `--json` स्थिर मशीन आकार देता है, जिसे कभी
लोकलाइज़ नहीं किया जाता।

```bash
npx omni-dsh-plugins discover memory --catalog .
npx omni-dsh-plugins discover vision --offline --catalog . --json
```

### `info` — एक सार्वजनिक कैटलॉग एंट्री दिखाएं

```text
dsh-plugins info [options] <id>
```

कैनोनिकल प्लगइन ID के अनुसार एक सार्वजनिक कैटलॉग एंट्री दिखाता है। जब ID कैटलॉग में नहीं है तो
`Plugin not found: <id>` के साथ `1` पर एग्ज़िट होता है।

```bash
npx omni-dsh-plugins info example-notes-search --catalog .
```

### `add` — आधिकारिक DSH डेलिगेशन के माध्यम से एक कैटलॉग प्लगइन जोड़ें

```text
dsh-plugins add [options] <id>
```

| विकल्प                   | अर्थ                                                            |
| ------------------------ | ------------------------------------------------------------------ |
| `--profile <name>`       | बदलने के लिए DSH प्रोफाइल (व्यवहार में आवश्यक; इसके बिना कमांड एरर देता है) |
| `--dry-run`              | बिना फ़ाइलों या सबप्रोसेस के सत्यापित योजना दिखाता है               |
| `--allow-code-execution` | DSH/pnpm लाइफ़साइकल कोड के लिए सहमति (नेटिव Windows पर अक्षम; WSL का उपयोग करें) |
| `--catalog` / `--revision` / `--json` | ऊपर दिए गए सामान्य विकल्प                                  |

इस वर्ज़न में ड्राई-रन सिमेंटिक्स: कमांड पिन की गई एंट्री के लिए योजना को हल और सत्यापित करता है और उसे प्रिंट करता है,
बिना कोई फ़ाइल बनाए और बिना कोई सबप्रोसेस स्पॉन किए। असली इंस्टॉलेशन आधिकारिक DSH टूलिंग को डेलिगेट करता है और केवल
`--allow-code-execution` के साथ आगे बढ़ता है।

```bash
# केवल प्रीव्यू — कुछ भी नहीं लिखा जाता, कुछ भी एग्ज़ीक्यूट नहीं होता:
npx omni-dsh-plugins add example-notes-search --profile default --dry-run

# असली इंस्टॉल — लाइफ़साइकल कोड के लिए स्पष्ट सहमति:
npx omni-dsh-plugins add example-notes-search --profile default --allow-code-execution
```

### `update` — आधिकारिक DSH डेलिगेशन के माध्यम से एक कैटलॉग प्लगइन अपडेट करें

```text
dsh-plugins update [options] <id>
```

`add` जैसे ही विकल्प और सहमति सिमेंटिक्स: `--profile <name>`, `--dry-run`, `--allow-code-execution`, साथ ही सामान्य
कैटलॉग विकल्प।

### `remove` — आधिकारिक DSH डेलिगेशन के माध्यम से एक कैटलॉग-प्रबंधित प्लगइन हटाएं

```text
dsh-plugins remove [options] <id>
```

`add` जैसे ही विकल्प और सहमति सिमेंटिक्स। केवल कैटलॉग-प्रबंधित इंस्टॉल हटाए जाते हैं।

### `recover` — बनाए रखे गए POSIX म्यूटेशन को रिकवर करें

```text
dsh-plugins recover
```

एक बाधित `add`/`update`/`remove` के बाद बनाए रखे गए POSIX म्यूटेशन को रिकवर करता है। जब कुछ भी पेंडिंग न हो तो यह
`No mutation recovery is pending.` प्रिंट करता है और `0` पर एग्ज़िट होता है। नेटिव Windows रिकवरी दस्तावेज़ीकृत नीति
के अनुसार मैनुअल ही रहती है।

### `list` — कैटलॉग-प्रबंधित इंस्टॉल की सूची दिखाएं

```text
dsh-plugins list [--profile <name>] [--json]
```

बिना प्रोफाइल में बदलाव किए कैटलॉग-प्रबंधित इंस्टॉल की सूची दिखाता है। `--profile <name>` DSH प्रोफाइल द्वारा
फ़िल्टर करता है। जब कोई इंस्टॉल न हो तो यह `No catalog-managed plugins installed.` प्रिंट करता है और `0` पर एग्ज़िट
होता है।

### `doctor` — रीड-ओनली डायग्नोस्टिक्स

```text
dsh-plugins doctor [--catalog <path-or-url>] [--revision <sha>] [--json]
```

रीड-ओनली Node, DSH, नेटिव Windows नीति और कैटलॉग डायग्नोस्टिक्स चलाता है। हर जांच `ok` या `error` की रिपोर्ट करती है;
कोई भी `error` समग्र एग्ज़िट कोड को `1` बना देता है। बिना `dsh` एक्ज़ीक्यूटेबल वाली मशीन पर उदाहरण आउटपुट:

```text
node [ok]: Node 24.16.0 is supported
dsh [error]: dsh executable was not found
catalog [ok]: catalog is valid and empty
```

## स्थानीय सत्यापन क्या सिद्ध नहीं करता

एक हरा (green) `catalog validate` रन केवल संरचना और स्थानीय सिमेंटिक्स की पुष्टि करता है। यह रिमोट रिपॉज़िटरी पहचान,
निर्माता स्वामित्व, या पिन की गई कमिट पर प्रमाण को सिद्ध नहीं करता — मेंटेनर किसी भी मर्ज से पहले वे अलग प्रोवेनेंस
गेट लागू करते हैं, जैसा [CONTRIBUTING.md](../../CONTRIBUTING.md) और [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md)
में वर्णित है।
