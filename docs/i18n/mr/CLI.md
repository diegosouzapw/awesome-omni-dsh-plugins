# CLI संदर्भ — `omni-dsh-plugins@1.0.1`

> 🌐 [English](../../docs/CLI.md) · [Português (Brasil)](../pt-BR/CLI.md) · [中文（简体）](../zh-CN/CLI.md) · **मराठी**

> **अनधिकृत समुदाय प्रकल्प. DeepSeek शी संलग्न नाही, त्यांच्याकडून मान्यताप्राप्त किंवा प्रायोजित नाही.**
> DeepSeek ची नावे आणि चिन्हे त्यांच्या संबंधित मालकांची आहेत.

हे पृष्ठ प्रकाशित CLI चे दस्तऐवजीकरण आवृत्ती `1.0.1` मधील तिच्या प्रत्यक्ष वर्तनाप्रमाणेच करते. खालील प्रत्येक
सारांश आणि फ्लॅग प्रकाशित कमांडच्या स्वतःच्या `--help` आउटपुटमधून आला आहे; इथे काहीही
अप्रकाशित वर्तनाचे वर्णन नाही. या रिपॉझिटरीमध्ये [`cli/`](../../cli) अंतर्गत विकसित केलेली ही CLI
npm वर [`omni-dsh-plugins`](https://www.npmjs.com/package/omni-dsh-plugins) म्हणून प्रकाशित केली जाते, प्रोव्हिनन्स
ॲटेस्टेशनसह जे प्रत्येक बिल्डला ती तयार करणारा कमिट आणि वर्कफ्लो रनशी जोडते.

```bash
npx omni-dsh-plugins --help
```

## v1.0.1 मधील डिझाइन तत्त्वे

- **मुळात फक्त-वाचनीय.** `catalog`, `search`, `info`, `list` आणि `doctor` कधीही प्रोफाइल्स
  बदलत नाहीत, फाइल्स लिहित नाहीत किंवा प्लगइन कोड चालवत नाहीत.
- **कोड एक्झिक्युशनसाठी संमती गेट.** `add`, `update` आणि `remove` तुम्ही `--allow-code-execution`
  दिल्याशिवाय DSH/pnpm लाइफसायकल कोड चालवण्यास नकार देतात. त्याशिवाय, पडताळलेली योजना पाहण्यासाठी
  `--dry-run` वापरा.
- **नेटिव्ह Windows धोरण.** कोड एक्झिक्युशनसह नेटिव्ह Windows `add`/`update`/`remove`
  v1.0.1 मध्ये अक्षम आहेत; WSL वापरा. ड्राय-रन आणि फक्त-वाचनीय कमांड्स उपलब्ध राहतात, आणि नेटिव्ह
  Windows रिकव्हरी मार्करना दस्तऐवजीकृत मॅन्युअल रिकव्हरी आवश्यक असते.
- **निश्चित केलेली इनपुट्स.** कॅटलॉग इनपुट स्थानिक निर्देशिका, स्नॅपशॉट फाइल किंवा निश्चित केलेली
  सार्वजनिक स्नॅपशॉट URL असू शकते, वैकल्पिकरित्या नेमक्या ४०-अक्षरी रिव्हिजनवर लॉक केलेली.

## सामान्य पर्याय

हे पर्याय कॅटलॉग-वापरणाऱ्या कमांड्सवर दिसतात (`catalog validate`, `search`, `info`,
`add`, `update`, `remove`, `doctor`):

| पर्याय                   | अर्थ                                                                 |
| ------------------------- | ------------------------------------------------------------------ |
| `--catalog <path-or-url>` | स्थानिक कॅटलॉग निर्देशिका, स्नॅपशॉट फाइल किंवा निश्चित केलेली सार्वजनिक स्नॅपशॉट URL |
| `--revision <sha>`        | नेमके ४०-अक्षरी स्नॅपशॉट रिव्हिजन                                   |
| `--json`                  | स्थिर JSON आउटपुट देते                                             |

जागतिक पर्याय: `-V, --version` CLI आवृत्ती छापते; `-h, --help` कोणत्याही कमांडसाठी मदत
छापते (`dsh-plugins help [command]` देखील कार्य करते).

## एक्झिट कोड्स

CLI पारंपारिक प्रोसेस एक्झिट कोड्स वापरते:

| एक्झिट कोड | अर्थ                                                                       |
| --------: | -------------------------------------------------------------------------- |
| `0`       | यश ("रिकामे पण वैध" परिणामांसह, जसे की रिकामा कॅटलॉग)                     |
| `1`       | अपयश: पडताळणी त्रुटी, एंट्री सापडली नाही, आवश्यक पर्याय गहाळ, किंवा निदान तपासणी त्रुटी नोंदवते |

v1.0.1 सह निरीक्षण केलेली उदाहरणे: वैध रिकाम्या कॅटलॉगवर `catalog validate` हे `0`
सह `0 entries valid; catalog is empty` एक्झिट करते; `info <unknown-id>` हे `1` सह `Plugin not found` एक्झिट करते;
`doctor` हे `1` एक्झिट करते जेव्हा कोणतीही तपासणी (जसे की गहाळ `dsh` एक्झिक्युटेबल) त्रुटी नोंदवते.

## कमांड्स

### `catalog` — सार्वजनिक कॅटलॉग पृष्ठभागांची पडताळणी करा

```text
dsh-plugins catalog validate [--catalog <path-or-url>] [--revision <sha>] [--json]
dsh-plugins catalog docs-check [root]
dsh-plugins catalog github-forms-check [root]
```

- **`catalog validate`** — कॅटलॉग YAML आणि सिमॅंटिक्सची पडताळणी करते: सुरक्षित YAML पार्सिंग, सार्वजनिक
  स्कीमा, SPDX अभिव्यक्ती पार्सिंग, अचूक SemVer, SHA-512 SRI, आणि डुप्लिकेट ID /
  रिपॉझिटरी-नोड-प्लस-सबपाथ नाकार. हे स्थानिक आणि फक्त-वाचनीय आहे: हे GitHub शी कनेक्ट होत
  नाही, रिपॉझिटरी ओळख निश्चित करत नाही किंवा निश्चित केलेल्या कमिटवरील पुराव्याची तपासणी करत नाही. हीच
  ती कमांड आहे जी `catalog-validation` CI जॉब प्रत्येक कॅटलॉग पुल रिक्वेस्टवर चालवतो.
- **`catalog docs-check [root]`** — आवश्यक सार्वजनिक कॅटलॉग दस्तऐवजीकरण अस्तित्वात आहे आणि
  Markdown फेन्सेस संतुलित आहेत हे तपासते.
- **`catalog github-forms-check [root]`** — संरचित सार्वजनिक GitHub इश्यू फॉर्म्स
  (क्लेम, करेक्शन, रिमूव्हल) तपासते.

```bash
# From the repository root:
npx omni-dsh-plugins catalog validate --catalog .
npx omni-dsh-plugins catalog docs-check .
npx omni-dsh-plugins catalog github-forms-check .
```

### `search` — सार्वजनिक कॅटलॉग फील्ड्स स्थानिक पातळीवर शोधा

```text
dsh-plugins search [options] <query...>
```

निवडलेल्या कॅटलॉग इनपुटविरुद्ध सार्वजनिक कॅटलॉग फील्ड्स स्थानिक पातळीवर शोधते. जुळणाऱ्या
एंट्रीज छापते, किंवा काहीही न जुळल्यास `No plugins found.` (एक्झिट `0`).

```bash
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins search notes markdown --catalog . --json
```

### `discover` — कॅटलॉगच्या पलीकडे प्लगइन शोधा

```text
dsh-plugins discover [options] <query...>
```

> `discover` हे `1.0.0` मध्ये आले, या पॅकेज नावाखालील पहिली रिलीज.

आधी क्युरेट केलेला कॅटलॉग शोधते, मग — `--offline` दिले नसल्यास — लाइव्ह GitHub
`dsh-plugin` टॉपिक, जेणेकरून अजून सादर न केलेले प्लगइन देखील शोधता येईल. कॅटलॉग निकाल
कॅटलॉगकडे असलेला पुरावा बाळगतात (निश्चित केलेला कमिट, निर्माता, परवाना); समुदाय निकाल
त्यापैकी काहीही बाळगत नाहीत आणि तसेच लेबल केले जातात, कारण त्यांच्याबद्दल काहीही पुनरावलोकन केलेले नाही.

`--limit <n>` प्रति स्तर निकाल मर्यादित करते (डीफॉल्ट `8`). `--json` स्थिर मशीन आकार देते, ज्याचे
कधीही स्थानिकीकरण होत नाही.

```bash
npx omni-dsh-plugins discover memory --catalog .
npx omni-dsh-plugins discover vision --offline --catalog . --json
```

### `info` — एक सार्वजनिक कॅटलॉग एंट्री दाखवा

```text
dsh-plugins info [options] <id>
```

प्रामाणिक प्लगइन ID द्वारे एक सार्वजनिक कॅटलॉग एंट्री दाखवते. कॅटलॉगमध्ये नसलेल्या ID साठी
`1` सह `Plugin not found: <id>` एक्झिट करते.

```bash
npx omni-dsh-plugins info example-notes-search --catalog .
```

### `add` — अधिकृत DSH डेलिगेशनद्वारे एक कॅटलॉग प्लगइन जोडा

```text
dsh-plugins add [options] <id>
```

| पर्याय                  | अर्थ                                                                 |
| ------------------------ | ------------------------------------------------------------------ |
| `--profile <name>`       | बदलण्याची DSH प्रोफाइल (प्रत्यक्षात आवश्यक; त्याशिवाय कमांड त्रुटी देते) |
| `--dry-run`              | फाइल्स किंवा सबप्रोसेसशिवाय पडताळलेली योजना दाखवा                    |
| `--allow-code-execution` | DSH/pnpm लाइफसायकल कोडसाठी संमती (नेटिव्ह Windows वर अक्षम; WSL वापरा) |
| `--catalog` / `--revision` / `--json` | वरील सामान्य पर्याय                                      |

या आवृत्तीतील ड्राय-रन सिमॅंटिक्स: कमांड निश्चित केलेल्या एंट्रीसाठी योजना निश्चित आणि पडताळून
छापते, कोणतीही फाइल न बनवता आणि कोणताही सबप्रोसेस न चालवता. प्रत्यक्ष इंस्टॉलेशन
अधिकृत DSH टूलिंगकडे सोपवले जाते आणि फक्त `--allow-code-execution` सह पुढे जाते.

```bash
# Preview only — nothing is written, nothing executes:
npx omni-dsh-plugins add example-notes-search --profile default --dry-run

# Real install — explicit consent to lifecycle code:
npx omni-dsh-plugins add example-notes-search --profile default --allow-code-execution
```

### `update` — अधिकृत DSH डेलिगेशनद्वारे एक कॅटलॉग प्लगइन अपडेट करा

```text
dsh-plugins update [options] <id>
```

`add` सारखेच पर्याय आणि संमती सिमॅंटिक्स: `--profile <name>`, `--dry-run`,
`--allow-code-execution`, तसेच सामान्य कॅटलॉग पर्याय.

### `remove` — अधिकृत DSH डेलिगेशनद्वारे एक कॅटलॉग-व्यवस्थापित प्लगइन काढा

```text
dsh-plugins remove [options] <id>
```

`add` सारखेच पर्याय आणि संमती सिमॅंटिक्स. फक्त कॅटलॉग-व्यवस्थापित इंस्टॉलेशन्स काढली जातात.

### `recover` — राखून ठेवलेले POSIX म्युटेशन पुनर्प्राप्त करा

```text
dsh-plugins recover
```

खंडित `add`/`update`/`remove` नंतर राखून ठेवलेले POSIX म्युटेशन पुनर्प्राप्त करते. काहीही
प्रलंबित नसल्यास ते `No mutation recovery is pending.` छापते आणि `0` एक्झिट करते. नेटिव्ह Windows रिकव्हरी
दस्तऐवजीकृत धोरणानुसार मॅन्युअलच राहते.

### `list` — कॅटलॉग-व्यवस्थापित इंस्टॉलेशन्स सूचीबद्ध करा

```text
dsh-plugins list [--profile <name>] [--json]
```

प्रोफाइल्स न बदलता कॅटलॉग-व्यवस्थापित इंस्टॉलेशन्स सूचीबद्ध करते. `--profile <name>` DSH
प्रोफाइलनुसार फिल्टर करते. इंस्टॉलेशन्स नसल्यास ते `No catalog-managed plugins installed.`
छापते आणि `0` एक्झिट करते.

### `doctor` — फक्त-वाचनीय निदान

```text
dsh-plugins doctor [--catalog <path-or-url>] [--revision <sha>] [--json]
```

फक्त-वाचनीय Node, DSH, नेटिव्ह Windows धोरण आणि कॅटलॉग निदाने चालवते. प्रत्येक तपासणी
`ok` किंवा `error` नोंदवते; कोणताही `error` एकूण एक्झिट कोड `1` करतो. `dsh`
एक्झिक्युटेबल नसलेल्या मशीनवरील उदाहरण आउटपुट:

```text
node [ok]: Node 24.16.0 is supported
dsh [error]: dsh executable was not found
catalog [ok]: catalog is valid and empty
```

## स्थानिक पडताळणी काय सिद्ध करत नाही

हिरवी `catalog validate` चाचणी फक्त रचना आणि स्थानिक सिमॅंटिक्सची पुष्टी करते. ती रिमोट
रिपॉझिटरी ओळख, निर्मात्याचे मालकत्व किंवा निश्चित केलेल्या कमिटवरील पुरावा सिद्ध करत नाही — मेंटेनर्स
कोणत्याही विलीनीकरणापूर्वी ते स्वतंत्र प्रोव्हिनन्स गेट्स लागू करतात, जसे
[CONTRIBUTING.md](../../CONTRIBUTING.md) आणि [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md) मध्ये वर्णन केले आहे.
