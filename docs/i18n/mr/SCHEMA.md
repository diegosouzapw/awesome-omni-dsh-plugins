# कॅटलॉग एंट्री स्कीमा संदर्भ

> 🌐 [English](../../docs/SCHEMA.md) · [Português (Brasil)](../pt-BR/SCHEMA.md) · [中文（简体）](../zh-CN/SCHEMA.md) · **मराठी**

> **अनधिकृत समुदाय प्रकल्प. DeepSeek शी संलग्न नाही, त्यांच्याकडून मान्यताप्राप्त किंवा प्रायोजित नाही.**
> DeepSeek ची नावे आणि चिन्हे त्यांच्या संबंधित मालकांची आहेत.

हे [`schemas/plugin.schema.yaml`](../../schemas/plugin.schema.yaml) साठी फील्ड-दर-फील्ड संदर्भ आहे,
ही सार्वजनिक JSON स्कीमा (draft 2020-12) आहे जिच्याविरुद्ध `catalog/plugins/` अंतर्गत प्रत्येक फाइल
पडताळली गेली पाहिजे. स्कीमा फाइल स्वतःच सत्याचा स्रोत आहे; जेव्हा हे पृष्ठ आणि स्कीमा
यांच्यात मतभेद असतो, तेव्हा स्कीमा जिंकते.

पडताळणीचे दोन स्तर लागू होतात. सार्वजनिक स्कीमा मर्यादित *सुरक्षित आकार* लागू करते (असे पॅटर्न आणि
लांबी जे ऑप्शनसारखी किंवा अमर्यादित मूल्ये नाकारतात). त्याच्या वर, `catalog validate` अनिवार्य
सिमॅंटिक पार्सर्स लागू करते: आवृत्त्यांसाठी अचूक SemVer, इंटेग्रिटी मूल्यांसाठी SHA-512 SRI,
परवान्यांसाठी SPDX अभिव्यक्ती पार्सिंग, आणि डुप्लिकेट-की नाकार. एखादे मूल्य स्कीमा
पॅटर्नशी जुळू शकते आणि तरीही सिमॅंटिकदृष्ट्या नाकारले जाऊ शकते.

टॉप-लेव्हल नियम: एंट्री ही एकच YAML ऑब्जेक्ट आहे, `additionalProperties: false` (अज्ञात
फील्ड्स नाकारले जातात), आणि खालील **सर्व** फील्ड्स आवश्यक आहेत.

## टॉप-लेव्हल फील्ड्स

| फील्ड           | प्रकार  | आवश्यक | सारांश                                                          |
| ----------------- | ------- | :------: | ------------------------------------------------------------- |
| `schemaVersion`   | const   |   होय    | नेमके `1` असले पाहिजे                                          |
| `id`              | string  |   होय    | लोअरकेस kebab-case एंट्री ID; फाइलनावाशी जुळला पाहिजे          |
| `name`            | string  |   होय    | प्रदर्शन नाव, 1–120 अक्षरे                                      |
| `description`     | object  |   होय    | क्युरेट केलेला इंग्रजी सारांश आणि त्याचा पुरावा पथ            |
| `unofficial`      | const   |   होय    | नेमके `true` असले पाहिजे                                       |
| `kind`            | enum    |   होय    | प्रामाणिक आर्टिफॅक्ट डिस्क्रिमिनेटर                            |
| `primaryCategory` | enum    |   होय    | एकमेव प्रमुख क्षमता श्रेणी                                      |
| `tags`            | array   |   होय    | अद्वितीय लोअरकेस kebab-case टॅग्स (रिकामे असू शकतात)           |
| `source`          | object  |   होय    | मूळ रिपॉझिटरी, नोड ID, सबपाथ आणि निश्चित केलेला कमिट          |
| `creator`         | object  |   होय    | निर्मात्याचा सार्वजनिक GitHub हँडल                              |
| `package`         | object  |   होय    | प्रामाणिक इंस्टॉल डिस्क्रिप्टर (npm **किंवा** सोर्स)           |
| `dsh`             | object  |   होय    | DSH प्रोफाइल्स आणि नेटिव्ह-एकत्रीकरण पुरावा पथ                 |
| `repositoryScope` | enum    |   होय    | `dedicated` किंवा `monorepo`                                   |
| `popularity`      | object  |   होय    | स्टार्स धोरण आणि स्टार संख्या (व्याप्तीवर सशर्त)               |
| `license`         | object  |   होय    | अपस्ट्रीम SPDX परवाना अभिव्यक्ती                              |
| `verification`    | object  |   होय    | पडताळणी स्थिती, तपासणी वेळ, ओळख आणि स्मोक टेस्ट               |
| `provenance`      | object  |   होय    | सार्वजनिक Discussion/comment URL किंवा `null`                  |

### `schemaVersion`

स्थिरांक `1`. सार्वजनिक स्कीमा आवृत्ती 1 ओळखते; इतर कोणतेही मूल्य अवैध आहे.

### `id`

`^[a-z0-9]+(?:-[a-z0-9]+)*$` शी जुळणारी स्ट्रिंग — लोअरकेस kebab-case, सुरुवातीला/शेवटी किंवा
दुहेरी हायफन्स नाहीत. [CONTRIBUTING.md](../../CONTRIBUTING.md) नुसार, एंट्री फाइलचे नाव
`catalog/plugins/<id>.yaml` हे सारख्याच मूल्यासह असले पाहिजे; व्हॅलिडेटर विसंगती नाकारतो
(`id-filename-mismatch`). ID निर्मात्याच्या नेमस्पेसने देखील सुरू झाला पाहिजे:
`creator.github` हँडल लोअरकेसमध्ये, `[a-z0-9]` बाहेरील प्रत्येक अक्षरसमूह एकाच
`-` मध्ये आकुंचित, आणि त्यानंतर `-` (`id-creator-prefix`).

### `name`

स्वैच्छिक प्रदर्शन नाव, `minLength: 1`, `maxLength: 120`.

### `description`

नेमक्या दोन आवश्यक प्रॉपर्टीज असलेली ऑब्जेक्ट (इतर कोणतीही मान्य नाही):

| प्रॉपर्टी    | प्रकार | नियम                                                                  |
| -------------- | ------ | --------------------------------------------------------------------- |
| `en`           | string | इंग्रजी सारांश, 20–320 अक्षरे                                          |
| `evidencePath` | string | रिपॉझिटरी-सापेक्ष पथ पॅटर्न; सुरुवातीला `/` नाही, बॅकस्लॅश नाहीत, `.`/`..` विभाग नाहीत |

इंग्रजी सारांश `evidencePath` वर जसा अस्तित्वात आहे तशा `source.commit` वरील फाइलमधून
क्युरेट केलेला असला पाहिजे — दुसऱ्या कॅटलॉगमधून कॉपी केलेला नाही.

### `unofficial`

स्थिरांक `true`. नोंदणी अनधिकृत आहे हे दर्शवणारे मशीन-वाचनीय चिन्ह.

### `kind`

**एकमेव** आर्टिफॅक्ट-प्रकार डिस्क्रिमिनेटर (दुसरे इंटेग्रेशन-काइंड फील्ड अस्तित्वात नाही). यापैकी एक:

`plugin` · `plugin-family` · `skin-theme` · `skill` · `preset-profile` · `client-interface` ·
`bridge-adapter` · `ecosystem-project`

अर्थ आणि क्रमवारी परिणाम [docs/CATEGORIES.md](../../docs/CATEGORIES.md) मध्ये परिभाषित आहेत.

### `primaryCategory`

तेरा क्षमता श्रेणींपैकी एक:

`user-interface-dashboards` · `memory-rag` · `search-research` · `coding-developer-tools` ·
`browser-automation` · `vision-audio-multimodal` · `sessions-productivity` ·
`security-permissions-approvals` · `diagnostics-observability` · `models-providers-routing` ·
`messaging-notifications` · `data-external-services` · `entertainment-customization`

प्रदर्शन लेबल्स आणि निवड मार्गदर्शन [docs/CATEGORIES.md](../../docs/CATEGORIES.md) मध्ये आहे.

### `tags`

अद्वितीय स्ट्रिंग्जचा अॅरे, प्रत्येक `^[a-z0-9]+(?:-[a-z0-9]+)*$` शी जुळणारी (लोअरकेस kebab-case).
स्कीमा किमान संख्या लादत नाही.

### `source`

नेमक्या चार आवश्यक प्रॉपर्टीज असलेली ऑब्जेक्ट:

| प्रॉपर्टी        | प्रकार         | नियम                                                                   |
| ------------------ | -------------- | ---------------------------------------------------------------------- |
| `repository`       | string         | `https://github.com/<owner>/<repo>` URL; owner GitHub वापरकर्तृत्व नाव नियमांचे पालन करतो, रिपॉझिटरी नाव 1–100 अक्षरे, `.`/`..` असू शकत नाही किंवा `.git` मध्ये संपू शकत नाही |
| `repositoryNodeId` | string         | अपरिवर्तनीय GitHub रिपॉझिटरी नोड ID, रिकामे नसावे                     |
| `subpath`          | string किंवा null | रिपॉझिटरीच्या आत प्लगइन सबपाथ (`evidencePath` सारखाच सुरक्षित सापेक्ष-पथ पॅटर्न), किंवा रिपॉझिटरी-रूट प्लगइनसाठी `null` |
| `commit`           | string         | पूर्ण ४०-अक्षरी हेक्झाडेसिमल कमिट OID                                 |

कॅटलॉग पडताळणीने `repositoryNodeId` निश्चित केले पाहिजे आणि रिपॉझिटरी URL विसंगती नाकारली
पाहिजे — ते निराकरण मेंटेनर-बाजूचे गेट आहे, स्थानिक संरचनात्मक तपासणीचा भाग नाही.

### `creator`

एकच आवश्यक प्रॉपर्टी असलेली ऑब्जेक्ट:

| प्रॉपर्टी | प्रकार | नियम                                              |
| -------- | ------ | ------------------------------------------------- |
| `github` | string | GitHub वापरकर्तृत्व नाव (1–39 अक्षरे, GitHub हँडल नियम) |

सार्वजनिक प्रोफाइल URL नेहमी `https://github.com/<handle>` म्हणून काढली जाते; दुसरे प्रोफाइल
फील्ड साठवले जात नाही, त्यामुळे दोन्ही कधीही वेगळे होऊ शकत नाहीत.

### `package`

प्रामाणिक इंस्टॉल डिस्क्रिप्टर. हा डेटा आहे, कधीही शेल कमांड नाही, आणि दोन आकारांपैकी नेमके एक घेतो
(`oneOf`):

**npm पॅकेज** — आवश्यक `ecosystem`, `name`, `version`; वैकल्पिक `integrity`:

| प्रॉपर्टी  | प्रकार | नियम                                                                       |
| ----------- | ----- | -------------------------------------------------------------------------- |
| `ecosystem` | const | `npm`                                                                      |
| `name`      | string | npm पॅकेज नाव आकार (वैकल्पिकरित्या स्कोप्ड), कमाल 214 अक्षरे               |
| `version`   | string | अचूक `x.y.z` आवृत्ती आकार (वैकल्पिक प्रिरिलीज/बिल्ड); रेंज नाकारल्या जातात. सिमॅंटिक स्तर अतिरिक्तरित्या पार्स करता येणारी, अचूक SemVer आवश्यक करतो |
| `integrity` | string | वैकल्पिक `sha512-…` SRI आकार, 8–256 अक्षरे. सिमॅंटिक स्तराने ते वैध SHA-512 SRI म्हणून पार्स केले पाहिजे |

**सोर्स इंस्टॉल** — फक्त आवश्यक `ecosystem`:

| प्रॉपर्टी  | प्रकार | नियम     |
| ----------- | ----- | -------- |
| `ecosystem` | const | `source` |

सोर्स डिस्क्रिप्टर जाणूनबुजून इतर काहीही साठवत नाही: रिपॉझिटरी, कमिट आणि सबपाथ
`source` मधून काढले जातात, त्यामुळे बदलणारी मूल्ये कधीही दुप्पट केली जात नाहीत.

### `dsh`

नेटिव्ह DSH एकत्रीकरण पुरावा:

| प्रॉपर्टी    | प्रकार | नियम                                                             |
| -------------- | ------ | -------------------------------------------------------------- |
| `profiles`     | array  | किमान एक अद्वितीय प्रोफाइल नाव जे `^[A-Za-z0-9][A-Za-z0-9._-]*$` शी जुळते |
| `evidencePath` | string | `source.commit` वरील DSH एकत्रीकरण पुराव्यासाठी सुरक्षित सापेक्ष पथ |

### `repositoryScope`

एकतर `dedicated` (रिपॉझिटरी स्टार्स या नेमक्या प्लगइनचे आहेत) किंवा `monorepo` (प्लगइन
मोठ्या प्रकल्पाच्या आत सबपाथ किंवा पॅकेज आहे). हे मूल्य खालील सशर्त लोकप्रियता
नियमांना चालना देते.

### `popularity`

| प्रॉपर्टी   | प्रकार          | नियम                                                 |
| ------------ | --------------- | ---------------------------------------------------- |
| `starsPolicy`| enum            | `exact-repository` किंवा `undefined-parent-repository` |
| `stars`      | integer किंवा null | अ-नकारात्मक पूर्णांक, किंवा `null`                   |

सशर्त नियम (स्कीमाच्या `allOf` ब्लॉक्सद्वारे लागू):

- `repositoryScope: monorepo` हे `starsPolicy: undefined-parent-repository` आणि
  `stars: null` **सक्तीचे** करते. पालक प्रकल्पाचे स्टार्स कधीही मोनोरेपो प्लगइनला दिले जात नाहीत.
- `repositoryScope: dedicated` हे `starsPolicy: exact-repository` आणि पूर्णांक
  `stars >= 0` **सक्तीचे** करते.

ही मूल्ये क्रमवारी निकषाला कसे खतपाणी घालतात यासाठी [docs/RANKING.md](../../docs/RANKING.md) पहा.

### `license`

| प्रॉपर्टी | प्रकार | नियम                                                             |
| -------- | ------ | -------------------------------------------------------------- |
| `spdx`   | string | SPDX अभिव्यक्ती आकार, 2–256 अक्षरे, सुरुवातीला हायफन नाही        |

स्कीमा फक्त सुरक्षित अक्षर-आकार लागू करते; कॅटलॉग पडताळणीने मूल्य खऱ्या SPDX अभिव्यक्ती पार्सरने
पार्स आणि नॉर्मलाइझ केले पाहिजे. निश्चित केलेल्या कमिटवर पुराव्यासह पूर्ण अपस्ट्रीम अभिव्यक्ती नोंदवा
(उदाहरणार्थ `Apache-2.0` किंवा `MIT OR GPL-3.0-only`).

### `verification`

पडताळणी `source.commit` वर लागू होते. चार आवश्यक प्रॉपर्टीज असलेली ऑब्जेक्ट:

| प्रॉपर्टी          | प्रकार         | नियम                                                   |
| -------------------- | -------------- | ------------------------------------------------------ |
| `status`             | enum           | `eligible` · `verified` · `stale` · `unavailable` · `archived` · `quarantined` |
| `checkedAt`          | string         | तपासणीचा `date-time` स्वरूपातील टाइमस्टॅम्प             |
| `repositoryIdentity` | const          | `resolved` असले पाहिजे                                  |
| `smokeTest`          | object किंवा null | स्मोक-टेस्ट रेकॉर्ड, किंवा पात्र टेस्ट नसल्यास `null`  |

अस्तित्वात असल्यास, `smokeTest` आवश्यक करतो:

| प्रॉपर्टी     | प्रकार | नियम                                                                  |
| --------------- | ------ | ----------------------------------------------------------------- |
| `installTarget` | const  | `canonical-install-descriptor` — बदलणारी मूल्ये दुप्पट न करता `package` किंवा निश्चित केलेल्या सोर्सचा संदर्भ घेतो |
| `check`         | object | आवश्यक `name` (पॅकेज-नाव आकार) आणि `version` (अचूक आवृत्ती आकार)    |
| `result`        | const  | `passed` — अयशस्वी स्मोक टेस्ट स्मोक टेस्ट म्हणून नोंदवली जात नाही   |

सशर्त नियम: `status: verified` ला नल-नसलेली `smokeTest` ऑब्जेक्ट **आवश्यक** आहे. पुनरावलोकनयोग्य
स्मोक पुरावा नसलेल्या एंट्रीज `status: eligible` आणि `smokeTest: null` वापरतात. कोणतीही स्थिती
मान्यता किंवा सुरक्षा प्रमाणपत्र नाही — [docs/RANKING.md](../../docs/RANKING.md) पहा.

### `provenance`

सार्वजनिक प्रोव्हिनन्स लिंक्स, प्रत्येक URI किंवा `null`:

| प्रॉपर्टी  | प्रकार        | नियम                                             |
| ------------ | ------------- | ------------------------------------------------ |
| `discussion` | string किंवा null | अस्तित्वात असल्यास सार्वजनिक Discussion URL     |
| `comment`    | string किंवा null | अस्तित्वात असल्यास सार्वजनिक टिप्पणी URL         |

## स्कीमा काय तपासत नाही

स्कीमा जाणूनबुजून स्थानिक आणि संरचनात्मक आहे. ती रिपॉझिटरी अस्तित्वात आहे का, नोड ID
URL शी जुळतो का, निश्चित केलेल्या कमिटवर पुरावा पथ अस्तित्वात आहेत का, स्टार
