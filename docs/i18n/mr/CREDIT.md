# निर्माता श्रेय आणि पुल रिक्वेस्ट प्राधान्य

> 🌐 [English](../../CREDIT.md) · [Português (Brasil)](../pt-BR/CREDIT.md) · [中文（简体）](../zh-CN/CREDIT.md) · **मराठी**

स्वतंत्र DSH काम त्याच्या निर्मात्यांकडून मालकी न घेता शोधण्यायोग्य बनवण्यासाठी कॅटलॉग
अस्तित्वात आहे. सार्वजनिक एंट्रीज मूळ रिपॉझिटरी आणि अपरिवर्तनीय सोर्स कमिटचा संदर्भ देतात.

## त्याच प्लगइनसाठी प्राधान्य

<!-- creator-first:direct-pr-supersedes-curation-and-automation -->

1. प्लगइन निर्मात्याने किंवा मालक संस्थेने उघडलेली पुल रिक्वेस्ट.
2. निर्मात्याने स्पष्टपणे मंजूर केलेली किंवा सह-लेखन केलेली समुदाय पुल रिक्वेस्ट.
3. विद्यमान वैध समुदाय पुल रिक्वेस्ट.
4. कॅटलॉग ऑटोमेशन पुल रिक्वेस्ट.
5. सार्वजनिक पुल रिक्वेस्ट नसलेला खाजगी उमेदवार.

निर्मात्याची थेट पुल रिक्वेस्ट नेहमी पसंतीची असते आणि त्याच प्रामाणिक प्लगइनसाठी कोणत्याही उघड्या
समुदाय क्युरेशन किंवा ऑटोमेशन पुल रिक्वेस्टपेक्षा वरचढ ठरते, कोणती आधी उघडली गेली किंवा
जास्त पुढे गेली आहे याची पर्वा न करता. निर्मात्याची पुल रिक्वेस्ट पुनरावलोकन साधन बनते; त्यांची ब्रँच कधीही
ओव्हरराइट, फोर्स-पुश किंवा क्युरेट केलेल्या पुल रिक्वेस्टमध्ये स्थानांतरित केली जात नाही. क्युरेट केलेली एंट्री आधीच
विलीन झाली असल्यास, इतिहास अखंड राहतो आणि निर्माता नवीन योगदानात ती दावा किंवा दुरुस्त करू शकतो.

## सार्वजनिक श्रेय

प्रत्येक कॅटलॉग एंट्री निर्मात्याचा सार्वजनिक GitHub हँडल, मूळ रिपॉझिटरी, रिपॉझिटरी
नोड ID, प्लगइन सबपाथ आणि पूर्ण निश्चित केलेला कमिट बाळगते. सार्वजनिक निर्माता प्रोफाइल दुसरी ओळख
म्हणून साठवण्याऐवजी एकाच हँडलमधून काढली जाते. वेगळा मेंटेनर प्रोव्हिनन्स
गेट नोड ID निश्चित करतो आणि रिपॉझिटरी URL विसंगती नाकारतो. पुल रिक्वेस्ट वर्णनात
`Created by @handle` असे नमूद करावे आणि सोर्स रिपॉझिटरी व सोर्स कमिट मेटाडेटा समाविष्ट करावा.

जो व्यक्ती डिस्कशनवर पोस्ट किंवा टिप्पणी करतो त्याला आपोआप निर्माता मानले जात नाही.
मालकी रिपॉझिटरी मालक किंवा संस्था, पॅकेज लेखकत्व, मॅनिफेस्ट
मेटाडेटा किंवा नेमक्या निश्चित केलेल्या सोर्स इतिहासाने समर्थित असली पाहिजे.

## Git ओळख

<!-- creator-first:source-bound-git-identity -->

कमिट लेखकत्व आणि पुल रिक्वेस्ट लेखकत्व वेगळे आहेत. निर्माता-उगम पुल रिक्वेस्ट
निर्मात्याला पुल रिक्वेस्ट लेखक म्हणून राखते, आणि त्यांचे कमिट्स लेखकत्व नैसर्गिकरित्या जतन करतात. मेंटेनर
किंवा ऑटोमेशन खाते कमिटर किंवा पडताळलेला सह-लेखक म्हणून दिसू शकते, पण निर्मात्याचे
लेखकत्व बदलू नये.

क्युरेट केलेल्या कमिटसाठी, निर्मात्याला Git लेखक म्हणून वापरा किंवा `Co-authored-by` ट्रेलर फक्त
तेव्हाच जोडा जेव्हा नेमकी ओळख सोर्स-बाउंड आणि सार्वजनिकरित्या पडताळण्यायोग्य असेल, जसे की
मूळ रिपॉझिटरीतील निर्मात्याच्या कमिटला आधीच जोडलेली ओळख. कधीही ईमेलचा अंदाज लावू नका, noreply
पत्ता बनवू नका किंवा अधिकृत सार्वजनिक स्रोताबाहेर सापडलेला खाजगी पत्ता वापरू नका.

पडताळलेली Git ओळख उपलब्ध नसल्यास, क्युरेटर किंवा ऑटोमेशन खाते कमिट लिहिते
आणि त्याऐवजी स्पष्ट दृश्यमान श्रेय देते: `Created by @handle`, जुळणारी सार्वजनिक प्रोफाइल आणि
एंट्री तसेच पुल रिक्वेस्टमध्ये मूळ रिपॉझिटरीची लिंक. दृश्यमान YAML श्रेय Git
ओळख मॅपिंगपासून स्वतंत्ररित्या नेहमीच आवश्यक आहे. नंतरची थेट निर्माता पुल रिक्वेस्ट उघडी
क्युरेट केलेली पुल रिक्वेस्ट तिचा कृत्रिम इतिहास वारशाने घेण्याऐवजी बदलते.

## आदरपूर्ण निर्माता उल्लेख

क्युरेट केलेली पुल रिक्वेस्ट तिच्या वर्णनात मूळ रिपॉझिटरी लिंकच्या शेजारी एक आदरपूर्ण सार्वजनिक
`@creator` उल्लेख वापरते. ती पुनरावलोकनासाठी किंवा बदली थेट पुल रिक्वेस्टसाठी आमंत्रित करू शकते.
उल्लेखाची पुनरावृत्ती करू नका, प्रचारात्मक इश्यू उघडू नका, क्रॉस-पोस्ट करू नका किंवा अनिच्छित थेट संदेश पाठवू नका.

## कॅटलॉग परवाना विरुद्ध अपस्ट्रीम परवाना

कॅटलॉग तथ्ये आणि संपादकीय YAML मेटाडेटा CC0-1.0 अंतर्गत समर्पित आहेत. ते समर्पण
अपस्ट्रीम प्लगइनचा परवाना बदलत नाही. अपस्ट्रीम कोड, दस्तऐवजीकरण, स्क्रीनशॉट्स, लोगो आणि इतर
सर्जनशील साहित्य त्यांच्या मूळ परवान्यांच्या आणि मालकांच्या अधीन राहते.
