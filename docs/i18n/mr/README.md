त्यांनी वापरलेली धोरणे बाळगते.

एका वेळी एक, मूळ निर्मात्याच्या रिपॉझिटरीमधून, निश्चित केलेल्या सोर्स कमिटसह आणि स्पष्ट श्रेयासह
दाखल होते.

## 🚀 CLI इंस्टॉल करा

```bash
npx @diegosouza.pw/dsh-plugins --help
```

स्कोप्ड पॅकेज `@diegosouza.pw/dsh-plugins@0.1.0` म्हणून प्रकाशित केलेले आहे आणि वरील कमांड आजची
प्रमाणित पद्धत आहे; इथे कोणतीही इंस्टॉलर स्क्रिप्ट होस्ट केलेली नाही.

### आज CLI वापरा

आवृत्ती 0.1.0 फक्त-वाचनीय शोध आणि पडताळणी कमांड्स, तसेच संमती-गेट केलेल्या इंस्टॉल कमांड्स पुरवते.
फ्लॅग्स, एक्झिट कोड्स आणि कोड-एक्झिक्युशन संमती गेटसह संपूर्ण कमांड संदर्भ [docs/CLI.md](../../docs/CLI.md)
मध्ये आहे.

| कमांड                        | हे काय करते                                                        | तुमच्या सिस्टीमला स्पर्श करते का?                    |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | कॅटलॉग YAML, स्कीमा आणि स्थानिक सिमॅंटिक्स पडताळते                   | नाही — फक्त-वाचनीय                          |
| `search <query...>`            | सार्वजनिक कॅटलॉग फील्ड्स स्थानिक पातळीवर शोधते                                | नाही — फक्त-वाचनीय                          |
| `info <id>`                    | एक सार्वजनिक कॅटलॉग एंट्री दाखवते                                       | नाही — फक्त-वाचनीय                          |
| `list`                         | प्रोफाइल न बदलता कॅटलॉग-व्यवस्थापित इंस्टॉलेशन्स सूचीबद्ध करते            | नाही — फक्त-वाचनीय                          |
| `doctor`                       | Node, DSH, नेटिव्ह Windows धोरण आणि कॅटलॉगचे फक्त-वाचनीय निदान  | नाही — फक्त-वाचनीय                          |
| `add <id> --profile <name> --dry-run` | फाइल्स किंवा सबप्रोसेसशिवाय पडताळलेली इंस्टॉल योजना दाखवते | नाही — ड्राय-रन                            |
| `add <id> --profile <name> --allow-code-execution` | अधिकृत DSH डेलिगेशनद्वारे इंस्टॉल करते        | होय — फक्त स्पष्ट संमती फ्लॅगसह   |

```bash
# Validate the catalog in this repository (what CI runs):
npx @diegosouza.pw/dsh-plugins@0.1.0 catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx @diegosouza.pw/dsh-plugins@0.1.0 search memory --catalog .
npx @diegosouza.pw/dsh-plugins@0.1.0 info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx @diegosouza.pw/dsh-plugins@0.1.0 add <plugin-id> --profile default --dry-run
```

बदल करणाऱ्या कमांड्स (`add`, `update`, `remove`) तुम्ही `--allow-code-execution` दिल्याशिवाय
कधीही प्लगइन लाइफसायकल कोड एक्झिक्यूट करत नाहीत. नेटिव्ह Windows वर, v0.1.0 मध्ये हे बदल अक्षम
केलेले आहेत; WSL वापरा. फक्त-वाचनीय आणि ड्राय-रन कमांड्स सर्वत्र कार्य करतात.

## 🔍 एखादा प्लगइन कॅटलॉगमध्ये कसा दाखल होतो

![एखादा प्लगइन कॅटलॉगमध्ये कसा दाखल होतो](../../docs/diagrams/catalog-flow-dark.svg#gh-dark-mode-only)
![एखादा प्लगइन कॅटलॉगमध्ये कसा दाखल होतो](../../docs/diagrams/catalog-flow-light.svg#gh-light-mode-only)

1. **एक प्लगइन, एक ब्रँच, एक पुल रिक्वेस्ट.** PR `catalog/plugins/` अंतर्गत नेमकी एकच YAML फाइल
   जोडते किंवा बदलते.
2. **निर्मात्याला प्राधान्य.** प्लगइनच्या निर्मात्याने किंवा मालक संस्थेने उघडलेल्या PR ला त्याच
   प्लगइनसाठी समुदाय क्युरेशन किंवा ऑटोमेशनपेक्षा नेहमीच प्राधान्य मिळते — पहा
   [docs/CREDIT.md](../../docs/CREDIT.md).
3. **मूळ स्रोतातील पुरावा.** प्रत्येक फील्ड निर्मात्याच्या रिपॉझिटरीमधून, निश्चित केलेल्या ४०-अक्षरी
   कमिटवर पुनर्रचित केले जाते: वर्णन, परवाना, DSH एकत्रीकरण, इंस्टॉल डिस्क्रिप्टर, स्टार्स.
4. **स्थानिक पडताळणी.** `catalog validate` रचना आणि स्थानिक सिमॅंटिक्स तपासते; हीच तपासणी
   `catalog-validation` हा CI job PR वर करतो.
5. **मेंटेनर गेट्स.** विलीनीकरणापूर्वी, मेंटेनर्स स्वतंत्रपणे रिपॉझिटरीची ओळख, निर्मात्याशी असलेला
   संबंध आणि निश्चित केलेला पुरावा पडताळतात. हिरवी स्थानिक पडताळणी आवश्यक आहे, पण ती कधीही पुरेशी
   नसते.

आवश्यक पुरावा, YAML नियम, स्टार्स धोरण, टक्कर हाताळणी आणि पुनरावलोकन गेट्ससह संपूर्ण करार
[CONTRIBUTING.md](../../CONTRIBUTING.md) मध्ये आहे. निर्णय कसे आणि कोणाकडून घेतले जातात हे
[docs/GOVERNANCE.md](../../docs/GOVERNANCE.md) मध्ये आहे.

## 📄 एका एंट्रीची रचना

प्रत्येक एंट्री ही तिच्या ID नुसार नावाची एक YAML फाइल आहे. खालील उदाहरण सध्याच्या स्कीमाविरुद्ध
पडताळले जाते (फील्ड-दर-फील्ड संदर्भासाठी [docs/SCHEMA.md](../../docs/SCHEMA.md)):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

स्कीमाद्वारे लागू केलेले प्रमुख अपरिवर्तनीय नियम:

- `unofficial: true` आणि `schemaVersion: 1` हे स्थिरांक आहेत.
- मोनोरेपो प्लगइनने `stars: null` वापरलेच पाहिजे — पालक प्रकल्पाचे स्टार्स कधीही वारशाने मिळत नाहीत.
- इंस्टॉल डिस्क्रिप्टर हे एकतर अचूक-आवृत्तीचे npm पॅकेज आहे किंवा निश्चित केलेला स्रोत स्वतः; हा डेटा
  आहे, कधीही शेल कमांड नाही.
- `verified` स्थितीसाठी पुनरावलोकनयोग्य स्मोक-टेस्ट पुरावा आवश्यक आहे; अन्यथा एंट्री `smokeTest: null`
  सह `eligible` असते.

## 🗂 इथे काय समाविष्ट आहे

हे रिपॉझिटरी DeepSeek Harness (DSH) साठी स्वतंत्रपणे प्रकाशित केलेल्या एकत्रीकरणांची कॅटलॉगिंग
करते, ज्यात नेटिव्ह प्लगइन, प्लगइन कुटुंबे, थीम्स, skills, क्लायंट्स आणि ब्रिज यांचा समावेश आहे.
आर्टिफॅक्ट प्रकार, क्षमता श्रेणी आणि इंटरफेस टॅग्स [docs/CATEGORIES.md](../../docs/CATEGORIES.md)
मध्ये परिभाषित केले आहेत.

प्रत्येक सार्वजनिक रेकॉर्ड ही `catalog/plugins/` अंतर्गत एक YAML फाइल आहे आणि तिने
`schemas/plugin.schema.yaml` विरुद्ध पडताळली गेली पाहिजे. एखादी नोंद म्हणजे दस्तऐवजीकृत पात्रता
किंवा पडताळणी तपासण्या पूर्ण झाल्या आहेत असे सूचित करते; हे सुरक्षा प्रमाणपत्र किंवा DeepSeek कडून
मान्यता नाही.

## 🏅 क्रमवारी आणि पडताळणी

फक्त समर्पित, नेटिव्ह, पात्र किंवा पडताळलेल्या प्लगइन रिपॉझिटरीज ज्यांचे स्टार्स त्याच अचूक
रिपॉझिटरीचे आहेत तेच स्टार क्रमवारीत समाविष्ट होऊ शकतात. मोठ्या मोनोरेपोंमध्ये साठवलेले
एकत्रीकरण शोधण्यायोग्य राहतात पण `stars: null` वापरतात आणि पालक प्रकल्पाचे स्टार्स कधीही वारशाने
मिळवत नाहीत. संपूर्ण निकषासाठी पहा [docs/RANKING.md](../../docs/RANKING.md).

सार्वजनिक पडताळणी स्थिती संरचनात्मक पात्रता आणि इंस्टॉलेशन स्मोक-टेस्ट यांच्यात फरक करते. कोणतीही
स्थिती परिपूर्ण सुरक्षिततेचे प्रतिनिधित्व करत नाही. वापरण्यापूर्वी प्लगइनची रिपॉझिटरी, निश्चित
केलेला कमिट, परवाना आणि इंस्टॉलेशन वर्तन तपासा.

## 🤝 योगदान द्या किंवा एखादी एंट्री दावा करा

पुल रिक्वेस्ट उघडण्यापूर्वी [CONTRIBUTING.md](../../CONTRIBUTING.md) वाचा. पुल रिक्वेस्टने नेमकी
एक प्लगइन एंट्री जोडली किंवा बदलली पाहिजे आणि दुसऱ्या कॅटलॉगऐवजी मूळ निर्मात्याच्या रिपॉझिटरीचा
संदर्भ दिला पाहिजे. निर्मात्याने लिहिलेल्या पुल रिक्वेस्ट्सना स्वयंचलित कॅटलॉग पुल रिक्वेस्ट्सपेक्षा
प्राधान्य मिळते.

निर्माता दावे, दुरुस्त्या आणि काढून टाकण्यासाठी संरचित इश्यू फॉर्म्स उपलब्ध आहेत. कधीही क्रेडेन्शियल्स,
खाजगी संपर्क तपशील किंवा इतर गुपिते सबमिट करू नका.
