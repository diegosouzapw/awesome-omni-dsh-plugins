## De un vistazo

| Surface     | Qué es                                                       | Dónde                                                                    |
| ----------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **Sitio web** | Navegador del catálogo renderizado con búsqueda y clasificación                 | [dsh-plugins.omniroute.online](https://dsh-plugins.omniroute.online)     |
| **Catálogo** | Un archivo YAML por plugin, la única fuente de verdad             | [`catalog/plugins/`](../../catalog/plugins)                                    |
| **Esquema**  | JSON Schema público (draft 2020-12) contra el que valida cada entrada | [`schemas/plugin.schema.yaml`](../../schemas/plugin.schema.yaml)               |
| **CLI**     | Busca, inspecciona, valida e instala desde el catálogo           | [`omni-dsh-plugins`](https://www.npmjs.com/package/omni-dsh-plugins) |
| **Feeds para máquinas** | `catalog.json` + `catalog.snapshot.json` para herramientas           | [catalog.json](https://dsh-plugins.omniroute.online/catalog.json) · [catalog.snapshot.json](https://dsh-plugins.omniroute.online/catalog.snapshot.json) |

Este repositorio es la fuente pública de verdad del catálogo. Cada listado es un archivo YAML
bajo `catalog/plugins/`, validado frente a un JSON Schema publicado, añadido mediante una pull
request revisada individualmente, y siempre acreditado al creador original del plugin.
Nada en el catálogo se genera a partir de otro catálogo o lista: cada entrada se reconstruye
a partir del repositorio original del creador, en un commit fijado.

El sitio web y la CLI se mantienen desde código fuente privado; este repositorio contiene los
datos públicos del catálogo, el esquema y las políticas que consumen.

## 🚀 Instala la CLI

```bash
npx omni-dsh-plugins --help
```

El paquete con ámbito se publica como `omni-dsh-plugins@1.0.1` y el comando anterior es
la invocación canónica hoy; aquí no se aloja ningún script de instalación.

### Usa la CLI hoy

La versión 1.0.1 incluye comandos de descubrimiento y validación de solo lectura, además de
comandos de instalación protegidos por consentimiento. La referencia completa de comandos,
incluidos los flags, los códigos de salida y la puerta de consentimiento para la ejecución de
código, está en [docs/CLI.md](../../docs/CLI.md).

| Comando                        | Qué hace                                                        | ¿Afecta tu sistema?                    |
| ------------------------------ | ------------------------------------------------------------------- | ---------------------------------------- |
| `catalog validate --catalog .` | Valida el YAML del catálogo, el schema y la semántica local          | No — solo lectura                       |
| `search <query...>`            | Busca campos públicos del catálogo localmente                        | No — solo lectura                       |
| `info <id>`                    | Muestra una entrada pública del catálogo                             | No — solo lectura                       |
| `list`                         | Lista las instalaciones gestionadas por el catálogo sin modificar perfiles | No — solo lectura                  |
| `doctor`                       | Diagnósticos de solo lectura de Node, DSH, política nativa de Windows y catálogo | No — solo lectura           |
| `add <id> --profile <name> --dry-run` | Muestra el plan de instalación verificado sin archivos ni subprocesos | No — dry-run                     |
| `add <id> --profile <name> --allow-code-execution` | Instala mediante delegación oficial a DSH          | Sí — solo con el flag de consentimiento explícito |

```bash
# Validate the catalog in this repository (what CI runs):
npx omni-dsh-plugins catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx omni-dsh-plugins add <plugin-id> --profile default --dry-run
```

Los comandos que modifican el sistema (`add`, `update`, `remove`) nunca ejecutan código del ciclo
de vida del plugin a menos que pases `--allow-code-execution`. En Windows nativo, esas
mutaciones están desactivadas en la v1.0.1; usa WSL. Los comandos de solo lectura y de
simulación (dry-run) funcionan en todas partes.

## 🔍 Cómo entra un plugin al catálogo

![How a plugin enters the catalog](../../docs/diagrams/catalog-flow-dark.svg#gh-dark-mode-only)
![How a plugin enters the catalog](../../docs/diagrams/catalog-flow-light.svg#gh-light-mode-only)

1. **Un plugin, una rama, una pull request.** La PR añade o cambia exactamente un archivo YAML
   en `catalog/plugins/`.
2. **Prioridad al creador.** Una PR abierta por el creador del plugin o por la organización
   propietaria siempre tiene precedencia sobre la curación comunitaria o la automatización para
   el mismo plugin — ver [docs/CREDIT.md](../../docs/CREDIT.md).
3. **Evidencia de la fuente original.** Cada campo se reconstruye a partir del repositorio del
   creador, en un commit fijado de 40 caracteres: descripción, licencia, integración con DSH,
   descriptor de instalación, estrellas.
4. **Validación local.** `catalog validate` comprueba la estructura y la semántica local; es la
   misma comprobación que ejecuta el job de CI `catalog-validation` sobre la PR.
5. **Puertas de los mantenedores.** Antes de fusionar, los mantenedores verifican por separado
   la identidad del repositorio, el vínculo con el creador y la evidencia fijada. Una validación
   local en verde es necesaria, pero nunca suficiente.

El contrato completo — evidencia requerida, reglas del YAML, política de estrellas, manejo de
colisiones y las puertas de revisión — está en [CONTRIBUTING.md](../../CONTRIBUTING.md). Cómo se
toman las decisiones y por quién está en [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md).

## 📄 Anatomía de una entrada

Cada entrada es un archivo YAML nombrado según su ID. El siguiente ejemplo valida frente al
esquema actual (referencia campo por campo en [docs/SCHEMA.md](../../docs/SCHEMA.md)):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

Invariantes clave impuestas por el esquema:

- `unofficial: true` y `schemaVersion: 1` son constantes.
- Un plugin de monorepo debe usar `stars: null` — las estrellas del proyecto principal nunca
  se heredan.
- El descriptor de instalación es un paquete npm de versión exacta o la propia fuente fijada;
  son datos, nunca un comando de shell.
- El estado `verified` requiere evidencia revisable de una prueba de humo; de lo contrario,
  la entrada es `eligible` con `smokeTest: null`.

## 🗂 Qué pertenece aquí

Este repositorio cataloga integraciones publicadas de forma independiente para DeepSeek Harness
(DSH), incluidos plugins nativos, familias de plugins, temas, skills, clientes y puentes. Los
tipos de artefacto, categorías de capacidad y etiquetas de interfaz se definen en
[docs/CATEGORIES.md](../../docs/CATEGORIES.md).

Cada registro público es un archivo YAML bajo `catalog/plugins/` y debe validar frente a
`schemas/plugin.schema.yaml`. Un listado significa que se completaron las comprobaciones
documentadas de elegibilidad o verificación; no es una certificación de seguridad ni un
respaldo de DeepSeek.

## 🏅 Clasificación y verificación

Solo los repositorios de plugins dedicados, nativos, elegibles o verificados, con estrellas
pertenecientes exactamente a ese repositorio, pueden entrar en una clasificación por estrellas.
Las integraciones almacenadas dentro de monorepos más amplios siguen siendo detectables, pero
usan `stars: null` y nunca heredan las estrellas del proyecto principal. Consulta
[docs/RANKING.md](../../docs/RANKING.md) para el predicado completo.

Los estados públicos de verificación distinguen la elegibilidad estructural de una prueba de
humo de instalación. Ningún estado representa una seguridad absoluta. Revisa el repositorio del
plugin, el commit fijado, la licencia y el comportamiento de instalación antes de usarlo.

## 🤝 Contribuye o reclama una entrada

Lee [CONTRIBUTING.md](../../CONTRIBUTING.md) antes de abrir una pull request. Una pull request
debe añadir o cambiar exactamente una entrada de plugin y debe citar el repositorio original del
creador, no otro catálogo. Las pull requests hechas por el creador tienen precedencia sobre las
pull requests automatizadas del catálogo.

Hay formularios de issue estructurados disponibles para reclamaciones de creadores, correcciones
y eliminaciones. Nunca envíes credenciales, datos de contacto privados u otros secretos.
