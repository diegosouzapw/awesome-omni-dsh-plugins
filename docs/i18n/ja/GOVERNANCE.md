# カタログのガバナンス

> 🌐 [English](../../GOVERNANCE.md) · [Português (Brasil)](../pt-BR/GOVERNANCE.md) · [中文（简体）](../zh-CN/GOVERNANCE.md) · **日本語**

> **これは非公式のコミュニティプロジェクトです。DeepSeek とは提携・承認・スポンサー関係はありません。**
> DeepSeek の名称および商標は、それぞれの権利者に帰属します。

公開カタログがどのように統治されているか: 何が掲載されるかを誰が決めるのか、競合する貢献がどのような順
序で尊重されるのか、どのチェックが自動的に実行されるのか、そしてどの判断が人間の手に残されるのか。ここで
参照されているポリシーは [CONTRIBUTING.md](../../CONTRIBUTING.md)、[docs/CREDIT.md](../../docs/CREDIT.md)、
[docs/RANKING.md](../../docs/RANKING.md) にあります。このページは、それらがどのように組み合わさっている
かを説明します。

## 原則

1. **クリエイター最優先。** このカタログは、クリエイターの作品を発見可能にするために存在するのであり、
   それを所有することは決してありません。同一の正規プラグインについて、クリエイター自身による直接のプル
   リクエストは、開いているコミュニティによるキュレーションや自動化のプルリクエストに優先します — 完全
   な優先順位とGitアイデンティティのルールは [docs/CREDIT.md](../../docs/CREDIT.md) にあります。
2. **1つのプラグイン、1件のレビュー済みプルリクエスト。** バッチマージや、公開カタログへの生成された一括
   インポートは一切行いません。各エントリは、それぞれ独自のレビューを経ます。
3. **信頼よりも証拠。** すべての公開フィールドは、固定されたコミットにおける元のクリエイターのリポジトリ
   まで遡ることができます。自動チェックが緑であることは、出所の証明として決して受け入れられません。
4. **常に非公式。** いかなるカタログの状態も、DeepSeek によるレビュー、認証、または推奨として提示される
   ことはありません。

## 変更が `main` に反映される仕組み

すべての変更は、レビュー済みのプルリクエストを通じて `main` に反映されます — 直接プッシュはありません。
デフォルトブランチに対する運用ポリシーは以下のとおりです:

- **プルリクエストのみ。** カタログエントリ、ドキュメント、スキーマの変更はすべてPRを通じて行われます。
  カタログのPRは、[CONTRIBUTING.md](../../CONTRIBUTING.md) にある「1ブランチにつき1プラグイン」のルール
  に従わなければなりません。
- **線形の履歴。** PRは、`main` が線形の、監査可能な履歴を保つように統合されます。マージされた公開履歴が
  書き換えられることはありません。クリエイターが名乗り出る前にキュレートされたエントリがマージされてい
  た場合、クリエイターは履歴を書き換えるのではなく、その後の貢献の中でそれをクレームまたは修正します。
- **レビュースレッドの解決。** レビューの会話はマージ前に解決されます。未解決のフィードバックは統合をブ
  ロックします。
- **メンテナーによるマージ。** プラグインエントリをマージするのはメンテナーのみであり、それも
  [CONTRIBUTING.md](../../CONTRIBUTING.md) → 「レビューゲート、衝突、マージ」にあるすべてのゲートが、現
  在のPRコミットに対して合格した後に限られます。

## `catalog-validation` チェック

`catalog/plugins/`、`schemas/`、またはワークフロー自体に触れるすべてのプルリクエストは、公開されたCLIに
固定された `catalog-validation` ジョブ (`.github/workflows/validate-catalog.yml`) を実行します:

```bash
npx --yes omni-dsh-plugins catalog validate --catalog .
```

**これが検証するもの** — ローカルな構造とセマンティクスのみです:

- `catalog/plugins/` 配下のすべてのエントリの安全なYAMLパース。
- 公開スキーマへの準拠(詳しくは [docs/SCHEMA.md](../../docs/SCHEMA.md) を参照)。
- SPDX表記のパース、正確なSemVerバージョン、有効なSHA-512 SRIのintegrity値。
- 重複の拒否: 繰り返されるエントリIDや、繰り返される正規のリポジトリノード+サブパスのキーがないこと。
- 意図的なゼロエントリのカタログが合格すること(`0 entries valid; catalog is empty`)。

**これが検証しないもの** — したがって、チェックが緑であっても決して証明されないもの:

- リモートのリポジトリの識別情報: GitHubに接続したり、URLに対してリポジトリノードIDを解決したりすること
  はありません。
- 固定されたコミットにおける証拠: 説明、ライセンス、DSH統合、スモークテストの証拠は、取得も検査もされま
  せん。
- クリエイターの所有権、スター数、または開いているプルリクエストとの衝突。

これらの判断は、マージ前に適用される、メンテナーの別個の来歴ゲートに属し、
[CONTRIBUTING.md](../../CONTRIBUTING.md) に記載されています。ローカルチェックは最低基準であり、合格基準
そのものではありません。

## 検証ステータス

検証は、公開スキーマで定義されたステータス(`eligible`、`verified`、`stale`、`unavailable`、
`archived`、`quarantined`)を使用して、各エントリのその正確な固定コミットに対して記録されます。2つの肯定
的なステータスは、意図的に狭く定義されています:

- `eligible` — 公開された構造とネイティブDSH統合が検証されました。
- `verified` — それに加えて、固定されたソースまたはパッケージについてインストールのスモークテストが合格
  しました。スキーマは、スモークテストの記録が存在することを要求します。

どちらのステータスも — 他のいかなるステータスも — 推奨、保証、またはセキュリティ認証ではありません。ラ
ンキングとステータスがどのように相互作用するかを含む完全な意味論は [docs/RANKING.md](../../docs/RANKING.md)
に、記録の形式は [docs/SCHEMA.md](../../docs/SCHEMA.md) にあります。

## クレーム、修正、削除

構造化されたGitHub issueフォーム (`.github/ISSUE_TEMPLATE/`) は、自分が提出していないエントリを変更する
ための、統治された経路です:

| フォーム | 誰が使用するか | 結果 |
| -------------- | ---------------------------------------- | ----------------------------------------------------- |
| **クレーム** | 自分のプラグインが他の誰かによってキュレートされたクリエイター | 所有権が元のソースに紐付けられ、クリエイターはその後直接貢献できるようになります |
| **修正** | 不正確な公開メタデータを見つけた人 | 影響を受けるエントリへのレビュー済みの修正 |
| **削除** | 自分の掲載の削除を望むクリエイター、またはポリシー違反の報告者 | エントリのレビュー済みの削除または隔離 |

この3つのフローすべてに適用されるルール:

- 所有権の主張は、検証可能な公開の証拠(リポジトリの所有権、パッケージの著者情報、マニフェストのメタデー
  タ、または固定されたソースの履歴)によって裏付けられなければなりません — Discussionへのコメントは、ク
  リエイターであることを立証しません([docs/CREDIT.md](../../docs/CREDIT.md))。
- 掲載されているプラグインのセキュリティ上の問題は、まずそのプラグイン自身のメンテナーに報告されます。カ
  タログ側は、その後、エクスプロイトの詳細を公開することなく、修正または隔離を処理します
  ([SECURITY.md](../../SECURITY.md))。
- フォームに認証情報、個人の連絡先情報、その他の秘密情報を決して含めないでください。

## 役割

- **クリエイター** は、自分のプラグインとその掲載の優先順位を所有します。直接貢献したり、コミュニティに
  よるキュレーションを承認したり、既存のエントリをクレーム/修正/削除したりできます。
- **コミュニティの貢献者** は、[docs/CREDIT.md](../../docs/CREDIT.md) にある敬意ある連絡とクレジットのル
  ールの下で、まだ貢献していないクリエイターのためにエントリをキュレートできます。キュレーションが、その
  後の直接のクリエイターによる貢献より優先されることは決してありません。
- **メンテナー** は、レビューを行い、来歴ゲートを適用し、衝突を解決し、マージを行います。彼らはまた、非
  公開のソースから、ウェブサイト ([dsh-plugins.omniroute.online](https://dsh-plugins.omniroute.online))
  と公開されたCLIを保守します。このリポジトリの公開データ、スキーマ、ポリシーは、それらの表面が利用する
  ものです。
