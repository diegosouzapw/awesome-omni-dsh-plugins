# Указание авторства создателя и приоритет pull request'ов

> 🌐 [English](../../CREDIT.md) · [Português (Brasil)](../pt-BR/CREDIT.md) · [中文（简体）](../zh-CN/CREDIT.md) · **Русский**

Каталог существует, чтобы сделать независимую работу над DSH доступной для обнаружения, не
отбирая право собственности у её создателей. Публичные записи ссылаются на оригинальный
репозиторий и неизменяемый исходный коммит.

## Приоритет для одного и того же плагина

<!-- creator-first:direct-pr-supersedes-curation-and-automation -->

1. Pull request, открытый создателем плагина или владеющей организацией.
2. Pull request сообщества, явно одобренный или соавторизованный создателем.
3. Существующий действительный pull request сообщества.
4. Pull request автоматизации каталога.
5. Приватный кандидат без публичного pull request'а.

Прямой pull request создателя всегда предпочтителен и имеет приоритет над любым открытым
кураторством сообщества или pull request'ом автоматизации для того же канонического плагина,
независимо от того, какой из них был открыт первым или продвинулся дальше. Pull request
создателя становится инструментом рецензии; его ветка никогда не перезаписывается, не
force-пушится и не пересаживается в курированный pull request. Если курированная запись уже
слита, история остаётся нетронутой, и создатель может заявить права на неё или исправить её в
новом вкладе.

## Публичное указание авторства

Каждая запись каталога несёт публичный GitHub-хендл создателя, оригинальный репозиторий, node
ID репозитория, подпуть плагина и полный закреплённый коммит. Публичный профиль создателя
выводится из единственного хендла, а не хранится как вторая идентичность. Отдельный барьер
происхождения мейнтейнера разрешает node ID и отклоняет несовпадение URL репозитория. Описания
pull request'ов должны содержать `Created by @handle` и включать метаданные исходного
репозитория и исходного коммита.

Человек, который публикует сообщение или комментирует в Discussion, автоматически не
считается создателем. Право собственности должно подтверждаться владельцем репозитория или
организации, авторством пакета, метаданными манифеста или точной закреплённой историей
источника.

## Git-идентичность

<!-- creator-first:source-bound-git-identity -->

Авторство коммита и авторство pull request'а — это разные вещи. Pull request, исходящий от
создателя, сохраняет создателя как автора pull request'а, а его коммиты естественным образом
сохраняют авторство. Аккаунт мейнтейнера или автоматизации может указываться как коммиттер или
как верифицированный соавтор, но не должен заменять авторство создателя.

Для курированного коммита используйте создателя как Git-автора или добавляйте трейлер
`Co-authored-by` только тогда, когда точная идентичность привязана к источнику и публично
проверяема, например идентичность, уже прикреплённая к коммиту создателя в оригинальном
репозитории. Никогда не угадывайте email, не изобретайте noreply-адрес и не используйте
приватный адрес, найденный вне авторизованного публичного источника.

Когда верифицированная Git-идентичность недоступна, куратор или аккаунт автоматизации
авторизует коммит и вместо этого даёт явное видимое указание авторства: `Created by @handle`,
соответствующий публичный профиль и ссылку на оригинальный репозиторий в записи и pull
request'е. Видимое указание авторства в YAML требуется всегда, независимо от сопоставления
Git-идентичности. Последующий прямой pull request создателя заменяет открытый курированный
pull request, а не наследует его синтетическую историю.

## Уважительное упоминание создателя

Курированный pull request использует одно уважительное публичное упоминание `@создатель` в
своём описании рядом со ссылкой на оригинальный репозиторий. Он может приглашать к рецензии или
к замене прямым pull request'ом. Не повторяйте упоминание, не открывайте промо-issue, не
делайте кросс-постинг и не отправляйте нежелательные личные сообщения.

## Лицензия каталога против upstream-лицензии

Факты каталога и редакторские YAML-метаданные переданы в общественное достояние по CC0-1.0. Эта
передача не меняет лицензию upstream-плагина. Upstream-код, документация, скриншоты, логотипы и
другие творческие материалы остаются под действием своих оригинальных лицензий и принадлежат
своим владельцам.
