# Справочник CLI — `omni-dsh-plugins@1.0.1`

> 🌐 [English](../../CLI.md) · [Português (Brasil)](../pt-BR/CLI.md) · [中文（简体）](../zh-CN/CLI.md) · **Русский**

> **Неофициальный проект сообщества. Не аффилирован, не одобрен и не спонсируется DeepSeek.**
> Имена и товарные знаки DeepSeek принадлежат их соответствующим владельцам.

Эта страница документирует опубликованный CLI именно так, как он ведёт себя в версии `1.0.1`.
Каждый синопсис и флаг ниже взяты из собственного вывода `--help` опубликованной команды; ничто
здесь не описывает нереализованное поведение. CLI разрабатывается в этом репозитории в
[`cli/`](../../cli) и публикуется в npm как
[`omni-dsh-plugins`](https://www.npmjs.com/package/omni-dsh-plugins), с аттестацией происхождения,
привязывающей каждую сборку к коммиту и запуску workflow, который её произвёл.

```bash
npx omni-dsh-plugins --help
```

## Принципы дизайна в v1.0.1

- **Только для чтения по умолчанию.** `catalog`, `search`, `info`, `list` и `doctor` никогда не
  изменяют профили, не пишут файлы и не запускают код плагина.
- **Барьер согласия для выполнения кода.** `add`, `update` и `remove` отказываются выполнять код
  жизненного цикла DSH/pnpm, если вы не передадите `--allow-code-execution`. Без него используйте
  `--dry-run`, чтобы увидеть проверенный план.
- **Политика для нативного Windows.** Нативные `add`/`update`/`remove` на Windows с выполнением
  кода отключены в v1.0.1; используйте WSL. Dry-run и команды только для чтения остаются
  доступными, а маркеры восстановления на нативном Windows требуют документированного ручного
  восстановления.
- **Закреплённые входные данные.** Входные данные каталога могут быть локальным каталогом, файлом
  снапшота или URL закреплённого публичного снапшота, опционально заблокированным на точную
  40-символьную ревизию.

## Общие опции

Эти опции присутствуют в командах, потребляющих каталог (`catalog validate`, `search`, `info`,
`add`, `update`, `remove`, `doctor`):

| Опция                     | Значение                                                            |
| -------------------------- | ------------------------------------------------------------------ |
| `--catalog <path-or-url>` | Локальный каталог-директория, файл снапшота или URL закреплённого публичного снапшота |
| `--revision <sha>`        | Точная 40-символьная ревизия снапшота                               |
| `--json`                  | Выводит стабильный JSON                                             |

Глобальные опции: `-V, --version` печатает версию CLI; `-h, --help` печатает справку для любой
команды (`dsh-plugins help [command]` тоже работает).

## Коды выхода

CLI использует стандартные коды выхода процесса:

| Код выхода | Значение                                                                   |
| ----------: | -------------------------------------------------------------------------- |
| `0`        | Успех (включая результаты «пусто, но валидно», такие как пустой каталог)   |
| `1`        | Ошибка: ошибка валидации, запись не найдена, отсутствует обязательная опция, либо диагностическая проверка сообщает об ошибке |

Примеры, наблюдаемые в v1.0.1: `catalog validate` на валидном пустом каталоге завершается с `0` и
`0 entries valid; catalog is empty`; `info <unknown-id>` завершается с `1` и `Plugin not found`;
`doctor` завершается с `1`, когда любая проверка (например, отсутствующий исполняемый файл `dsh`)
сообщает об ошибке.

## Команды

### `catalog` — проверяет публичные поверхности каталога

```text
dsh-plugins catalog validate [--catalog <path-or-url>] [--revision <sha>] [--json]
dsh-plugins catalog docs-check [root]
dsh-plugins catalog github-forms-check [root]
```

- **`catalog validate`** — проверяет YAML и семантику каталога: безопасный парсинг YAML, публичную
  схему, парсинг SPDX-выражений, точный SemVer, SHA-512 SRI и отклонение дублирующихся ID /
  ключей node-репозитория-плюс-подпуть. Это локальная проверка только для чтения: она не обращается
  к GitHub, не разрешает идентичность репозитория и не проверяет доказательства на закреплённом
  коммите. Это именно та команда, которую задача CI `catalog-validation` запускает при каждом
  pull request каталога.
- **`catalog docs-check [root]`** — проверяет, что обязательная публичная документация каталога
  существует и что ограждения Markdown сбалансированы.
- **`catalog github-forms-check [root]`** — проверяет структурированные публичные формы issue
  GitHub (заявление прав, исправление, удаление).

```bash
# Из корня репозитория:
npx omni-dsh-plugins catalog validate --catalog .
npx omni-dsh-plugins catalog docs-check .
npx omni-dsh-plugins catalog github-forms-check .
```

### `search` — поиск по публичным полям каталога локально

```text
dsh-plugins search [options] <query...>
```

Ищет публичные поля каталога локально по выбранным входным данным каталога. Печатает совпавшие
записи или `No plugins found.` (выход `0`), когда ничего не найдено.

```bash
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins search notes markdown --catalog . --json
```

### `discover` — находит плагины за пределами каталога

```text
dsh-plugins discover [options] <query...>
```

> `discover` появляется в `1.0.0` — первом релизе под этим именем пакета.

Сначала ищет в курируемом каталоге, затем — если не указан `--offline` — в живом теме GitHub
`dsh-plugin`, так что плагин, который ещё не отправлен, всё равно можно найти. Результаты каталога
несут доказательства, которые хранит каталог (закреплённый коммит, создатель, лицензия); результаты
сообщества не несут ничего из этого и помечены соответственно, потому что ничто в них не было
проверено.

`--limit <n>` ограничивает число результатов на уровень (по умолчанию `8`). `--json` выводит
стабильную машинную форму, которая никогда не локализуется.

```bash
npx omni-dsh-plugins discover memory --catalog .
npx omni-dsh-plugins discover vision --offline --catalog . --json
```

### `info` — показывает одну публичную запись каталога

```text
dsh-plugins info [options] <id>
```

Показывает одну публичную запись каталога по каноническому ID плагина. Завершается с `1` и
`Plugin not found: <id>`, когда ID отсутствует в каталоге.

```bash
npx omni-dsh-plugins info example-notes-search --catalog .
```

### `add` — добавляет один плагин каталога через официальное делегирование DSH

```text
dsh-plugins add [options] <id>
```

| Опция                    | Значение                                                            |
| ------------------------ | -------------------------------------------------------------------- |
| `--profile <name>`       | Профиль DSH для изменения (на практике обязателен; команда завершится ошибкой без него) |
| `--dry-run`              | Показывает проверенный план без файлов или подпроцессов               |
| `--allow-code-execution` | Согласие на код жизненного цикла DSH/pnpm (отключено на нативном Windows; используйте WSL) |
| `--catalog` / `--revision` / `--json` | Общие опции выше                                          |

Семантика dry-run в этой версии: команда разрешает и проверяет план для закреплённой записи и
печатает его, не создавая файлов и не запуская подпроцессов. Фактическая установка делегируется
официальным инструментам DSH и продолжается только с `--allow-code-execution`.

```bash
# Только предпросмотр — ничего не записывается, ничего не выполняется:
npx omni-dsh-plugins add example-notes-search --profile default --dry-run

# Реальная установка — явное согласие на код жизненного цикла:
npx omni-dsh-plugins add example-notes-search --profile default --allow-code-execution
```

### `update` — обновляет один плагин каталога через официальное делегирование DSH

```text
dsh-plugins update [options] <id>
```

Те же опции и семантика согласия, что и у `add`: `--profile <name>`, `--dry-run`,
`--allow-code-execution`, плюс общие опции каталога.

### `remove` — удаляет один управляемый каталогом плагин через официальное делегирование DSH

```text
dsh-plugins remove [options] <id>
```

Те же опции и семантика согласия, что и у `add`. Удаляются только установки, управляемые
каталогом.

### `recover` — восстанавливает удержанную мутацию POSIX

```text
dsh-plugins recover
```

Восстанавливает удержанную мутацию POSIX после прерванного `add`/`update`/`remove`. Если ничего не
ожидает восстановления, печатает `No mutation recovery is pending.` и завершается с `0`.
Восстановление на нативном Windows остаётся ручным, согласно документированной политике.

### `list` — выводит список управляемых каталогом установок

```text
dsh-plugins list [--profile <name>] [--json]
```

Выводит список управляемых каталогом установок, не изменяя профили. `--profile <name>` фильтрует
по профилю DSH. При отсутствии установок печатает `No catalog-managed plugins installed.` и
завершается с `0`.

### `doctor` — диагностика только для чтения

```text
dsh-plugins doctor [--catalog <path-or-url>] [--revision <sha>] [--json]
```

Запускает диагностику Node, DSH, политики нативного Windows и каталога только для чтения. Каждая
проверка сообщает `ok` или `error`; любая `error` делает общий код выхода `1`. Пример вывода на
машине без исполняемого файла `dsh`:

```text
node [ok]: Node 24.16.0 is supported
dsh [error]: dsh executable was not found
catalog [ok]: catalog is valid and empty
```

## Что не доказывает локальная проверка

Успешный запуск `catalog validate` подтверждает только структуру и локальную семантику. Он не
доказывает идентичность удалённого репозитория, владение создателя или доказательства на
закреплённом коммите — мейнтейнеры применяют эти отдельные барьеры проверки происхождения перед
любым слиянием, как описано в [CONTRIBUTING.md](../../CONTRIBUTING.md) и
[docs/GOVERNANCE.md](../../docs/GOVERNANCE.md).
