| **Машинные фиды** | `catalog.json` + `catalog.snapshot.json` для инструментов    | [catalog.json](https://dsh-plugins.omniroute.online/catalog.json) · [catalog.snapshot.json](https://dsh-plugins.omniroute.online/catalog.snapshot.json) |

Этот репозиторий — публичный источник истины для каталога. Каждая запись представляет собой один
YAML-файл в `catalog/plugins/`, проверенный по опубликованной JSON Schema, добавленный через один
индивидуально отрецензированный pull request и всегда с указанием оригинального создателя плагина.
Ничто в каталоге не сгенерировано из другого каталога или списка: каждая запись восстановлена
из оригинального репозитория создателя на закреплённом коммите.

Сайт и CLI поддерживаются из закрытого исходного кода; этот репозиторий содержит публичные данные
каталога, схему и политики, которые они используют.

## 🚀 Установка CLI

```bash
npx omni-dsh-plugins --help
```

Пакет с областью видимости опубликован как `omni-dsh-plugins@1.0.1`, и приведённая выше
команда — канонический способ вызова на сегодня; никакого установочного скрипта здесь не размещено.

### Как пользоваться CLI сегодня

Версия 1.0.1 предоставляет команды поиска и валидации только для чтения, а также команды установки
с обязательным подтверждением согласия. Полный справочник команд, включая флаги, коды возврата и
барьер согласия на выполнение кода, находится в [docs/CLI.md](../../docs/CLI.md).

| Команда                        | Что делает                                                          | Затрагивает вашу систему?               |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | Проверяет YAML каталога, схему и локальную семантику                | Нет — только чтение                     |
| `search <query...>`            | Ищет по публичным полям каталога локально                           | Нет — только чтение                     |
| `info <id>`                    | Показывает одну публичную запись каталога                           | Нет — только чтение                     |
| `list`                         | Перечисляет установки, управляемые каталогом, не меняя профили       | Нет — только чтение                     |
| `doctor`                       | Диагностика Node, DSH, нативной политики Windows и каталога (чтение) | Нет — только чтение                     |
| `add <id> --profile <name> --dry-run` | Показывает проверенный план установки без файлов и подпроцессов | Нет — пробный прогон                    |
| `add <id> --profile <name> --allow-code-execution` | Устанавливает через официальное делегирование DSH | Да — только с явным флагом согласия     |

```bash
# Validate the catalog in this repository (what CI runs):
npx omni-dsh-plugins catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx omni-dsh-plugins add <plugin-id> --profile default --dry-run
```

Изменяющие команды (`add`, `update`, `remove`) никогда не выполняют код жизненного цикла плагина,
если вы не передали `--allow-code-execution`. В нативной Windows эти изменения отключены в
версии 1.0.1 — используйте WSL. Команды только для чтения и пробные прогоны работают везде.

## 🔍 Как плагин попадает в каталог

![Как плагин попадает в каталог](../../docs/diagrams/catalog-flow-dark.svg#gh-dark-mode-only)
![Как плагин попадает в каталог](../../docs/diagrams/catalog-flow-light.svg#gh-light-mode-only)

1. **Один плагин, одна ветка, один pull request.** PR добавляет или изменяет ровно один YAML-файл
   в `catalog/plugins/`.
2. **Приоритет создателя.** PR, открытый создателем плагина или владеющей организацией, всегда имеет
   приоритет над кураторством сообщества или автоматизацией для того же плагина — см.
   [docs/CREDIT.md](../../docs/CREDIT.md).
3. **Доказательства из оригинального источника.** Каждое поле восстановлено из репозитория
   создателя на закреплённом 40-символьном коммите: описание, лицензия, интеграция с DSH,
   дескриптор установки, звёзды.
4. **Локальная валидация.** `catalog validate` проверяет структуру и локальную семантику; это та же
   проверка, которую задание CI `catalog-validation` выполняет для PR.
5. **Барьеры мейнтейнеров.** Перед слиянием мейнтейнеры отдельно проверяют идентичность репозитория,
   привязку к создателю и закреплённые доказательства. Зелёная локальная валидация необходима, но
   никогда не достаточна.

Полный контракт — требуемые доказательства, правила YAML, политика звёзд, разрешение коллизий и
барьеры проверки — в [CONTRIBUTING.md](../../CONTRIBUTING.md). Как и кем принимаются решения —
в [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md).

## 📄 Анатомия записи

Каждая запись — один YAML-файл, названный по своему ID. Пример ниже проходит валидацию по текущей
схеме (пополевой справочник — в [docs/SCHEMA.md](../../docs/SCHEMA.md)):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

Ключевые инварианты, обеспечиваемые схемой:

- `unofficial: true` и `schemaVersion: 1` — константы.
- Плагин из монорепозитория обязан использовать `stars: null` — звёзды родительского проекта
  никогда не наследуются.
- Дескриптор установки — это либо npm-пакет точной версии, либо сам закреплённый исходник;
  это данные, а не команда оболочки.
- Статус `verified` требует проверяемых доказательств дымового теста; в противном случае запись
  имеет статус `eligible` с `smokeTest: null`.

## 🗂 Что здесь размещается

Этот репозиторий каталогизирует независимо опубликованные интеграции для DeepSeek Harness (DSH),
включая нативные плагины, семейства плагинов, темы, навыки, клиенты и мосты. Виды артефактов,
категории возможностей и теги интерфейсов определены в [docs/CATEGORIES.md](../../docs/CATEGORIES.md).

Каждая публичная запись — один YAML-файл в `catalog/plugins/`, и она обязана проходить валидацию по
`schemas/plugin.schema.yaml`. Наличие в списке означает, что задокументированные проверки права на
включение или верификации были выполнены; это не сертификация безопасности и не одобрение от DeepSeek.

## 🏅 Ранжирование и верификация

Только выделенные, нативные, подходящие или верифицированные репозитории плагинов со звёздами,
принадлежащими именно этому репозиторию, могут попасть в звёздный рейтинг. Интеграции, хранящиеся
внутри более широких монорепозиториев, остаются доступными для поиска, но используют `stars: null`
и никогда не наследуют звёзды родительского проекта. Полный предикат см. в
[docs/RANKING.md](../../docs/RANKING.md).

Публичные состояния верификации отличают структурное соответствие требованиям от дымового теста
установки. Ни одно состояние не означает абсолютной безопасности. Перед использованием изучите
репозиторий плагина, закреплённый коммит, лицензию и поведение при установке.

должен добавлять или изменять ровно одну запись плагина и должен ссылаться на оригинальный
репозиторий создателя, а не на другой каталог. Pull request'ы, созданные самими создателями, имеют
приоритет над автоматическими pull request'ами каталога.

Для заявок создателей, исправлений и удалений доступны структурированные формы issue. Никогда не
отправляйте учётные данные, приватные контакты или другие секреты.
