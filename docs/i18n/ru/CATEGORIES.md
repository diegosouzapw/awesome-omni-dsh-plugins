# Категории каталога

> 🌐 [English](../../CATEGORIES.md) · [Português (Brasil)](../pt-BR/CATEGORIES.md) · [中文（简体）](../zh-CN/CATEGORIES.md) · **Русский**

Каждая запись каталога имеет один вид артефакта, одну основную категорию возможностей и ноль
или больше тегов. Основная категория определяет, где появляется запись; теги обеспечивают
кросс-категориальный поиск без дублирования записи.

## Виды артефактов

<!-- catalog-policy:aggregators-never-entries -->

| Значение | Значение (смысл) | Ранжируется по звёздам как плагин |
|---|---|---:|
| `plugin` | Устанавливаемый нативный бандл DSH | Только когда выполнены все условия ранжирования |
| `plugin-family` | Репозиторий, содержащий несколько плагинов DSH | Нет; отдельный раздел |
| `skin-theme` | Скин или визуальная тема интерфейса DSH | Нет; отдельный раздел |
| `skill` | Навык агента с поддержкой DSH | Нет |
| `preset-profile` | Профиль или пресет DSH | Нет |
| `client-interface` | Настольный, TUI, редакторский или удалённый клиент | Нет |
| `bridge-adapter` | Интеграция из другого продукта в DSH | Нет |
| `ecosystem-project` | Более широкий проект, содержащий интеграцию с DSH | Нет |

Зонтичный репозиторий, агрегатор, маркетплейс, каталог инсталляторов или список никогда не
является записью каталога, даже если сам агрегатор устанавливаем. Он может использоваться
только как наводка. Проследите каждую наводку до независимо устанавливаемого дочернего
артефакта и определите фактического создателя, оригинальный репозиторий, пакет и подпуть
источника этого артефакта, прежде чем отправлять его. Настоящий монорепозиторий создателя
может быть оригинальным репозиторием для дочернего плагина, но дочерний плагин должен
использовать именно этот подпуть и политику звёзд монорепозитория.

Поле `kind` — это канонический дискриминатор артефакта DSH. Отдельного вида интеграции не
существует: `plugin` уже означает нативный бандл DSH, а `ecosystem-project` уже означает более
широкий проект с интеграцией DSH. Это предотвращает противоречивые пары классификации.

## Основные категории возможностей

| Значение | Отображаемая метка |
|---|---|
| `user-interface-dashboards` | Пользовательский интерфейс и дашборды |
| `memory-rag` | Память и RAG |
| `search-research` | Поиск и исследования |
| `coding-developer-tools` | Кодинг и инструменты разработчика |
| `browser-automation` | Браузер и автоматизация |
| `vision-audio-multimodal` | Зрение, звук и мультимодальность |
| `sessions-productivity` | Сессии и продуктивность |
| `security-permissions-approvals` | Безопасность, права и подтверждения |
| `diagnostics-observability` | Диагностика и наблюдаемость |
| `models-providers-routing` | Модели, провайдеры и маршрутизация |
| `messaging-notifications` | Сообщения и уведомления |
| `data-external-services` | Данные и внешние сервисы |
| `entertainment-customization` | Развлечения и кастомизация |
| `finance-trading` | Финансы, трейдинг и бухгалтерия |

Выбирайте категорию, которая лучше всего отражает основную задачу плагина, а не категорию,
которая с наибольшей вероятностью повысит видимость.

## Теги интерфейса

Стандартные теги интерфейса включают `web-ui`, `sidebar`, `settings`, `tui`, `cli`, `desktop`,
`mobile`, `remote`, `editor`, `headless` и `theme`. Дополнительные теги возможностей в нижнем
регистре kebab-case допускаются, когда они описывают доказательства, видимые в закреплённом
оригинальном источнике.

## Область репозитория

Используйте `dedicated` только тогда, когда звёзды репозитория принадлежат именно
каталогизированному плагину. Используйте `monorepo`, когда плагин — это подпуть или пакет
внутри более широкого проекта. Запись monorepo должна использовать
`popularity.starsPolicy: undefined-parent-repository` и `popularity.stars: null`.
