# קטגוריות הקטלוג

> 🌐 [English](../../CATEGORIES.md) · [Português (Brasil)](../pt-BR/CATEGORIES.md) · [中文（简体）](../zh-CN/CATEGORIES.md) · **עברית**

לכל רשומת קטלוג יש סוג חפץ (artifact kind) אחד, קטגוריית יכולת ראשית אחת, ואפס או יותר תגים.
הקטגוריה הראשית קובעת היכן הרשומה מופיעה; התגים מספקים חיפוש חוצה-קטגוריות בלי לשכפל את
הרשומה.

## סוגי חפצים (Artifact kinds)

<!-- catalog-policy:aggregators-never-entries -->

| ערך | משמעות | מדורג בכוכבים כתוסף |
|---|---|---:|
| `plugin` | חבילת DSH מקורית שניתנת להתקנה | רק כאשר כל תנאי הדירוג מתקיימים |
| `plugin-family` | מאגר המכיל כמה תוספי DSH | לא; חלק נפרד |
| `skin-theme` | ערכת נושא או עיצוב חזותי לממשק DSH | לא; חלק נפרד |
| `skill` | מיומנות סוכן (agent skill) עם תמיכת DSH | לא |
| `preset-profile` | פרופיל או preset של DSH | לא |
| `client-interface` | לקוח שולחני, TUI, עורך או מרוחק | לא |
| `bridge-adapter` | אינטגרציה ממוצר אחר אל DSH | לא |
| `ecosystem-project` | פרויקט רחב יותר המכיל אינטגרציית DSH | לא |

מאגר-על, מאגר-אב, שוק מקוון (marketplace), קטלוג מתקין או רשימה לעולם אינם רשומת קטלוג, גם
כאשר מאגר-העל עצמו ניתן להתקנה. ניתן להשתמש בו רק כחוט קצה (lead). עקבו אחר כל חוט קצה עד
לחפץ-בן שניתן להתקין באופן עצמאי ופתרו את היוצר בפועל של אותו חפץ, את המאגר המקורי, את
החבילה ואת תת-נתיב המקור לפני הגשתו. מונו-ריפו אמיתי של יוצר יכול להיות המאגר המקורי עבור
תוסף-בן, אך התוסף-בן חייב להשתמש בתת-הנתיב המדויק שלו ובמדיניות הכוכבים למונו-ריפו.

השדה `kind` הוא מבחין חפץ ה-DSH הקנוני. אין שדה סוג אינטגרציה נפרד: `plugin` כבר אומר
חבילת DSH מקורית, בעוד `ecosystem-project` כבר אומר פרויקט רחב יותר עם אינטגרציית DSH. זה
מונע זוגות סיווג סותרים.

## קטגוריות יכולת ראשיות

| ערך | תווית תצוגה |
|---|---|
| `user-interface-dashboards` | ממשק משתמש ולוחות מחוונים |
| `memory-rag` | זיכרון ו-RAG |
| `search-research` | חיפוש ומחקר |
| `coding-developer-tools` | קידוד וכלי פיתוח |
| `browser-automation` | דפדפן ואוטומציה |
| `vision-audio-multimodal` | ראייה, אודיו ומולטימודלי |
| `sessions-productivity` | סשנים ופרודוקטיביות |
| `security-permissions-approvals` | אבטחה, הרשאות ואישורים |
| `diagnostics-observability` | אבחון ותצפיתיות |
| `models-providers-routing` | מודלים, ספקים וניתוב |
| `messaging-notifications` | הודעות והתראות |
| `data-external-services` | נתונים ושירותים חיצוניים |
| `entertainment-customization` | בידור והתאמה אישית |

בחרו את הקטגוריה המייצגת בצורה הטובה ביותר את התפקיד הראשי של התוסף, לא את הקטגוריה
הסבירה ביותר להגביר חשיפה.

## תגי ממשק

תגי ממשק סטנדרטיים כוללים `web-ui`, `sidebar`, `settings`, `tui`, `cli`, `desktop`,
`mobile`, `remote`, `editor`, `headless` ו-`theme`. תגי יכולת נוספים ב-kebab-case באותיות
קטנות מותרים כאשר הם מתארים ראיה הנראית במקור המוצמד המקורי.

## היקף המאגר

השתמשו ב-`dedicated` רק כאשר כוכבי המאגר שייכים לתוסף המקוטלג המדויק. השתמשו ב-`monorepo`
כאשר התוסף הוא תת-נתיב או חבילה בתוך פרויקט רחב יותר. רשומת מונו-ריפו חייבת להשתמש
ב-`popularity.starsPolicy: undefined-parent-repository` וב-`popularity.stars: null`.
