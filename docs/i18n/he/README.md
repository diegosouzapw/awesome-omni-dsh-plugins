מאגר זה הוא מקור האמת הציבורי לקטלוג. כל רשומה היא קובץ YAML אחד תחת `catalog/plugins/`, מאומתת מול סכימת JSON שפורסמה, נוספה דרך בקשת משיכה (pull request) אחת שנבדקה בנפרד, ומקבלת תמיד קרדיט ליוצר המקורי של התוסף. שום דבר בקטלוג אינו נוצר מקטלוג או רשימה אחרת: כל רשומה נבנית מחדש ממאגר היוצר המקורי בקומיט מוצמד.

האתר וה-CLI מתוחזקים ממקור פרטי; מאגר זה נושא את נתוני הקטלוג הציבוריים, הסכימה והמדיניות שהם צורכים.

## מצב הקטלוג

## 🚀 התקנת ה-CLI

```bash
npx @diegosouza.pw/dsh-plugins --help
```

החבילה בעלת ההיקף המוגבל מפורסמת בתור `@diegosouza.pw/dsh-plugins@0.1.0`, והפקודה שלמעלה היא הקריאה הקנונית כיום; אין כאן סקריפט התקנה מתארח.

### שימוש ב-CLI כיום

גרסה 0.1.0 כוללת פקודות גילוי ואימות לקריאה בלבד, בנוסף לפקודות התקנה המותנות בהסכמה. הפניה המלאה לפקודות, כולל דגלים, קודי יציאה ושער ההסכמה להרצת קוד, נמצאת ב-[docs/CLI.md](../../docs/CLI.md).

| פקודה | מה היא עושה | האם היא נוגעת במערכת שלכם? |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | אימות ה-YAML, הסכימה והסמנטיקה המקומית של הקטלוג | לא — לקריאה בלבד |
| `search <query...>` | חיפוש שדות ציבוריים של הקטלוג באופן מקומי | לא — לקריאה בלבד |
| `info <id>` | הצגת רשומה ציבורית אחת מהקטלוג | לא — לקריאה בלבד |
| `list` | הצגת רשימת ההתקנות המנוהלות על ידי הקטלוג בלי לשנות פרופילים | לא — לקריאה בלבד |
| `doctor` | אבחון לקריאה בלבד של Node, DSH, מדיניות Windows מקומית והקטלוג | לא — לקריאה בלבד |
| `add <id> --profile <name> --dry-run` | הצגת תוכנית ההתקנה המאומתת בלי קבצים או תת-תהליכים | לא — הרצה יבשה (dry-run) |
| `add <id> --profile <name> --allow-code-execution` | התקנה דרך האצלה רשמית של DSH | כן — רק עם דגל הסכמה מפורש |

```bash
# Validate the catalog in this repository (what CI runs):
npx @diegosouza.pw/dsh-plugins@0.1.0 catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx @diegosouza.pw/dsh-plugins@0.1.0 search memory --catalog .
npx @diegosouza.pw/dsh-plugins@0.1.0 info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx @diegosouza.pw/dsh-plugins@0.1.0 add <plugin-id> --profile default --dry-run
```

פקודות משנות (`add`, `update`, `remove`) לעולם לא מריצות קוד מחזור חיים של תוסף אלא אם תעבירו `--allow-code-execution`. ב-Windows מקורי שינויים אלו מושבתים ב-v0.1.0; השתמשו ב-WSL. פקודות לקריאה בלבד ופקודות dry-run פועלות בכל מקום.

## 🔍 כיצד תוסף נכנס לקטלוג

```mermaid
flowchart LR
    A["מאגר היוצר<br/>(קומיט מוצמד)"] --> B["ענף אחד,<br/>PR אחד,<br/>רשומת YAML אחת"]
    B --> C["catalog-validation CI<br/>(סכימה + סמנטיקה מקומית)"]
    C --> D["שערי מתחזק<br/>(זהות, קשירת יוצר,<br/>ראיה מוצמדת)"]
    D --> E["catalog/plugins/*.yaml<br/>מוזג"]
    E --> F["אתר"]
    E --> G["CLI"]
    E --> H["הזנות catalog.json"]
```

1. **תוסף אחד, ענף אחד, בקשת משיכה אחת.** ה-PR מוסיף או משנה בדיוק קובץ YAML אחד תחת `catalog/plugins/`.
2. **עדיפות ליוצר.** PR שנפתח על ידי יוצר התוסף או הארגון הבעלים תמיד קודם לאצירה קהילתית או אוטומציה עבור אותו תוסף — ראו [docs/CREDIT.md](../../docs/CREDIT.md).
3. **ראיה מהמקור המקורי.** כל שדה נבנה מחדש ממאגר היוצר בקומיט מוצמד בן 40 תווים: תיאור, רישיון, אינטגרציית DSH, מתאר התקנה, כוכבים.
4. **אימות מקומי.** `catalog validate` בודק מבנה וסמנטיקה מקומית; זו אותה בדיקה שמריצה עבודת ה-CI `catalog-validation` על ה-PR.
5. **שערי מתחזק.** לפני המיזוג, המתחזקים מאמתים בנפרד את זהות המאגר, קשירת היוצר והראיה המוצמדת. אימות מקומי ירוק הכרחי, אך לעולם לא מספיק.

החוזה המלא — הראיות הנדרשות, כללי YAML, מדיניות הכוכבים, טיפול בהתנגשויות ושערי הבדיקה — נמצא ב-[CONTRIBUTING.md](../../CONTRIBUTING.md). כיצד מתקבלות ההחלטות ועל ידי מי מתועד ב-[docs/GOVERNANCE.md](../../docs/GOVERNANCE.md).

## 📄 אנטומיה של רשומה

כל רשומה היא קובץ YAML אחד הנקרא על שם ה-ID שלו. הדוגמה שלהלן מאומתת מול הסכימה הנוכחית (הפניה שדה-אחר-שדה ב-[docs/SCHEMA.md](../../docs/SCHEMA.md)):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

אינווריאנטים מרכזיים שנאכפים על ידי הסכימה:

- `unofficial: true` ו-`schemaVersion: 1` הם קבועים.
- תוסף מונו-ריפו חייב להשתמש ב-`stars: null` — כוכבים של פרויקט האב לעולם אינם עוברים בירושה.
- מתאר ההתקנה הוא או חבילת npm בגרסה מדויקת או המקור המוצמד עצמו; זהו נתון, לעולם לא פקודת מעטפת (shell).
- מצב `verified` דורש ראיית smoke test הניתנת לבדיקה; אחרת הרשומה היא `eligible` עם `smokeTest: null`.

## 🗂 מה שייך כאן

מאגר זה מקטלג אינטגרציות שפורסמו באופן עצמאי עבור DeepSeek Harness (DSH), כולל תוספים מקוריים, משפחות תוספים, ערכות נושא, מיומנויות, לקוחות וגשרים. סוגי חפצים (artifacts), קטגוריות יכולת ותגי ממשק מוגדרים ב-[docs/CATEGORIES.md](../../docs/CATEGORIES.md).

כל רשומה ציבורית היא קובץ YAML אחד תחת `catalog/plugins/` וחייבת להיות מאומתת מול `schemas/plugin.schema.yaml`. רישום פירושו שבדיקות הזכאות או האימות המתועדות הושלמו; זה אינו תעודת אבטחה או אישור של DeepSeek.

## 🏅 דירוג ואימות

רק מאגרי תוספים ייעודיים, מקוריים, זכאים או מאומתים שהכוכבים שלהם שייכים לאותו מאגר בדיוק יכולים להיכנס לדירוג כוכבים. אינטגרציות המאוחסנות בתוך מונו-ריפואים רחבים יותר נשארות ניתנות לגילוי אך משתמשות ב-`stars: null` ולעולם אינן יורשות כוכבים של פרויקט אב. ראו [docs/RANKING.md](../../docs/RANKING.md) לכלל המלא.

מצבי אימות ציבוריים מבחינים בין זכאות מבנית לבין בדיקת התקנה (smoke test). אף מצב אינו מייצג ביטחון מוחלט. בדקו את המאגר של התוסף, את הקומיט המוצמד, את הרישיון ואת התנהגות ההתקנה לפני השימוש.
