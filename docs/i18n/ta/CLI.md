# CLI குறிப்பு — `omni-dsh-plugins@1.0.1`

> 🌐 [English](../../CLI.md) · [Português (Brasil)](../pt-BR/CLI.md) · [中文（简体）](../zh-CN/CLI.md) · **தமிழ்**

> **அதிகாரப்பூர்வமற்ற சமூகத் திட்டம். DeepSeek உடன் இணைப்போ, ஏற்புடையதோ, ஆதரவு பெற்றதோ அல்ல.**
> DeepSeek பெயர்களும் குறியீடுகளும் அவற்றின் உரிமையாளருக்கே சொந்தமானவை.

இந்தப் பக்கம் வெளியிடப்பட்ட CLI-ஐ அது `1.0.1` பதிப்பில் சரியாகச் செயல்படும் விதமாக
ஆவணப்படுத்துகிறது. கீழே உள்ள ஒவ்வொரு தொகுப்பும் கொடியும் வெளியிடப்பட்ட கட்டளையின் சொந்த
`--help` வெளியீட்டிலிருந்தே வருகிறது; இங்கு எதுவும் வெளியிடப்படாத நடத்தையை
விவரிப்பதில்லை. CLI இந்தக் களஞ்சியத்தில் [`cli/`](../../cli) கீழ் உருவாக்கப்பட்டு, npm-இல்
[`omni-dsh-plugins`](https://www.npmjs.com/package/omni-dsh-plugins) என வெளியிடப்படுகிறது,
ஒவ்வொரு build-ஐயும் அதை உருவாக்கிய commit மற்றும் workflow run உடன் இணைக்கும் ஒரு மரபுரிமை
சான்றுடன்.

```bash
npx omni-dsh-plugins --help
```

## v1.0.1-இல் வடிவமைப்புக் கொள்கைகள்

- **இயல்பாக படிக்க-மட்டும்.** `catalog`, `search`, `info`, `list` மற்றும் `doctor`
  ஒருபோதும் சுயவிவரங்களை மாற்றுவதில்லை, கோப்புகளை எழுதுவதில்லை அல்லது செருகுநிரல்
  குறியீட்டை இயக்குவதில்லை.
- **குறியீடு இயக்கத்திற்கு ஒப்புதல் நுழைவாயில்.** `add`, `update` மற்றும் `remove`,
  `--allow-code-execution` கொடுக்காவிட்டால் DSH/pnpm வாழ்க்கைச் சுழற்சிக் குறியீட்டை இயக்க
  மறுக்கின்றன. அது இல்லாமல், சரிபார்க்கப்பட்ட திட்டத்தைக் காண `--dry-run` பயன்படுத்தவும்.
- **சொந்த Windows கொள்கை.** குறியீடு இயக்கத்துடன் கூடிய சொந்த Windows
  `add`/`update`/`remove` v1.0.1-இல் முடக்கப்பட்டுள்ளன; WSL பயன்படுத்தவும். Dry-run மற்றும்
  படிக்க-மட்டும் கட்டளைகள் கிடைக்கின்றன, மேலும் சொந்த Windows மீட்பு குறிப்புகள்
  ஆவணப்படுத்தப்பட்ட கைமுறை மீட்பைக் கோருகின்றன.
- **பின்னிணைக்கப்பட்ட உள்ளீடுகள்.** பட்டியல் உள்ளீடு ஒரு உள்ளூர் கோப்பகம், ஒரு ஸ்நாப்ஷாட்
  கோப்பு, அல்லது ஒரு பின்னிணைக்கப்பட்ட பொது ஸ்நாப்ஷாட் URL ஆக இருக்கலாம், விருப்பமாக
  சரியான 40-எழுத்து திருத்தத்துடன் பூட்டப்படலாம்.

## பொதுவான விருப்பங்கள்

இந்த விருப்பங்கள் பட்டியலைப் பயன்படுத்தும் கட்டளைகளில் தோன்றுகின்றன (`catalog validate`,
`search`, `info`, `add`, `update`, `remove`, `doctor`):

| விருப்பம்                    | பொருள்                                                            |
| ------------------------- | ------------------------------------------------------------------ |
| `--catalog <path-or-url>` | உள்ளூர் பட்டியல் கோப்பகம், ஸ்நாப்ஷாட் கோப்பு, அல்லது பின்னிணைக்கப்பட்ட பொது ஸ்நாப்ஷாட் URL |
| `--revision <sha>`        | சரியான 40-எழுத்து ஸ்நாப்ஷாட் திருத்தம்                               |
| `--json`                  | நிலையான JSON வெளியீட்டை வழங்கு                                            |

உலகளாவிய விருப்பங்கள்: `-V, --version` CLI பதிப்பை அச்சிடுகிறது; `-h, --help` எந்தக்
கட்டளைக்கும் உதவியை அச்சிடுகிறது (`dsh-plugins help [command]`-உம் வேலை செய்யும்).

## வெளியேறும் குறியீடுகள்

CLI வழக்கமான செயல்முறை வெளியேறும் குறியீடுகளைப் பயன்படுத்துகிறது:

| வெளியேறும் குறியீடு | பொருள்                                                                    |
| --------: | -------------------------------------------------------------------------- |
| `0`       | வெற்றி ("காலியான ஆனால் செல்லுபடியாகும்" முடிவுகள் உட்பட, எடுத்துக்காட்டாக காலியான பட்டியல்)     |
| `1`       | தோல்வி: சரிபார்ப்புப் பிழை, பதிவு காணப்படவில்லை, தேவையான விருப்பம் இல்லை, அல்லது நோயறிதல் சோதனை பிழையைப் புகாரளிக்கிறது |

v1.0.1-இல் கவனிக்கப்பட்ட எடுத்துக்காட்டுகள்: செல்லுபடியாகும் காலியான பட்டியலில்
`catalog validate` `0 entries valid; catalog is empty` உடன் `0`-இல் வெளியேறுகிறது;
`info <unknown-id>` `Plugin not found` உடன் `1`-இல் வெளியேறுகிறது; ஏதேனும் சோதனை
(எடுத்துக்காட்டாக `dsh` இயங்கக்கூடிய கோப்பு இல்லை) பிழையைப் புகாரளிக்கும்போது `doctor`
`1`-இல் வெளியேறுகிறது.

## கட்டளைகள்

### `catalog` — பொது பட்டியல் மேற்பரப்புகளைச் சரிபார்த்தல்

```text
dsh-plugins catalog validate [--catalog <path-or-url>] [--revision <sha>] [--json]
dsh-plugins catalog docs-check [root]
dsh-plugins catalog github-forms-check [root]
```

- **`catalog validate`** — பட்டியல் YAML மற்றும் சொற்பொருளைச் சரிபார்க்கிறது: பாதுகாப்பான
  YAML பாகுபடுத்தல், பொது திட்டவரைவு, SPDX கோவை பாகுபடுத்தல், சரியான SemVer, SHA-512 SRI,
  மற்றும் நகல் ID / களஞ்சிய-நோட்-கூடுதல்-துணைப்பாதை நிராகரிப்பு. இது உள்ளூர் மற்றும்
  படிக்க-மட்டும்: இது GitHub உடன் தொடர்பு கொள்வதில்லை, களஞ்சிய அடையாளத்தைத் தீர்ப்பதில்லை
  அல்லது பின்னிணைக்கப்பட்ட commit-இல் ஆதாரத்தை ஆய்வு செய்வதில்லை. `catalog-validation` CI
  job ஒவ்வொரு பட்டியல் pull request-இலும் இயக்கும் சரியான கட்டளை இதுவே.
- **`catalog docs-check [root]`** — தேவையான பொது பட்டியல் ஆவணங்கள் உள்ளனவா என்றும் Markdown
  வேலிகள் சமநிலையில் உள்ளனவா என்றும் சரிபார்க்கிறது.
- **`catalog github-forms-check [root]`** — கட்டமைக்கப்பட்ட பொது GitHub issue படிவங்களை
  (உரிமைகோரல், திருத்தம், அகற்றல்) சரிபார்க்கிறது.

```bash
# From the repository root:
npx omni-dsh-plugins catalog validate --catalog .
npx omni-dsh-plugins catalog docs-check .
npx omni-dsh-plugins catalog github-forms-check .
```

### `search` — பொது பட்டியல் புலங்களில் உள்ளூராகத் தேடுதல்

```text
dsh-plugins search [options] <query...>
```

தேர்ந்தெடுக்கப்பட்ட பட்டியல் உள்ளீட்டுக்கு எதிராகப் பொது பட்டியல் புலங்களில் உள்ளூராகத்
தேடுகிறது. பொருந்தும் பதிவுகளை அச்சிடுகிறது, அல்லது எதுவும் பொருந்தாவிட்டால்
`No plugins found.` (வெளியேறும் குறியீடு `0`) அச்சிடுகிறது.

```bash
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins search notes markdown --catalog . --json
```

### `discover` — பட்டியலுக்கு அப்பால் செருகுநிரல்களைக் கண்டறிதல்

```text
dsh-plugins discover [options] <query...>
```

> `discover` `1.0.0`-இல் வெளியிடப்படுகிறது, இந்தத் தொகுப்புப் பெயரின் கீழ் முதல் வெளியீடு.

முதலில் க்யூரேட் செய்யப்பட்ட பட்டியலைத் தேடுகிறது, பின்னர் — `--offline` கொடுக்கப்படாவிட்டால் —
நேரடி GitHub `dsh-plugin` தலைப்பைத் தேடுகிறது, இதனால் இன்னும் சமர்ப்பிக்கப்படாத ஒரு
செருகுநிரலும் கண்டறியக்கூடியதாக இருக்கும். பட்டியல் முடிவுகள் பட்டியல் வைத்திருக்கும்
ஆதாரத்தைக் கொண்டிருக்கும் (பின்னிணைக்கப்பட்ட commit, படைப்பாளர், உரிமம்); சமூக முடிவுகள்
அவற்றில் எதையும் கொண்டிருக்காது, மேலும் அவை பற்றி எதுவும் மதிப்பாய்வு செய்யப்படாததால்
அப்படியே பெயரிடப்படுகின்றன.

`--limit <n>` ஒவ்வொரு நிலைக்கும் முடிவுகளை மட்டுப்படுத்துகிறது (இயல்புநிலை `8`). `--json`
நிலையான இயந்திர வடிவத்தை வழங்குகிறது, அது ஒருபோதும் உள்ளூர்மயமாக்கப்படாது.

```bash
npx omni-dsh-plugins discover memory --catalog .
npx omni-dsh-plugins discover vision --offline --catalog . --json
```

### `info` — ஒரு பொது பட்டியல் பதிவைக் காட்டுதல்

```text
dsh-plugins info [options] <id>
```

அதிகாரப்பூர்வ செருகுநிரல் ID மூலம் ஒரு பொது பட்டியல் பதிவைக் காட்டுகிறது. ID பட்டியலில்
இல்லாதபோது `Plugin not found: <id>` உடன் `1`-இல் வெளியேறுகிறது.

```bash
npx omni-dsh-plugins info example-notes-search --catalog .
```

### `add` — அதிகாரப்பூர்வ DSH ஒதுக்கீட்டின் மூலம் ஒரு பட்டியல் செருகுநிரலைச் சேர்த்தல்

```text
dsh-plugins add [options] <id>
```

| விருப்பம்                   | பொருள்                                                            |
| ------------------------ | ------------------------------------------------------------------ |
| `--profile <name>`       | மாற்ற வேண்டிய DSH சுயவிவரம் (நடைமுறையில் தேவை; இது இல்லாமல் கட்டளை பிழை தருகிறது) |
| `--dry-run`              | கோப்புகள் அல்லது துணைச் செயல்முறைகள் இன்றிச் சரிபார்க்கப்பட்ட திட்டத்தைக் காட்டு               |
| `--allow-code-execution` | DSH/pnpm வாழ்க்கைச் சுழற்சிக் குறியீட்டிற்கு ஒப்புதல் (சொந்த Windows முடக்கப்பட்டது; WSL பயன்படுத்தவும்) |
| `--catalog` / `--revision` / `--json` | மேலே உள்ள பொதுவான விருப்பங்கள்                                  |

இந்தப் பதிப்பில் dry-run சொற்பொருள்: கட்டளை பின்னிணைக்கப்பட்ட பதிவுக்கான திட்டத்தைத்
தீர்த்துச் சரிபார்த்து அதை அச்சிடுகிறது, எந்தக் கோப்புகளையும் உருவாக்காமல், எந்தத்
துணைச் செயல்முறைகளையும் இயக்காமல். உண்மையான நிறுவல் அதிகாரப்பூர்வ DSH கருவிகளுக்கு
ஒதுக்கப்படுகிறது, மேலும் `--allow-code-execution` உடன் மட்டுமே தொடரும்.

```bash
# Preview only — nothing is written, nothing executes:
npx omni-dsh-plugins add example-notes-search --profile default --dry-run

# Real install — explicit consent to lifecycle code:
npx omni-dsh-plugins add example-notes-search --profile default --allow-code-execution
```

### `update` — அதிகாரப்பூர்வ DSH ஒதுக்கீட்டின் மூலம் ஒரு பட்டியல் செருகுநிரலைப் புதுப்பித்தல்

```text
dsh-plugins update [options] <id>
```

`add` போலவே அதே விருப்பங்களும் ஒப்புதல் சொற்பொருளும்: `--profile <name>`, `--dry-run`,
`--allow-code-execution`, கூடுதலாக பொதுவான பட்டியல் விருப்பங்கள்.

### `remove` — அதிகாரப்பூர்வ DSH ஒதுக்கீட்டின் மூலம் பட்டியல்-நிர்வகிக்கப்படும் செருகுநிரலை அகற்றுதல்

```text
dsh-plugins remove [options] <id>
```

`add` போலவே அதே விருப்பங்களும் ஒப்புதல் சொற்பொருளும். பட்டியல்-நிர்வகிக்கப்படும் நிறுவல்கள்
மட்டுமே அகற்றப்படுகின்றன.

### `recover` — தக்கவைக்கப்பட்ட POSIX மாற்றத்தை மீட்க

```text
dsh-plugins recover
```

தடைப்பட்ட `add`/`update`/`remove`-க்குப் பிறகு தக்கவைக்கப்பட்ட POSIX மாற்றத்தை மீட்கிறது.
நிலுவையில் எதுவும் இல்லாதபோது `No mutation recovery is pending.` என அச்சிட்டு `0`-இல்
வெளியேறுகிறது. ஆவணப்படுத்தப்பட்ட கொள்கையின்படி சொந்த Windows மீட்பு கைமுறையாகவே இருக்கும்.

### `list` — பட்டியல்-நிர்வகிக்கப்படும் நிறுவல்களைப் பட்டியலிடு

```text
dsh-plugins list [--profile <name>] [--json]
```

சுயவிவரங்களை மாற்றாமல் பட்டியல்-நிர்வகிக்கப்படும் நிறுவல்களைப் பட்டியலிடுகிறது.
`--profile <name>` DSH சுயவிவரம் மூலம் வடிகட்டுகிறது. நிறுவல்கள் இல்லாதபோது
`No catalog-managed plugins installed.` என அச்சிட்டு `0`-இல் வெளியேறுகிறது.

### `doctor` — படிக்க-மட்டும் நோயறிதல்

```text
dsh-plugins doctor [--catalog <path-or-url>] [--revision <sha>] [--json]
```

படிக்க-மட்டும் Node, DSH, சொந்த Windows கொள்கை மற்றும் பட்டியல் நோயறிதல்களை இயக்குகிறது.
ஒவ்வொரு சோதனையும் `ok` அல்லது `error` எனப் புகாரளிக்கிறது; ஏதேனும் `error` ஒட்டுமொத்த
வெளியேறும் குறியீட்டை `1` ஆக்குகிறது. `dsh` இயங்கக்கூடிய கோப்பு இல்லாத கணினியில்
எடுத்துக்காட்டு வெளியீடு:

```text
node [ok]: Node 24.16.0 is supported
dsh [error]: dsh executable was not found
catalog [ok]: catalog is valid and empty
```
