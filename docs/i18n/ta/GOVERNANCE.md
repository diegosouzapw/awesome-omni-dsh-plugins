# பட்டியல் நிர்வாகம்

> 🌐 [English](../../GOVERNANCE.md) · [Português (Brasil)](../pt-BR/GOVERNANCE.md) · [中文（简体）](../zh-CN/GOVERNANCE.md) · **தமிழ்**

> **அதிகாரப்பூர்வமற்ற சமூகத் திட்டம். DeepSeek உடன் இணைப்போ, ஏற்புடையதோ, ஆதரவு பெற்றதோ அல்ல.**
> DeepSeek பெயர்களும் குறியீடுகளும் அவற்றின் உரிமையாளருக்கே சொந்தமானவை.

பொது பட்டியல் எவ்வாறு நிர்வகிக்கப்படுகிறது: எது நுழைகிறது என்பதை யார் முடிவு செய்கிறார்கள்,
போட்டியிடும் பங்களிப்புகள் எந்த வரிசையில் மதிக்கப்படுகின்றன, எந்தச் சோதனைகள் தானாக
இயங்குகின்றன, மற்றும் எந்தத் தீர்ப்புகள் மனிதர்களிடமே இருக்கின்றன. இங்கு குறிப்பிடப்படும்
கொள்கைகள் [CONTRIBUTING.md](../../CONTRIBUTING.md), [docs/CREDIT.md](../../docs/CREDIT.md)
மற்றும் [docs/RANKING.md](../../docs/RANKING.md)-இல் உள்ளன; அவை எவ்வாறு ஒன்றிணைகின்றன
என்பதை இந்தப் பக்கம் விவரிக்கிறது.

## கொள்கைகள்

1. **படைப்பாளர்-முன்னுரிமை.** பட்டியல் படைப்பாளர்களின் வேலையைக் கண்டறியக்கூடியதாக்குவதற்காக
   உள்ளது, அதன் உரிமையை எடுத்துக்கொள்வதற்கு ஒருபோதும் அல்ல. அதே அதிகாரப்பூர்வ செருகுநிரலுக்கு,
   ஒரு நேரடி படைப்பாளர் pull request திறந்த நிலையில் உள்ள எந்தச் சமூக க்யூரேஷன் அல்லது
   தானியங்கிமயமாக்கல் pull request-ஐயும் மீறுகிறது — முழுமையான முன்னுரிமை வரிசை மற்றும் Git
   அடையாள விதிகள் [docs/CREDIT.md](../../docs/CREDIT.md)-இல் உள்ளன.
2. **ஒரு செருகுநிரல், ஒரு மதிப்பாய்வு செய்யப்பட்ட pull request.** தொகுப்பு இணைப்புகள் இல்லை,
   பொது பட்டியலுக்குள் உருவாக்கப்பட்ட மொத்த இறக்குமதிகள் இல்லை. ஒவ்வொரு பதிவும் அதன் சொந்த
   மதிப்பாய்வைப் பெறுகிறது.
3. **நம்பிக்கைக்குப் பதிலாக ஆதாரம்.** ஒவ்வொரு பொது புலமும் பின்னிணைக்கப்பட்ட commit-இல்
   அசல் படைப்பாளர் களஞ்சியத்தைத் தடமறியும். பச்சை தானியங்கி சோதனை ஒருபோதும் தோற்றுவாய்
   ஆதாரமாக ஏற்கப்படாது.
4. **அதிகாரப்பூர்வமற்றது, எப்போதும்.** எந்தப் பட்டியல் நிலையும் DeepSeek மதிப்பாய்வு,
   சான்றிதழ் அல்லது ஏற்பாக வழங்கப்படாது.

## மாற்றங்கள் `main`-இல் எவ்வாறு வந்து சேருகின்றன

அனைத்து மாற்றங்களும் மதிப்பாய்வு செய்யப்பட்ட pull request-கள் வழியாகவே `main`-ஐ
அடைகின்றன — நேரடி push-கள் இல்லை. இயல்புநிலைக் கிளைக்கான நடைமுறைக் கொள்கை:

- **pull request-கள் மட்டுமே.** பட்டியல் பதிவுகள், ஆவணங்கள் மற்றும் திட்டவரைவு மாற்றங்கள்
  அனைத்தும் ஒரு PR வழியாக நுழைகின்றன; பட்டியல் PR-கள்
  [CONTRIBUTING.md](../../CONTRIBUTING.md)-இல் உள்ள ஒரு-கிளைக்கு-ஒரு-செருகுநிரல் விதியைப்
  பின்பற்ற வேண்டும்.
- **நேரியல் வரலாறு.** PR-கள் `main` நேரியல், தணிக்கை செய்யக்கூடிய வரலாற்றைப் பேணும் வகையில்
  ஒருங்கிணைக்கப்படுகின்றன; இணைக்கப்பட்ட பொது வரலாறு மீண்டும் எழுதப்படாது. படைப்பாளர்
  முன்வருவதற்கு முன் ஒரு க்யூரேட் செய்யப்பட்ட பதிவு இணைக்கப்பட்டிருந்தால், படைப்பாளர் வரலாற்றை
  மீண்டும் எழுதுவதற்குப் பதிலாக ஒரு தொடர் பங்களிப்பில் அதை உரிமைகோரலாம் அல்லது திருத்தலாம்.
- **மதிப்பாய்வு-நூல் தீர்வு.** மதிப்பாய்வு உரையாடல்கள் இணைப்புக்கு முன் தீர்க்கப்படுகின்றன;
  தீர்க்கப்படாத கருத்து ஒருங்கிணைப்பைத் தடுக்கிறது.
- **பராமரிப்பாளர் இணைப்பு.** ஒரு பராமரிப்பாளர் மட்டுமே ஒரு செருகுநிரல் பதிவை இணைக்கிறார்,
  அதுவும் [CONTRIBUTING.md](../../CONTRIBUTING.md) → "மதிப்பாய்வு நுழைவாயில்கள், மோதல்கள்
  மற்றும் இணைப்பு"-இல் உள்ள ஒவ்வொரு நுழைவாயிலும் தற்போதைய PR commit-இல் தேர்ச்சி பெற்ற
  பிறகே.

## `catalog-validation` சோதனை

`catalog/plugins/`, `schemas/` அல்லது workflow-ஐயே தொடும் ஒவ்வொரு pull request-உம்
வெளியிடப்பட்ட CLI-க்குப் பின்னிணைக்கப்பட்ட `catalog-validation` job-ஐ
(`.github/workflows/validate-catalog.yml`) இயக்குகிறது:

```bash
npx --yes omni-dsh-plugins catalog validate --catalog .
```

**இது என்ன சரிபார்க்கிறது** — உள்ளூர் கட்டமைப்பு மற்றும் சொற்பொருள் மட்டுமே:

- `catalog/plugins/` கீழ் உள்ள ஒவ்வொரு பதிவின் பாதுகாப்பான YAML பாகுபடுத்தல்.
- பொது திட்டவரைவுக்கு இணக்கம் ([docs/SCHEMA.md](../../docs/SCHEMA.md) பார்க்கவும்).
- SPDX கோவை பாகுபடுத்தல், சரியான SemVer பதிப்புகள், செல்லுபடியாகும் SHA-512 SRI ஒருமைப்பாட்டு
  மதிப்புகள்.
- நகல் நிராகரிப்பு: மீளும் பதிவு ID-கள் இல்லை, மீளும் அதிகாரப்பூர்வ
  களஞ்சிய-நோட்-கூடுதல்-துணைப்பாதை விசைகள் இல்லை.
- வேண்டுமென்றே காலியான பட்டியல் தேர்ச்சி பெறுகிறது (`0 entries valid; catalog is empty`).

**இது என்ன சரிபார்ப்பதில்லை** — எனவே பச்சை சோதனை ஒருபோதும் நிரூபிப்பதில்லை என்ன:

- தொலை களஞ்சிய அடையாளம்: இது GitHub உடன் தொடர்பு கொள்வதில்லை அல்லது களஞ்சிய நோட் ID-ஐ
  URL-உடன் தீர்ப்பதில்லை.
- பின்னிணைக்கப்பட்ட commit-இல் ஆதாரம்: விளக்கங்கள், உரிமங்கள், DSH ஒருங்கிணைப்பு மற்றும்
  புகை ஆதாரம் ஆகியவை பெறப்படுவதில்லை அல்லது ஆய்வு செய்யப்படுவதில்லை.
- படைப்பாளர் உரிமை, நட்சத்திர எண்ணிக்கைகள், அல்லது திறந்த pull request-களுடன் மோதல்.

அந்தத் தீர்ப்புகள் இணைப்புக்கு முன் பயன்படுத்தப்படும் பராமரிப்பாளர்களின் தனி மரபுரிமை
நுழைவாயில்களுக்குரியவை, [CONTRIBUTING.md](../../CONTRIBUTING.md)-இல் விவரிக்கப்பட்டுள்ளன.
உள்ளூர் சோதனை என்பது அடித்தளம், உயர்வு அளவுகோல் அல்ல.

## சரிபார்ப்பு நிலைகள்

சரிபார்ப்பு ஒவ்வொரு பதிவுக்கும் அதன் சரியான பின்னிணைக்கப்பட்ட commit-ஐ எதிராக, பொது
திட்டவரைவில் வரையறுக்கப்பட்ட நிலைகளைப் பயன்படுத்திப் பதிவு செய்யப்படுகிறது (`eligible`,
`verified`, `stale`, `unavailable`, `archived`, `quarantined`). இரண்டு நேர்மறை நிலைகள்
வேண்டுமென்றே குறுகியவை:

- `eligible` — பொது கட்டமைப்பும் சொந்த DSH ஒருங்கிணைப்பும் சரிபார்க்கப்பட்டன.
- `verified` — கூடுதலாக, பின்னிணைக்கப்பட்ட மூலம் அல்லது தொகுப்புக்கு ஒரு நிறுவல் புகை சோதனை
  தேர்ச்சி பெற்றது; திட்டவரைவு புகை சோதனை பதிவு இருக்க வேண்டும் எனக் கோருகிறது.

எந்த நிலையும் — அல்லது வேறு எதுவும் — ஏற்பு, உத்தரவாதம் அல்லது பாதுகாப்புச் சான்றிதழ் அல்ல.
நிலைகள் தரவரிசையுடன் எவ்வாறு தொடர்பு கொள்கின்றன உட்பட முழு சொற்பொருள்
[docs/RANKING.md](../../docs/RANKING.md)-இல் உள்ளது; பதிவு வடிவம்
[docs/SCHEMA.md](../../docs/SCHEMA.md)-இல் உள்ளது.

## உரிமைகோரல்கள், திருத்தங்கள் மற்றும் அகற்றல்கள்

கட்டமைக்கப்பட்ட GitHub issue படிவங்கள் (`.github/ISSUE_TEMPLATE/`) நீங்கள் சமர்ப்பிக்காத
ஒரு பதிவை மாற்றுவதற்கான நிர்வகிக்கப்படும் பாதை:

| படிவம்           | யார் பயன்படுத்துகிறார்கள்                              | விளைவு                                             |
| -------------- | ---------------------------------------- | --------------------------------------------------- |
| **உரிமைகோரல்**      | தனது செருகுநிரல் வேறொருவரால் க்யூரேட் செய்யப்பட்ட படைப்பாளர் | உரிமை அசல் மூலத்துடன் பிணைக்கப்படுகிறது; படைப்பாளர் பின்னர் நேரடியாகப் பங்களிக்கலாம் |
| **திருத்தம்** | துல்லியமற்ற பொது மெட்டாடேட்டாவைக் கவனிக்கும் எவரும் | பாதிக்கப்பட்ட பதிவுக்கு மதிப்பாய்வு செய்யப்பட்ட திருத்தம்             |
| **அகற்றல்**    | தனது பட்டியலை அகற்ற விரும்பும் படைப்பாளர், அல்லது கொள்கை மீறலைப் புகாரளிப்பவர் | பதிவின் மதிப்பாய்வு செய்யப்பட்ட அகற்றல் அல்லது தனிமைப்படுத்தல் |

மூன்று ஓட்டங்களுக்கும் பொருந்தும் விதிகள்:

- உரிமைகோரல்கள் சரிபார்க்கக்கூடிய பொது ஆதாரத்தால் ஆதரிக்கப்பட வேண்டும் (களஞ்சிய உரிமை,
  தொகுப்பு ஆசிரியம், மேனிஃபெஸ்ட் மெட்டாடேட்டா அல்லது பின்னிணைக்கப்பட்ட மூல வரலாறு) — ஒரு
  Discussion-இல் கருத்துரைப்பது படைப்பாளர்தன்மையை நிலைநாட்டாது
  ([docs/CREDIT.md](../../docs/CREDIT.md)).
- பட்டியலில் உள்ள செருகுநிரலின் பாதுகாப்புப் பிரச்சினைகள் முதலில் அந்தச் செருகுநிரலின் சொந்த
  பராமரிப்பாளருக்குச் செல்கின்றன; பட்டியல் பக்கம் பின்னர் exploit விவரத்தை வெளியிடாமல்
  திருத்தம் அல்லது தனிமைப்படுத்தலைக் கையாள்கிறது
  ([SECURITY.md](../../SECURITY.md)).
- ஒரு படிவத்தில் நம்பிக்கைச் சான்றுகள், தனிப்பட்ட தொடர்பு விவரங்கள் அல்லது பிற ரகசியங்களை
  ஒருபோதும் சேர்க்க வேண்டாம்.

## பங்குகள்

- **படைப்பாளர்கள்** தங்கள் செருகுநிரல்களையும் தங்கள் பட்டியல்களின் முன்னுரிமையையும்
  வைத்திருக்கிறார்கள். அவர்கள் நேரடியாகப் பங்களிக்கலாம், சமூக க்யூரேஷனை அங்கீகரிக்கலாம்,
  அல்லது ஏற்கனவே உள்ள பதிவை உரிமைகோரலாம்/திருத்தலாம்/அகற்றலாம்.
- **சமூகப் பங்களிப்பாளர்கள்** இன்னும் பங்களிக்காத படைப்பாளர்களுக்காக
  [docs/CREDIT.md](../../docs/CREDIT.md)-இல் உள்ள மரியாதையான-தொடர்பு மற்றும் வரவு விதிகளின்
  கீழ் பதிவுகளைக் க்யூரேட் செய்யலாம். க்யூரேஷன் ஒருபோதும் பிற்காலத்திய நேரடி படைப்பாளர்
  பங்களிப்பை விட மேலாகாது.
- **பராமரிப்பாளர்கள்** மதிப்பாய்வு செய்து, மரபுரிமை நுழைவாயில்களைப் பயன்படுத்தி, மோதல்களைத்
  தீர்த்து இணைக்கிறார்கள். அவர்கள் வலைத்தளம்
  ([dsh-plugins.omniroute.online](https://dsh-plugins.omniroute.online)) மற்றும் வெளியிடப்பட்ட
  CLI-ஐயும் தனிப்பட்ட மூலத்திலிருந்து பராமரிக்கிறார்கள்; இந்தக் களஞ்சியத்தின் பொது தரவு,
  திட்டவரைவு மற்றும் கொள்கைகளே அந்த மேற்பரப்புகள் பயன்படுத்துவன.
