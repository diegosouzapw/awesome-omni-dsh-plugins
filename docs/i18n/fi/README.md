Tämä repositorio on katalogin julkinen totuuden lähde. Jokainen merkintä on yksi YAML-tiedosto
hakemistossa `catalog/plugins/`, validoitu julkaistua JSON Schemaa vasten, lisätty yhden
yksilöllisesti tarkastetun pull requestin kautta ja aina tunnustettu laajennuksen alkuperäiselle
luojalle. Mikään katalogissa ei ole generoitu toisesta katalogista tai listasta: jokainen merkintä
on rakennettu uudelleen alkuperäisen luojan repositoriosta kiinnitetyssä commitissa.

Verkkosivustoa ylläpidetään yksityisestä lähteestä. CLI sijaitsee täällä, hakemistossa
[`cli/`](../../cli), ja tämä repositorio sisältää julkisen katalogidatan, skeeman ja käytännöt,
joita molemmat käyttävät.

## Katalogin tila

**877 laajennusta yhdistetty.** Jokainen laajennus tulee mukaan yksilöllisesti tarkastetun pull
requestin kautta, yksi kerrallaan, alkuperäisen luojan repositoriosta, kiinnitetyllä
lähdekommitilla ja selkeällä tunnustuksella.

## 🚀 Asenna CLI

```bash
npx omni-dsh-plugins --help
```

Paketti on julkaistu nimellä `omni-dsh-plugins@1.0.1`, ja yllä oleva komento on
tällä hetkellä kanoninen kutsutapa; täällä ei isännöidä asennusskriptiä.

### Käytä CLI:tä jo tänään

Versio 1.0.1 sisältää vain luku -tilaiset löytämis- ja validointikomennot sekä suostumuksen taakse
lukitut asennuskomennot. Täydellinen komentoreferenssi, mukaan lukien liput, poistumiskoodit ja
koodin suoritukseen liittyvä suostumusportti, löytyy tiedostosta [docs/CLI.md](../../docs/CLI.md).

| Komento                        | Mitä se tekee                                                        | Vaikuttaako järjestelmääsi?                    |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | Validoi katalogin YAML:n, skeeman ja paikallisen semantiikan                   | Ei — vain luku                          |
| `search <query...>`            | Hae julkisen katalogin kentistä paikallisesti                                | Ei — vain luku                          |
| `info <id>`                    | Näytä yksi julkinen katalogimerkintä                                       | Ei — vain luku                          |
| `list`                         | Listaa katalogin hallinnoimat asennukset muuttamatta profiileja            | Ei — vain luku                          |
| `doctor`                       | Vain luku -tilainen Node-, DSH-, natiivin Windowsin käytäntö- ja katalogidiagnostiikka  | Ei — vain luku                          |
| `add <id> --profile <name> --dry-run` | Näytä varmennettu asennussuunnitelma ilman tiedostoja tai aliprosesseja | Ei — kuivaharjoitus                            |
| `add <id> --profile <name> --allow-code-execution` | Asenna virallisen DSH-delegoinnin kautta        | Kyllä — vain nimenomaisella suostumuslipulla   |

```bash
# Validate the catalog in this repository (what CI runs):
npx omni-dsh-plugins catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx omni-dsh-plugins add <plugin-id> --profile default --dry-run
```

Muuttavat komennot (`add`, `update`, `remove`) eivät koskaan suorita laajennuksen elinkaarikoodia,
ellet anna lippua `--allow-code-execution`. Natiivissa Windowsissa nämä muutokset on poistettu
käytöstä versiossa v1.0.1; käytä WSL:ää. Vain luku- ja kuivaharjoituskomennot toimivat kaikkialla.

## 🔍 Miten laajennus liittyy katalogiin

![Miten laajennus liittyy katalogiin](../../docs/diagrams/catalog-flow-dark.svg#gh-dark-mode-only)
![Miten laajennus liittyy katalogiin](../../docs/diagrams/catalog-flow-light.svg#gh-light-mode-only)

1. **Yksi laajennus, yksi haara, yksi pull request.** PR lisää tai muuttaa täsmälleen yhden
   YAML-tiedoston hakemistossa `catalog/plugins/`.
2. **Luojalähtöisyys.** Laajennuksen luojan tai omistavan organisaation avaama PR menee aina
   yhteisön kuratoinnin tai automaation edelle saman laajennuksen kohdalla — katso
   [docs/CREDIT.md](../../docs/CREDIT.md).
3. **Todisteet alkuperäisestä lähteestä.** Jokainen kenttä rakennetaan uudelleen luojan
   repositoriosta kiinnitetyssä 40-merkkisessä commitissa: kuvaus, lisenssi, DSH-integraatio,
   asennuskuvaaja, tähdet.
4. **Paikallinen validointi.** `catalog validate` tarkistaa rakenteen ja paikallisen semantiikan;
   se on sama tarkistus, jonka `catalog-validation`-CI-työ suorittaa PR:lle.
5. **Ylläpitäjän portit.** Ennen yhdistämistä ylläpitäjät varmistavat erikseen repositorion
   identiteetin, luojan sidonnan ja kiinnitetyt todisteet. Vihreä paikallinen validointi on
   välttämätön, mutta ei koskaan riittävä.

Täydellinen sopimus — vaadittavat todisteet, YAML-säännöt, tähtikäytäntö, törmäysten käsittely ja
tarkastusportit — löytyy tiedostosta [CONTRIBUTING.md](../../CONTRIBUTING.md). Miten päätökset
tehdään ja kenen toimesta, kerrotaan tiedostossa [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md).

## 📄 Merkinnän anatomia

Jokainen merkintä on yksi YAML-tiedosto, joka on nimetty sen ID:n mukaan. Alla oleva esimerkki
validoituu nykyistä skeemaa vasten (kenttäkohtainen referenssi tiedostossa
[docs/SCHEMA.md](../../docs/SCHEMA.md)):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

Skeeman pakottamat keskeiset invariantit:

- `unofficial: true` ja `schemaVersion: 1` ovat vakioita.
- Monorepo-laajennuksen on käytettävä arvoa `stars: null` — emoprojektin tähtiä ei koskaan
  peritä.
- Asennuskuvaaja on joko tarkkaversioinen npm-paketti tai kiinnitetty lähde itse; se on dataa,
  ei koskaan shell-komento.
- Tila `verified` vaatii tarkastettavissa olevan smoke-testin todisteen; muutoin merkintä on
  `eligible` ja `smokeTest: null`.

## 🗂 Mitä tänne kuuluu

Tämä repositorio luetteloi itsenäisesti julkaistuja integraatioita DeepSeek Harnessille (DSH),
mukaan lukien natiivit laajennukset, laajennusperheet, teemat, taidot, asiakasohjelmat ja sillat.
Artefaktityypit, ominaisuuskategoriat ja käyttöliittymätunnisteet on määritelty tiedostossa
[docs/CATEGORIES.md](../../docs/CATEGORIES.md).

Jokainen julkinen tietue on yksi YAML-tiedosto hakemistossa `catalog/plugins/`, ja sen on
validoiduttava skeemaa `schemas/plugin.schema.yaml` vasten. Listaus tarkoittaa, että dokumentoidut
kelpoisuus- tai varmennustarkistukset on suoritettu; se ei ole tietoturvasertifikaatti eikä
DeepSeekin hyväksyntä.

## 🏅 Järjestys ja varmennus

Vain omistautuneet, natiivit, kelpoiset tai varmennetut laajennusrepositoriot, joiden tähdet
kuuluvat juuri kyseiseen repositorioon, voivat päästä tähtijärjestykseen. Laajemmissa
monorepoissa säilytettävät integraatiot pysyvät löydettävinä, mutta niissä käytetään arvoa
`stars: null`, eikä emoprojektin tähtiä koskaan peritä. Katso täydellinen ehto tiedostosta
[docs/RANKING.md](../../docs/RANKING.md).

Julkiset varmennustilat erottavat rakenteellisen kelpoisuuden asennuksen smoke-testistä. Mikään
tila ei edusta absoluuttista turvallisuutta. Tarkasta laajennuksen repositorio, kiinnitetty
commit, lisenssi ja asennuskäyttäytyminen ennen sen käyttöä.

## 🤝 Osallistu tai vaadi merkintä omaksesi

Lue [CONTRIBUTING.md](../../CONTRIBUTING.md) ennen pull requestin avaamista. Pull requestin on
lisättävä tai muutettava täsmälleen yksi laajennusmerkintä, ja sen on viitattava alkuperäisen
luojan repositorioon eikä toiseen katalogiin. Luojan itsensä tekemät pull requestit menevät
automatisoitujen katalogi-pull requestien edelle.

Strukturoituja issue-lomakkeita on saatavilla luojien vaatimuksiin, korjauksiin ja poistoihin.
Älä koskaan lähetä tunnuksia, yksityisiä yhteystietoja tai muita salaisuuksia.
