# স্রষ্টা কৃতিত্ব এবং পুল রিকোয়েস্ট অগ্রাধিকার

> 🌐 [English](../../CREDIT.md) · [Português (Brasil)](../pt-BR/CREDIT.md) · [中文（简体）](../zh-CN/CREDIT.md) · **বাংলা**

ক্যাটালগের অস্তিত্ব রয়েছে স্বাধীন DSH কাজকে তার স্রষ্টাদের থেকে মালিকানা না নিয়ে আবিষ্কারযোগ্য করার
জন্য। পাবলিক এন্ট্রি মূল রিপোজিটরি এবং একটি অপরিবর্তনীয় সোর্স কমিট উল্লেখ করে।

## একই প্লাগইনের জন্য অগ্রাধিকার

<!-- creator-first:direct-pr-supersedes-curation-and-automation -->

1. প্লাগইন স্রষ্টা বা মালিকানাধীন সংস্থার দ্বারা খোলা একটি পুল রিকোয়েস্ট।
2. স্রষ্টার দ্বারা স্পষ্টভাবে অনুমোদিত বা সহ-রচিত একটি কমিউনিটি পুল রিকোয়েস্ট।
3. একটি বিদ্যমান বৈধ কমিউনিটি পুল রিকোয়েস্ট।
4. একটি ক্যাটালগ অটোমেশন পুল রিকোয়েস্ট।
5. পাবলিক পুল রিকোয়েস্ট ছাড়া একটি প্রাইভেট প্রার্থী।

একটি সরাসরি স্রষ্টা পুল রিকোয়েস্ট সর্বদা পছন্দনীয় এবং একই প্রামাণ্য প্লাগইনের জন্য যেকোনো খোলা কমিউনিটি
কিউরেশন বা অটোমেশন পুল রিকোয়েস্টকে প্রতিস্থাপন করে, কোনটি প্রথমে খোলা হয়েছে বা আরও অগ্রসর হয়েছে তা
নির্বিশেষে। স্রষ্টার পুল রিকোয়েস্ট পর্যালোচনার বাহন হয়ে ওঠে; তাদের ব্রাঞ্চ কখনও ওভাররাইট, ফোর্স-পুশ বা
কিউরেটেড পুল রিকোয়েস্টে স্থানান্তরিত করা হয় না। যদি একটি কিউরেটেড এন্ট্রি ইতিমধ্যে মার্জ হয়ে থাকে, তাহলে
ইতিহাস অক্ষত থাকে এবং স্রষ্টা একটি নতুন অবদানে এটি দাবি বা সংশোধন করতে পারেন।

## পাবলিক কৃতিত্ব

প্রতিটি ক্যাটালগ এন্ট্রি স্রষ্টার পাবলিক GitHub হ্যান্ডেল, মূল রিপোজিটরি, রিপোজিটরি নোড ID, প্লাগইন
সাবপাথ এবং সম্পূর্ণ পিন করা কমিট বহন করে। পাবলিক স্রষ্টা প্রোফাইল একক হ্যান্ডেল থেকে উদ্ভূত, দ্বিতীয়
পরিচয় হিসেবে সংরক্ষিত না হয়ে। পৃথক মেইনটেইনার প্রোভেন্যান্স গেট নোড ID সমাধান করে এবং একটি রিপোজিটরি
URL অমিল প্রত্যাখ্যান করে। পুল রিকোয়েস্ট বিবরণে `Created by @handle` বলা উচিত এবং সোর্স রিপোজিটরি ও
সোর্স কমিট মেটাডেটা অন্তর্ভুক্ত করা উচিত।

একটি Discussion-এ পোস্ট বা মন্তব্য করা একজন ব্যক্তিকে স্বয়ংক্রিয়ভাবে স্রষ্টা হিসেবে বিবেচনা করা হয় না।
মালিকানা অবশ্যই রিপোজিটরি মালিক বা সংস্থা, প্যাকেজ লেখকত্ব, ম্যানিফেস্ট মেটাডেটা বা সঠিক পিন করা সোর্স
ইতিহাস দ্বারা সমর্থিত হতে হবে।

## Git পরিচয়

<!-- creator-first:source-bound-git-identity -->

কমিট লেখকত্ব এবং পুল রিকোয়েস্ট লেখকত্ব পৃথক। একটি স্রষ্টা-উৎসারিত পুল রিকোয়েস্ট স্রষ্টাকে পুল রিকোয়েস্ট
লেখক হিসেবে রাখে, এবং তাদের কমিটগুলি স্বাভাবিকভাবে লেখকত্ব সংরক্ষণ করে। একজন মেইনটেইনার বা অটোমেশন
অ্যাকাউন্ট কমিটার বা একজন যাচাইকৃত সহ-লেখক হিসেবে প্রদর্শিত হতে পারে, কিন্তু স্রষ্টার লেখকত্ব প্রতিস্থাপন
করা উচিত নয়।

একটি কিউরেটেড কমিটের জন্য, স্রষ্টাকে Git লেখক হিসেবে ব্যবহার করুন অথবা একটি `Co-authored-by` ট্রেইলার
শুধুমাত্র তখনই যোগ করুন যখন সঠিক পরিচয় উৎস-আবদ্ধ এবং সর্বজনীনভাবে যাচাইযোগ্য, যেমন মূল রিপোজিটরিতে
স্রষ্টার কমিটে ইতিমধ্যে সংযুক্ত একটি পরিচয়। কখনও একটি ইমেইল অনুমান করবেন না, একটি noreply ঠিকানা তৈরি
করবেন না বা একটি অনুমোদিত পাবলিক সোর্সের বাইরে পাওয়া একটি প্রাইভেট ঠিকানা ব্যবহার করবেন না।

যখন একটি যাচাইকৃত Git পরিচয় অনুপলব্ধ থাকে, তখন কিউরেটর বা অটোমেশন অ্যাকাউন্ট কমিটটি রচনা করে এবং
পরিবর্তে সুস্পষ্ট দৃশ্যমান কৃতিত্ব দেয়: `Created by @handle`, সংশ্লিষ্ট পাবলিক প্রোফাইল এবং এন্ট্রি ও
পুল রিকোয়েস্টে মূল রিপোজিটরির একটি লিঙ্ক। Git পরিচয় ম্যাপিং থেকে স্বাধীনভাবে দৃশ্যমান YAML কৃতিত্ব সর্বদা
প্রয়োজনীয়। একটি পরবর্তী সরাসরি স্রষ্টা পুল রিকোয়েস্ট তার কৃত্রিম ইতিহাসের উত্তরাধিকার সূত্রে পাওয়ার
পরিবর্তে একটি খোলা কিউরেটেড পুল রিকোয়েস্টকে প্রতিস্থাপন করে।

## শ্রদ্ধাশীল স্রষ্টা উল্লেখ

একটি কিউরেটেড পুল রিকোয়েস্ট তার বিবরণে মূল রিপোজিটরি লিঙ্কের পাশে একটি শ্রদ্ধাশীল সর্বজনীন `@creator`
উল্লেখ ব্যবহার করে। এটি পর্যালোচনা বা একটি প্রতিস্থাপনকারী সরাসরি পুল রিকোয়েস্টের জন্য আমন্ত্রণ জানাতে
পারে। উল্লেখটি পুনরাবৃত্তি করবেন না, প্রচারমূলক ইস্যু খুলবেন না, ক্রস-পোস্ট করবেন না বা অযাচিত সরাসরি
বার্তা পাঠাবেন না।

## ক্যাটালগ লাইসেন্স বনাম আপস্ট্রিম লাইসেন্স

ক্যাটালগ তথ্য এবং সম্পাদকীয় YAML মেটাডেটা CC0-1.0-এর অধীনে উৎসর্গীকৃত। সেই উৎসর্গ আপস্ট্রিম প্লাগইনের
লাইসেন্স পরিবর্তন করে না। আপস্ট্রিম কোড, ডকুমেন্টেশন, স্ক্রিনশট, লোগো এবং অন্যান্য সৃজনশীল উপাদান তাদের
মূল লাইসেন্স এবং মালিকদের অধীন থেকে যায়।
