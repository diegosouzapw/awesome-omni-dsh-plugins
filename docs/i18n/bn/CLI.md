# CLI রেফারেন্স — `omni-dsh-plugins@1.0.1`

> 🌐 [English](../../CLI.md) · [Português (Brasil)](../pt-BR/CLI.md) · [中文（简体）](../zh-CN/CLI.md) · **বাংলা**

> **অনানুষ্ঠানিক কমিউনিটি প্রকল্প। DeepSeek-এর সাথে সংযুক্ত নয়, অনুমোদিত নয়, বা পৃষ্ঠপোষকতাপ্রাপ্ত নয়।**
> DeepSeek-এর নাম এবং চিহ্নগুলি তাদের নিজ নিজ মালিকের অন্তর্গত।

এই পৃষ্ঠাটি প্রকাশিত CLI-কে ঠিক যেভাবে এটি সংস্করণ `1.0.1`-এ আচরণ করে সেভাবে নথিভুক্ত করে। নিচের প্রতিটি
সিনোপসিস এবং ফ্ল্যাগ প্রকাশিত কমান্ডের নিজস্ব `--help` আউটপুট থেকে আসে; এখানে কিছুই অপ্রকাশিত আচরণ বর্ণনা
করে না। CLI-টি এই রিপোজিটরিতে [`cli/`](../../cli)-এর অধীনে বিকশিত হয় এবং npm-এ
[`omni-dsh-plugins`](https://www.npmjs.com/package/omni-dsh-plugins) হিসেবে প্রকাশিত হয়, একটি
প্রোভেন্যান্স সত্যায়নসহ যা প্রতিটি বিল্ডকে তা তৈরিকারী কমিট এবং ওয়ার্কফ্লো রানের সাথে সংযুক্ত করে।

```bash
npx omni-dsh-plugins --help
```

## v1.0.1-এ ডিজাইন নীতি

- **ডিফল্টরূপে রিড-অনলি।** `catalog`, `search`, `info`, `list` এবং `doctor` কখনও প্রোফাইল পরিবর্তন
  করে না, ফাইল লেখে না বা প্লাগইন কোড স্পন করে না।
- **কোড এক্সিকিউশনের জন্য সম্মতি গেট।** `add`, `update` এবং `remove` DSH/pnpm লাইফসাইকেল কোড চালাতে
  অস্বীকার করে যদি না আপনি `--allow-code-execution` পাস করেন। এটি ছাড়া, যাচাইকৃত পরিকল্পনা দেখতে
  `--dry-run` ব্যবহার করুন।
- **নেটিভ Windows নীতি।** কোড এক্সিকিউশনসহ নেটিভ Windows `add`/`update`/`remove` v1.0.1-এ নিষ্ক্রিয়
  করা আছে; WSL ব্যবহার করুন। ড্রাই-রান এবং রিড-অনলি কমান্ডগুলি উপলব্ধ থাকে, এবং নেটিভ Windows রিকভারি
  মার্কারের জন্য নথিভুক্ত ম্যানুয়াল রিকভারি প্রয়োজন।
- **পিন করা ইনপুট।** ক্যাটালগ ইনপুট একটি লোকাল ডিরেক্টরি, একটি স্ন্যাপশট ফাইল, অথবা একটি পিন করা পাবলিক
  স্ন্যাপশট URL হতে পারে, ঐচ্ছিকভাবে একটি সঠিক ৪০-অক্ষরের রিভিশনে লক করা।

## সাধারণ অপশন

এই অপশনগুলি ক্যাটালগ-ব্যবহারকারী কমান্ডগুলিতে দেখা যায় (`catalog validate`, `search`, `info`,
`add`, `update`, `remove`, `doctor`):

| Option                    | অর্থ                                                            |
| ------------------------- | ------------------------------------------------------------------ |
| `--catalog <path-or-url>` | লোকাল ক্যাটালগ ডিরেক্টরি, স্ন্যাপশট ফাইল, অথবা পিন করা পাবলিক স্ন্যাপশট URL |
| `--revision <sha>`        | সঠিক ৪০-অক্ষরের স্ন্যাপশট রিভিশন                               |
| `--json`                  | স্থিতিশীল JSON আউটপুট প্রদান করে                                            |

গ্লোবাল অপশন: `-V, --version` CLI সংস্করণ প্রিন্ট করে; `-h, --help` যেকোনো কমান্ডের জন্য সাহায্য প্রিন্ট
করে (`dsh-plugins help [command]`ও কাজ করে)।

## এক্সিট কোড

CLI প্রচলিত প্রসেস এক্সিট কোড ব্যবহার করে:

| Exit code | অর্থ                                                                    |
| --------: | -------------------------------------------------------------------------- |
| `0`       | সফলতা (একটি খালি ক্যাটালগের মতো "খালি কিন্তু বৈধ" ফলাফলসহ)     |
| `1`       | ব্যর্থতা: বৈধতা যাচাইকরণ ত্রুটি, এন্ট্রি পাওয়া যায়নি, প্রয়োজনীয় অপশন অনুপস্থিত, অথবা একটি ডায়াগনস্টিক চেক যা একটি ত্রুটি রিপোর্ট করে |

v1.0.1-এ পর্যবেক্ষিত উদাহরণ: একটি বৈধ খালি ক্যাটালগে `catalog validate` `0 entries valid; catalog
is empty`-সহ `0`-এ প্রস্থান করে; `info <unknown-id>` `Plugin not found`-সহ `1`-এ প্রস্থান করে;
`doctor` `1`-এ প্রস্থান করে যখন কোনো চেক (যেমন একটি অনুপস্থিত `dsh` এক্সিকিউটেবল) একটি ত্রুটি রিপোর্ট
করে।

## Commands

### `catalog` — পাবলিক ক্যাটালগ সারফেস যাচাই করে

```text
dsh-plugins catalog validate [--catalog <path-or-url>] [--revision <sha>] [--json]
dsh-plugins catalog docs-check [root]
dsh-plugins catalog github-forms-check [root]
```

- **`catalog validate`** — ক্যাটালগ YAML এবং সিমান্টিক্স যাচাই করে: নিরাপদ YAML পার্সিং, পাবলিক
  স্কিমা, SPDX এক্সপ্রেশন পার্সিং, সঠিক SemVer, SHA-512 SRI, এবং ডুপ্লিকেট ID / রিপোজিটরি-নোড-প্লাস-
  সাবপাথ প্রত্যাখ্যান। এটি স্থানীয় এবং রিড-অনলি: এটি GitHub-এর সাথে যোগাযোগ করে না, রিপোজিটরির
  পরিচয় সমাধান করে না বা পিন করা কমিটে প্রমাণ পরীক্ষা করে না। এটি প্রতিটি ক্যাটালগ পুল রিকোয়েস্টে
  `catalog-validation` CI জব যে ঠিক কমান্ডটি চালায়।
- **`catalog docs-check [root]`** — প্রয়োজনীয় পাবলিক ক্যাটালগ ডকুমেন্টেশন বিদ্যমান কিনা এবং Markdown
  ফেন্স সুষম কিনা তা পরীক্ষা করে।
- **`catalog github-forms-check [root]`** — স্ট্রাকচার্ড পাবলিক GitHub ইস্যু ফর্ম (দাবি, সংশোধন,
  অপসারণ) পরীক্ষা করে।

```bash
# From the repository root:
npx omni-dsh-plugins catalog validate --catalog .
npx omni-dsh-plugins catalog docs-check .
npx omni-dsh-plugins catalog github-forms-check .
```

### `search` — লোকালভাবে পাবলিক ক্যাটালগ ফিল্ড সার্চ করে

```text
dsh-plugins search [options] <query...>
```

নির্বাচিত ক্যাটালগ ইনপুটের বিপরীতে লোকালভাবে পাবলিক ক্যাটালগ ফিল্ড সার্চ করে। মিলে যাওয়া এন্ট্রি প্রিন্ট
করে, অথবা যখন কিছু মেলে না তখন `No plugins found.` (exit `0`)।

```bash
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins search notes markdown --catalog . --json
```

### `discover` — ক্যাটালগের বাইরে প্লাগইন খুঁজে বের করে

```text
dsh-plugins discover [options] <query...>
```

> `discover` `1.0.0`-এ শিপ হয়, এই প্যাকেজ নামের অধীনে প্রথম রিলিজ।

প্রথমে কিউরেট করা ক্যাটালগ খোঁজে, তারপর — যদি না `--offline` দেওয়া হয় — লাইভ GitHub `dsh-plugin`
টপিক, যাতে এখনও জমা দেওয়া হয়নি এমন একটি প্লাগইনও খুঁজে পাওয়া যায়। ক্যাটালগ ফলাফল ক্যাটালগের ধারণ করা
প্রমাণ বহন করে (পিন করা কমিট, স্রষ্টা, লাইসেন্স); কমিউনিটি ফলাফল তার কোনোটিই বহন করে না এবং সেভাবেই
লেবেল করা হয়, কারণ সেগুলি সম্পর্কে কিছুই পর্যালোচিত হয়নি।

`--limit <n>` প্রতি স্তরে ফলাফল সীমাবদ্ধ করে (ডিফল্ট `8`)। `--json` স্থিতিশীল মেশিন আকার প্রদান করে,
যা কখনও লোকালাইজড নয়।

```bash
npx omni-dsh-plugins discover memory --catalog .
npx omni-dsh-plugins discover vision --offline --catalog . --json
```

### `info` — একটি পাবলিক ক্যাটালগ এন্ট্রি দেখায়

```text
dsh-plugins info [options] <id>
```

প্রামাণ্য প্লাগইন ID দ্বারা একটি পাবলিক ক্যাটালগ এন্ট্রি দেখায়। যখন ID ক্যাটালগে নেই তখন
`Plugin not found: <id>`-সহ `1`-এ প্রস্থান করে।

```bash
npx omni-dsh-plugins info example-notes-search --catalog .
```

### `add` — অফিসিয়াল DSH ডেলিগেশনের মাধ্যমে একটি ক্যাটালগ প্লাগইন যোগ করে

```text
dsh-plugins add [options] <id>
```

| Option                   | অর্থ                                                            |
| ------------------------ | ------------------------------------------------------------------ |
| `--profile <name>`       | পরিবর্তনের জন্য DSH প্রোফাইল (বাস্তবে প্রয়োজনীয়; এটি ছাড়া কমান্ড ত্রুটি দেয়) |
| `--dry-run`              | ফাইল বা সাবপ্রসেস ছাড়াই যাচাইকৃত পরিকল্পনা দেখায়               |
| `--allow-code-execution` | DSH/pnpm লাইফসাইকেল কোডে সম্মতি (নেটিভ Windows নিষ্ক্রিয়; WSL ব্যবহার করুন) |
| `--catalog` / `--revision` / `--json` | উপরের সাধারণ অপশন                                  |

এই সংস্করণে ড্রাই-রান সিমান্টিক্স: কমান্ডটি পিন করা এন্ট্রির জন্য পরিকল্পনা সমাধান ও যাচাই করে এবং এটি
প্রিন্ট করে, কোনো ফাইল তৈরি না করে এবং কোনো সাবপ্রসেস স্পন না করে। প্রকৃত ইনস্টলেশন অফিসিয়াল DSH
টুলিংকে ডেলিগেট করে এবং শুধুমাত্র `--allow-code-execution`-সহ এগিয়ে যায়।

```bash
# Preview only — nothing is written, nothing executes:
npx omni-dsh-plugins add example-notes-search --profile default --dry-run

# Real install — explicit consent to lifecycle code:
npx omni-dsh-plugins add example-notes-search --profile default --allow-code-execution
```

### `update` — অফিসিয়াল DSH ডেলিগেশনের মাধ্যমে একটি ক্যাটালগ প্লাগইন আপডেট করে

```text
dsh-plugins update [options] <id>
```

`add`-এর মতো একই অপশন এবং সম্মতি সিমান্টিক্স: `--profile <name>`, `--dry-run`,
`--allow-code-execution`, প্লাস সাধারণ ক্যাটালগ অপশন।

### `remove` — অফিসিয়াল DSH ডেলিগেশনের মাধ্যমে একটি ক্যাটালগ-পরিচালিত প্লাগইন সরায়

```text
dsh-plugins remove [options] <id>
```

`add`-এর মতো একই অপশন এবং সম্মতি সিমান্টিক্স। শুধুমাত্র ক্যাটালগ-পরিচালিত ইনস্টল সরানো হয়।

### `recover` — একটি ধরে রাখা POSIX মিউটেশন পুনরুদ্ধার করে

```text
dsh-plugins recover
```

একটি ব্যাহত `add`/`update`/`remove`-এর পরে একটি ধরে রাখা POSIX মিউটেশন পুনরুদ্ধার করে। কিছু
পেন্ডিং না থাকলে এটি `No mutation recovery is pending.` প্রিন্ট করে এবং `0`-এ প্রস্থান করে। নথিভুক্ত
নীতি অনুযায়ী নেটিভ Windows রিকভারি ম্যানুয়াল থেকে যায়।

### `list` — ক্যাটালগ-পরিচালিত ইনস্টলের তালিকা দেখায়

```text
dsh-plugins list [--profile <name>] [--json]
```

প্রোফাইল পরিবর্তন না করে ক্যাটালগ-পরিচালিত ইনস্টলের তালিকা দেখায়। `--profile <name>` DSH প্রোফাইল
দিয়ে ফিল্টার করে। কোনো ইনস্টল না থাকলে এটি `No catalog-managed plugins installed.` প্রিন্ট করে এবং
`0`-এ প্রস্থান করে।

### `doctor` — রিড-অনলি ডায়াগনস্টিকস

```text
dsh-plugins doctor [--catalog <path-or-url>] [--revision <sha>] [--json]
```

রিড-অনলি Node, DSH, নেটিভ Windows পলিসি এবং ক্যাটালগ ডায়াগনস্টিকস চালায়। প্রতিটি চেক `ok` অথবা
`error` রিপোর্ট করে; যেকোনো `error` সামগ্রিক এক্সিট কোডকে `1` করে তোলে। `dsh` এক্সিকিউটেবল ছাড়া একটি
মেশিনে উদাহরণ আউটপুট:

```text
node [ok]: Node 24.16.0 is supported
dsh [error]: dsh executable was not found
catalog [ok]: catalog is valid and empty
```

## স্থানীয় বৈধতা যাচাইকরণ কী প্রমাণ করে না

একটি সবুজ `catalog validate` রান শুধুমাত্র স্ট্রাকচার এবং স্থানীয় সিমান্টিক্স নিশ্চিত করে। এটি দূরবর্তী
রিপোজিটরির পরিচয়, স্রষ্টার মালিকানা, বা পিন করা কমিটে প্রমাণ প্রমাণ করে না — মেইনটেইনাররা যেকোনো মার্জের
আগে সেই পৃথক প্রোভেন্যান্স গেটগুলি প্রয়োগ করেন, যেমনটি [CONTRIBUTING.md](../../CONTRIBUTING.md) এবং
[docs/GOVERNANCE.md](../../docs/GOVERNANCE.md)-এ বর্ণিত।
