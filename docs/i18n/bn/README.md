এই রিপোজিটরি ক্যাটালগের জন্য সত্যের পাবলিক উৎস। প্রতিটি তালিকাভুক্তি `catalog/plugins/`-এর অধীনে একটি YAML
ফাইল, যা একটি প্রকাশিত JSON Schema-র বিপরীতে যাচাই করা হয়, একটি পৃথকভাবে পর্যালোচিত পুল রিকোয়েস্টের মাধ্যমে যুক্ত করা
হয়, এবং সর্বদা প্লাগইনের মূল নির্মাতাকে কৃতিত্ব দেওয়া হয়। ক্যাটালগের কোনো কিছুই অন্য কোনো ক্যাটালগ বা তালিকা থেকে
তৈরি করা হয় না: প্রতিটি এন্ট্রি একটি পিন করা কমিটে মূল নির্মাতার রিপোজিটরি থেকে পুনর্গঠিত হয়।

ওয়েবসাইট এবং CLI প্রাইভেট সোর্স থেকে রক্ষণাবেক্ষণ করা হয়; এই রিপোজিটরি তাদের ব্যবহৃত পাবলিক ক্যাটালগ ডেটা, স্কিমা এবং
নীতিমালা বহন করে।

## ক্যাটালগের অবস্থা

**১৩৫৬টি প্লাগইন মার্জ হয়েছে।** প্রতিটি প্লাগইন একটি করে, মূল নির্মাতার রিপোজিটরি থেকে, একটি পৃথকভাবে পর্যালোচিত পুল
রিকোয়েস্টের মাধ্যমে, একটি পিন করা সোর্স কমিট এবং স্পষ্ট কৃতিত্ব-সহ প্রবেশ করে।

## 🚀 CLI ইনস্টল করুন

```bash
npx omni-dsh-plugins --help
```

স্কোপড প্যাকেজটি `omni-dsh-plugins@1.0.1` হিসেবে প্রকাশিত, এবং উপরের কমান্ডটি আজকের হিসেবে প্রামাণিক
আহ্বান; এখানে কোনো ইনস্টলার স্ক্রিপ্ট হোস্ট করা হয় না।

### আজই CLI ব্যবহার করুন

সংস্করণ 1.0.1-এ রিড-অনলি ডিসকভারি ও ভ্যালিডেশন কমান্ড এবং সম্মতি-নিয়ন্ত্রিত ইনস্টল কমান্ড অন্তর্ভুক্ত। ফ্ল্যাগ,
এক্সিট কোড এবং কোড-এক্সিকিউশন সম্মতি গেটসহ সম্পূর্ণ কমান্ড রেফারেন্স [docs/CLI.md](../../docs/CLI.md)-এ পাওয়া যাবে।

| Command                        | এটি কী করে                                                        | এটি কি আপনার সিস্টেম স্পর্শ করে?                    |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | ক্যাটালগ YAML, স্কিমা এবং লোকাল সিমান্টিক্স যাচাই করে                   | না — রিড-অনলি                          |
| `search <query...>`            | লোকালভাবে পাবলিক ক্যাটালগ ফিল্ড সার্চ করে                                | না — রিড-অনলি                          |
| `info <id>`                    | একটি পাবলিক ক্যাটালগ এন্ট্রি দেখায়                                       | না — রিড-অনলি                          |
| `list`                         | প্রোফাইল পরিবর্তন না করে ক্যাটালগ-পরিচালিত ইনস্টলের তালিকা দেখায়            | না — রিড-অনলি                          |
| `doctor`                       | Node, DSH, নেটিভ Windows পলিসি এবং ক্যাটালগের রিড-অনলি ডায়াগনস্টিকস  | না — রিড-অনলি                          |
| `add <id> --profile <name> --dry-run` | ফাইল বা সাবপ্রসেস ছাড়াই যাচাইকৃত ইনস্টল পরিকল্পনা দেখায় | না — ড্রাই-রান                            |
| `add <id> --profile <name> --allow-code-execution` | অফিসিয়াল DSH ডেলিগেশনের মাধ্যমে ইনস্টল করে        | হ্যাঁ — শুধুমাত্র স্পষ্ট সম্মতি ফ্ল্যাগসহ   |

```bash
# Validate the catalog in this repository (what CI runs):
npx omni-dsh-plugins catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx omni-dsh-plugins add <plugin-id> --profile default --dry-run
```

পরিবর্তনকারী কমান্ডগুলো (`add`, `update`, `remove`) কখনও প্লাগইন লাইফসাইকেল কোড এক্সিকিউট করে না যদি না আপনি
`--allow-code-execution` পাস করেন। নেটিভ Windows-এ এই পরিবর্তনগুলো v1.0.1-এ নিষ্ক্রিয় করা আছে; WSL ব্যবহার
করুন। রিড-অনলি এবং ড্রাই-রান কমান্ড সর্বত্র কাজ করে।

## 🔍 কীভাবে একটি প্লাগইন ক্যাটালগে প্রবেশ করে

![কীভাবে একটি প্লাগইন ক্যাটালগে প্রবেশ করে](../../docs/diagrams/catalog-flow-dark.svg#gh-dark-mode-only)
![কীভাবে একটি প্লাগইন ক্যাটালগে প্রবেশ করে](../../docs/diagrams/catalog-flow-light.svg#gh-light-mode-only)

1. **একটি প্লাগইন, একটি ব্রাঞ্চ, একটি পুল রিকোয়েস্ট।** PR-টি `catalog/plugins/`-এর অধীনে ঠিক একটি YAML ফাইল
   যোগ করে বা পরিবর্তন করে।
2. **স্রষ্টা-প্রথম।** প্লাগইনের নির্মাতা বা মালিক প্রতিষ্ঠানের খোলা একটি PR একই প্লাগইনের জন্য কমিউনিটি কিউরেশন বা
   অটোমেশনের চেয়ে সর্বদা অগ্রাধিকার পায় — দেখুন [docs/CREDIT.md](../../docs/CREDIT.md)।
3. **মূল উৎস থেকে প্রমাণ।** প্রতিটি ফিল্ড নির্মাতার রিপোজিটরি থেকে একটি পিন করা ৪০-অক্ষরের কমিটে পুনর্গঠিত হয়:
   বিবরণ, লাইসেন্স, DSH ইন্টিগ্রেশন, ইনস্টল ডেসক্রিপ্টর, স্টার।
4. **স্থানীয় যাচাই।** `catalog validate` কাঠামো এবং স্থানীয় সিমান্টিক্স পরীক্ষা করে; এটি একই চেক যা
   `catalog-validation` CI জব PR-এ চালায়।
5. **মেইনটেইনার গেট।** মার্জের আগে, মেইনটেইনাররা আলাদাভাবে রিপোজিটরি পরিচয়, নির্মাতা-বাঁধন এবং পিন করা প্রমাণ
   যাচাই করেন। একটি সবুজ স্থানীয় যাচাই প্রয়োজনীয়, কিন্তু কখনও যথেষ্ট নয়।

সম্পূর্ণ চুক্তি — প্রয়োজনীয় প্রমাণ, YAML নিয়ম, স্টার নীতি, সংঘর্ষ পরিচালনা এবং পর্যালোচনা গেট — [CONTRIBUTING.md](../../CONTRIBUTING.md)-এ
রয়েছে। কীভাবে এবং কার দ্বারা সিদ্ধান্ত নেওয়া হয় তা [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md)-এ রয়েছে।

## 📄 একটি এন্ট্রির অ্যানাটমি

প্রতিটি এন্ট্রি তার ID অনুযায়ী নামকরণ করা একটি YAML ফাইল। নিচের উদাহরণটি বর্তমান স্কিমার বিপরীতে যাচাই হয়
(ফিল্ড-বাই-ফিল্ড রেফারেন্স [docs/SCHEMA.md](../../docs/SCHEMA.md)-এ):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

স্কিমা দ্বারা প্রয়োগকৃত মূল ইনভ্যারিয়েন্ট:

- `unofficial: true` এবং `schemaVersion: 1` ধ্রুবক।
- একটি মনোরিপো প্লাগইনকে অবশ্যই `stars: null` ব্যবহার করতে হবে — প্যারেন্ট-প্রকল্পের স্টার কখনও উত্তরাধিকারসূত্রে পাওয়া যায় না।
- ইনস্টল ডেসক্রিপ্টর হয় একটি সঠিক-সংস্করণ npm প্যাকেজ অথবা পিন করা সোর্স নিজেই; এটি ডেটা, কখনও শেল কমান্ড নয়।
- `verified` স্ট্যাটাসের জন্য পর্যালোচনাযোগ্য স্মোক-টেস্ট প্রমাণ প্রয়োজন; অন্যথায় এন্ট্রিটি `smokeTest: null`-সহ `eligible`।

## 🗂 এখানে কী থাকে

এই রিপোজিটরি DeepSeek Harness (DSH)-এর জন্য স্বাধীনভাবে প্রকাশিত ইন্টিগ্রেশনগুলো ক্যাটালগভুক্ত করে, যার মধ্যে রয়েছে
নেটিভ প্লাগইন, প্লাগইন পরিবার, থিম, স্কিল, ক্লায়েন্ট এবং ব্রিজ। আর্টিফ্যাক্ট প্রকার, সক্ষমতা বিভাগ এবং ইন্টারফেস ট্যাগ
[docs/CATEGORIES.md](../../docs/CATEGORIES.md)-এ সংজ্ঞায়িত করা আছে।

প্রতিটি পাবলিক রেকর্ড `catalog/plugins/`-এর অধীনে একটি YAML ফাইল এবং অবশ্যই `schemas/plugin.schema.yaml`-এর
বিপরীতে যাচাই হতে হবে। একটি তালিকাভুক্তি মানে হলো নথিভুক্ত যোগ্যতা বা যাচাইকরণ চেক সম্পন্ন হয়েছে; এটি কোনো নিরাপত্তা
সার্টিফিকেশন বা DeepSeek অনুমোদন নয়।

## 🏅 র‍্যাঙ্কিং এবং যাচাইকরণ

শুধুমাত্র ডেডিকেটেড, নেটিভ, যোগ্য বা যাচাইকৃত প্লাগইন রিপোজিটরি যাদের স্টার সেই সঠিক রিপোজিটরির অন্তর্গত, তারাই স্টার
র‍্যাঙ্কিংয়ে প্রবেশ করতে পারে। বৃহত্তর মনোরিপোর ভেতরে সংরক্ষিত ইন্টিগ্রেশনগুলো আবিষ্কারযোগ্য থাকে কিন্তু `stars: null`
ব্যবহার করে এবং কখনও প্যারেন্ট-প্রকল্পের স্টার উত্তরাধিকারসূত্রে পায় না। সম্পূর্ণ নির্ণায়কের জন্য [docs/RANKING.md](../../docs/RANKING.md)
দেখুন।

পাবলিক যাচাইকরণ অবস্থাগুলো কাঠামোগত যোগ্যতাকে একটি ইনস্টলেশন স্মোক-টেস্ট থেকে আলাদা করে। কোনো অবস্থাই সম্পূর্ণ
নিরাপত্তার প্রতিনিধিত্ব করে না। ব্যবহারের আগে প্লাগইনের রিপোজিটরি, পিন করা কমিট, লাইসেন্স এবং ইনস্টলেশন আচরণ পর্যালোচনা
করুন।

## 🤝 অবদান রাখুন বা একটি এন্ট্রি দাবি করুন

একটি পুল রিকোয়েস্ট খোলার আগে [CONTRIBUTING.md](../../CONTRIBUTING.md) পড়ুন। একটি পুল রিকোয়েস্ট অবশ্যই ঠিক একটি
প্লাগইন এন্ট্রি যোগ বা পরিবর্তন করবে এবং অন্য কোনো ক্যাটালগের পরিবর্তে মূল নির্মাতার রিপোজিটরি উল্লেখ করবে। নির্মাতা-রচিত
পুল রিকোয়েস্ট স্বয়ংক্রিয় ক্যাটালগ পুল রিকোয়েস্টের চেয়ে অগ্রাধিকার পায়।

নির্মাতা দাবি, সংশোধন এবং অপসারণের জন্য কাঠামোবদ্ধ ইস্যু ফর্ম উপলব্ধ। কখনও ক্রেডেনশিয়াল, ব্যক্তিগত যোগাযোগের বিবরণ
বা অন্যান্য গোপনীয় তথ্য জমা দেবেন না।
