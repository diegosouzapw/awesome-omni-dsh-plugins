## W skrócie

| Powierzchnia     | Czym jest                                                       | Gdzie                                                                    |
| ----------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **Strona** | Renderowana przeglądarka katalogu z wyszukiwaniem i rankingiem                 | [dsh-plugins.omniroute.online](https://dsh-plugins.omniroute.online)     |
| **Katalog** | Jeden plik YAML na wtyczkę, jedyne źródło prawdy             | [`catalog/plugins/`](../../catalog/plugins)                                    |
| **Schemat**  | Publiczny JSON Schema (draft 2020-12), z którym walidowany jest każdy wpis | [`schemas/plugin.schema.yaml`](../../schemas/plugin.schema.yaml)               |
| **CLI**     | Wyszukuje, sprawdza, waliduje i instaluje z katalogu           | [`omni-dsh-plugins`](https://www.npmjs.com/package/omni-dsh-plugins) |
| **Kanały maszynowe** | `catalog.json` + `catalog.snapshot.json` dla narzędzi           | [catalog.json](https://dsh-plugins.omniroute.online/catalog.json) · [catalog.snapshot.json](https://dsh-plugins.omniroute.online/catalog.snapshot.json) |

To repozytorium jest publicznym źródłem prawdy dla katalogu. Każdy wpis to jeden plik YAML
w `catalog/plugins/`, walidowany względem opublikowanego JSON Schema, dodany przez jeden
indywidualnie zrecenzowany pull request, i zawsze przypisany oryginalnemu twórcy wtyczki.
Nic w katalogu nie jest generowane z innego katalogu ani listy: każdy wpis jest odtwarzany
z oryginalnego repozytorium twórcy, przy przypiętym commicie.

Strona i CLI są utrzymywane z prywatnego źródła; to repozytorium zawiera publiczne dane
katalogu, schemat i zasady, z których korzystają.

## 🚀 Zainstaluj CLI

```bash
npx omni-dsh-plugins --help
```

Pakiet jest publikowany jako `omni-dsh-plugins@1.0.1`, a powyższa komenda
jest dziś kanonicznym wywołaniem; nie jest tu hostowany żaden skrypt instalacyjny.

### Używaj CLI już dziś

Wersja 1.0.1 zawiera komendy odkrywania i walidacji tylko do odczytu oraz komendy
instalacyjne chronione zgodą. Pełna referencja komend, w tym flagi, kody wyjścia i bramkę
zgody na wykonanie kodu, znajduje się w [docs/CLI.md](../../docs/CLI.md).

| Komenda                        | Co robi                                                        | Dotyka twojego systemu?                    |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | Waliduje YAML katalogu, schemat i lokalną semantykę                   | Nie — tylko do odczytu                          |
| `search <query...>`            | Przeszukuje lokalnie publiczne pola katalogu                                | Nie — tylko do odczytu                          |
| `info <id>`                    | Pokazuje jeden publiczny wpis katalogu                                       | Nie — tylko do odczytu                          |
| `list`                         | Wyświetla instalacje zarządzane przez katalog bez modyfikowania profili            | Nie — tylko do odczytu                          |
| `doctor`                       | Diagnostyka tylko do odczytu Node, DSH, natywnej polityki Windows i katalogu  | Nie — tylko do odczytu                          |
| `add <id> --profile <name> --dry-run` | Pokazuje zweryfikowany plan instalacji bez plików i podprocesów | Nie — dry-run                            |
| `add <id> --profile <name> --allow-code-execution` | Instaluje przez oficjalną delegację DSH        | Tak — tylko z wyraźną flagą zgody   |

```bash
# Validate the catalog in this repository (what CI runs):
npx omni-dsh-plugins catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx omni-dsh-plugins add <plugin-id> --profile default --dry-run
```

Komendy mutujące (`add`, `update`, `remove`) nigdy nie wykonują kodu cyklu życia wtyczki,
chyba że przekażesz `--allow-code-execution`. Na natywnym Windowsie te mutacje są wyłączone
w v1.0.1; użyj WSL. Komendy tylko do odczytu i dry-run działają wszędzie.

## 🔍 Jak wtyczka trafia do katalogu

![Jak wtyczka trafia do katalogu](../../docs/diagrams/catalog-flow-dark.svg#gh-dark-mode-only)
![Jak wtyczka trafia do katalogu](../../docs/diagrams/catalog-flow-light.svg#gh-light-mode-only)

1. **Jedna wtyczka, jeden branch, jeden pull request.** PR dodaje lub zmienia dokładnie jeden
   plik YAML w `catalog/plugins/`.
2. **Priorytet dla twórcy.** PR otwarty przez twórcę wtyczki lub organizację będącą właścicielem
   zawsze ma pierwszeństwo przed kuratorstwem społeczności lub automatyzacją dla tej samej
   wtyczki — zobacz [docs/CREDIT.md](../../docs/CREDIT.md).
3. **Dowód z oryginalnego źródła.** Każde pole jest odtwarzane z repozytorium twórcy, przy
   przypiętym 40-znakowym commicie: opis, licencja, integracja z DSH, deskryptor instalacji,
   gwiazdki.
4. **Walidacja lokalna.** `catalog validate` sprawdza strukturę i lokalną semantykę; to ta
   sama kontrola, którą zadanie CI `catalog-validation` wykonuje na PR.
5. **Bramki opiekunów.** Przed scaleniem opiekunowie osobno weryfikują tożsamość
   repozytorium, powiązanie z twórcą i przypięty dowód. Zielona walidacja lokalna jest
   konieczna, ale nigdy wystarczająca.

Pełna umowa — wymagane dowody, reguły YAML, polityka gwiazdek, obsługa kolizji i bramki
przeglądu — znajduje się w [CONTRIBUTING.md](../../CONTRIBUTING.md). Jak podejmowane są decyzje
i przez kogo, opisano w [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md).

## 📄 Anatomia wpisu

Każdy wpis to jeden plik YAML nazwany według swojego ID. Poniższy przykład jest zgodny
z aktualnym schematem (referencja pole po polu w [docs/SCHEMA.md](../../docs/SCHEMA.md)):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

Kluczowe niezmienniki wymuszane przez schemat:

- `unofficial: true` i `schemaVersion: 1` są stałymi.
- Wtyczka z monorepo musi używać `stars: null` — gwiazdki projektu nadrzędnego nigdy nie są dziedziczone.
- Deskryptor instalacji to albo pakiet npm w dokładnej wersji, albo sam przypięty
  materiał źródłowy; to dane, nigdy komenda powłoki.
- Status `verified` wymaga weryfikowalnego dowodu testu dymnego; w przeciwnym razie wpis
  ma status `eligible` z `smokeTest: null`.

## 🗂 Co się tu znajduje

To repozytorium kataloguje niezależnie publikowane integracje dla DeepSeek Harness (DSH),
w tym wtyczki natywne, rodziny wtyczek, motywy, skille, klientów i mosty. Rodzaje artefaktów,
kategorie możliwości i tagi interfejsu są zdefiniowane w [docs/CATEGORIES.md](../../docs/CATEGORIES.md).

Każdy publiczny rekord to jeden plik YAML w `catalog/plugins/`, który musi być zgodny
z `schemas/plugin.schema.yaml`. Wpis oznacza, że udokumentowane kontrole kwalifikowalności
lub weryfikacji zostały zakończone; nie jest to certyfikacja bezpieczeństwa ani aprobata
DeepSeek.

## 🏅 Ranking i weryfikacja

Tylko dedykowane, natywne, kwalifikujące się lub zweryfikowane repozytoria wtyczek z
gwiazdkami należącymi dokładnie do tego repozytorium mogą wejść do rankingu gwiazdek.
Integracje przechowywane w szerszych monorepo pozostają możliwe do znalezienia, ale
używają `stars: null` i nigdy nie dziedziczą gwiazdek projektu nadrzędnego. Zobacz
[docs/RANKING.md](../../docs/RANKING.md) po pełny predykat.

Publiczne stany weryfikacji odróżniają kwalifikowalność strukturalną od testu dymnego
instalacji. Żaden stan nie oznacza absolutnego bezpieczeństwa. Przejrzyj repozytorium
wtyczki, przypięty commit, licencję i zachowanie instalacji przed jej użyciem.

## 🤝 Współtwórz lub zgłoś prawo do wpisu

Przeczytaj [CONTRIBUTING.md](../../CONTRIBUTING.md) przed otwarciem pull requesta. Pull
request musi dodawać lub zmieniać dokładnie jeden wpis wtyczki i musi powoływać się na
oryginalne repozytorium twórcy, a nie na inny katalog. Pull requesty autorstwa twórcy mają
pierwszeństwo przed zautomatyzowanymi pull requestami katalogu.

Dostępne są ustrukturyzowane formularze zgłoszeń dla roszczeń twórców, poprawek i usunięć.
Nigdy nie przesyłaj danych uwierzytelniających, prywatnych danych kontaktowych ani innych
sekretów.
