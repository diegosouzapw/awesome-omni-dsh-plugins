# 카탈로그 거버넌스

> 🌐 [English](../../GOVERNANCE.md) · [Português (Brasil)](../pt-BR/GOVERNANCE.md) · [中文（简体）](../zh-CN/GOVERNANCE.md) · **한국어**

> **비공식 커뮤니티 프로젝트입니다. DeepSeek와 제휴, 승인, 후원 관계가 없습니다.**
> DeepSeek의 이름과 상표는 각 소유자에게 귀속됩니다.

공개 카탈로그가 어떻게 운영되는지: 누가 무엇이 등록될지를 결정하는지, 경쟁하는 기여가 어떤
순서로 존중되는지, 어떤 검사가 자동으로 실행되는지, 그리고 어떤 판단이 사람의 몫으로 남는지.
여기서 참조하는 정책은 [CONTRIBUTING.md](../../CONTRIBUTING.md), [docs/CREDIT.md](../../docs/CREDIT.md),
[docs/RANKING.md](../../docs/RANKING.md)에 있습니다; 이 페이지는 그것들이 어떻게 맞물리는지를
설명합니다.

## 원칙

1. **크리에이터 우선.** 카탈로그는 크리에이터의 작업을 발견 가능하게 만들기 위해 존재하며,
   결코 그것의 소유권을 가져가기 위해 존재하지 않습니다. 동일한 정규 플러그인에 대해, 크리에이터의
   직접적인 풀 리퀘스트는 열려 있는 어떤 커뮤니티 큐레이션이나 자동화 풀 리퀘스트보다 우선합니다 —
   전체 우선순위와 Git 신원 규칙은 [docs/CREDIT.md](../../docs/CREDIT.md)에 있습니다.
2. **하나의 플러그인, 하나의 검토된 풀 리퀘스트.** 공개 카탈로그로의 배치 병합이나 생성된 대량
   가져오기는 없습니다. 각 항목은 자신만의 검토를 거칩니다.
3. **신뢰보다 증거.** 모든 공개 필드는 고정된 커밋 시점의 원 크리에이터 저장소로 추적됩니다.
   초록불의 자동 검사는 절대 출처의 증명으로 받아들여지지 않습니다.
4. **항상 비공식.** 어떤 카탈로그 상태도 DeepSeek의 검토, 인증 또는 보증으로 제시되지 않습니다.

## 변경 사항이 `main`에 반영되는 방법

모든 변경 사항은 검토된 풀 리퀘스트를 통해서만 `main`에 도달합니다 — 직접 푸시는 없습니다.
기본 브랜치에 대한 운영 정책:

- **오직 풀 리퀘스트만.** 카탈로그 항목, 문서, 스키마 변경은 모두 PR을 통해 들어옵니다; 카탈로그
  PR은 [CONTRIBUTING.md](../../CONTRIBUTING.md)의 브랜치당 하나의 플러그인 규칙을 따라야 합니다.
- **선형 히스토리.** PR은 `main`이 선형적이고 감사 가능한 히스토리를 유지하도록 통합됩니다; 병합된
  공개 히스토리는 다시 쓰이지 않습니다. 크리에이터가 나서기 전에 큐레이션된 항목이 병합되었다면,
  크리에이터는 히스토리를 다시 쓰는 대신 후속 기여로 그것을 클레임하거나 정정합니다.
- **리뷰 스레드 해결.** 병합 전에 리뷰 대화가 해결됩니다; 해결되지 않은 피드백은 통합을 막습니다.
- **메인테이너 병합.** 오직 메인테이너만이 플러그인 항목을 병합하며, 그것도 [CONTRIBUTING.md](../../CONTRIBUTING.md)
  → "검토 게이트, 충돌 및 병합"의 모든 게이트가 현재 PR 커밋에서 통과한 이후에만 그렇게 합니다.

## `catalog-validation` 검사

`catalog/plugins/`, `schemas/` 또는 워크플로 자체를 건드리는 모든 풀 리퀘스트는 배포된 CLI에
고정된 `catalog-validation` 작업(`.github/workflows/validate-catalog.yml`)을 실행합니다:

```bash
npx --yes omni-dsh-plugins catalog validate --catalog .
```

**이것이 검증하는 것** — 오직 로컬 구조와 시맨틱스만:

- `catalog/plugins/` 아래의 모든 항목에 대한 안전한 YAML 파싱.
- 공개 스키마 준수(참고: [docs/SCHEMA.md](../../docs/SCHEMA.md)).
- SPDX 표현식 파싱, 정확한 SemVer 버전, 유효한 SHA-512 SRI 무결성 값.
- 중복 거부: 반복되는 항목 ID가 없고 반복되는 정규 저장소-노드-플러스-서브패스 키가 없음.
- 의도적으로 비어 있는 카탈로그는 통과합니다(`0 entries valid; catalog is empty`).

**이것이 검증하지 않는 것** — 따라서 초록불이 절대 증명하지 않는 것:

- 원격 저장소 신원: GitHub에 연결하거나 저장소 노드 ID를 URL에 대해 확인하지 않습니다.
- 고정된 커밋 시점의 증거: 설명, 라이선스, DSH 통합, 스모크 테스트 증거는 가져오거나 검사되지
  않습니다.
- 크리에이터의 소유권, 스타 수, 또는 열려 있는 풀 리퀘스트와의 충돌.

이러한 판단은 병합 전에 적용되는 메인테이너의 별도 프로버넌스 게이트에 속하며,
[CONTRIBUTING.md](../../CONTRIBUTING.md)에 설명되어 있습니다. 로컬 검사는 최소 기준이지, 통과
기준이 아닙니다.

## 검증 상태

검증은 공개 스키마에 정의된 상태(`eligible`, `verified`, `stale`, `unavailable`, `archived`,
`quarantined`)를 사용하여 항목별로 그 정확한 고정 커밋에 대해 기록됩니다. 두 개의 긍정적인
상태는 의도적으로 좁게 정의되어 있습니다:

- `eligible` — 공개 구조와 네이티브 DSH 통합이 검증되었습니다.
- `verified` — 추가로, 고정된 소스나 패키지에 대해 설치 스모크 테스트가 통과했습니다; 스키마는
  스모크 테스트 기록이 존재할 것을 요구합니다.

이 상태들 중 어느 것도 — 다른 어떤 상태도 마찬가지로 — 보증, 보장 또는 보안 인증이 아닙니다.
상태가 순위와 어떻게 상호작용하는지를 포함한 전체 시맨틱스는 [docs/RANKING.md](../../docs/RANKING.md)에
있습니다; 기록의 형태는 [docs/SCHEMA.md](../../docs/SCHEMA.md)에 있습니다.

## 클레임, 정정, 삭제

구조화된 GitHub 이슈 양식(`.github/ISSUE_TEMPLATE/`)은 당신이 제출하지 않은 항목을 변경하기
위한 공식적인 경로입니다:

| 양식         | 누가 사용하는가                              | 결과                                             |
| ------------ | ---------------------------------------- | --------------------------------------------------- |
| **클레임**   | 자신의 플러그인이 다른 사람에 의해 큐레이션된 크리에이터 | 소유권이 원본 소스에 결속됩니다; 이후 크리에이터가 직접 기여할 수 있습니다 |
| **정정**     | 부정확한 공개 메타데이터를 발견한 누구든 | 영향을 받은 항목에 대한 검토된 수정             |
| **삭제**     | 자신의 목록이 삭제되길 원하는 크리에이터, 또는 정책 위반을 신고하는 사람 | 항목의 검토된 삭제 또는 격리 |

세 가지 흐름 모두에 적용되는 규칙:

- 소유권 클레임은 검증 가능한 공개 증거(저장소 소유권, 패키지 저작권, 매니페스트 메타데이터
  또는 고정된 소스 히스토리)로 뒷받침되어야 합니다 — Discussion에 댓글을 다는 것만으로는
  크리에이터임이 성립되지 않습니다([docs/CREDIT.md](../../docs/CREDIT.md)).
- 등록된 플러그인의 보안 문제는 먼저 그 플러그인 자신의 메인테이너에게 전달됩니다; 카탈로그
  측은 그 다음에 취약점 악용 세부 정보를 공개하지 않고 정정이나 격리를 처리합니다
  ([SECURITY.md](../../SECURITY.md)).
- 양식에 자격 증명, 개인 연락처 또는 그 밖의 비밀 정보를 절대 포함하지 마세요.

## 역할

- **크리에이터**는 자신의 플러그인과 그 목록의 우선순위를 소유합니다. 직접 기여하거나,
  커뮤니티 큐레이션을 승인하거나, 기존 항목을 클레임/정정/삭제할 수 있습니다.
- **커뮤니티 기여자**는 [docs/CREDIT.md](../../docs/CREDIT.md)의 정중한 연락과 크레딧 규칙에
  따라, 아직 기여하지 않은 크리에이터를 위해 항목을 큐레이션할 수 있습니다. 큐레이션은 절대
  이후의 직접적인 크리에이터 기여보다 우선하지 않습니다.
- **메인테이너**는 검토하고, 프로버넌스 게이트를 적용하고, 충돌을 해결하고, 병합합니다. 또한
  웹사이트([dsh-plugins.omniroute.online](https://dsh-plugins.omniroute.online))와 비공개
  소스로부터의 배포된 CLI를 유지 관리합니다; 이 저장소의 공개 데이터, 스키마, 정책이 바로 그
  표면들이 소비하는 것입니다.
