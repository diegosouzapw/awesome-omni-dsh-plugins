# 크리에이터 크레딧과 풀 리퀘스트 우선순위

카탈로그는 크리에이터로부터 소유권을 빼앗지 않으면서 독립적인 DSH 작업을 발견 가능하게 만들기
위해 존재합니다. 공개 항목은 원본 저장소와 불변의 소스 커밋을 인용합니다.

## 동일한 플러그인에 대한 우선순위

<!-- creator-first:direct-pr-supersedes-curation-and-automation -->

1. 플러그인 크리에이터나 소유 조직이 연 풀 리퀘스트.
2. 크리에이터가 명시적으로 승인하거나 공동 저작한 커뮤니티 풀 리퀘스트.
3. 이미 존재하는 유효한 커뮤니티 풀 리퀘스트.
4. 카탈로그 자동화 풀 리퀘스트.
5. 공개 풀 리퀘스트가 없는 비공개 후보.

크리에이터의 직접적인 풀 리퀘스트는 항상 선호되며, 어느 것이 먼저 열렸거나 더 진행되었는지와
무관하게, 동일한 정규 플러그인에 대한 열려 있는 어떤 커뮤니티 큐레이션이나 자동화 풀 리퀘스트보다
우선합니다. 크리에이터의 풀 리퀘스트가 검토 수단이 됩니다; 그들의 브랜치는 절대 덮어써지거나,
force-push되거나, 큐레이션된 풀 리퀘스트로 이식되지 않습니다. 큐레이션된 항목이 이미 병합된 경우,
히스토리는 그대로 유지되며 크리에이터는 새로운 기여에서 그것을 클레임하거나 정정할 수 있습니다.

## 공개 출처 표시

모든 카탈로그 항목은 크리에이터의 공개 GitHub 핸들, 원본 저장소, 저장소 노드 ID, 플러그인
서브패스, 전체 고정 커밋을 담고 있습니다. 공개 크리에이터 프로필은 두 번째 신원으로 저장되는
대신 단일 핸들로부터 도출됩니다. 별도의 메인테이너 프로버넌스 게이트가 노드 ID를 확인하고
저장소 URL 불일치를 거부합니다. 풀 리퀘스트 설명에는 `Created by @handle`이라고 명시하고 소스
저장소와 소스 커밋 메타데이터를 포함해야 합니다.

Discussion에 게시하거나 댓글을 다는 사람이 자동으로 크리에이터로 취급되지는 않습니다. 소유권은
저장소 소유자나 조직, 패키지 저작권, 매니페스트 메타데이터, 또는 정확한 고정 소스 히스토리로
뒷받침되어야 합니다.

## Git 신원

<!-- creator-first:source-bound-git-identity -->

커밋 저작자와 풀 리퀘스트 저작자는 별개입니다. 크리에이터가 시작한 풀 리퀘스트는 크리에이터를
풀 리퀘스트 저작자로 유지하며, 그들의 커밋은 자연스럽게 저작자 정보를 보존합니다. 메인테이너나
자동화 계정은 커미터나 검증된 공동 저자로 나타날 수 있지만, 크리에이터의 저작권을 대체해서는
안 됩니다.

큐레이션된 커밋의 경우, 정확한 신원이 소스에 결속되어 있고 공개적으로 검증 가능할 때만 —
예를 들어 원본 저장소의 크리에이터 커밋에 이미 첨부된 신원처럼 — 크리에이터를 Git 저작자로
사용하거나 `Co-authored-by` 트레일러를 추가하세요. 절대 이메일을 추측하거나, noreply 주소를
지어내거나, 승인된 공개 소스 밖에서 발견된 비공개 주소를 사용하지 마세요.

검증된 Git 신원을 사용할 수 없을 때, 큐레이터나 자동화 계정이 커밋을 저작하고 대신 명시적으로
눈에 보이는 크레딧을 부여합니다: 항목과 풀 리퀘스트에 `Created by @handle`, 대응하는 공개
프로필, 원본 저장소로의 링크. 눈에 보이는 YAML 출처 표시는 Git 신원 매핑과 무관하게 항상
필수입니다. 이후의 직접적인 크리에이터 풀 리퀘스트는 그 합성된 히스토리를 물려받는 대신 열려
있는 큐레이션된 풀 리퀘스트를 대체합니다.

## 정중한 크리에이터 멘션

큐레이션된 풀 리퀘스트는 원본 저장소 링크 옆의 설명란에서 정중한 공개 `@creator` 멘션을 한 번
사용합니다. 이는 검토나 대체할 직접적인 풀 리퀘스트를 초대할 수 있습니다. 멘션을 반복하거나,
홍보성 이슈를 열거나, 크로스 포스팅하거나, 원치 않는 다이렉트 메시지를 보내지 마세요.

## 카탈로그 라이선스 대 업스트림 라이선스

카탈로그 사실과 편집상의 YAML 메타데이터는 CC0-1.0 하에 제공됩니다. 이 제공은 업스트림
플러그인의 라이선스를 변경하지 않습니다. 업스트림 코드, 문서, 스크린샷, 로고, 그 밖의 창작
자료는 원래의 라이선스와 소유자에게 계속 귀속됩니다.
