## Sekilas

| Permukaan     | Apa itu                                                       | Di mana                                                                    |
| ----------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **Situs web** | Peramban katalog yang sudah dirender, dengan pencarian dan peringkat                 | [dsh-plugins.omniroute.online](https://dsh-plugins.omniroute.online)     |
| **Katalog** | Satu file YAML per plugin, satu-satunya sumber kebenaran             | [`catalog/plugins/`](../../catalog/plugins)                                    |
| **Skema**  | JSON Schema publik (draft 2020-12) yang menjadi acuan validasi setiap entri | [`schemas/plugin.schema.yaml`](../../schemas/plugin.schema.yaml)               |
| **CLI**     | Mencari, memeriksa, memvalidasi, dan menginstal dari katalog           | [`@diegosouza.pw/dsh-plugins`](https://www.npmjs.com/package/@diegosouza.pw/dsh-plugins) |
| **Feed untuk mesin** | `catalog.json` + `catalog.snapshot.json` untuk berbagai alat           | [catalog.json](https://dsh-plugins.omniroute.online/catalog.json) · [catalog.snapshot.json](https://dsh-plugins.omniroute.online/catalog.snapshot.json) |

Repositori ini adalah sumber kebenaran publik untuk katalog. Setiap entri adalah satu file YAML di bawah
`catalog/plugins/`, tervalidasi terhadap JSON Schema yang dipublikasikan, ditambahkan melalui satu pull request yang
direview secara individual, dan selalu memberikan kredit kepada kreator asli plugin tersebut. Tidak ada satu pun isi
katalog yang dihasilkan dari katalog atau daftar lain: setiap entri direkonstruksi dari repositori asli kreator pada
commit yang dipatok.

Situs web dan CLI dikelola dari kode sumber privat; repositori ini menyimpan data katalog publik, skema, dan kebijakan
yang mereka gunakan.

## 🚀 Instal CLI

```bash
npx @diegosouza.pw/dsh-plugins --help
```

Paket berlingkup ini dipublikasikan sebagai `@diegosouza.pw/dsh-plugins@0.1.0`, dan perintah di atas adalah cara
pemanggilan resmi saat ini; tidak ada skrip pemasang yang dihosting di sini.

### Gunakan CLI sekarang

Versi 0.1.0 menyediakan perintah penemuan dan validasi yang bersifat baca-saja, ditambah perintah instalasi yang
memerlukan persetujuan. Referensi perintah lengkap, termasuk flag, kode keluar, dan gerbang persetujuan eksekusi kode,
ada di [docs/CLI.md](../../docs/CLI.md).

| Perintah                        | Fungsinya                                                        | Memengaruhi sistem Anda?                    |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | Memvalidasi YAML katalog, skema, dan semantik lokal                   | Tidak — hanya baca                          |
| `search <query...>`            | Mencari field katalog publik secara lokal                                | Tidak — hanya baca                          |
| `info <id>`                    | Menampilkan satu entri katalog publik                                       | Tidak — hanya baca                          |
| `list`                         | Menampilkan daftar instalasi yang dikelola katalog tanpa mengubah profil            | Tidak — hanya baca                          |
| `doctor`                       | Diagnostik baca-saja untuk Node, DSH, kebijakan Windows native, dan katalog  | Tidak — hanya baca                          |
| `add <id> --profile <name> --dry-run` | Menampilkan rencana instalasi yang sudah divalidasi tanpa membuat file atau subproses | Tidak — dry-run                            |
| `add <id> --profile <name> --allow-code-execution` | Menginstal melalui delegasi resmi DSH        | Ya — hanya jika flag persetujuan eksplisit diberikan   |

```bash
# Validate the catalog in this repository (what CI runs):
npx @diegosouza.pw/dsh-plugins@0.1.0 catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx @diegosouza.pw/dsh-plugins@0.1.0 search memory --catalog .
npx @diegosouza.pw/dsh-plugins@0.1.0 info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx @diegosouza.pw/dsh-plugins@0.1.0 add <plugin-id> --profile default --dry-run
```

Perintah yang mengubah keadaan (`add`, `update`, `remove`) tidak pernah menjalankan kode siklus hidup plugin kecuali
Anda memberikan `--allow-code-execution`. Di Windows native, operasi perubahan ini dinonaktifkan pada v0.1.0; gunakan
WSL. Perintah baca-saja dan dry-run berfungsi di mana saja.

## 🔍 Bagaimana sebuah plugin masuk ke katalog

```mermaid
flowchart LR
    A["Repositori kreator<br/>(commit dipatok)"] --> B["Satu branch,<br/>satu PR,<br/>satu entri YAML"]
    B --> C["CI catalog-validation<br/>(skema + semantik lokal)"]
    C --> D["Gerbang maintainer<br/>(identitas, keterikatan kreator,<br/>bukti yang dipatok)"]
    D --> E["catalog/plugins/*.yaml<br/>digabungkan"]
    E --> F["Situs web"]
    E --> G["CLI"]
    E --> H["Feed catalog.json"]
```

1. **Satu plugin, satu branch, satu pull request.** PR hanya menambahkan atau mengubah tepat satu file YAML di bawah
   `catalog/plugins/`.
2. **Kreator diutamakan.** PR yang dibuka oleh kreator plugin itu sendiri atau organisasi pemiliknya selalu didahulukan
   dibanding kurasi komunitas atau otomatisasi untuk plugin yang sama — lihat [docs/CREDIT.md](../../docs/CREDIT.md).
3. **Bukti dari sumber asli.** Setiap field direkonstruksi dari repositori kreator pada commit 40 karakter yang
   dipatok: deskripsi, lisensi, integrasi DSH, deskriptor instalasi, jumlah bintang.
4. **Validasi lokal.** `catalog validate` memeriksa struktur dan semantik lokal; ini adalah pemeriksaan yang sama
   dengan yang dijalankan job CI `catalog-validation` pada PR.
5. **Gerbang maintainer.** Sebelum digabungkan, maintainer secara terpisah memverifikasi identitas repositori,
   keterikatan kreator, dan bukti yang dipatok. Validasi lokal yang hijau adalah syarat perlu, tapi tidak pernah cukup
   dengan sendirinya.

Perjanjian lengkap — bukti yang dibutuhkan, aturan YAML, kebijakan bintang, penanganan konflik, dan gerbang review —
ada di [CONTRIBUTING.md](../../CONTRIBUTING.md). Bagaimana keputusan dibuat dan oleh siapa ada di
[docs/GOVERNANCE.md](../../docs/GOVERNANCE.md).

## 📄 Anatomi sebuah entri

Setiap entri adalah satu file YAML yang dinamai sesuai ID-nya. Contoh di bawah ini tervalidasi terhadap skema saat ini
(referensi per-field di [docs/SCHEMA.md](../../docs/SCHEMA.md)):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

Invarian kunci yang dipaksakan oleh skema:

- `unofficial: true` dan `schemaVersion: 1` adalah konstanta.
- Plugin dalam monorepo wajib menggunakan `stars: null` — bintang milik proyek induk tidak pernah diwariskan.
- Deskriptor instalasi harus berupa paket npm dengan versi persis, atau sumber yang dipatok itu sendiri; itu adalah
  data, bukan perintah shell.
- Status `verified` membutuhkan bukti smoke-test yang bisa direview; jika tidak, entri berstatus `eligible` dengan
  `smokeTest: null`.

## 🗂 Apa yang termasuk di sini

Repositori ini mengkatalogkan integrasi yang dipublikasikan secara independen untuk DeepSeek Harness (DSH), termasuk
plugin native, keluarga plugin, tema, skill, klien, dan bridge. Jenis artefak, kategori kemampuan, dan tag antarmuka
didefinisikan di [docs/CATEGORIES.md](../../docs/CATEGORIES.md).

Setiap catatan publik adalah satu file YAML di bawah `catalog/plugins/` dan wajib tervalidasi terhadap
`schemas/plugin.schema.yaml`. Sebuah listing berarti pemeriksaan kelayakan atau verifikasi yang terdokumentasi telah
diselesaikan; itu bukan sertifikasi keamanan atau dukungan dari DeepSeek.

## 🏅 Peringkat dan verifikasi

Hanya repositori plugin yang dedicated, native, eligible, atau verified, dengan bintang yang benar-benar milik
repositori itu sendiri, yang bisa masuk peringkat bintang. Integrasi yang disimpan di dalam monorepo yang lebih besar
tetap bisa ditemukan, tapi menggunakan `stars: null` dan tidak pernah mewarisi bintang proyek induk. Lihat predikat
lengkapnya di [docs/RANKING.md](../../docs/RANKING.md).

Status verifikasi publik membedakan kelayakan struktural dari smoke test instalasi. Tidak ada status yang merepresentasikan
keamanan mutlak. Tinjau repositori, commit yang dipatok, lisensi, dan perilaku instalasi sebuah plugin sebelum
menggunakannya.

## 🤝 Berkontribusi atau mengklaim sebuah entri

Baca [CONTRIBUTING.md](../../CONTRIBUTING.md) sebelum membuka pull request. Sebuah pull request harus menambahkan atau
mengubah tepat satu entri plugin, dan harus mengutip repositori kreator asli, bukan katalog lain. Pull request yang
dibuat oleh kreator lebih diutamakan dibanding pull request otomatis dari katalog.

Formulir issue terstruktur tersedia untuk klaim kreator, koreksi, dan penghapusan. Jangan pernah mengirimkan kredensial,
detail kontak pribadi, atau rahasia lainnya.
