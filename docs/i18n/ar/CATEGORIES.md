# فئات الكتالوج

> 🌐 [English](../../CATEGORIES.md) · [Português (Brasil)](../pt-BR/CATEGORIES.md) · [中文（简体）](../zh-CN/CATEGORIES.md) · **العربية**

لكل إدخال في الكتالوج نوع قطعة (artifact kind) واحد، وفئة قدرة أساسية واحدة، وصفر أو أكثر من
الوسوم (tags). تُحدِّد الفئة الأساسية أين يظهر الإدخال؛ وتُوفِّر الوسوم بحثًا عبر الفئات دون
تكرار الإدخال.

## أنواع القطع (Artifact kinds)

<!-- catalog-policy:aggregators-never-entries -->

| القيمة | المعنى | مُرتَّب بالنجوم كإضافة |
|---|---|---:|
| `plugin` | حزمة DSH أصلية قابلة للتثبيت | فقط عندما تُستوفى كل شروط الترتيب |
| `plugin-family` | مستودع يحتوي على عدة إضافات DSH | لا؛ قسم منفصل |
| `skin-theme` | سمة (skin) أو قالب مرئي لواجهة DSH | لا؛ قسم منفصل |
| `skill` | مهارة وكيل (agent skill) مع دعم DSH | لا |
| `preset-profile` | ملف شخصي (profile) أو إعداد مسبق لـ DSH | لا |
| `client-interface` | عميل (client) سطح مكتب، أو TUI، أو محرر، أو عن بُعد | لا |
| `bridge-adapter` | تكامل من منتج آخر إلى DSH | لا |
| `ecosystem-project` | مشروع أوسع يحتوي على تكامل DSH | لا |

مستودع شامل (umbrella)، أو مُجمِّع (aggregator)، أو سوق (marketplace)، أو كتالوج مُثبِّتات، أو
قائمة، ليس أبدًا إدخال كتالوج، حتى عندما يكون المُجمِّع نفسه قابلًا للتثبيت. يمكن استخدامه فقط
كدليل أوّلي (lead). اتبع كل دليل أوّلي إلى قطعة فرعية قابلة للتثبيت بشكل مستقل وحدِّد منشئها
الحقيقي، ومستودعها الأصلي، وحزمتها، ومسارها الفرعي المصدري قبل تقديمها. يمكن أن يكون مستودع
المُنشئ الأحادي (monorepo) الحقيقي هو المستودع الأصلي لإضافة فرعية، لكن يجب أن تستخدم الفرعية
ذلك المسار الفرعي الدقيق وسياسة نجوم المستودع الأحادي.

حقل `kind` هو المُميِّز القانوني الوحيد لقطعة DSH. لا يوجد نوع تكامل منفصل: يعني `plugin` بالفعل
حزمة DSH أصلية، بينما يعني `ecosystem-project` بالفعل مشروعًا أوسع بتكامل DSH. هذا يمنع أزواج
تصنيف متناقضة.

## فئات القدرة الأساسية

| القيمة | تسمية العرض |
|---|---|
| `user-interface-dashboards` | واجهة المستخدم ولوحات التحكم |
| `memory-rag` | الذاكرة و RAG |
| `search-research` | البحث والاستقصاء |
| `coding-developer-tools` | البرمجة وأدوات المطورين |
| `browser-automation` | المتصفح والأتمتة |
| `vision-audio-multimodal` | الرؤية، والصوت، ومتعدد الوسائط |
| `sessions-productivity` | الجلسات والإنتاجية |
| `security-permissions-approvals` | الأمان، والأذونات، والموافقات |
| `diagnostics-observability` | التشخيص وقابلية الرصد (observability) |
| `models-providers-routing` | النماذج، ومزوّدو الخدمة، والتوجيه (routing) |
| `messaging-notifications` | المراسلة والإشعارات |
| `data-external-services` | البيانات والخدمات الخارجية |
| `entertainment-customization` | الترفيه والتخصيص |

اختر الفئة التي تمثّل أفضل تمثيل المهمة الأساسية للإضافة، لا الفئة الأكثر احتمالًا لزيادة
الظهور.

## وسوم الواجهة

تشمل وسوم الواجهة القياسية: `web-ui`، و`sidebar`، و`settings`، و`tui`، و`cli`، و`desktop`،
و`mobile`، و`remote`، و`editor`، و`headless`، و`theme`. يُسمح بوسوم قدرة إضافية بصيغة
kebab-case بأحرف صغيرة عندما تصف دليلًا مرئيًا في المصدر الأصلي المثبَّت.

## نطاق المستودع

استخدم `dedicated` فقط عندما تخصّ نجوم المستودع الإضافة المُفهرَسة بالضبط. استخدم `monorepo`
عندما تكون الإضافة مسارًا فرعيًا أو حزمة داخل مشروع أوسع. يجب أن يستخدم إدخال المستودع الأحادي
`popularity.starsPolicy: undefined-parent-repository` و `popularity.stars: null`.
