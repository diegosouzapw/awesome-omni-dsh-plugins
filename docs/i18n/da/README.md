## Kort overblik

| Overflade     | Hvad det er                                                       | Hvor                                                                    |
| ----------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **Hjemmeside** | Renderet katalogbrowser med søgning og rangering                 | [dsh-plugins.omniroute.online](https://dsh-plugins.omniroute.online)     |
| **Katalog** | Én YAML-fil pr. plugin, den eneste kilde til sandhed             | [`catalog/plugins/`](../../catalog/plugins)                                    |
| **Skema**  | Offentligt JSON Schema (draft 2020-12), som hver post valideres imod | [`schemas/plugin.schema.yaml`](../../schemas/plugin.schema.yaml)               |
| **CLI**     | Søg, undersøg, valider og installer fra kataloget           | [`@diegosouza.pw/dsh-plugins`](https://www.npmjs.com/package/@diegosouza.pw/dsh-plugins) |
| **Maskinfeeds** | `catalog.json` + `catalog.snapshot.json` til værktøjer           | [catalog.json](https://dsh-plugins.omniroute.online/catalog.json) · [catalog.snapshot.json](https://dsh-plugins.omniroute.online/catalog.snapshot.json) |

Dette repository er den offentlige kilde til sandhed for kataloget. Hver post er én YAML-fil
under `catalog/plugins/`, valideret mod et offentliggjort JSON Schema, tilføjet gennem én
individuelt gennemgået pull request og altid krediteret pluginnets oprindelige skaber. Intet i
kataloget genereres fra et andet katalog eller en anden liste: hver post genskabes fra skaberens
oprindelige repository ved en fastlåst commit.

Hjemmesiden og CLI'en vedligeholdes fra privat kildekode; dette repository indeholder de
offentlige katalogdata, skema og politikker, de bruger.

## 🚀 Installer CLI'en

```bash
npx @diegosouza.pw/dsh-plugins --help
```

Den scopede pakke udgives som `@diegosouza.pw/dsh-plugins@0.1.0`, og kommandoen ovenfor er i dag
den kanoniske måde at kalde den på; der hostes ikke noget installationsscript her.

### Brug CLI'en i dag

Version 0.1.0 leverer skrivebeskyttede opdagelses- og valideringskommandoer samt
installationskommandoer, der kræver samtykke. Den fulde kommandoreference, inklusive flag,
exitkoder og samtykkeporten for kodeudførelse, findes i [docs/CLI.md](../../docs/CLI.md).

| Kommando                        | Hvad det gør                                                        | Rører den ved dit system?                    |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | Validerer katalog-YAML, skema og lokal semantik                   | Nej — skrivebeskyttet                          |
| `search <query...>`            | Søger lokalt i offentlige katalogfelter                                | Nej — skrivebeskyttet                          |
| `info <id>`                    | Viser én offentlig katalogpost                                       | Nej — skrivebeskyttet                          |
| `list`                         | Viser installationer styret af kataloget uden at ændre profiler            | Nej — skrivebeskyttet                          |
| `doctor`                       | Skrivebeskyttet diagnostik af Node, DSH, native Windows-politik og katalog  | Nej — skrivebeskyttet                          |
| `add <id> --profile <name> --dry-run` | Viser den verificerede installationsplan uden filer eller underprocesser | Nej — dry-run                            |
| `add <id> --profile <name> --allow-code-execution` | Installerer via officiel DSH-delegering        | Ja — kun med eksplicit samtykkeflag   |

```bash
# Validate the catalog in this repository (what CI runs):
npx @diegosouza.pw/dsh-plugins@0.1.0 catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx @diegosouza.pw/dsh-plugins@0.1.0 search memory --catalog .
npx @diegosouza.pw/dsh-plugins@0.1.0 info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx @diegosouza.pw/dsh-plugins@0.1.0 add <plugin-id> --profile default --dry-run
```

Kommandoer, der ændrer noget (`add`, `update`, `remove`), udfører aldrig plugin-livscykluskode,
medmindre du angiver `--allow-code-execution`. På native Windows er disse ændringer deaktiveret
i v0.1.0; brug WSL. Skrivebeskyttede og dry-run-kommandoer fungerer overalt.

## 🔍 Sådan kommer et plugin ind i kataloget

```mermaid
flowchart LR
    A["Skaberens repository<br/>(fastlåst commit)"] --> B["Én branch,<br/>én PR,<br/>én YAML-post"]
    B --> C["catalog-validation CI<br/>(skema + lokal semantik)"]
    C --> D["Vedligeholder-porte<br/>(identitet, skaberbinding,<br/>fastlåst dokumentation)"]
    D --> E["catalog/plugins/*.yaml<br/>sammenflettet"]
    E --> F["Hjemmeside"]
    E --> G["CLI"]
    E --> H["catalog.json-feeds"]
```

1. **Ét plugin, én branch, én pull request.** PR'en tilføjer eller ændrer præcis én YAML-fil
   under `catalog/plugins/`.
2. **Skaberen først.** En PR åbnet af pluginnets skaber eller ejerorganisation har altid forrang
   frem for community-kuratering eller automatisering for samme plugin — se
   [docs/CREDIT.md](../../docs/CREDIT.md).
3. **Dokumentation fra den oprindelige kilde.** Hvert felt genskabes fra skaberens repository ved
   en fastlåst 40-tegns commit: beskrivelse, licens, DSH-integration, installationsdeskriptor,
   stjerner.
4. **Lokal validering.** `catalog validate` kontrollerer struktur og lokal semantik; det er det
   samme tjek, som CI-jobbet `catalog-validation` kører på PR'en.
5. **Vedligeholder-porte.** Før sammenfletning verificerer vedligeholderne separat
   repository-identitet, skaberbinding og fastlåst dokumentation. En grøn lokal validering er
   nødvendig, men aldrig tilstrækkelig.

Den fulde kontrakt — påkrævet dokumentation, YAML-regler, stjernepolitik, håndtering af
kollisioner og gennemgangsporte — findes i [CONTRIBUTING.md](../../CONTRIBUTING.md). Hvordan
beslutninger træffes, og af hvem, findes i [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md).

## 📄 Opbygningen af en post

Hver post er én YAML-fil opkaldt efter sit ID. Eksemplet nedenfor validerer mod det aktuelle
skema (felt-for-felt-reference i [docs/SCHEMA.md](../../docs/SCHEMA.md)):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

Vigtige invarianter, som skemaet håndhæver:

- `unofficial: true` og `schemaVersion: 1` er konstanter.
- Et monorepo-plugin skal bruge `stars: null` — forælderprojektets stjerner nedarves aldrig.
- Installationsdeskriptoren er enten en npm-pakke med præcis version eller selve den fastlåste
  kilde; det er data, aldrig en shell-kommando.
- Status `verified` kræver dokumentation fra en gennemgåelig smoke-test; ellers er posten
  `eligible` med `smokeTest: null`.

## 🗂 Hvad hører til her

Dette repository katalogiserer uafhængigt udgivne integrationer til DeepSeek Harness (DSH),
herunder native plugins, pluginfamilier, temaer, skills, klienter og broer. Artefakttyper,
funktionskategorier og interface-tags er defineret i [docs/CATEGORIES.md](../../docs/CATEGORIES.md).

Hver offentlig post er én YAML-fil under `catalog/plugins/` og skal validere mod
`schemas/plugin.schema.yaml`. En optagelse betyder, at de dokumenterede berettigelses- eller
verifikationstjek er gennemført; det er ikke en sikkerhedscertificering eller en anbefaling fra
DeepSeek.

## 🏅 Rangering og verifikation

Kun dedikerede, native, berettigede eller verificerede plugin-repositories med stjerner, der
tilhører netop det repository, kan komme med i en stjernerangering. Integrationer, der ligger
inde i bredere monorepos, forbliver søgbare, men bruger `stars: null` og nedarver aldrig
forælderprojektets stjerner. Se [docs/RANKING.md](../../docs/RANKING.md) for det fulde prædikat.

Offentlige verifikationstilstande adskiller strukturel berettigelse fra en installations-smoke-test.
Ingen tilstand repræsenterer absolut sikkerhed. Gennemgå et plugins repository, fastlåste commit,
licens og installationsadfærd, før du bruger det.

## 🤝 Bidrag eller gør krav på en post

Læs [CONTRIBUTING.md](../../CONTRIBUTING.md), før du åbner en pull request. En pull request skal
tilføje eller ændre præcis én pluginpost og skal citere skaberens oprindelige repository frem for
et andet katalog. Pull requests forfattet af skaberen har forrang frem for automatiserede
katalog-pull-requests.

Der findes strukturerede issue-formularer til krav fra skabere, rettelser og fjernelser. Send
aldrig legitimationsoplysninger, private kontaktoplysninger eller andre hemmeligheder.
