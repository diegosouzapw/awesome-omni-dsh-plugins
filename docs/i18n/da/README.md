## Kort overblik

| Komponent   | Hvad det er                                                       | Hvor                                                                    |
| ----------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **Hjemmeside** | Renderet katalogbrowser med søgning og rangering                 | [dsh-plugins.omniroute.online](https://dsh-plugins.omniroute.online)     |
| **Katalog** | Én YAML-fil pr. plugin, den eneste kilde til sandhed             | [`catalog/plugins/`](../../catalog/plugins)                                    |
| **Skema**  | Offentligt JSON Schema (draft 2020-12), som hver post valideres imod | [`schemas/plugin.schema.yaml`](../../schemas/plugin.schema.yaml)               |
| **CLI**     | Søg, inspicér, validér og installér fra kataloget           | [`omni-dsh-plugins`](https://www.npmjs.com/package/omni-dsh-plugins) |
| **Maskinfeeds** | `catalog.json` + `catalog.snapshot.json` til værktøjer           | [catalog.json](https://dsh-plugins.omniroute.online/catalog.json) · [catalog.snapshot.json](https://dsh-plugins.omniroute.online/catalog.snapshot.json) |

Dette repository er den offentlige kilde til sandhed for kataloget. Hver post er én YAML-fil
under `catalog/plugins/`, valideret mod et offentliggjort JSON Schema, tilføjet via én
individuelt gennemgået pull request og altid krediteret pluginnets oprindelige skaber.
Intet i kataloget er genereret fra et andet katalog eller en anden liste: hver post er
rekonstrueret fra skaberens oprindelige repository ved et fastlåst commit.

Webstedet vedligeholdes fra privat kilde. CLI'en bor her, under [`cli/`](../../cli), og dette
repository indeholder de offentlige katalogdata, skemaet og de politikker, som begge dele bruger.

## 🚀 Installér CLI'en

```bash
npx omni-dsh-plugins --help
```

Pakken udgives som `omni-dsh-plugins@1.0.1`, og kommandoen ovenfor er i dag
den kanoniske måde at køre den på; der hostes ikke noget installationsscript her.

### Brug CLI'en i dag

Version 1.0.1 leveres med skrivebeskyttede opdagelses- og valideringskommandoer samt
installationskommandoer, der kræver samtykke. Den fulde kommandoreference, inklusive flag,
exitkoder og samtykkespærren for kodeudførelse, findes i [docs/CLI.md](../../docs/CLI.md).

| Kommando                        | Hvad den gør                                                        | Rører den ved dit system?                    |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | Validerer katalogets YAML, skema og lokal semantik                   | Nej — skrivebeskyttet                          |
| `search <query...>`            | Søger i offentlige katalogfelter lokalt                                | Nej — skrivebeskyttet                          |
| `info <id>`                    | Viser én offentlig katalogpost                                       | Nej — skrivebeskyttet                          |
| `list`                         | Lister katalogstyrede installationer uden at ændre profiler            | Nej — skrivebeskyttet                          |
| `doctor`                       | Skrivebeskyttet diagnostik af Node, DSH, native Windows-politik og katalog  | Nej — skrivebeskyttet                          |
| `add <id> --profile <name> --dry-run` | Viser den verificerede installationsplan uden filer eller underprocesser | Nej — dry-run                            |
| `add <id> --profile <name> --allow-code-execution` | Installerer via officiel DSH-delegering        | Ja — kun med eksplicit samtykkeflag   |

```bash
# Validate the catalog in this repository (what CI runs):
npx omni-dsh-plugins catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx omni-dsh-plugins add <plugin-id> --profile default --dry-run
```

Kommandoer, der ændrer noget (`add`, `update`, `remove`), udfører aldrig plugin-livscykluskode,
medmindre du angiver `--allow-code-execution`. På native Windows er disse ændringer deaktiveret
i v1.0.1; brug WSL. Skrivebeskyttede og dry-run-kommandoer virker overalt.

## 🔍 Sådan kommer et plugin ind i kataloget

![Sådan kommer et plugin ind i kataloget](../../docs/diagrams/catalog-flow-dark.svg#gh-dark-mode-only)
![Sådan kommer et plugin ind i kataloget](../../docs/diagrams/catalog-flow-light.svg#gh-light-mode-only)

1. **Ét plugin, én branch, én pull request.** PR'en tilføjer eller ændrer præcis én YAML-fil
   under `catalog/plugins/`.
2. **Skaber først.** En PR åbnet af pluginnets skaber eller den ejende organisation har altid
   forrang frem for community-kuratering eller automatisering af det samme plugin — se
   [docs/CREDIT.md](../../docs/CREDIT.md).
3. **Dokumentation fra den oprindelige kilde.** Hvert felt rekonstrueres fra skaberens
   repository ved et fastlåst 40-tegns commit: beskrivelse, licens, DSH-integration,
   installationsdeskriptor, stjerner.
4. **Lokal validering.** `catalog validate` tjekker struktur og lokal semantik; det er det
   samme tjek, som CI-jobbet `catalog-validation` kører på PR'en.
5. **Vedligeholder-gates.** Før merge verificerer vedligeholderne separat repository-identitet,
   skaberbinding og fastlåst dokumentation. En grøn lokal validering er nødvendig, men aldrig
   tilstrækkelig.

Den fulde kontrakt — krævet dokumentation, YAML-regler, stjernepolitik, håndtering af
kollisioner og gennemgangs-gates — findes i [CONTRIBUTING.md](../../CONTRIBUTING.md). Hvordan
beslutninger træffes, og af hvem, står i [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md).

## 📄 Anatomien af en post

Hver post er én YAML-fil opkaldt efter sit ID. Eksemplet nedenfor validerer mod det aktuelle
skema (felt-for-felt-reference i [docs/SCHEMA.md](../../docs/SCHEMA.md)):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

Vigtige invarianter, som skemaet håndhæver:

- `unofficial: true` og `schemaVersion: 1` er konstanter.
- Et monorepo-plugin skal bruge `stars: null` — stjerner fra det overordnede projekt nedarves
  aldrig.
- Installationsdeskriptoren er enten en npm-pakke med en eksakt version eller selve den
  fastlåste kilde; det er data, aldrig en shell-kommando.
- Statussen `verified` kræver dokumentation fra en gennemgåelig smoke-test; ellers er posten
  `eligible` med `smokeTest: null`.

## 🗂 Hvad hører hjemme her

Dette repository katalogiserer uafhængigt udgivne integrationer til DeepSeek Harness (DSH),
herunder native plugins, pluginfamilier, temaer, skills, klienter og broer. Artefakttyper,
kapacitetskategorier og interface-tags er defineret i [docs/CATEGORIES.md](../../docs/CATEGORIES.md).

Hver offentlig post er én YAML-fil under `catalog/plugins/` og skal validere mod
`schemas/plugin.schema.yaml`. En optagelse betyder, at de dokumenterede egnetheds- eller
verificeringstjek er gennemført; det er ikke en sikkerhedscertificering eller en anbefaling fra
DeepSeek.

## 🏅 Rangering og verificering

Kun dedikerede, native, egnede eller verificerede plugin-repositories med stjerner, der
tilhører præcis det repository, kan indgå i en stjernerangering. Integrationer, der ligger i
bredere monorepos, forbliver søgbare, men bruger `stars: null` og nedarver aldrig stjerner fra
det overordnede projekt. Se [docs/RANKING.md](../../docs/RANKING.md) for det fulde prædikat.

Offentlige verificeringstilstande skelner mellem strukturel egnethed og en
installations-smoke-test. Ingen tilstand repræsenterer absolut sikkerhed. Gennemgå et plugins
repository, fastlåste commit, licens og installationsadfærd, før du bruger det.

## 🤝 Bidrag eller gør krav på en post

Læs [CONTRIBUTING.md](../../CONTRIBUTING.md), før du åbner en pull request. En pull request skal
tilføje eller ændre præcis én pluginpost og skal henvise til skaberens oprindelige repository
frem for et andet katalog. Pull requests forfattet af skaberen har forrang frem for
automatiserede katalog-pull requests.

Der findes strukturerede issue-formularer til skaberkrav, rettelser og fjernelser. Indsend
aldrig adgangskoder, private kontaktoplysninger eller andre hemmeligheder.
