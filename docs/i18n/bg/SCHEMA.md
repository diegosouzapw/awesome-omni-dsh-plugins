# Справочник на схемата за запис в каталога

> 🌐 [English](../../SCHEMA.md) · [Português (Brasil)](../pt-BR/SCHEMA.md) · [中文（简体）](../zh-CN/SCHEMA.md) · **Български**

> **Неофициален общностен проект. Не е свързан с, одобрен от или спонсориран от DeepSeek.**
> Имената и марките на DeepSeek принадлежат на съответните им собственици.

Това е справочникът поле по поле за
[`schemas/plugin.schema.yaml`](../../schemas/plugin.schema.yaml), публичната JSON Schema
(draft 2020-12), на която трябва да отговаря всеки файл в `catalog/plugins/`. Самият файл на
схемата е източникът на истина; когато тази страница и схемата се разминават, схемата има
предимство.

Прилагат се два слоя валидация. Публичната схема налага ограничени *безопасни форми* (образци и
дължини, които отхвърлят стойности, приличащи на опции, или неограничени стойности). Върху нея
`catalog validate` прилага задължителни семантични парсери: точен SemVer за версии, SHA-512 SRI
за стойности за цялост, parsing на SPDX изрази за лицензи и отхвърляне на дублирани ключове.
Дадена стойност може да съвпада с образеца на схемата и въпреки това да бъде отхвърлена
семантично.

Правила на най-горно ниво: записът е един YAML обект, `additionalProperties: false`
(непознатите полета се отхвърлят), а всички полета по-долу са задължителни с изключение на
`media` — единственото незадължително поле.

## Полета на най-високо ниво

| Поле               | Тип     | Задължително | Резюме                                                         |
| ------------------- | ------- | :-----------: | ---------------------------------------------------------------- |
| `schemaVersion`     | const   |      да       | Трябва да е точно `1`                                            |
| `id`                | string  |      да       | ID на записа в малки букви и kebab-case; трябва да съвпада с името на файла |
| `name`              | string  |      да       | Име за показване, 1–120 символа                                  |
| `description`       | object  |      да       | Курирано резюме на английски плюс път до доказателството         |
| `unofficial`        | const   |      да       | Трябва да е точно `true`                                         |
| `kind`              | enum    |      да       | Каноничен дискриминатор на артефакта                              |
| `primaryCategory`   | enum    |      да       | Единствена основна категория на възможностите                     |
| `tags`              | array   |      да       | Уникални тагове в малки букви и kebab-case (може да е празен)     |
| `source`            | object  |      да       | Оригинално хранилище, ID на възел, подпът и закрепен commit       |
| `creator`           | object  |      да       | Публичен GitHub handle на създателя                              |
| `package`           | object  |      да       | Каноничен дескриптор за инсталация (npm **или** source)           |
| `dsh`               | object  |      да       | DSH профили и път до доказателство за нативна интеграция          |
| `repositoryScope`   | enum    |      да       | `dedicated` или `monorepo`                                       |
| `popularity`        | object  |      да       | Политика за звезди и брой звезди (условно спрямо обхвата)         |
| `license`           | object  |      да       | Upstream SPDX израз на лиценза                                    |
| `verification`      | object  |      да       | Статус на верификация, момент на проверка, самоличност и smoke test |
| `provenance`        | object  |      да       | Публични URL адреси на Discussion/коментар или `null`             |
| `media`           | array   |    не    | До 6 екранни снимки/видеа, всеки URL закрепен към `source.commit` |

### `schemaVersion`

Константа `1`. Идентифицира публична версия на схемата 1; всяка друга стойност е невалидна.

### `id`

Низ, съвпадащ с `^[a-z0-9]+(?:-[a-z0-9]+)*$` — малки букви и kebab-case, без водещи/завършващи
или двойни тирета. Съгласно [CONTRIBUTING.md](../../CONTRIBUTING.md) файлът на записа трябва да
се казва `catalog/plugins/<id>.yaml` с идентичната стойност; валидаторът отхвърля несъответствие
(`id-filename-mismatch`). ID-то трябва също да започва с пространството от имена (namespace) на
създателя: `creator.github` handle-ът с малки букви, като всяка поредица от символи извън
`[a-z0-9]` се свива до едно `-`, последвано от `-` (`id-creator-prefix`).

### `name`

Свободно име за показване, `minLength: 1`, `maxLength: 120`.

### `description`

Обект с точно две задължителни свойства (никакви други не са разрешени):

| Свойство       | Тип    | Правила                                                                  |
| -------------- | ------ | --------------------------------------------------------------------------- |
| `en`           | string | Резюме на английски, 20–320 символа                                         |
| `evidencePath` | string | Образец за относителен път в хранилището; без водеща `/`, без обратни наклонени черти, без сегменти `.`/`..` |

Резюмето на английски трябва да бъде курирано от файла в `evidencePath`, такъв какъвто съществува
при `source.commit` — не копирано от друг каталог.

### `unofficial`

Константа `true`. Машинно четим маркер, че записът е неофициален.

### `kind`

**Единственият** дискриминатор на типа артефакт (не съществува второ поле за тип на
интеграцията). Едно от:

`plugin` · `plugin-family` · `skin-theme` · `skill` · `preset-profile` · `client-interface` ·
`bridge-adapter` · `ecosystem-project`

Значенията и последствията за класирането са определени в
[docs/CATEGORIES.md](../../docs/CATEGORIES.md).

### `primaryCategory`

Една от четиринадесетте категории на възможностите:

`user-interface-dashboards` · `memory-rag` · `search-research` · `coding-developer-tools` ·
`browser-automation` · `vision-audio-multimodal` · `sessions-productivity` ·
`security-permissions-approvals` · `diagnostics-observability` · `models-providers-routing` ·
`messaging-notifications` · `data-external-services` · `entertainment-customization` · `finance-trading`

Етикетите за показване и насоките за избор са в
[docs/CATEGORIES.md](../../docs/CATEGORIES.md).

### `tags`

Масив от уникални низове, всеки съвпадащ с `^[a-z0-9]+(?:-[a-z0-9]+)*$` (малки букви,
kebab-case). Схемата не налага минимален брой.

### `source`

Обект с точно четири задължителни свойства:

| Свойство           | Тип             | Правила                                                                 |
| ------------------- | ---------------- | ---------------------------------------------------------------------------- |
| `repository`        | string           | URL `https://github.com/<owner>/<repo>`; owner следва правилата за GitHub потребителско име, името на repo е 1–100 символа, не може да е `.`/`..`, нито да завършва на `.git` |
| `repositoryNodeId`  | string           | Неизменно ID на възел на GitHub хранилището, непразно                        |
| `subpath`           | string или null  | Подпът на плъгина в хранилището (същия безопасен образец за относителен път като `evidencePath`), или `null` за плъгин в корена на хранилището |
| `commit`            | string           | Пълен 40-символен шестнадесетичен commit OID                                 |

Валидацията на каталога трябва да установи `repositoryNodeId` и да отхвърли несъответствие в URL
адреса на хранилището — това установяване е gate от страна на поддръжника, не част от локалната
структурна проверка.

### `creator`

Обект с едно задължително свойство:

| Свойство | Тип    | Правила                                                    |
| -------- | ------ | -------------------------------------------------------------- |
| `github` | string | GitHub потребителско име (1–39 символа, правила за GitHub handle) |

URL адресът на публичния профил винаги се извежда като `https://github.com/<handle>`; не се
съхранява второ поле за профил, така че двете никога не могат да се разминат.

### `package`

Каноничният дескриптор за инсталация. Той е данни, никога shell команда, и приема точно една от
две форми (`oneOf`):

**npm пакет** — задължителни `ecosystem`, `name`, `version`; по избор `integrity`:

| Свойство    | Тип    | Правила                                                                         |
| ------------ | ------ | -------------------------------------------------------------------------------------- |
| `ecosystem`  | const  | `npm`                                                                                   |
| `name`       | string | Форма на име на npm пакет (по избор с scope), максимум 214 символа                     |
| `version`    | string | Точна `x.y.z` форма на версия (по избор prerelease/build); диапазони се отхвърлят. Семантичният слой допълнително изисква разпознаваем точен SemVer |
| `integrity`  | string | По избор форма на SRI `sha512-…`, 8–256 символа. Семантичният слой трябва да я разпознае като валиден SHA-512 SRI |

**инсталация от source** — задължително само `ecosystem`:

| Свойство    | Тип    | Правила  |
| ------------ | ------ | -------- |
| `ecosystem`  | const  | `source` |

Дескриптор на source умишлено не съхранява нищо друго: хранилището, commit-ът и подпътят се
извеждат от `source`, така че променливи стойности никога не се дублират.

### `dsh`

Доказателство за нативна DSH интеграция:

| Свойство       | Тип    | Правила                                                                    |
| --------------- | ------ | -------------------------------------------------------------------------------- |
| `profiles`      | array  | Поне едно уникално име на профил, съвпадащо с `^[A-Za-z0-9][A-Za-z0-9._-]*$`     |
| `evidencePath`  | string | Безопасен относителен път до доказателството за DSH интеграция при `source.commit` |

### `repositoryScope`

`dedicated` (звездите на хранилището принадлежат точно на този плъгин) или `monorepo` (плъгинът
е подпът или пакет вътре в по-широк проект). Тази стойност определя условните правила за
популярност по-долу.

### `popularity`

| Свойство      | Тип                | Правила                                                    |
| -------------- | ------------------- | ------------------------------------------------------------- |
| `starsPolicy`  | enum                | `exact-repository` или `undefined-parent-repository`          |
| `stars`        | integer или null    | Неотрицателно цяло число, или `null`                           |

Условни правила (наложени от блоковете `allOf` на схемата):

- `repositoryScope: monorepo` **налага** `starsPolicy: undefined-parent-repository` и
  `stars: null`. Звездите на родителския проект никога не се приписват на плъгин от monorepo.
- `repositoryScope: dedicated` **налага** `starsPolicy: exact-repository` и цяло число
  `stars >= 0`.

Вижте [docs/RANKING.md](../../docs/RANKING.md) за това как тези стойности захранват предиката
за класиране.

### `license`

| Свойство | Тип    | Правила                                                        |
| -------- | ------ | ------------------------------------------------------------------- |
| `spdx`   | string | Форма на SPDX израз, 2–256 символа, без водещо тире                 |

Схемата налага само безопасна форма на символите; валидацията на каталога трябва да разпознае и
нормализира стойността с истински парсер за SPDX израз. Записвайте пълния upstream израз,
доказан при закрепения commit (например `Apache-2.0` или `MIT OR GPL-3.0-only`).

### `verification`

Верификацията се прилага към `source.commit`. Обект с четири задължителни свойства:

| Свойство              | Тип             | Правила                                                    |
| ---------------------- | ---------------- | --------------------------------------------------------------- |
| `status`               | enum             | `eligible` · `verified` · `stale` · `unavailable` · `archived` · `quarantined` |
| `checkedAt`            | string           | Времеви маркер на проверката във формат `date-time`              |
| `repositoryIdentity`   | const            | Трябва да е `resolved`                                           |
| `smokeTest`            | object или null  | Запис за smoke test, или `null`, когато не съществува квалифициран тест |

Когато е налично, `smokeTest` изисква:

| Свойство         | Тип    | Правила                                                                |
| ----------------- | ------ | ----------------------------------------------------------------------------- |
| `installTarget`   | const  | `canonical-install-descriptor` — сочи към `package` или закрепения source, без да дублира променливи стойности |
| `check`           | object | Задължителни `name` (форма на име на пакет) и `version` (форма на точна версия) |
| `result`          | const  | `passed` — неуспешен smoke test не се записва като smoke test                 |

Условно правило: `status: verified` **изисква** обект `smokeTest`, различен от null. Записи без
рецензируемо доказателство за smoke test използват `status: eligible` и `smokeTest: null`. Нито
един статус не е одобрение или сертификация за сигурност — вижте
[docs/RANKING.md](../../docs/RANKING.md).

### `provenance`

Публични линкове за произход, всеки от които URI или `null`:

| Свойство     | Тип             | Правила                                            |
| ------------- | ---------------- | -------------------------------------------------------- |
| `discussion`  | string или null  | Публичен URL на Discussion, когато съществува             |
| `comment`     | string или null  | Публичен URL на коментар, когато съществува                |

### `media`

Единственото незадължително поле. Масив с най-много **6** елемента, всеки от които описва една екранна снимка или кратко видео на приставката:

| Свойство | Тип | Правила |
| -------- | ------ | ----- |
| `kind`   | enum   | `screenshot` или `video` |
| `url`    | string | Непроменим URL на GitHub, най-много 2048 знака (виж по-долу) |
| `alt`    | string | Алтернативен текст, 1–120 знака |

URL тук трябва да е също толкова непроменим, колкото `source.commit`. Път
`raw.githubusercontent.com` с име на клон (`.../main/docs/shot.png`) показва това, което клонът
съдържа днес, така че записът би публикувал непрегледано изображение в деня, в който клонът се
премести. Приемат се две форми:

- `https://raw.githubusercontent.com/<owner>/<repo>/<commit>/<path>` — закрепеният към комита raw път;
- `https://github.com/<owner>/<repo>/assets/…` — адресираният по съдържание URL за качване на GitHub, за елементи `video`.

Схемата налага само безопасната форма (хост, 40-знакова шестнадесетична референция, ограничена
дължина). Останалото `catalog validate` налага семантично: URL трябва да закрепва `source.commit`
**на самия запис** в хранилището **на самия запис**, а URL на клон се отхвърля с
`media[n].url must pin the entry commit, not a branch`.

Пропуснете полето изцяло, когато няма какво да се покаже — `media: []` не е валиден начин да се
каже „без екранни снимки“. Полето е добавъчно: записите, публикувани преди то да съществува,
остават валидни, а потребител, който го игнорира, чете всеки запис точно както преди.

## Записи `kind: skill`

Схема версия 1 определя също втори, самостоятелен договор за запис за `kind: skill`,
публикуван като [`schemas/skill.schema.yaml`](../../schemas/skill.schema.yaml) (SKL-01 фаза 0).
Той никога не докосва схемата за плъгини по-горе: записите с `kind: plugin` продължават да се
валидират точно както преди, а файлът на skill схемата е източникът на истина за записите на
skill-ове по същия начин, по който схемата за плъгини е за записите на плъгини.

Един skill не се инсталира, той се **зарежда** от harness-а, така че дескрипторите за
инсталация само за плъгини (`package`, `dsh`) не съществуват върху запис на skill и се заменят
от `usage` + `compat`. Един skill също често живее в поддиректория на хранилище, което
приютява много skill-ове, така че идентичността и дедупликацията са `source.repository` +
`source.subpath`, а не само хранилището. Запис на skill не допуска галерия `media`: skill-ът е
текст, който harness-ът зарежда, така че няма какво да се снима
(`additionalProperties: false` е това, което го налага).

Тези полета запазват точно формата и правилата, документирани за записите на плъгини по-горе:
`schemaVersion`, `id`, `name`, `description`, `unofficial`, `primaryCategory`, `tags`,
`source`, `creator`, `repositoryScope`, `license`, `provenance`. Всяко поле е задължително с
изключение на `triggers`, единственото незадължително поле на skill.

### Полета, специфични за skill

| Поле                 | Тип    | Задължително | Правила                                                     |
| -------------------- | ------ | :----------: | ----------------------------------------------------------- |
| `kind`               | const  |      да      | Трябва да е точно `skill`                                   |
| `skillScope`         | enum   |      да      | `repository` (цялото хранилище **е** skill-ът) или `subdirectory` (skill-ът живее в `source.subpath`) |
| `triggers`           | array  |      не      | Кога skill-ът се задейства — текстът, който потребителят оценява, преди да го зареди. Поне 1 уникален низ, всеки от 3–200 символа; пропуснете полето изцяло, когато няма такива (`triggers: []` е невалидно) |
| `usage.load`         | string |      да      | Как harness-ът зарежда skill-а, 1–200 символа; skill се зарежда, никога не се инсталира |
| `usage.evidencePath` | string |      да      | Безопасен относителен път (същия образец като `description.evidencePath`) до доказателството за зареждане при `source.commit` |
| `compat.harnessMin`  | string |      да      | Минимална версия на harness-а, срещу която skill-ът е бил верифициран; точна `x.y.z` форма (по избор prerelease/build), максимум 64 символа. Семантичният слой допълнително изисква разпознаваем точен SemVer |

Условни правила (наложени от блоковете `allOf` на skill схемата):

- `skillScope: subdirectory` **налага** `source.subpath` да е низ с безопасен относителен
  път — skill, разположен в поддиректория, трябва да закрепи тази поддиректория.
- `skillScope: repository` **налага** `source.subpath: null` — skill, обхващащ цяло хранилище,
  не трябва да декларира подпът.

`verification` запазва формата от плъгините (`status`, `checkedAt`, `repositoryIdentity`,
`smokeTest`), но `smokeTest` трябва да е точно `null`: skill няма инсталационен smoke test, а
рецензията на съдържанието е gate-ът за допускане. Skill схемата не носи условието
`status: verified` → `smokeTest`, нито условията `repositoryScope` → `popularity`; тези
обвързвания са правила само на схемата за плъгини.

### Семантичен слой за skill-ове

Върху схемата валидацията на каталога прилага същите задължителни семантични парсери като при
плъгините, там където полетата съществуват: `license.spdx` трябва да се разпознае като валиден
SPDX израз (`invalid-spdx`), а `compat.harnessMin` трябва да е точен SemVer
(`invalid-semver`). Няма случай `invalid-sri` — skill няма `package.integrity`.

### Идентичност и дедупликация на skill

Каноничният ключ на един skill е `skill:<source.repositoryNodeId>:<normalized subpath>`.
Подпътят се нормализира само за целите на идентичността: обратните наклонени черти стават `/`,
празните и `.` сегментите се изхвърлят, а празен резултат (или `subpath: null`) става `.` —
цялото хранилище. Подпът, съдържащ NUL байтове или `..` сегменти, се отхвърля, никога не се
„почиства“. Два skill-а от едно и също хранилище са два записа; същото хранилище + подпът два
пъти е колизия.

### Минимален пример за skill

```yaml
schemaVersion: 1
id: alice-dsh-commit-lint-skill
name: DSH Commit Lint Skill
description:
  en: Loads a commit-message linting skill that checks Conventional Commit shape before the harness commits.
  evidencePath: skills/commit-lint/SKILL.md
unofficial: true
kind: skill
skillScope: subdirectory
primaryCategory: coding-developer-tools
tags:
  - git
  - linting
triggers:
  - When the user asks to commit staged work
source:
  repository: https://github.com/alice/dsh-skills
  repositoryNodeId: R_kgDOexample1
  subpath: skills/commit-lint
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: alice
usage:
  load: dsh skill load skills/commit-lint
  evidencePath: skills/commit-lint/SKILL.md
compat:
  harnessMin: 1.4.0
repositoryScope: monorepo
popularity:
  starsPolicy: undefined-parent-repository
```
