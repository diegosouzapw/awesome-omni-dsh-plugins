# సృష్టికర్త క్రెడిట్ మరియు పుల్ రిక్వెస్ట్ ప్రాధాన్యత

స్వతంత్రమైనవారి నుండి యాజమాన్యాన్ని లాక్కోకుండా, స్వతంత్ర పనిని కనుగొనదగినదిగా చేయడానికి
కేటలాగ్ ఉంది. పబ్లిక్ ఎంట్రీలు అసలు రిపాజిటరీని మరియు మారని సోర్స్ కమిట్‌ను ఉదహరిస్తాయి.

## అదే ప్లగిన్ కోసం ప్రాధాన్యత

<!-- creator-first:direct-pr-supersedes-curation-and-automation -->

1. ప్లగిన్ సృష్టికర్త లేదా యాజమాన్య సంస్థ తెరిచిన పుల్ రిక్వెస్ట్.
2. సృష్టికర్త స్పష్టంగా ఆమోదించిన లేదా కో-అథర్ చేసిన కమ్యూనిటీ పుల్ రిక్వెస్ట్.
3. ఇప్పటికే ఉన్న చెల్లుబాటు అయ్యే కమ్యూనిటీ పుల్ రిక్వెస్ట్.
4. కేటలాగ్ ఆటోమేషన్ పుల్ రిక్వెస్ట్.
5. పబ్లిక్ పుల్ రిక్వెస్ట్ లేని ప్రైవేట్ అభ్యర్థి.

ప్రత్యక్ష సృష్టికర్త పుల్ రిక్వెస్ట్ ఎల్లప్పుడూ ప్రాధాన్యమైనది మరియు అదే కానానికల్ ప్లగిన్ కోసం తెరిచి
ఉన్న ఏదైనా కమ్యూనిటీ క్యూరేషన్ లేదా ఆటోమేషన్ పుల్ రిక్వెస్ట్‌ను భర్తీ చేస్తుంది, ఏది ముందు తెరవబడినా
లేదా ఏది మరింత ముందుకు సాగినా. సృష్టికర్త పుల్ రిక్వెస్ట్ సమీక్షా వాహనంగా మారుతుంది; వారి బ్రాంచ్
ఎప్పుడూ ఓవర్‌రైట్ చేయబడదు, ఫోర్స్-పుష్ చేయబడదు లేదా క్యూరేటెడ్ పుల్ రిక్వెస్ట్‌లోకి మార్పిడీ
చేయబడదు. క్యూరేటెడ్ ఎంట్రీ ఇప్పటికే మెర్జ్ అయి ఉంటే, చరిత్ర చెక్కుచెదరకుండా ఉంటుంది మరియు
సృష్టికర్త కొత్త సహకారంలో దానిని క్లెయిమ్ చేయవచ్చు లేదా సరిదిద్దవచ్చు.

## పబ్లిక్ అట్రిబ్యూషన్

ప్రతి కేటలాగ్ ఎంట్రీ సృష్టికర్త పబ్లిక్ GitHub హ్యాండిల్, అసలు రిపాజిటరీ, రిపాజిటరీ నోడ్ ID,
ప్లగిన్ సబ్‌పాత్ మరియు పూర్తి పిన్ చేయబడిన కమిట్‌ను కలిగి ఉంటుంది. పబ్లిక్ సృష్టికర్త ప్రొఫైల్ రెండవ
గుర్తింపుగా నిల్వ చేయబడకుండా ఒక్క హ్యాండిల్ నుండి ఉత్పాదించబడుతుంది. వేరైన మెయింటైనర్ ప్రోవెనెన్స్
గేట్ నోడ్ IDని పరిష్కరించి రిపాజిటరీ URL అసమానతను తిరస్కరిస్తుంది. పుల్ రిక్వెస్ట్ వివరణలు
`Created by @handle` అని చెప్పాలి మరియు సోర్స్ రిపాజిటరీ, సోర్స్ కమిట్ మెటాడేటాను
కలిగి ఉండాలి.

డిస్కషన్‌ను పోస్ట్ చేసే లేదా దానిపై వ్యాఖ్యానించే వ్యక్తి ఆటోమేటిక్‌గా సృష్టికర్తగా పరిగణించబడరు. యాజమాన్యం
రిపాజిటరీ యజమాని లేదా సంస్థ, ప్యాకేజీ కర్తృత్వం, మానిఫెస్ట్ మెటాడేటా లేదా ఖచ్చితమైన పిన్ చేయబడిన
సోర్స్ చరిత్ర ద్వారా మద్దతు ఇవ్వబడాలి.

## Git గుర్తింపు

<!-- creator-first:source-bound-git-identity -->

కమిట్ కర్తృత్వం మరియు పుల్ రిక్వెస్ట్ కర్తృత్వం వేర్వేరు. సృష్టికర్త మూలంగా ఉన్న పుల్ రిక్వెస్ట్
సృష్టికర్తను పుల్ రిక్వెస్ట్ రచయితగా ఉంచుతుంది, మరియు వారి కమిట్‌లు కర్తృత్వాన్ని సహజంగా
భద్రపరుస్తాయి. మెయింటైనర్ లేదా ఆటోమేషన్ ఖాతా కమిటర్‌గా లేదా ధృవీకరించిన కో-రచయితగా కనిపించవచ్చు,
కానీ సృష్టికర్త కర్తృత్వాన్ని భర్తీ చేయకూడదు.

క్యూరేటెడ్ కమిట్ కోసం, ఖచ్చితమైన గుర్తింపు సోర్స్‌కు బంధించబడి, పబ్లిక్‌గా ధృవీకరించదగినదిగా ఉన్నప్పుడు
మాత్రమే సృష్టికర్తను Git రచయితగా ఉపయోగించండి లేదా `Co-authored-by` ట్రైలర్‌ను జోడించండి,
ఉదాహరణకు అసలు రిపాజిటరీలో సృష్టికర్త కమిట్‌కు ఇప్పటికే జతచేసిన గుర్తింపు. ఇమెయిల్‌ను ఎప్పుడూ
ఊహించవద్దు, noreply చిరునామాను తయారు చేయవద్దు లేదా అధీకృత పబ్లిక్ సోర్స్ బయట కనుగొన్న ప్రైవేట్
చిరునామాను ఉపయోగించవద్దు.

ధృవీకరించిన Git గుర్తింపు అందుబాటులో లేనప్పుడు, క్యూరేటర్ లేదా ఆటోమేషన్ ఖాతా కమిట్‌కు రచయిత అవుతుంది
మరియు బదులుగా స్పష్టమైన కనిపించే క్రెడిట్ ఇస్తుంది: `Created by @handle`, సరిపోలిన
పబ్లిక్ ప్రొఫైల్ మరియు ఎంట్రీ, పుల్ రిక్వెస్ట్‌లలో అసలు రిపాజిటరీకి లింక్. Git గుర్తింపు మ్యాపింగ్‌తో
సంబంధం లేకుండా కనిపించే YAML ఆపాదింపు ఎల్లప్పుడూ అవసరం. తదుపరి ప్రత్యక్ష సృష్టికర్త పుల్ రిక్వెస్ట్
తెరిచి ఉన్న క్యూరేటెడ్ పుల్ రిక్వెస్ట్‌ను భర్తీ చేస్తుంది, దాని సింథటిక్ చరిత్రను వారసత్వంగా తీసుకోదు.

## గౌరవప్రదమైన సృష్టికర్త ప్రస్తావన

క్యూరేటెడ్ పుల్ రిక్వెస్ట్ దాని వివరణలో అసలు రిపాజిటరీ లింక్ పక్కన ఒక గౌరవప్రదమైన పబ్లిక్ `@creator`
ప్రస్తావనను ఉపయోగిస్తుంది. ఇది సమీక్షను లేదా భర్తీ ప్రత్యక్ష పుల్ రిక్వెస్ట్‌ను ఆహ్వానించవచ్చు. ప్రస్తావనను
పునరావృతం చేయవద్దు, ప్రమోషనల్ ఇష్యూలను తెరవవద్దు, క్రాస్-పోస్ట్ చేయవద్దు లేదా అభ్యర్థించని డైరెక్ట్
సందేశాలను పంపవద్దు.

## కేటలాగ్ లైసెన్స్ వర్సెస్ అప్‌స్ట్రీమ్ లైసెన్స్

కేటలాగ్ వాస్తవాలు మరియు సంపాదకీయ YAML మెటాడేటా CC0-1.0 కింద అంకితం చేయబడ్డాయి. ఆ అంకితం
అప్‌స్ట్రీమ్ ప్లగిన్ లైసెన్స్‌ను మార్చదు. అప్‌స్ట్రీమ్ కోడ్, డాక్యుమెంటేషన్, స్క్రీన్‌షాట్‌లు, లోగోలు
మరియు ఇతర సృజనాత్మక సామగ్రి వాటి అసలు లైసెన్స్‌లు మరియు యజమానులకు లోబడి ఉంటాయి.
