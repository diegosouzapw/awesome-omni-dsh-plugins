# కేటలాగ్ ఎంట్రీ స్కీమా రిఫరెన్స్

> 🌐 [English](../../SCHEMA.md) · [Português (Brasil)](../pt-BR/SCHEMA.md) · [中文（简体）](../zh-CN/SCHEMA.md) · **తెలుగు**

> **అనధికారిక కమ్యూనిటీ ప్రాజెక్ట్. DeepSeekతో అనుబంధం లేదు, ఆమోదం పొందలేదు లేదా స్పాన్సర్ చేయబడలేదు.**
> DeepSeek పేర్లు మరియు గుర్తులు వాటి సంబంధిత యజమానికి చెందినవి.

ఇది [`schemas/plugin.schema.yaml`](../../schemas/plugin.schema.yaml) కోసం ఫీల్డ్-బై-ఫీల్డ్ రిఫరెన్స్ —
ఇది `catalog/plugins/` కింద ఉన్న ప్రతి ఫైల్ తప్పనిసరిగా పాటించాల్సిన పబ్లిక్ JSON స్కీమా (draft 2020-12).
స్కీమా ఫైల్ స్వయంగా మూలం (సోర్స్ ఆఫ్ ట్రూత్); ఈ పేజీ మరియు స్కీమా విభేదించినప్పుడు, స్కీమాయే ప్రామాణికం.

రెండు పొరల వాలిడేషన్ వర్తిస్తాయి. పబ్లిక్ స్కీమా పరిమిత *సేఫ్ షేప్‌లను* (ఆప్షన్-లాంటి లేదా పరిమితి లేని
విలువలను తిరస్కరించే ప్యాటర్న్‌లు మరియు పొడవులు) అమలు చేస్తుంది. దానిపై, `catalog validate` తప్పనిసరి
సెమాంటిక్ పార్సర్‌లను వర్తింపజేస్తుంది: వెర్షన్‌లకు ఖచ్చితమైన SemVer, ఇంటిగ్రిటీ విలువలకు SHA-512 SRI,
లైసెన్స్‌లకు SPDX ఎక్స్‌ప్రెషన్ పార్సింగ్ మరియు నకలు-కీ తిరస్కరణ. ఒక విలువ స్కీమా ప్యాటర్న్‌తో సరిపోలినా
సెమాంటిక్‌గా తిరస్కరించబడవచ్చు.

అగ్ర-స్థాయి నియమాలు: ఎంట్రీ ఒకే ఒక YAML ఆబ్జెక్ట్, `additionalProperties: false`
(తెలియని ఫీల్డ్‌లు తిరస్కరించబడతాయి), మరియు కింది అన్ని ఫీల్డ్‌లూ తప్పనిసరి — ఏకైక ఐచ్ఛిక
ఫీల్డ్ అయిన `media` తప్ప.

## టాప్-లెవల్ ఫీల్డ్‌లు

| ఫీల్డ్          | రకం     | అవసరం | సారాంశం                                                        |
| ----------------- | ------- | :------: | ------------------------------------------------------------- |
| `schemaVersion`   | const   |   అవును    | ఖచ్చితంగా `1` అయి ఉండాలి                                           |
| `id`              | string  |   అవును    | లోయర్‌కేస్ కేబాబ్-కేస్ ఎంట్రీ ID; ఫైల్ పేరుతో సరిపోలాలి        |
| `name`            | string  |   అవును    | డిస్‌ప్లే పేరు, 1–120 అక్షరాలు                                |
| `description`     | object  |   అవును    | క్యూరేట్ చేసిన ఇంగ్లీష్ సారాంశం మరియు దాని ఎవిడెన్స్ పాత్                |
| `unofficial`      | const   |   అవును    | ఖచ్చితంగా `true` అయి ఉండాలి                                        |
| `kind`            | enum    |   అవును    | కానానికల్ ఆర్టిఫ్యాక్ట్ డిస్క్రిమినేటర్                              |
| `primaryCategory` | enum    |   అవును    | ఏకైక ప్రాథమిక సామర్థ్య వర్గం                            |
| `tags`            | array   |   అవును    | ప్రత్యేకమైన లోయర్‌కేస్ కేబాబ్-కేస్ ట్యాగ్‌లు (ఖాళీగా ఉండవచ్చు)               |
| `source`          | object  |   అవును    | అసలు రిపాజిటరీ, నోడ్ ID, సబ్‌పాత్ మరియు పిన్ చేయబడిన కమిట్       |
| `creator`         | object  |   అవును    | సృష్టికర్త పబ్లిక్ GitHub హ్యాండిల్                                |
| `package`         | object  |   అవును    | కానానికల్ ఇన్‌స్టాల్ డిస్క్రిప్టర్ (npm **లేదా** సోర్స్)              |
| `dsh`             | object  |   అవును    | DSH ప్రొఫైల్‌లు మరియు నేటివ్-ఇంటిగ్రేషన్ ఎవిడెన్స్ పాత్             |
| `repositoryScope` | enum    |   అవును    | `dedicated` లేదా `monorepo`                                     |
| `popularity`      | object  |   అవును    | స్టార్ల పాలసీ మరియు స్టార్ కౌంట్ (స్కోప్‌పై ఆధారపడి)            |
| `license`         | object  |   అవును    | అప్‌స్ట్రీమ్ SPDX లైసెన్స్ ఎక్స్‌ప్రెషన్                              |
| `verification`    | object  |   అవును    | ధృవీకరణ స్థితి, తనిఖీ సమయం, ఐడెంటిటీ మరియు స్మోక్ టెస్ట్      |
| `provenance`      | object  |   అవును    | పబ్లిక్ Discussion/కామెంట్ URLలు లేదా `null`                      |
| `media`           | array   |    కాదు    | గరిష్ఠంగా 6 స్క్రీన్‌షాట్‌లు/వీడియోలు, ప్రతి URL `source.commit`కు పిన్ |

### `schemaVersion`

స్థిరాంకం `1`. పబ్లిక్ స్కీమా వెర్షన్ 1ని గుర్తిస్తుంది; మరేదైనా విలువ చెల్లదు.

### `id`

`^[a-z0-9]+(?:-[a-z0-9]+)*$`తో సరిపోలిన స్ట్రింగ్ — లోయర్‌కేస్ కేబాబ్-కేస్, ముందు/వెనుక లేదా
డబుల్ హైఫన్‌లు ఉండకూడదు. [CONTRIBUTING.md](../../CONTRIBUTING.md) ప్రకారం, ఎంట్రీ ఫైల్
`catalog/plugins/<id>.yaml` అనే ఒకే విలువతో పేరు పెట్టబడాలి; వ్యాలిడేటర్ అసమానతను తిరస్కరిస్తుంది
(`id-filename-mismatch`). ID సృష్టికర్త నేమ్‌స్పేస్‌తో కూడా ప్రారంభం కావాలి: `creator.github`
హ్యాండిల్ లోయర్‌కేస్‌లో, `[a-z0-9]` వెలుపలి ప్రతి అక్షరాల వరుస ఒకే `-`గా కుదించబడి, తర్వాత `-`
ఉండాలి (`id-creator-prefix`).

### `name`

స్వేచ్ఛా-ఫార్మాట్ డిస్‌ప్లే పేరు, `minLength: 1`, `maxLength: 120`.

### `description`

ఖచ్చితంగా రెండు అవసరమైన ప్రాపర్టీలతో ఉన్న ఆబ్జెక్ట్ (వేరేవి అనుమతించబడవు):

| ప్రాపర్టీ        | రకం    | నియమాలు                                                                 |
| -------------- | ------ | --------------------------------------------------------------------- |
| `en`           | string | ఇంగ్లీష్ సారాంశం, 20–320 అక్షరాలు                                    |
| `evidencePath` | string | రిలేటివ్ రిపో పాత్ ప్యాటర్న్; ముందు `/` లేదు, బ్యాక్‌స్లాష్‌లు లేవు, `.`/`..` సెగ్మెంట్‌లు లేవు |

ఇంగ్లీష్ సారాంశం `source.commit` వద్ద ఉన్నట్లుగా `evidencePath` వద్ద ఉన్న ఫైల్ నుండి క్యూరేట్
చేయబడాలి — మరొక కేటలాగ్ నుండి కాపీ చేయకూడదు.

### `unofficial`

స్థిరాంకం `true`. లిస్టింగ్ అనధికారికమని తెలిపే మెషిన్-రీడబుల్ గుర్తు.

### `kind`

**ఏకైక** ఆర్టిఫ్యాక్ట్-రకం డిస్క్రిమినేటర్ (రెండవ ఇంటిగ్రేషన్-రకం ఫీల్డ్ ఏదీ లేదు). వీటిలో ఒకటి:

`plugin` · `plugin-family` · `skin-theme` · `skill` · `preset-profile` · `client-interface` ·
`bridge-adapter` · `ecosystem-project`

అర్థాలు మరియు ర్యాంకింగ్ పర్యవసానాలు [docs/CATEGORIES.md](../../docs/CATEGORIES.md)లో నిర్వచించబడ్డాయి.

### `primaryCategory`

పద్నాలుగు సామర్థ్య వర్గాలలో ఒకటి:

`user-interface-dashboards` · `memory-rag` · `search-research` · `coding-developer-tools` ·
`browser-automation` · `vision-audio-multimodal` · `sessions-productivity` ·
`security-permissions-approvals` · `diagnostics-observability` · `models-providers-routing` ·
`messaging-notifications` · `data-external-services` · `entertainment-customization` · `finance-trading`

డిస్‌ప్లే లేబుల్స్ మరియు ఎంపిక మార్గదర్శకత్వం [docs/CATEGORIES.md](../../docs/CATEGORIES.md)లో ఉన్నాయి.

### `tags`

ప్రత్యేకమైన స్ట్రింగ్‌ల అర్రే, ప్రతిదీ `^[a-z0-9]+(?:-[a-z0-9]+)*$`తో సరిపోలాలి (లోయర్‌కేస్ కేబాబ్-కేస్).
స్కీమా కనీస సంఖ్యను విధించదు.

### `source`

ఖచ్చితంగా నాలుగు అవసరమైన ప్రాపర్టీలతో ఉన్న ఆబ్జెక్ట్:

| ప్రాపర్టీ          | రకం            | నియమాలు                                                                  |
| ------------------ | -------------- | ---------------------------------------------------------------------- |
| `repository`       | string         | `https://github.com/<owner>/<repo>` URL; ఓనర్ GitHub యూజర్‌నేమ్ నియమాలను అనుసరిస్తుంది, రిపో పేరు 1–100 అక్షరాలు, `.`/`..` కాకూడదు లేదా `.git`తో ముగియకూడదు |
| `repositoryNodeId` | string         | మారని GitHub రిపాజిటరీ నోడ్ ID, ఖాళీగా ఉండకూడదు                         |
| `subpath`          | string or null | రిపాజిటరీ లోపల ప్లగిన్ సబ్‌పాత్ (`evidencePath` వలె అదే సేఫ్ రిలేటివ్-పాత్ ప్యాటర్న్), లేదా రిపాజిటరీ-రూట్ ప్లగిన్ అయితే `null` |
| `commit`           | string         | పూర్తి 40-అక్షరాల హెక్సాడెసిమల్ కమిట్ OID                               |

కేటలాగ్ వాలిడేషన్ `repositoryNodeId`ని పరిష్కరించి రిపాజిటరీ URL అసమానతను తిరస్కరించాలి — ఆ
పరిష్కారం మెయింటైనర్-వైపు గేట్, లోకల్ స్ట్రక్చరల్ తనిఖీలో భాగం కాదు.

### `creator`

ఒకే అవసరమైన ప్రాపర్టీతో ఉన్న ఆబ్జెక్ట్:

| ప్రాపర్టీ | రకం    | నియమాలు                                             |
| -------- | ------ | ------------------------------------------------- |
| `github` | string | GitHub యూజర్‌నేమ్ (1–39 అక్షరాలు, GitHub హ్యాండిల్ నియమాలు) |

పబ్లిక్ ప్రొఫైల్ URL ఎల్లప్పుడూ `https://github.com/<handle>`గా ఉత్పాదించబడుతుంది; రెండవ ప్రొఫైల్
ఫీల్డ్ నిల్వ చేయబడదు, కాబట్టి రెండూ ఎప్పుడూ విభేదించలేవు.

### `package`

కానానికల్ ఇన్‌స్టాల్ డిస్క్రిప్టర్. ఇది డేటా, ఎప్పుడూ షెల్ కమాండ్ కాదు, మరియు ఖచ్చితంగా రెండు రూపాలలో
ఒకటి (`oneOf`) తీసుకుంటుంది:

**npm ప్యాకేజీ** — `ecosystem`, `name`, `version` అవసరం; `integrity` ఐచ్ఛికం:

| ప్రాపర్టీ     | రకం   | నియమాలు                                                                      |
| ----------- | ----- | -------------------------------------------------------------------------- |
| `ecosystem` | const | `npm`                                                                      |
| `name`      | string | npm ప్యాకేజీ పేరు రూపం (ఐచ్ఛికంగా స్కోప్డ్), గరిష్టంగా 214 అక్షరాలు                 |
| `version`   | string | ఖచ్చితమైన `x.y.z` వెర్షన్ రూపం (ఐచ్ఛిక ప్రీరిలీజ్/బిల్డ్); రేంజ్‌లు తిరస్కరించబడతాయి. సెమాంటిక్ పొర అదనంగా పార్స్ చేయదగిన, ఖచ్చితమైన SemVerను అవసరం చేస్తుంది |
| `integrity` | string | ఐచ్ఛిక `sha512-…` SRI రూపం, 8–256 అక్షరాలు. సెమాంటిక్ పొర దానిని చెల్లుబాటు అయ్యే SHA-512 SRIగా పార్స్ చేయాలి |

**సోర్స్ ఇన్‌స్టాల్** — `ecosystem` మాత్రమే అవసరం:

| ప్రాపర్టీ     | రకం   | నియమాలు    |
| ----------- | ----- | -------- |
| `ecosystem` | const | `source` |

సోర్స్ డిస్క్రిప్టర్ ఉద్దేశపూర్వకంగా వేరేమీ నిల్వ చేయదు: రిపాజిటరీ, కమిట్ మరియు సబ్‌పాత్ `source` నుండి
ఉత్పాదించబడతాయి, కాబట్టి మారే విలువలు ఎప్పుడూ నకలు చేయబడవు.

### `dsh`

నేటివ్ DSH ఇంటిగ్రేషన్ సాక్ష్యం:

| ప్రాపర్టీ        | రకం    | నియమాలు                                                          |
| -------------- | ------ | -------------------------------------------------------------- |
| `profiles`     | array  | `^[A-Za-z0-9][A-Za-z0-9._-]*$`తో సరిపోలిన కనీసం ఒక ప్రత్యేకమైన ప్రొఫైల్ పేరు |
| `evidencePath` | string | `source.commit` వద్ద ఉన్న DSH ఇంటిగ్రేషన్ సాక్ష్యానికి సేఫ్ రిలేటివ్ పాత్ |

### `repositoryScope`

`dedicated` (రిపాజిటరీ స్టార్లు ఈ ఖచ్చితమైన ప్లగిన్‌కు చెందుతాయి) లేదా `monorepo` (ప్లగిన్ విస్తృత
ప్రాజెక్ట్ లోపల ఒక సబ్‌పాత్ లేదా ప్యాకేజీ). ఈ విలువ క్రింది ఆధారిత పాపులారిటీ నియమాలను నడిపిస్తుంది.

### `popularity`

| ప్రాపర్టీ      | రకం             | నియమాలు                                                |
| ------------ | --------------- | ---------------------------------------------------- |
| `starsPolicy`| enum            | `exact-repository` లేదా `undefined-parent-repository`  |
| `stars`      | integer or null | నెగటివ్ కాని పూర్ణాంకం, లేదా `null`                      |

ఆధారిత నియమాలు (స్కీమా యొక్క `allOf` బ్లాక్‌ల ద్వారా అమలు చేయబడతాయి):

- `repositoryScope: monorepo` తప్పనిసరిగా `starsPolicy: undefined-parent-repository` మరియు
  `stars: null`ను **బలవంతం** చేస్తుంది. మాతృ-ప్రాజెక్ట్ స్టార్లు ఎప్పుడూ మోనోరెపో ప్లగిన్‌కు ఆపాదించబడవు.
- `repositoryScope: dedicated` తప్పనిసరిగా `starsPolicy: exact-repository` మరియు పూర్ణాంకం
  `stars >= 0`ను **బలవంతం** చేస్తుంది.

ఈ విలువలు ర్యాంకింగ్ ప్రిడికేట్‌కు ఎలా సమాచారం అందిస్తాయో [docs/RANKING.md](../../docs/RANKING.md)లో చూడండి.

### `license`

| ప్రాపర్టీ | రకం    | నియమాలు                                                          |
| -------- | ------ | -------------------------------------------------------------- |
| `spdx`   | string | SPDX ఎక్స్‌ప్రెషన్ రూపం, 2–256 అక్షరాలు, ముందు హైఫన్ లేదు          |

స్కీమా సేఫ్ క్యారెక్టర్ రూపాన్ని మాత్రమే అమలు చేస్తుంది; కేటలాగ్ వాలిడేషన్ నిజమైన SPDX ఎక్స్‌ప్రెషన్
పార్సర్‌తో విలువను పార్స్ చేసి నార్మలైజ్ చేయాలి. పిన్ చేయబడిన కమిట్ వద్ద సాక్ష్యంతో ఉన్న పూర్తి అప్‌స్ట్రీమ్
ఎక్స్‌ప్రెషన్‌ను నమోదు చేయండి (ఉదాహరణకు `Apache-2.0` లేదా `MIT OR GPL-3.0-only`).

### `verification`

ధృవీకరణ `source.commit`కు వర్తిస్తుంది. నాలుగు అవసరమైన ప్రాపర్టీలతో ఉన్న ఆబ్జెక్ట్:

| ప్రాపర్టీ            | రకం             | నియమాలు                                                  |
| -------------------- | -------------- | ------------------------------------------------------ |
| `status`             | enum           | `eligible` · `verified` · `stale` · `unavailable` · `archived` · `quarantined` |
| `checkedAt`          | string         | తనిఖీ యొక్క `date-time` ఫార్మాట్ టైమ్‌స్టాంప్           |
| `repositoryIdentity` | const          | `resolved` అయి ఉండాలి                                     |
| `smokeTest`          | object or null | స్మోక్-టెస్ట్ రికార్డ్, లేదా అర్హత కలిగిన టెస్ట్ లేనప్పుడు `null` |

ఉన్నప్పుడు, `smokeTest`కు అవసరం:

| ప్రాపర్టీ         | రకం    | నియమాలు                                                             |
| --------------- | ------ | ----------------------------------------------------------------- |
| `installTarget` | const  | `canonical-install-descriptor` — మారే విలువలను నకలు చేయకుండా `package`ను లేదా పిన్ చేయబడిన సోర్స్‌ను సూచిస్తుంది |
| `check`         | object | అవసరమైన `name` (ప్యాకేజీ-పేరు రూపం) మరియు `version` (ఖచ్చితమైన వెర్షన్ రూపం) |
| `result`        | const  | `passed` — విఫలమైన స్మోక్ టెస్ట్ స్మోక్ టెస్ట్‌గా నమోదు చేయబడదు    |

ఆధారిత నియమం: `status: verified`కు నల్ కాని `smokeTest` ఆబ్జెక్ట్ **అవసరం**. సమీక్షించదగిన
స్మోక్ ఎవిడెన్స్ లేని ఎంట్రీలు `status: eligible` మరియు `smokeTest: null` ఉపయోగిస్తాయి. ఏ స్థితి
కూడా ఆమోదం లేదా సెక్యూరిటీ సర్టిఫికేషన్ కాదు — [docs/RANKING.md](../../docs/RANKING.md) చూడండి.

### `provenance`

పబ్లిక్ ప్రోవెనెన్స్ లింక్‌లు, ప్రతిదీ ఒక URI లేదా `null`:

| ప్రాపర్టీ      | రకం             | నియమాలు                                            |
| ------------ | ------------- | ------------------------------------------------ |
| `discussion` | string or null | ఉన్నప్పుడు పబ్లిక్ Discussion URL            |
| `comment`    | string or null | ఉన్నప్పుడు పబ్లిక్ కామెంట్ URL               |

### `media`

ఏకైక ఐచ్ఛిక ఫీల్డ్. గరిష్ఠంగా **6** అంశాల శ్రేణి; ప్రతి అంశం ప్లగిన్ యొక్క ఒక స్క్రీన్‌షాట్‌ను లేదా ఒక చిన్న వీడియోను వివరిస్తుంది:

| లక్షణం | రకం | నియమాలు |
| -------- | ------ | ----- |
| `kind`   | enum   | `screenshot` లేదా `video` |
| `url`    | string | మార్పులేని GitHub URL, గరిష్ఠంగా 2048 అక్షరాలు (కింద చూడండి) |
| `alt`    | string | ప్రత్యామ్నాయ వచనం, 1–120 అక్షరాలు |

ఇక్కడి URL `source.commit` అంతే మార్పులేనిదిగా ఉండాలి. బ్రాంచ్ పేరును మోసే
`raw.githubusercontent.com` మార్గం (`.../main/docs/shot.png`) ఆ బ్రాంచ్ ఈ రోజు కలిగి ఉన్నదాన్ని
చూపుతుంది, కాబట్టి బ్రాంచ్ కదిలిన రోజున ఎంట్రీ సమీక్షించని చిత్రాన్ని ప్రచురిస్తుంది. రెండు రూపాలే
ఆమోదించబడతాయి:

- `https://raw.githubusercontent.com/<owner>/<repo>/<commit>/<path>` — కమిట్‌కు పిన్ చేసిన raw మార్గం;
- `https://github.com/<owner>/<repo>/assets/…` — GitHub యొక్క కంటెంట్-ఆధారిత అప్‌లోడ్ URL, `video` అంశాల కోసం.

స్కీమా సురక్షిత రూపాన్ని మాత్రమే అమలు చేస్తుంది (హోస్ట్, 40 అక్షరాల హెక్సాడెసిమల్ సూచన, పరిమిత
పొడవు). మిగిలినది `catalog validate` అర్థపరంగా అమలు చేస్తుంది: URL **ఎంట్రీ స్వంత** రిపాజిటరీలో
**ఎంట్రీ స్వంత** `source.commit`ను పిన్ చేయాలి, బ్రాంచ్ URL
`media[n].url must pin the entry commit, not a branch` తో తిరస్కరించబడుతుంది.

చూపడానికి ఏమీ లేనప్పుడు ఫీల్డ్‌ను పూర్తిగా వదిలేయండి — `media: []` అనేది "స్క్రీన్‌షాట్‌లు లేవు"
అని చెప్పడానికి చెల్లుబాటు అయ్యే మార్గం కాదు. ఈ ఫీల్డ్ అదనపుది: ఇది ఉనికిలోకి రాకముందు ప్రచురించిన
ఎంట్రీలు చెల్లుబాటులోనే ఉంటాయి, దీన్ని విస్మరించే వినియోగదారు ప్రతి ఎంట్రీని మునుపటిలాగే చదువుతారు.

## `kind: skill` ఎంట్రీలు

స్కీమా వెర్షన్ 1, `kind: skill` కోసం రెండవ, స్వతంత్ర ఎంట్రీ కాంట్రాక్ట్‌ను కూడా నిర్వచిస్తుంది; ఇది
[`schemas/skill.schema.yaml`](../../schemas/skill.schema.yaml)గా ప్రచురించబడింది (SKL-01 దశ 0).
ఇది పైన ఉన్న ప్లగిన్ స్కీమాను ఎప్పుడూ తాకదు: `kind: plugin` ఉన్న ఎంట్రీలు మునుపటిలాగే ఖచ్చితంగా
వాలిడేట్ అవుతూనే ఉంటాయి, మరియు ప్లగిన్ ఎంట్రీలకు ప్లగిన్ స్కీమా ఎలాగో అలాగే స్కిల్ ఎంట్రీలకు స్కిల్
స్కీమా ఫైల్ మూలం (సోర్స్ ఆఫ్ ట్రూత్).

స్కిల్ ఇన్‌స్టాల్ చేయబడదు, హార్నెస్ దాన్ని **లోడ్ చేస్తుంది**; కాబట్టి ప్లగిన్-మాత్రమే ఇన్‌స్టాల్
డిస్క్రిప్టర్‌లు (`package`, `dsh`) స్కిల్ ఎంట్రీపై ఉండవు, వాటి స్థానంలో `usage` + `compat`
ఉంటాయి. స్కిల్ తరచుగా అనేక స్కిల్స్‌ను హోస్ట్ చేసే రిపాజిటరీ యొక్క సబ్‌డైరెక్టరీలో కూడా
నివసిస్తుంది; కాబట్టి ఐడెంటిటీ మరియు డీడూప్ రిపాజిటరీ మాత్రమే కాకుండా `source.repository` +
`source.subpath`. స్కిల్ ఎంట్రీ `media` గ్యాలరీని అనుమతించదు: స్కిల్ అనేది హార్నెస్ లోడ్ చేసే
టెక్స్ట్, కాబట్టి స్క్రీన్‌షాట్ తీయడానికి ఏమీ లేదు (దీన్ని అమలు చేసేది
`additionalProperties: false`).

ఈ ఫీల్డ్‌లు పైన ప్లగిన్ ఎంట్రీలకు డాక్యుమెంట్ చేసిన రూపం మరియు నియమాలను ఖచ్చితంగా
ఉంచుకుంటాయి: `schemaVersion`, `id`, `name`, `description`, `unofficial`, `primaryCategory`,
`tags`, `source`, `creator`, `repositoryScope`, `license`, `provenance`. ఏకైక ఐచ్ఛిక స్కిల్
ఫీల్డ్ అయిన `triggers` తప్ప ప్రతి ఫీల్డ్ తప్పనిసరి.

### స్కిల్-ప్రత్యేక ఫీల్డ్‌లు

| ఫీల్డ్               | రకం    | అవసరం | నియమాలు                                                       |
| -------------------- | ------ | :------: | ----------------------------------------------------------- |
| `kind`               | const  |   అవును    | ఖచ్చితంగా `skill` అయి ఉండాలి                                     |
| `skillScope`         | enum   |   అవును    | `repository` (రిపాజిటరీ మొత్తం **స్కిల్లే**) లేదా `subdirectory` (స్కిల్ `source.subpath` వద్ద నివసిస్తుంది) |
| `triggers`           | array  |    కాదు    | స్కిల్ ఎప్పుడు ప్రేరేపితమవుతుందో — లోడ్ చేసే ముందు వినియోగదారు అంచనా వేసే టెక్స్ట్. కనీసం 1 ప్రత్యేకమైన స్ట్రింగ్, ప్రతిదీ 3–200 అక్షరాలు; ఏవీ లేనప్పుడు ఫీల్డ్‌ను పూర్తిగా వదిలేయండి (`triggers: []` చెల్లదు) |
| `usage.load`         | string |   అవును    | హార్నెస్ స్కిల్‌ను ఎలా లోడ్ చేస్తుందో, 1–200 అక్షరాలు; స్కిల్ లోడ్ చేయబడుతుంది, ఎప్పుడూ ఇన్‌స్టాల్ చేయబడదు |
| `usage.evidencePath` | string |   అవును    | `source.commit` వద్ద లోడ్ ఎవిడెన్స్‌కు సేఫ్ రిలేటివ్ పాత్ (`description.evidencePath` వలె అదే ప్యాటర్న్) |
| `compat.harnessMin`  | string |   అవును    | స్కిల్ ధృవీకరించబడిన కనీస హార్నెస్ వెర్షన్; ఖచ్చితమైన `x.y.z` రూపం (ఐచ్ఛిక ప్రీరిలీజ్/బిల్డ్), గరిష్టంగా 64 అక్షరాలు. సెమాంటిక్ పొర అదనంగా పార్స్ చేయదగిన, ఖచ్చితమైన SemVerను అవసరం చేస్తుంది |

ఆధారిత నియమాలు (స్కిల్ స్కీమా యొక్క `allOf` బ్లాక్‌ల ద్వారా అమలు చేయబడతాయి):

- `skillScope: subdirectory` `source.subpath` సేఫ్ రిలేటివ్-పాత్ స్ట్రింగ్ అయి ఉండాలని
  **బలవంతం** చేస్తుంది — సబ్‌డైరెక్టరీలో హోస్ట్ అయిన స్కిల్ ఆ సబ్‌డైరెక్టరీని పిన్ చేయాలి.
- `skillScope: repository` `source.subpath: null`ను **బలవంతం** చేస్తుంది — మొత్తం-రిపాజిటరీ
  స్కిల్ సబ్‌పాత్‌ను ప్రకటించకూడదు.

`verification` ప్లగిన్ రూపాన్నే (`status`, `checkedAt`, `repositoryIdentity`, `smokeTest`)
ఉంచుకుంటుంది, కానీ `smokeTest` ఖచ్చితంగా `null` అయి ఉండాలి: స్కిల్‌కు ఇన్‌స్టాల్ స్మోక్ టెస్ట్
లేదు, కంటెంట్ సమీక్షే ప్రవేశ గేట్. స్కిల్ స్కీమా `status: verified` → `smokeTest` షరతును గానీ
`repositoryScope` → `popularity` షరతులను గానీ మోయదు; ఆ బంధాలు ప్లగిన్-స్కీమా నియమాలు
మాత్రమే.

### స్కిల్స్ కోసం సెమాంటిక్ పొర

స్కీమాపై, ఫీల్డ్‌లు ఉన్న చోట ప్లగిన్‌ల కోసం ఉపయోగించే అవే తప్పనిసరి సెమాంటిక్ పార్సర్‌లను
కేటలాగ్ వాలిడేషన్ వర్తింపజేస్తుంది: `license.spdx` చెల్లుబాటు అయ్యే SPDX ఎక్స్‌ప్రెషన్‌గా పార్స్
కావాలి (`invalid-spdx`), మరియు `compat.harnessMin` ఖచ్చితమైన SemVer అయి ఉండాలి
(`invalid-semver`). `invalid-sri` కేసు లేదు — స్కిల్‌కు `package.integrity` లేదు.

### స్కిల్ ఐడెంటిటీ మరియు డీడూప్

స్కిల్ యొక్క కానానికల్ కీ `skill:<source.repositoryNodeId>:<normalized subpath>`. సబ్‌పాత్
ఐడెంటిటీ ప్రయోజనాల కోసం మాత్రమే నార్మలైజ్ చేయబడుతుంది: బ్యాక్‌స్లాష్‌లు `/` అవుతాయి, ఖాళీ
మరియు `.` సెగ్మెంట్‌లు తొలగించబడతాయి, మరియు ఖాళీ ఫలితం (లేదా `subpath: null`) `.` అవుతుంది —
రిపాజిటరీ మొత్తం. NUL బైట్‌లు లేదా `..` సెగ్మెంట్‌లు ఉన్న సబ్‌పాత్ తిరస్కరించబడుతుంది, ఎప్పుడూ
"శుభ్రం" చేయబడదు. ఒకే రిపాజిటరీకి చెందిన రెండు స్కిల్స్ రెండు ఎంట్రీలు; అదే రిపాజిటరీ +
సబ్‌పాత్ రెండుసార్లు ఉంటే అది ఘర్షణ.
