# CLI రిఫరెన్స్ — `omni-dsh-plugins@1.0.1`

> 🌐 [English](../../CLI.md) · [Português (Brasil)](../pt-BR/CLI.md) · [中文（简体）](../zh-CN/CLI.md) · **తెలుగు**

> **అనధికారిక కమ్యూనిటీ ప్రాజెక్ట్. DeepSeekతో అనుబంధం లేదు, ఆమోదం పొందలేదు లేదా స్పాన్సర్ చేయబడలేదు.**
> DeepSeek పేర్లు మరియు గుర్తులు వాటి సంబంధిత యజమానికి చెందినవి.

ఈ పేజీ ప్రచురించబడిన CLIని వెర్షన్ `1.0.1`లో అది ఎలా ప్రవర్తిస్తుందో అలాగే డాక్యుమెంట్ చేస్తుంది.
క్రింది ప్రతి సినాప్సిస్ మరియు ఫ్లాగ్ ప్రచురించబడిన కమాండ్ యొక్క సొంత `--help` అవుట్‌పుట్ నుండి
తీసుకోబడింది; ఇక్కడ ఏదీ విడుదల కాని ప్రవర్తనను వివరించదు. CLI ఈ రిపాజిటరీలో [`cli/`](../../cli)
కింద అభివృద్ధి చేయబడి, [`omni-dsh-plugins`](https://www.npmjs.com/package/omni-dsh-plugins)గా
npmకు విడుదల చేయబడింది, ప్రతి బిల్డ్‌ను దానిని ఉత్పత్తి చేసిన కమిట్ మరియు వర్క్‌ఫ్లో రన్‌కు అనుసంధానించే
ప్రోవెనెన్స్ అటెస్టేషన్‌తో.

```bash
npx omni-dsh-plugins --help
```

## v1.0.1లో డిజైన్ సూత్రాలు

- **డిఫాల్ట్‌గా రీడ్-ఓన్లీ.** `catalog`, `search`, `info`, `list` మరియు `doctor` ప్రొఫైల్‌లను ఎప్పుడూ
  మార్చవు, ఫైల్‌లను వ్రాయవు లేదా ప్లగిన్ కోడ్‌ను స్పాన్ చేయవు.
- **కోడ్ ఎగ్జిక్యూషన్ కోసం కన్సెంట్ గేట్.** `add`, `update` మరియు `remove` మీరు
  `--allow-code-execution` పాస్ చేయకపోతే DSH/pnpm లైఫ్‌సైకిల్ కోడ్‌ను రన్ చేయడానికి నిరాకరిస్తాయి.
  అది లేకుండా, ధృవీకరించిన ప్లాన్‌ను చూడటానికి `--dry-run` ఉపయోగించండి.
- **నేటివ్ Windows పాలసీ.** కోడ్ ఎగ్జిక్యూషన్‌తో కూడిన నేటివ్ Windows `add`/`update`/`remove`
  v1.0.1లో డిసేబుల్ చేయబడ్డాయి; WSL ఉపయోగించండి. డ్రై-రన్ మరియు రీడ్-ఓన్లీ కమాండ్‌లు అందుబాటులోనే
  ఉంటాయి, మరియు నేటివ్ Windows రికవరీ మార్కర్‌లకు డాక్యుమెంట్ చేసిన మాన్యువల్ రికవరీ అవసరం.
- **పిన్ చేయబడిన ఇన్‌పుట్‌లు.** కేటలాగ్ ఇన్‌పుట్ లోకల్ డైరెక్టరీ, స్నాప్‌షాట్ ఫైల్ లేదా పిన్ చేయబడిన
  పబ్లిక్ స్నాప్‌షాట్ URL కావచ్చు, ఐచ్ఛికంగా ఖచ్చితమైన 40-అక్షరాల రివిజన్‌కు లాక్ చేయబడవచ్చు.

## సాధారణ ఆప్షన్‌లు

ఈ ఆప్షన్‌లు కేటలాగ్-వినియోగించే కమాండ్‌లపై కనిపిస్తాయి (`catalog validate`, `search`, `info`,
`add`, `update`, `remove`, `doctor`):

| ఆప్షన్                    | అర్థం                                                            |
| ------------------------- | ------------------------------------------------------------------ |
| `--catalog <path-or-url>` | లోకల్ కేటలాగ్ డైరెక్టరీ, స్నాప్‌షాట్ ఫైల్ లేదా పిన్ చేయబడిన పబ్లిక్ స్నాప్‌షాట్ URL |
| `--revision <sha>`        | ఖచ్చితమైన 40-అక్షరాల స్నాప్‌షాట్ రివిజన్                               |
| `--json`                  | స్థిరమైన JSON అవుట్‌పుట్‌ను విడుదల చేస్తుంది                                            |

గ్లోబల్ ఆప్షన్‌లు: `-V, --version` CLI వెర్షన్‌ను ప్రింట్ చేస్తుంది; `-h, --help` ఏదైనా కమాండ్ కోసం
హెల్ప్‌ను ప్రింట్ చేస్తుంది (`dsh-plugins help [command]` కూడా పని చేస్తుంది).

## ఎగ్జిట్ కోడ్‌లు

CLI సాంప్రదాయ ప్రాసెస్ ఎగ్జిట్ కోడ్‌లను ఉపయోగిస్తుంది:

| ఎగ్జిట్ కోడ్ | అర్థం                                                                    |
| --------: | -------------------------------------------------------------------------- |
| `0`       | విజయం (ఖాళీ కేటలాగ్ వంటి "ఖాళీ కానీ చెల్లుబాటు అయ్యే" ఫలితాలతో సహా)     |
| `1`       | వైఫల్యం: వాలిడేషన్ లోపం, ఎంట్రీ కనుగొనబడలేదు, అవసరమైన ఆప్షన్ లేదు, లేదా లోపాన్ని నివేదించే డయాగ్నస్టిక్ తనిఖీ |

v1.0.1తో గమనించిన ఉదాహరణలు: చెల్లుబాటు అయ్యే ఖాళీ కేటలాగ్‌పై `catalog validate`
`0 entries valid; catalog is empty`తో `0` వద్ద నిష్క్రమిస్తుంది; `info <unknown-id>`
`Plugin not found`తో `1` వద్ద నిష్క్రమిస్తుంది; ఏదైనా తనిఖీ (ఉదా. `dsh` ఎగ్జిక్యూటబుల్ లేకపోవడం)
లోపాన్ని నివేదిస్తే `doctor` `1` వద్ద నిష్క్రమిస్తుంది.

## కమాండ్‌లు

### `catalog` — పబ్లిక్ కేటలాగ్ సర్ఫేస్‌లను ధృవీకరించండి

```text
dsh-plugins catalog validate [--catalog <path-or-url>] [--revision <sha>] [--json]
dsh-plugins catalog docs-check [root]
dsh-plugins catalog github-forms-check [root]
```

- **`catalog validate`** — కేటలాగ్ YAML మరియు సెమాంటిక్స్‌ను ధృవీకరిస్తుంది: సేఫ్ YAML పార్సింగ్,
  పబ్లిక్ స్కీమా, SPDX ఎక్స్‌ప్రెషన్ పార్సింగ్, ఖచ్చితమైన SemVer, SHA-512 SRI మరియు నకలు ID /
  రిపాజిటరీ-నోడ్-ప్లస్-సబ్‌పాత్ తిరస్కరణ. ఇది లోకల్ మరియు రీడ్-ఓన్లీ: ఇది GitHubను సంప్రదించదు,
  రిపాజిటరీ ఐడెంటిటీని పరిష్కరించదు లేదా పిన్ చేయబడిన కమిట్ వద్ద సాక్ష్యాన్ని పరిశీలించదు. ప్రతి కేటలాగ్
  పుల్ రిక్వెస్ట్‌పై `catalog-validation` CI జాబ్ రన్ చేసే ఖచ్చితమైన కమాండ్ ఇదే.
- **`catalog docs-check [root]`** — అవసరమైన పబ్లిక్ కేటలాగ్ డాక్యుమెంటేషన్ ఉనికిలో ఉందని మరియు
  మార్క్‌డౌన్ ఫెన్స్‌లు సమతుల్యంగా ఉన్నాయని తనిఖీ చేస్తుంది.
- **`catalog github-forms-check [root]`** — స్ట్రక్చర్డ్ పబ్లిక్ GitHub ఇష్యూ ఫారమ్‌లను తనిఖీ చేస్తుంది
  (క్లెయిమ్, సవరణ, తొలగింపు).

```bash
# From the repository root:
npx omni-dsh-plugins catalog validate --catalog .
npx omni-dsh-plugins catalog docs-check .
npx omni-dsh-plugins catalog github-forms-check .
```

### `search` — పబ్లిక్ కేటలాగ్ ఫీల్డ్‌లను స్థానికంగా శోధించండి

```text
dsh-plugins search [options] <query...>
```

ఎంచుకున్న కేటలాగ్ ఇన్‌పుట్‌పై పబ్లిక్ కేటలాగ్ ఫీల్డ్‌లను స్థానికంగా శోధిస్తుంది. సరిపోలిన ఎంట్రీలను
ప్రింట్ చేస్తుంది, లేదా ఏదీ సరిపోలనప్పుడు `No plugins found.` (ఎగ్జిట్ `0`) ప్రింట్ చేస్తుంది.

```bash
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins search notes markdown --catalog . --json
```

### `discover` — కేటలాగ్ దాటి ప్లగిన్‌లను కనుగొనండి

```text
dsh-plugins discover [options] <query...>
```

> `discover` `1.0.0`లో విడుదలైంది, ఈ ప్యాకేజీ పేరుతో మొదటి రిలీజ్.

ముందుగా క్యూరేట్ చేసిన కేటలాగ్‌ను శోధిస్తుంది, ఆపై — `--offline` ఇవ్వకపోతే — లైవ్ GitHub
`dsh-plugin` టాపిక్‌ను కూడా శోధిస్తుంది, తద్వారా ఇంకా సమర్పించని ప్లగిన్ కూడా కనుగొనదగినదిగా
ఉంటుంది. కేటలాగ్ ఫలితాలు కేటలాగ్ కలిగి ఉన్న సాక్ష్యాన్ని (పిన్ చేయబడిన కమిట్, సృష్టికర్త, లైసెన్స్)
కలిగి ఉంటాయి; కమ్యూనిటీ ఫలితాలు దేనినీ కలిగి ఉండవు మరియు అలాగే లేబుల్ చేయబడతాయి, ఎందుకంటే వాటి
గురించి ఏదీ సమీక్షించబడలేదు.

`--limit <n>` ప్రతి టైర్‌కు ఫలితాలను పరిమితం చేస్తుంది (డిఫాల్ట్ `8`). `--json` స్థిరమైన మెషిన్ రూపాన్ని
విడుదల చేస్తుంది, ఇది ఎప్పుడూ లోకలైజ్ చేయబడదు.

```bash
npx omni-dsh-plugins discover memory --catalog .
npx omni-dsh-plugins discover vision --offline --catalog . --json
```

### `info` — ఒక పబ్లిక్ కేటలాగ్ ఎంట్రీని చూపండి

```text
dsh-plugins info [options] <id>
```

కానానికల్ ప్లగిన్ ID ద్వారా ఒక పబ్లిక్ కేటలాగ్ ఎంట్రీని చూపుతుంది. ఆ కేటలాగ్‌లో లేనప్పుడు
`Plugin not found: <id>`తో `1` వద్ద నిష్క్రమిస్తుంది.

```bash
npx omni-dsh-plugins info example-notes-search --catalog .
```

### `add` — అధికారిక DSH డెలిగేషన్ ద్వారా ఒక కేటలాగ్ ప్లగిన్‌ను జోడించండి

```text
dsh-plugins add [options] <id>
```

| ఆప్షన్                    | అర్థం                                                            |
| ------------------------ | ------------------------------------------------------------------ |
| `--profile <name>`       | మార్చవలసిన DSH ప్రొఫైల్ (ఆచరణలో అవసరం; దీని లేకుండా కమాండ్ లోపం ఇస్తుంది) |
| `--dry-run`              | ఫైల్‌లు లేదా సబ్‌ప్రాసెస్‌లు లేకుండా ధృవీకరించిన ప్లాన్‌ను చూపండి               |
| `--allow-code-execution` | DSH/pnpm లైఫ్‌సైకిల్ కోడ్‌కు కన్సెంట్ (నేటివ్ Windows డిసేబుల్; WSL ఉపయోగించండి) |
| `--catalog` / `--revision` / `--json` | పైన సాధారణ ఆప్షన్‌లు                                  |

ఈ వెర్షన్‌లో డ్రై-రన్ సెమాంటిక్స్: కమాండ్ పిన్ చేయబడిన ఎంట్రీ కోసం ప్లాన్‌ను పరిష్కరించి ధృవీకరించి
ప్రింట్ చేస్తుంది, ఫైల్‌లను సృష్టించదు మరియు సబ్‌ప్రాసెస్‌లను స్పాన్ చేయదు. వాస్తవ ఇన్‌స్టాలేషన్ అధికారిక
DSH టూలింగ్‌కు డెలిగేట్ అవుతుంది మరియు `--allow-code-execution`తో మాత్రమే ముందుకు సాగుతుంది.

```bash
# Preview only — nothing is written, nothing executes:
npx omni-dsh-plugins add example-notes-search --profile default --dry-run

# Real install — explicit consent to lifecycle code:
npx omni-dsh-plugins add example-notes-search --profile default --allow-code-execution
```

### `update` — అధికారిక DSH డెలిగేషన్ ద్వారా ఒక కేటలాగ్ ప్లగిన్‌ను అప్‌డేట్ చేయండి

```text
dsh-plugins update [options] <id>
```

`add` వలె అదే ఆప్షన్‌లు మరియు కన్సెంట్ సెమాంటిక్స్: `--profile <name>`, `--dry-run`,
`--allow-code-execution`, మరియు సాధారణ కేటలాగ్ ఆప్షన్‌లు.

### `remove` — అధికారిక DSH డెలిగేషన్ ద్వారా ఒక కేటలాగ్-నిర్వహిత ప్లగిన్‌ను తొలగించండి

```text
dsh-plugins remove [options] <id>
```

`add` వలె అదే ఆప్షన్‌లు మరియు కన్సెంట్ సెమాంటిక్స్. కేటలాగ్-నిర్వహిత ఇన్‌స్టాల్‌లు మాత్రమే తొలగించబడతాయి.

### `recover` — నిలిచిపోయిన POSIX మ్యుటేషన్‌ను రికవర్ చేయండి

```text
dsh-plugins recover
```

అంతరాయం కలిగిన `add`/`update`/`remove` తర్వాత నిలిచిపోయిన POSIX మ్యుటేషన్‌ను రికవర్ చేస్తుంది.
ఏదీ పెండింగ్‌లో లేనప్పుడు ఇది `No mutation recovery is pending.` అని ప్రింట్ చేసి `0` వద్ద
నిష్క్రమిస్తుంది. డాక్యుమెంట్ చేసిన పాలసీ ప్రకారం, నేటివ్ Windows రికవరీ మాన్యువల్‌గానే ఉంటుంది.

### `list` — కేటలాగ్-నిర్వహిత ఇన్‌స్టాల్‌లను జాబితా చేయండి

```text
dsh-plugins list [--profile <name>] [--json]
```

ప్రొఫైల్‌లను మార్చకుండా కేటలాగ్-నిర్వహిత ఇన్‌స్టాల్‌లను జాబితా చేస్తుంది. `--profile <name>` DSH
ప్రొఫైల్ ద్వారా ఫిల్టర్ చేస్తుంది. ఇన్‌స్టాల్‌లు లేనప్పుడు ఇది `No catalog-managed plugins installed.`
అని ప్రింట్ చేసి `0` వద్ద నిష్క్రమిస్తుంది.

### `doctor` — రీడ్-ఓన్లీ డయాగ్నస్టిక్స్

```text
dsh-plugins doctor [--catalog <path-or-url>] [--revision <sha>] [--json]
```

రీడ్-ఓన్లీ Node, DSH, నేటివ్ Windows పాలసీ మరియు కేటలాగ్ డయాగ్నస్టిక్స్‌ను రన్ చేస్తుంది. ప్రతి
తనిఖీ `ok` లేదా `error`ని నివేదిస్తుంది; ఏదైనా `error` మొత్తం ఎగ్జిట్ కోడ్‌ను `1` చేస్తుంది.
`dsh` ఎగ్జిక్యూటబుల్ లేని మెషిన్‌పై ఉదాహరణ అవుట్‌పుట్:

```text
node [ok]: Node 24.16.0 is supported
dsh [error]: dsh executable was not found
catalog [ok]: catalog is valid and empty
```
