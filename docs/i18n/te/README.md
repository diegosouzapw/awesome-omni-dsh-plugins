# 🧩 Awesome Omni DSH Plugins

> **అనధికారిక కమ్యూనిటీ ప్రాజెక్ట్. DeepSeekతో అనుబంధం లేదు, ఆమోదం పొందలేదు లేదా స్పాన్సర్ చేయబడలేదు.**

ఈ రిపాజిటరీ కేటలాగ్ కోసం పబ్లిక్ సోర్స్ ఆఫ్ ట్రూత్. ప్రతి లిస్టింగ్ `catalog/plugins/` కింద ఒక YAML ఫైల్,
ఇది పబ్లిష్ చేయబడిన JSON స్కీమాకు వ్యతిరేకంగా ధృవీకరించబడుతుంది, ఒక వ్యక్తిగతంగా సమీక్షించిన పుల్ రిక్వెస్ట్
ద్వారా జోడించబడుతుంది, మరియు ఎల్లప్పుడూ ప్లగిన్ యొక్క అసలు సృష్టికర్తకు క్రెడిట్ ఇవ్వబడుతుంది.
కేటలాగ్‌లో దేనినీ మరొక కేటలాగ్ లేదా జాబితా నుండి జనరేట్ చేయరు: ప్రతి ఎంట్రీ పిన్ చేయబడిన కమిట్ వద్ద
అసలు సృష్టికర్త రిపాజిటరీ నుండి పునర్నిర్మించబడుతుంది.

వెబ్‌సైట్ ప్రైవేట్ సోర్స్ నుండి నిర్వహించబడుతుంది. CLI ఇక్కడ ఈ రిపాజిటరీలోనే, [`cli/`](../../cli) కింద ఉంది,
మరియు ఈ రిపాజిటరీ ఆ రెండూ వినియోగించే పబ్లిక్ కేటలాగ్ డేటా, స్కీమా మరియు పాలసీలను కలిగి ఉంటుంది.

## కేటలాగ్ స్థితి

**483 ప్లగిన్‌లు మెర్జ్ చేయబడ్డాయి.** ప్రతి ప్లగిన్ ఒక వ్యక్తిగతంగా సమీక్షించిన పుల్ రిక్వెస్ట్ ద్వారా, ఒక్కొక్కటిగా,
అసలు సృష్టికర్త రిపాజిటరీ నుండి, పిన్ చేయబడిన సోర్స్ కమిట్ మరియు స్పష్టమైన అట్రిబ్యూషన్‌తో ప్రవేశిస్తుంది.

| `catalog validate --catalog .` | కేటలాగ్ YAML, స్కీమా మరియు లోకల్ సెమాంటిక్స్‌ను ధృవీకరించండి                   | కాదు — రీడ్-ఓన్లీ                          |
| `search <query...>`            | పబ్లిక్ కేటలాగ్ ఫీల్డ్‌లను స్థానికంగా శోధించండి                                | కాదు — రీడ్-ఓన్లీ                          |
| `info <id>`                    | ఒక పబ్లిక్ కేటలాగ్ ఎంట్రీని చూపండి                                       | కాదు — రీడ్-ఓన్లీ                          |
| `list`                         | ప్రొఫైల్‌లను సవరించకుండా కేటలాగ్-నిర్వహించే ఇన్‌స్టాల్‌లను జాబితా చేయండి            | కాదు — రీడ్-ఓన్లీ                          |
| `doctor`                       | రీడ్-ఓన్లీ Node, DSH, నేటివ్ Windows పాలసీ మరియు కేటలాగ్ డయాగ్నస్టిక్స్  | కాదు — రీడ్-ఓన్లీ                          |
| `add <id> --profile <name> --dry-run` | ఫైల్‌లు లేదా సబ్‌ప్రాసెస్‌లు లేకుండా ధృవీకరించిన ఇన్‌స్టాల్ ప్లాన్‌ను చూపండి | కాదు — డ్రై-రన్                            |
| `add <id> --profile <name> --allow-code-execution` | అధికారిక DSH డెలిగేషన్ ద్వారా ఇన్‌స్టాల్ చేయండి        | అవును — స్పష్టమైన కన్సెంట్ ఫ్లాగ్‌తో మాత్రమే   |

```bash
# Validate the catalog in this repository (what CI runs):
npx omni-dsh-plugins catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx omni-dsh-plugins add <plugin-id> --profile default --dry-run
```

మ్యుటేటింగ్ కమాండ్‌లు (`add`, `update`, `remove`) మీరు `--allow-code-execution` పాస్ చేయకపోతే ప్లగిన్
లైఫ్‌సైకిల్ కోడ్‌ను ఎప్పుడూ ఎగ్జిక్యూట్ చేయవు. నేటివ్ Windowsలో ఆ మ్యుటేషన్‌లు v1.0.1లో డిసేబుల్ చేయబడ్డాయి;
WSL ఉపయోగించండి. రీడ్-ఓన్లీ మరియు డ్రై-రన్ కమాండ్‌లు ప్రతిచోటా పని చేస్తాయి.

## 🔍 కేటలాగ్‌లోకి ప్లగిన్ ఎలా ప్రవేశిస్తుంది

![కేటలాగ్‌లోకి ప్లగిన్ ఎలా ప్రవేశిస్తుంది](../../docs/diagrams/catalog-flow-dark.svg#gh-dark-mode-only)
![కేటలాగ్‌లోకి ప్లగిన్ ఎలా ప్రవేశిస్తుంది](../../docs/diagrams/catalog-flow-light.svg#gh-light-mode-only)

1. **ఒక ప్లగిన్, ఒక బ్రాంచ్, ఒక పుల్ రిక్వెస్ట్.** PR `catalog/plugins/` కింద సరిగ్గా ఒక YAML ఫైల్‌ను
   జోడిస్తుంది లేదా మారుస్తుంది.
2. **సృష్టికర్త-ప్రాధాన్యం.** ప్లగిన్ యొక్క సృష్టికర్త లేదా యాజమాన్య సంస్థ తెరిచిన PR అదే ప్లగిన్ కోసం
   కమ్యూనిటీ క్యూరేషన్ లేదా ఆటోమేషన్ కంటే ఎల్లప్పుడూ ప్రాధాన్యత పొందుతుంది — చూడండి
   [docs/CREDIT.md](../../docs/CREDIT.md).
3. **అసలు మూలం నుండి సాక్ష్యం.** ప్రతి ఫీల్డ్ పిన్ చేయబడిన 40-అక్షరాల కమిట్ వద్ద సృష్టికర్త రిపాజిటరీ
   నుండి పునర్నిర్మించబడుతుంది: వివరణ, లైసెన్స్, DSH ఇంటిగ్రేషన్, ఇన్‌స్టాల్ డిస్క్రిప్టర్, స్టార్లు.
4. **లోకల్ వాలిడేషన్.** `catalog validate` స్ట్రక్చర్ మరియు లోకల్ సెమాంటిక్స్‌ను తనిఖీ చేస్తుంది; ఇది
   `catalog-validation` CI జాబ్ PRపై రన్ చేసే అదే తనిఖీ.
5. **మెయింటైనర్ గేట్‌లు.** మెర్జ్‌కు ముందు, మెయింటైనర్‌లు రిపాజిటరీ ఐడెంటిటీ, సృష్టికర్త బైండింగ్ మరియు
   పిన్ చేయబడిన సాక్ష్యాన్ని విడిగా ధృవీకరిస్తారు. గ్రీన్ లోకల్ వాలిడేషన్ అవసరం, కానీ ఎప్పుడూ సరిపోదు.

పూర్తి ఒప్పందం — అవసరమైన సాక్ష్యం, YAML నియమాలు, స్టార్ల పాలసీ, కొల్లిజన్ హ్యాండ్లింగ్ మరియు సమీక్ష
గేట్‌లు — [CONTRIBUTING.md](../../CONTRIBUTING.md)లో ఉంది. నిర్ణయాలు ఎలా తీసుకోబడతాయో మరియు ఎవరు
తీసుకుంటారో [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md)లో ఉంది.

## 📄 ఒక ఎంట్రీ యొక్క అనాటమీ

ప్రతి ఎంట్రీ దాని IDతో పేరు పెట్టబడిన ఒక YAML ఫైల్. క్రింది ఉదాహరణ ప్రస్తుత స్కీమాకు వ్యతిరేకంగా
ధృవీకరించబడుతుంది (ఫీల్డ్-బై-ఫీల్డ్ రిఫరెన్స్ [docs/SCHEMA.md](../../docs/SCHEMA.md)లో ఉంది):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

కీలక ఇన్వేరియంట్‌లు స్కీమా ద్వారా అమలు చేయబడతాయి:

- `unofficial: true` మరియు `schemaVersion: 1` స్థిరాంకాలు.
- మోనోరెపో ప్లగిన్ తప్పనిసరిగా `stars: null` ఉపయోగించాలి — మాతృ-ప్రాజెక్ట్ స్టార్లు ఎప్పుడూ వారసత్వంగా రావు.
- ఇన్‌స్టాల్ డిస్క్రిప్టర్ ఖచ్చితమైన-వెర్షన్ npm ప్యాకేజీ లేదా పిన్ చేయబడిన సోర్స్ కావచ్చు; ఇది డేటా,
  ఎప్పుడూ షెల్ కమాండ్ కాదు.
- `verified` స్థితికి సమీక్షించదగిన స్మోక్-టెస్ట్ సాక్ష్యం అవసరం; లేకపోతే ఎంట్రీ `smokeTest: null`తో
  `eligible`గా ఉంటుంది.

## 🗂 ఇక్కడ ఏమి ఉంటుంది

ఈ రిపాజిటరీ DeepSeek Harness (DSH) కోసం స్వతంత్రంగా ప్రచురించబడిన ఇంటిగ్రేషన్‌లను కేటలాగ్ చేస్తుంది,
నేటివ్ ప్లగిన్‌లు, ప్లగిన్ ఫ్యామిలీలు, థీమ్‌లు, స్కిల్‌లు, క్లయింట్‌లు మరియు బ్రిడ్జ్‌లతో సహా. ఆర్టిఫ్యాక్ట్
రకాలు, సామర్థ్య వర్గాలు మరియు ఇంటర్‌ఫేస్ ట్యాగ్‌లు [docs/CATEGORIES.md](../../docs/CATEGORIES.md)లో
నిర్వచించబడ్డాయి.

ప్రతి పబ్లిక్ రికార్డ్ `catalog/plugins/` కింద ఒక YAML ఫైల్ మరియు తప్పనిసరిగా
`schemas/plugin.schema.yaml`కు వ్యతిరేకంగా ధృవీకరించబడాలి. లిస్టింగ్ అంటే డాక్యుమెంట్ చేయబడిన అర్హత లేదా
ధృవీకరణ తనిఖీలు పూర్తయ్యాయని అర్థం; ఇది సెక్యూరిటీ సర్టిఫికేషన్ లేదా DeepSeek ఆమోదం కాదు.

## 🏅 ర్యాంకింగ్ మరియు ధృవీకరణ

ఖచ్చితంగా ఆ రిపాజిటరీకి చెందిన స్టార్లతో ఉన్న డెడికేటెడ్, నేటివ్, ఎలిజిబుల్ లేదా వెరిఫైడ్ ప్లగిన్
రిపాజిటరీలు మాత్రమే స్టార్ ర్యాంకింగ్‌లో ప్రవేశించగలవు. విస్తృత మోనోరెపోల లోపల నిల్వ చేయబడిన
ఇంటిగ్రేషన్‌లు కనుగొనదగినవిగానే ఉంటాయి కానీ `stars: null` ఉపయోగిస్తాయి మరియు మాతృ-ప్రాజెక్ట్ స్టార్లను
ఎప్పుడూ వారసత్వంగా పొందవు. పూర్తి ప్రిడికేట్ కోసం [docs/RANKING.md](../../docs/RANKING.md) చూడండి.

పబ్లిక్ వెరిఫికేషన్ స్థితులు స్ట్రక్చరల్ ఎలిజిబిలిటీని ఇన్‌స్టాలేషన్ స్మోక్-టెస్ట్ నుండి వేరు చేస్తాయి. ఏ స్థితి
కూడా సంపూర్ణ భద్రతను సూచించదు. ఉపయోగించే ముందు ప్లగిన్ యొక్క రిపాజిటరీ, పిన్ చేయబడిన కమిట్, లైసెన్స్
మరియు ఇన్‌స్టాలేషన్ ప్రవర్తనను సమీక్షించండి.
