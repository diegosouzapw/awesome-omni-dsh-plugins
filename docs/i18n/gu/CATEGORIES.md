# કેટલોગ શ્રેણીઓ

> 🌐 [English](../../CATEGORIES.md) · [Português (Brasil)](../pt-BR/CATEGORIES.md) · [中文（简体）](../zh-CN/CATEGORIES.md) · **ગુજરાતી**

દરેક કેટલોગ એન્ટ્રીમાં એક આર્ટિફેક્ટ પ્રકાર, એક પ્રાથમિક ક્ષમતા શ્રેણી અને શૂન્ય કે વધુ ટૅગ્સ હોય છે.
પ્રાથમિક શ્રેણી નક્કી કરે છે કે એન્ટ્રી ક્યાં દેખાય છે; ટૅગ્સ એન્ટ્રીની ડુપ્લિકેશન વિના
શ્રેણી-વચ્ચેની શોધ પૂરી પાડે છે.

## આર્ટિફેક્ટ પ્રકારો

<!-- catalog-policy:aggregators-never-entries -->

| મૂલ્ય | અર્થ | પ્લગિન તરીકે સ્ટાર-રેન્ક થાય છે? |
|---|---|---:|
| `plugin` | ઇન્સ્ટોલ કરી શકાય તેવું નેટિવ DSH બન્ડલ | ફક્ત જ્યારે દરેક રેન્કિંગ શરત પૂરી થાય |
| `plugin-family` | અનેક DSH પ્લગિન્સ ધરાવતી રિપોઝિટરી | ના; અલગ વિભાગ |
| `skin-theme` | DSH UI સ્કિન કે વિઝ્યુઅલ થીમ | ના; અલગ વિભાગ |
| `skill` | DSH સપોર્ટ ધરાવતી એજન્ટ સ્કિલ | ના |
| `preset-profile` | DSH પ્રોફાઇલ કે પ્રીસેટ | ના |
| `client-interface` | ડેસ્કટોપ, TUI, એડિટર કે રિમોટ ક્લાયન્ટ | ના |
| `bridge-adapter` | બીજા પ્રોડક્ટમાંથી DSH માં ઇન્ટિગ્રેશન | ના |
| `ecosystem-project` | DSH ઇન્ટિગ્રેશન ધરાવતો વ્યાપક પ્રોજેક્ટ | ના |

અમ્બ્રેલા રિપોઝિટરી, એગ્રિગેટર, માર્કેટપ્લેસ, ઇન્સ્ટોલર કેટલોગ કે યાદી ક્યારેય કેટલોગ
એન્ટ્રી નથી, ભલે એગ્રિગેટર પોતે ઇન્સ્ટોલ કરી શકાય તેવું હોય. તેનો ઉપયોગ ફક્ત લીડ તરીકે થઈ શકે છે. દરેક
લીડને સ્વતંત્ર રીતે ઇન્સ્ટોલ કરી શકાય તેવા ચાઇલ્ડ આર્ટિફેક્ટ સુધી અનુસરો અને તે આર્ટિફેક્ટના વાસ્તવિક ક્રિએટર,
મૂળ રિપોઝિટરી, પેકેજ અને સોર્સ સબપાથ સબમિટ કરતા પહેલા ઉકેલો. સાચું ક્રિએટર મોનોરેપો
ચાઇલ્ડ પ્લગિન માટે મૂળ રિપોઝિટરી હોઈ શકે છે, પરંતુ ચાઇલ્ડે તે ચોક્કસ સબપાથ અને
મોનોરેપો સ્ટાર્સ પોલિસીનો ઉપયોગ કરવો જ પડે.

`kind` ફિલ્ડ કેનોનિકલ DSH આર્ટિફેક્ટ ડિસ્ક્રિમિનેટર છે. અલગ ઇન્ટિગ્રેશન
કાઇન્ડ નથી: `plugin` એટલે પહેલેથી જ નેટિવ DSH બન્ડલ, જ્યારે
`ecosystem-project` એટલો પહેલેથી જ DSH ઇન્ટિગ્રેશન ધરાવતો વ્યાપક પ્રોજેક્ટ. આ
વિરોધાભાસી વર્ગીકરણ જોડીઓને અટકાવે છે.

## પ્રાથમિક ક્ષમતા શ્રેણીઓ

| મૂલ્ય | ડિસ્પ્લે લેબલ |
|---|---|
| `user-interface-dashboards` | યુઝર ઇન્ટરફેસ અને ડેશબોર્ડ્સ |
| `memory-rag` | મેમરી અને RAG |
| `search-research` | સર્ચ અને રિસર્ચ |
| `coding-developer-tools` | કોડિંગ અને ડેવલપર ટૂલ્સ |
| `browser-automation` | બ્રાઉઝર અને ઓટોમેશન |
| `vision-audio-multimodal` | વિઝન, ઓડિયો અને મલ્ટિમોડલ |
| `sessions-productivity` | સેશન્સ અને પ્રોડક્ટિવિટી |
| `security-permissions-approvals` | સુરક્ષા, પરમિશન્સ અને એપ્રૂવલ્સ |
| `diagnostics-observability` | ડાયગ્નોસ્ટિક્સ અને ઓબ્ઝર્વેબિલિટી |
| `models-providers-routing` | મોડલ્સ, પ્રોવાઇડર્સ અને રાઉટિંગ |
| `messaging-notifications` | મેસેજિંગ અને નોટિફિકેશન્સ |
| `data-external-services` | ડેટા અને એક્સટર્નલ સર્વિસીઝ |
| `entertainment-customization` | એન્ટરટેઇનમેન્ટ અને કસ્ટમાઇઝેશન |

એવી શ્રેણી પસંદ કરો જે પ્લગિનના પ્રાથમિક કામને શ્રેષ્ઠ રજૂ કરે, દૃશ્યતા વધારવાની
સૌથી વધુ શક્યતા ધરાવતી શ્રેણી નહીં.

## ઇન્ટરફેસ ટૅગ્સ

પ્રમાણભૂત ઇન્ટરફેસ ટૅગ્સમાં `web-ui`, `sidebar`, `settings`, `tui`, `cli`, `desktop`,
`mobile`, `remote`, `editor`, `headless` અને `theme`નો સમાવેશ થાય છે. વધારાના લોઅરકેસ
kebab-case ક્ષમતા ટૅગ્સની મંજૂરી છે જ્યારે તે પિન કરેલા મૂળ સ્ત્રોતમાં દેખાતા પુરાવાનું વર્ણન કરતા હોય.

## રિપોઝિટરી સ્કોપ

`dedicated` ફક્ત ત્યારે જ વાપરો જ્યારે રિપોઝિટરી સ્ટાર્સ ચોક્કસ કેટલોગ કરાયેલા પ્લગિનના હોય.
`monorepo` ત્યારે વાપરો જ્યારે પ્લગિન વ્યાપક પ્રોજેક્ટની અંદર સબપાથ કે પેકેજ હોય. મોનોરેપો એન્ટ્રીએ
`popularity.starsPolicy: undefined-parent-repository` અને `popularity.stars: null` વાપરવું જ પડે.
