આ રિપોઝીટરી કેટલોગ માટે પબ્લિક સોર્સ ઓફ ટ્રુથ છે. દરેક લિસ્ટિંગ `catalog/plugins/` હેઠળની
એક YAML ફાઇલ છે, જે પ્રકાશિત JSON સ્કીમા સામે વેલિડેટ થયેલ છે, એક વ્યક્તિગત રીતે
રિવ્યૂ થયેલ પુલ રિક્વેસ્ટ દ્વારા ઉમેરવામાં આવે છે, અને હંમેશા પ્લગિનના મૂળ ક્રિએટરને ક્રેડિટ આપવામાં આવે છે.
કેટલોગમાં કંઈ પણ બીજા કેટલોગ કે લિસ્ટમાંથી જનરેટ થયેલું નથી: દરેક એન્ટ્રી પિન કરેલા કમિટ પર
મૂળ ક્રિએટર રિપોઝીટરીમાંથી ફરીથી બનાવવામાં આવે છે.

વેબસાઇટ ખાનગી સોર્સમાંથી જાળવવામાં આવે છે. CLI અહીં, [`cli/`](../../cli) હેઠળ છે, અને આ
રિપોઝીટરી પબ્લિક કેટલોગ ડેટા, સ્કીમા અને પોલિસીઓ ધરાવે છે જેનો બંને ઉપયોગ કરે છે.

## કેટલોગ સ્ટેટસ

**1814 પ્લગિન્સ મર્જ થયા.** દરેક પ્લગિન એક વ્યક્તિગત રીતે રિવ્યૂ થયેલ પુલ રિક્વેસ્ટ દ્વારા, એક સમયે એક,
મૂળ ક્રિએટર રિપોઝીટરીમાંથી, પિન કરેલા સોર્સ કમિટ અને સ્પષ્ટ
એટ્રિબ્યુશન સાથે દાખલ થાય છે.

## 🚀 CLI ઇન્સ્ટોલ કરો

```bash
npx omni-dsh-plugins --help
```

પેકેજ `omni-dsh-plugins@1.0.1` તરીકે પ્રકાશિત થાય છે અને ઉપરનો કમાન્ડ આજે
કેનોનિકલ ઇન્વોકેશન છે; અહીં કોઈ ઇન્સ્ટોલર સ્ક્રિપ્ટ હોસ્ટ કરવામાં આવી નથી.

### આજે CLI નો ઉપયોગ કરો

વર્ઝન 1.0.1 રીડ-ઓન્લી ડિસ્કવરી અને વેલિડેશન કમાન્ડ્સ ઉપરાંત કન્સેન્ટ-ગેટેડ ઇન્સ્ટોલ
કમાન્ડ્સ પ્રદાન કરે છે. ફ્લેગ્સ, એક્ઝિટ કોડ્સ અને કોડ-એક્ઝિક્યુશન
કન્સેન્ટ ગેટ સહિતનો સંપૂર્ણ કમાન્ડ સંદર્ભ [docs/CLI.md](../../docs/CLI.md) માં છે.

| કમાન્ડ                        | તે શું કરે છે                                                        | શું તે તમારી સિસ્ટમને સ્પર્શે છે?                    |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | કેટલોગ YAML, સ્કીમા અને લોકલ સિમેન્ટિક્સ વેલિડેટ કરો                   | ના — રીડ-ઓન્લી                          |
| `search <query...>`            | પબ્લિક કેટલોગ ફિલ્ડ્સ લોકલી સર્ચ કરો                                | ના — રીડ-ઓન્લી                          |
| `info <id>`                    | એક પબ્લિક કેટલોગ એન્ટ્રી બતાવો                                       | ના — રીડ-ઓન્લી                          |
| `list`                         | પ્રોફાઇલ્સમાં ફેરફાર કર્યા વિના કેટલોગ-મેનેજ્ડ ઇન્સ્ટોલ્સ લિસ્ટ કરો            | ના — રીડ-ઓન્લી                          |
| `doctor`                       | રીડ-ઓન્લી Node, DSH, નેટિવ Windows પોલિસી અને કેટલોગ ડાયગ્નોસ્ટિક્સ  | ના — રીડ-ઓન્લી                          |
| `add <id> --profile <name> --dry-run` | ફાઇલો કે સબપ્રોસેસ વિના વેરિફાઇડ ઇન્સ્ટોલ પ્લાન બતાવો | ના — ડ્રાય-રન                            |
| `add <id> --profile <name> --allow-code-execution` | ઓફિશિયલ DSH ડેલિગેશન દ્વારા ઇન્સ્ટોલ કરો        | હા — ફક્ત સ્પષ્ટ કન્સેન્ટ ફ્લેગ સાથે   |

```bash
# Validate the catalog in this repository (what CI runs):
npx omni-dsh-plugins catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx omni-dsh-plugins add <plugin-id> --profile default --dry-run
```

મ્યુટેટિંગ કમાન્ડ્સ (`add`, `update`, `remove`) ક્યારેય પ્લગિન લાઇફસાયકલ કોડ એક્ઝિક્યુટ કરતા નથી જ્યાં સુધી તમે
`--allow-code-execution` પાસ ન કરો. નેટિવ Windows પર આ મ્યુટેશન્સ v1.0.1 માં ડિસેબલ છે; વાપરો
WSL. રીડ-ઓન્લી અને ડ્રાય-રન કમાન્ડ્સ દરેક જગ્યાએ કામ કરે છે.

## 🔍 એક પ્લગિન કેટલોગમાં કેવી રીતે દાખલ થાય છે

![એક પ્લગિન કેટલોગમાં કેવી રીતે દાખલ થાય છે](../../docs/diagrams/catalog-flow-dark.svg#gh-dark-mode-only)
![એક પ્લગિન કેટલોગમાં કેવી રીતે દાખલ થાય છે](../../docs/diagrams/catalog-flow-light.svg#gh-light-mode-only)

1. **એક પ્લગિન, એક બ્રાન્ચ, એક પુલ રિક્વેસ્ટ.** PR `catalog/plugins/` હેઠળ બરાબર એક YAML ફાઇલ
   ઉમેરે છે અથવા બદલે છે.
2. **ક્રિએટર-ફર્સ્ટ.** પ્લગિનના ક્રિએટર અથવા માલિકી ધરાવતી સંસ્થા દ્વારા ખોલવામાં આવેલ PR હંમેશા
   એ જ પ્લગિન માટે સામુદાયિક ક્યુરેશન અથવા ઓટોમેશન કરતાં અગ્રતા ધરાવે છે — જુઓ
   [docs/CREDIT.md](../../docs/CREDIT.md).
3. **મૂળ સ્ત્રોતમાંથી પુરાવો.** દરેક ફિલ્ડ ક્રિએટરની રિપોઝીટરીમાંથી પિન કરેલા 40-અક્ષરના
   કમિટ પર ફરીથી બનાવવામાં આવે છે: વર્ણન, લાઇસન્સ, DSH ઇન્ટિગ્રેશન, ઇન્સ્ટોલ
   ડિસ્ક્રિપ્ટર, સ્ટાર્સ.
4. **લોકલ વેલિડેશન.** `catalog validate` સ્ટ્રક્ચર અને લોકલ સિમેન્ટિક્સ ચકાસે છે; આ એ જ
   ચકાસણી છે જે `catalog-validation` CI જોબ PR પર ચલાવે છે.
5. **મેન્ટેનર ગેટ્સ.** મર્જ પહેલાં, મેન્ટેનર્સ અલગથી રિપોઝીટરી ઓળખ,
   ક્રિએટર બાઇન્ડિંગ અને પિન કરેલા પુરાવાની ચકાસણી કરે છે. ગ્રીન લોકલ વેલિડેશન જરૂરી છે, પણ ક્યારેય પૂરતું નથી.

સંપૂર્ણ કરાર — જરૂરી પુરાવો, YAML નિયમો, સ્ટાર્સ પોલિસી, કોલિઝન હેન્ડલિંગ અને
રિવ્યૂ ગેટ્સ — [CONTRIBUTING.md](../../CONTRIBUTING.md) માં છે. નિર્ણયો કેવી રીતે અને કોના દ્વારા લેવાય છે તે
[docs/GOVERNANCE.md](../../docs/GOVERNANCE.md) માં છે.

## 📄 એન્ટ્રીની રચના

દરેક એન્ટ્રી તેના ID પરથી નામ આપેલી એક YAML ફાઇલ છે. નીચેનું ઉદાહરણ વર્તમાન
સ્કીમા સામે વેલિડેટ થાય છે (ફિલ્ડ-બાય-ફિલ્ડ સંદર્ભ [docs/SCHEMA.md](../../docs/SCHEMA.md) માં):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

સ્કીમા દ્વારા લાગુ કરાયેલા મુખ્ય ઇન્વેરિયન્ટ્સ:

- `unofficial: true` અને `schemaVersion: 1` સ્થિર (constant) છે.
- મોનોરેપો પ્લગિને `stars: null` વાપરવું જ પડે — પેરેન્ટ-પ્રોજેક્ટના સ્ટાર્સ ક્યારેય ઇનહેરિટ થતા નથી.
- ઇન્સ્ટોલ ડિસ્ક્રિપ્ટર કાં તો ચોક્કસ-વર્ઝન npm પેકેજ છે અથવા પિન કરેલો સોર્સ પોતે;
  તે ડેટા છે, ક્યારેય શેલ કમાન્ડ નથી.
- `verified` સ્ટેટસ માટે રિવ્યુ કરી શકાય તેવો સ્મોક-ટેસ્ટ પુરાવો જરૂરી છે; અન્યથા એન્ટ્રી `eligible`
  છે અને `smokeTest: null` સાથે.

## 🗂 અહીં શું સામેલ છે

આ રિપોઝીટરી DeepSeek Harness (DSH) માટે સ્વતંત્ર રીતે પ્રકાશિત થયેલા ઇન્ટિગ્રેશન્સનું કેટલોગ બનાવે છે,
જેમાં નેટિવ પ્લગિન્સ, પ્લગિન ફેમિલીઝ, થીમ્સ, સ્કિલ્સ, ક્લાયન્ટ્સ અને બ્રિજનો સમાવેશ થાય છે. આર્ટિફેક્ટ પ્રકારો,
ક્ષમતા શ્રેણીઓ અને ઇન્ટરફેસ ટૅગ્સ [docs/CATEGORIES.md](../../docs/CATEGORIES.md) માં વ્યાખ્યાયિત છે.

દરેક પબ્લિક રેકોર્ડ `catalog/plugins/` હેઠળની એક YAML ફાઇલ છે અને તેણે
`schemas/plugin.schema.yaml` સામે વેલિડેટ થવું જ પડે. લિસ્ટિંગનો અર્થ એ છે કે દસ્તાવેજીકૃત પાત્રતા અથવા વેરિફિકેશન ચકાસણી
પૂર્ણ થઈ ગઈ છે; તે સિક્યુરિટી સર્ટિફિકેશન કે DeepSeek સમર્થન નથી.

## 🏅 રેન્કિંગ અને વેરિફિકેશન

ફક્ત ડેડિકેટેડ, નેટિવ, પાત્ર અથવા વેરિફાઇડ પ્લગિન રિપોઝીટરીઓ કે જેમના સ્ટાર્સ તે
ચોક્કસ રિપોઝીટરીના જ છે તે સ્ટાર રેન્કિંગમાં દાખલ થઈ શકે છે. મોટા મોનોરેપોમાં સંગ્રહિત ઇન્ટિગ્રેશન્સ
શોધી શકાય તેવા રહે છે પણ `stars: null` વાપરે છે અને પેરેન્ટ-પ્રોજેક્ટના સ્ટાર્સ ક્યારેય ઇનહેરિટ કરતા નથી. સંપૂર્ણ
પ્રિડિકેટ માટે [docs/RANKING.md](../../docs/RANKING.md) જુઓ.

પબ્લિક વેરિફિકેશન સ્ટેટ્સ સ્ટ્રક્ચરલ પાત્રતાને ઇન્સ્ટોલેશન સ્મોક-ટેસ્ટથી અલગ પાડે છે.
કોઈ પણ સ્ટેટ સંપૂર્ણ સલામતી દર્શાવતું નથી. ઉપયોગ કરતા પહેલા પ્લગિનની રિપોઝીટરી, પિન કરેલ કમિટ, લાઇસન્સ અને
ઇન્સ્ટોલેશન વર્તનની સમીક્ષા કરો.

## 🤝 એન્ટ્રીમાં યોગદાન આપો અથવા દાવો કરો

પુલ રિક્વેસ્ટ ખોલતા પહેલા [CONTRIBUTING.md](../../CONTRIBUTING.md) વાંચો. પુલ રિક્વેસ્ટે બરાબર એક

ક્રેડેન્શિયલ્સ, ખાનગી સંપર્ક વિગતો કે અન્ય ગુપ્ત માહિતી સબમિટ ન કરો.
