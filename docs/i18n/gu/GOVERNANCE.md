# કેટલોગ ગવર્નન્સ

> **બિનસત્તાવાર સામુદાયિક પ્રોજેક્ટ. DeepSeek સાથે સંલગ્ન નથી, તેના દ્વારા સમર્થિત નથી કે પ્રાયોજિત નથી.**
> DeepSeek નામો અને ચિહ્નો તેમના સંબંધિત માલિકના છે.

પબ્લિક કેટલોગનું સંચાલન કેવી રીતે થાય છે: શું દાખલ થાય છે તે કોણ નક્કી કરે છે, સ્પર્ધાત્મક
યોગદાનો કયા ક્રમમાં સ્વીકારવામાં આવે છે, કઈ ચકાસણીઓ આપોઆપ ચાલે છે, અને કયા નિર્ણયો માનવીય રહે છે.
અહીં સંદર્ભિત પોલિસીઓ [CONTRIBUTING.md](../../CONTRIBUTING.md),
[docs/CREDIT.md](../../docs/CREDIT.md) અને [docs/RANKING.md](../../docs/RANKING.md) માં છે; આ પેજ વર્ણવે છે કે તેઓ કેવી રીતે
એકબીજા સાથે જોડાય છે.

## સિદ્ધાંતો

1. **ક્રિએટર-ફર્સ્ટ.** કેટલોગ ક્રિએટર્સના કામને શોધી શકાય તેવું બનાવવા અસ્તિત્વમાં છે, તેની માલિકી
   લેવા માટે ક્યારેય નહીં. એ જ કેનોનિકલ પ્લગિન માટે, ક્રિએટરનો સીધો પુલ રિક્વેસ્ટ કોઈપણ
   ખુલ્લા સામુદાયિક ક્યુરેશન કે ઓટોમેશન પુલ રિક્વેસ્ટને બદલી નાખે છે — સંપૂર્ણ અગ્રતા ક્રમ અને Git ઓળખ
   નિયમો [docs/CREDIT.md](../../docs/CREDIT.md) માં.
2. **એક પ્લગિન, એક રિવ્યૂ થયેલ પુલ રિક્વેસ્ટ.** બેચ મર્જ નહીં, પબ્લિક કેટલોગમાં જનરેટેડ બલ્ક
   ઇમ્પોર્ટ નહીં. દરેક એન્ટ્રી પોતાનું રિવ્યૂ મેળવે છે.
3. **વિશ્વાસ કરતાં પુરાવો.** દરેક પબ્લિક ફિલ્ડ પિન કરેલા કમિટ પર મૂળ ક્રિએટર રિપોઝિટરી સુધી
   ટ્રેસ થાય છે. ગ્રીન ઓટોમેટેડ ચેક ક્યારેય ઓરિજિનના પુરાવા તરીકે સ્વીકારવામાં આવતું નથી.
4. **બિનસત્તાવાર, હંમેશા.** કોઈપણ કેટલોગ સ્ટેટને DeepSeek રિવ્યૂ, સર્ટિફિકેશન કે
   સમર્થન તરીકે રજૂ કરવામાં આવતું નથી.

## ફેરફારો `main` પર કેવી રીતે લેન્ડ થાય છે

બધા ફેરફારો `main` પર રિવ્યૂ થયેલા પુલ રિક્વેસ્ટ્સ દ્વારા પહોંચે છે — ડાયરેક્ટ પુશ નથી. ડિફોલ્ટ
બ્રાન્ચ માટેની કાર્યરત પોલિસી:

- **ફક્ત પુલ રિક્વેસ્ટ્સ.** કેટલોગ એન્ટ્રીઝ, દસ્તાવેજીકરણ અને સ્કીમા ફેરફારો બધું PR દ્વારા
  દાખલ થાય છે; કેટલોગ PR એ [CONTRIBUTING.md](../../CONTRIBUTING.md) માંના
  એક-બ્રાન્ચ-એ-પ્લગિન નિયમનું પાલન કરવું જોઈએ.
- **લિનિયર ઇતિહાસ.** PR એવી રીતે ઇન્ટિગ્રેટ થાય છે કે `main` લિનિયર, ઓડિટ કરી શકાય તેવો
  ઇતિહાસ જાળવે; મર્જ થયેલો પબ્લિક ઇતિહાસ ફરીથી લખવામાં આવતો નથી. જો ક્રિએટર સામે આવે તે પહેલાં
  ક્યુરેટેડ એન્ટ્રી મર્જ થઈ ગઈ હોય, તો ક્રિએટર ઇતિહાસ ફરીથી લખવાને બદલે ફોલો-અપ યોગદાનમાં તેનો દાવો કે સુધારો કરે છે.
- **રિવ્યૂ-થ્રેડ રિઝોલ્યુશન.** મર્જ પહેલાં રિવ્યૂ વાર્તાલાપો ઉકેલવામાં આવે છે; ઉકેલ્યા વગરનો
  ફીડબેક ઇન્ટિગ્રેશનને અટકાવે છે.
- **મેન્ટેનર મર્જ.** પ્લગિન એન્ટ્રી ફક્ત મેન્ટેનર જ મર્જ કરે છે, અને ફક્ત
  [CONTRIBUTING.md](../../CONTRIBUTING.md) → "રિવ્યૂ ગેટ્સ, કોલિઝન અને મર્જ" ના દરેક ગેટ વર્તમાન
  PR કમિટ પર પાસ થયા પછી જ.

## `catalog-validation` ચેક

`catalog/plugins/`, `schemas/` કે વર્કફ્લો પોતે બદલતો દરેક પુલ રિક્વેસ્ટ
`catalog-validation` જોબ ચલાવે છે (`.github/workflows/validate-catalog.yml`), પ્રકાશિત
CLI પર પિન કરેલ:

```bash
npx --yes omni-dsh-plugins catalog validate --catalog .
```

**તે શું વેલિડેટ કરે છે** — ફક્ત લોકલ સ્ટ્રક્ચર અને સિમેન્ટિક્સ:

- `catalog/plugins/` હેઠળની દરેક એન્ટ્રીનું સેફ YAML પાર્સિંગ.
- પબ્લિક સ્કીમા સાથે અનુરૂપતા ([docs/SCHEMA.md](../../docs/SCHEMA.md) જુઓ).
- SPDX એક્સપ્રેશન પાર્સિંગ, ચોક્કસ SemVer વર્ઝન, માન્ય SHA-512 SRI ઇન્ટિગ્રિટી મૂલ્યો.
- ડુપ્લિકેટ નકાર: કોઈ પુનરાવર્તિત એન્ટ્રી ID નહીં અને કોઈ પુનરાવર્તિત કેનોનિકલ
  રિપોઝિટરી-નોડ-પ્લસ-સબપાથ કી નહીં.
- ઇરાદાપૂર્વક ખાલી કેટલોગ પાસ થાય છે (`0 entries valid; catalog is empty`).

**તે શું વેલિડેટ કરતું નથી** — અને તેથી ગ્રીન ચેક શું ક્યારેય સાબિત કરતું નથી:

- રિમોટ રિપોઝિટરી ઓળખ: તે GitHub સાથે સંપર્ક કરતું નથી કે રિપોઝિટરી નોડ ID ને
  URL સામે ઉકેલતું નથી.
- પિન કરેલા કમિટ પર પુરાવો: વર્ણનો, લાઇસન્સ, DSH ઇન્ટિગ્રેશન અને સ્મોક પુરાવો
  ફેચ કે ઇન્સ્પેક્ટ થતા નથી.
- ક્રિએટર માલિકી, સ્ટાર ગણતરીઓ, કે ખુલ્લા પુલ રિક્વેસ્ટ્સ સાથે કોલિઝન.

તે નિર્ણયો મેન્ટેનર્સના અલગ પ્રોવેનન્સ ગેટ્સની જવાબદારી છે, જે મર્જ પહેલાં લાગુ થાય છે અને
[CONTRIBUTING.md](../../CONTRIBUTING.md) માં વર્ણવેલા છે. લોકલ ચેક ન્યૂનતમ મર્યાદા છે, ધોરણ નહીં.

## વેરિફિકેશન સ્ટેટ્સ

વેરિફિકેશન દરેક એન્ટ્રી માટે તેના ચોક્કસ પિન કરેલા કમિટ સામે રેકોર્ડ થાય છે, પબ્લિક સ્કીમામાં
વ્યાખ્યાયિત સ્ટેટ્સનો ઉપયોગ કરીને (`eligible`, `verified`, `stale`, `unavailable`, `archived`, `quarantined`).
બે સકારાત્મક સ્ટેટ્સ જાણીજોઈને સાંકડા છે:

- `eligible` — પબ્લિક સ્ટ્રક્ચર અને નેટિવ DSH ઇન્ટિગ્રેશન વેલિડેટ થયા.
- `verified` — વધારામાં, પિન કરેલા સોર્સ કે પેકેજ માટે ઇન્સ્ટોલેશન સ્મોક ટેસ્ટ પાસ થયો;
  સ્કીમા સ્મોક-ટેસ્ટ રેકોર્ડ હાજર હોવો જરૂરી બનાવે છે.

કોઈ પણ સ્ટેટ — કે બીજી કોઈ — સમર્થન, ગેરંટી કે સુરક્ષા પ્રમાણપત્ર નથી.
રેન્કિંગ સાથે સ્ટેટ્સ કેવી રીતે ક્રિયાપ્રતિક્રિયા કરે છે તે સહિતની સંપૂર્ણ સિમેન્ટિક્સ
[docs/RANKING.md](../../docs/RANKING.md) માં છે; રેકોર્ડ શેપ [docs/SCHEMA.md](../../docs/SCHEMA.md) માં છે.

## ક્લેમ, કરેક્શન અને રિમૂવલ

સ્ટ્રક્ચર્ડ GitHub ઇશ્યુ ફોર્મ્સ (`.github/ISSUE_TEMPLATE/`) તમે સબમિટ ન કરી હોય તેવી
એન્ટ્રી બદલવા માટેનો ગવર્ન્ડ માર્ગ છે:

| ફોર્મ          | કોણ ઉપયોગ કરે છે                       | પરિણામ                                              |
| -------------- | ---------------------------------------- | --------------------------------------------------- |
| **ક્લેમ**      | ક્રિએટર જેમનું પ્લગિન કોઈ બીજાએ ક્યુરેટ કર્યું હોય | માલિકી મૂળ સ્ત્રોત સાથે બંધાય છે; ક્રિએટર પછી સીધું યોગદાન આપી શકે છે |
| **કરેક્શન**    | કોઈપણ જેમને અચોક્કસ પબ્લિક મેટાડેટા દેખાય | અસરગ્રસ્ત એન્ટ્રીનું રિવ્યૂ થયેલ સુધારો              |
| **રિમૂવલ**     | ક્રિએટર જેમને તેમનું લિસ્ટિંગ દૂર કરવું હોય, અથવા પોલિસી ઉલ્લંઘનની જાણ કરનાર | એન્ટ્રીનું રિવ્યૂ થયેલ રિમૂવલ કે ક્વોરન્ટાઇન |

ત્રણેય ફ્લો પર લાગુ પડતા નિયમો:

- માલિકીના દાવા ચકાસી શકાય તેવા પબ્લિક પુરાવા દ્વારા સમર્થિત હોવા જોઈએ (રિપોઝિટરી માલિકી,
  પેકેજ ઓથરશિપ, મેનિફેસ્ટ મેટાડેટા કે પિન કરેલ સોર્સ ઇતિહાસ) — Discussion પર કોમેન્ટ કરવું
  ક્રિએટરશિપ સ્થાપિત કરતું નથી ([docs/CREDIT.md](../../docs/CREDIT.md)).
- લિસ્ટ થયેલ પ્લગિનની સુરક્ષા સમસ્યાઓ પહેલા તે પ્લગિનના પોતાના મેન્ટેનર પાસે જાય છે; કેટલોગ
  બાજુ પછી એક્સપ્લોઇટ વિગત પ્રકાશિત કર્યા વિના સુધારો કે ક્વોરન્ટાઇન સંભાળે છે
  ([SECURITY.md](../../SECURITY.md)).
- ફોર્મમાં ક્યારેય ક્રેડેન્શિયલ્સ, ખાનગી સંપર્ક વિગતો કે અન્ય ગુપ્ત માહિતી સામેલ ન કરો.

## ભૂમિકાઓ

- **ક્રિએટર્સ** તેમના પ્લગિન્સ અને તેમના લિસ્ટિંગ્સની અગ્રતાના માલિક છે. તેઓ સીધું યોગદાન આપી શકે છે,
  સામુદાયિક ક્યુરેશન મંજૂર કરી શકે છે, અથવા હાલની એન્ટ્રીનો દાવો/સુધારો/રિમૂવલ કરી શકે છે.
- **સામુદાયિક યોગદાનકર્તાઓ** એવા ક્રિએટર્સ માટે એન્ટ્રીઝ ક્યુરેટ કરી શકે છે જેમણે હજુ યોગદાન આપ્યું નથી,
  [docs/CREDIT.md](../../docs/CREDIT.md) માંના આદરપૂર્ણ-સંપર્ક અને ક્રેડિટ નિયમો હેઠળ. ક્યુરેશન ક્યારેય
  પછીના સીધા ક્રિએટર યોગદાન કરતાં ઉપર આવતું નથી.
- **મેન્ટેનર્સ** રિવ્યૂ કરે છે, પ્રોવેનન્સ ગેટ્સ લાગુ કરે છે, કોલિઝન ઉકેલે છે અને મર્જ કરે છે. તેઓ
  વેબસાઇટ ([dsh-plugins.omniroute.online](https://dsh-plugins.omniroute.online))
  અને પ્રકાશિત CLI ખાનગી સોર્સમાંથી પણ જાળવે છે; આ રિપોઝિટરીનો પબ્લિક ડેટા, સ્કીમા અને પોલિસીઓ
  જ તે સરફેસ વાપરે છે.
