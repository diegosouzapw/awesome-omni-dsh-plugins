# કેટલોગ એન્ટ્રી સ્કીમા સંદર્ભ

> 🌐 [English](../../SCHEMA.md) · [Português (Brasil)](../pt-BR/SCHEMA.md) · [中文（简体）](../zh-CN/SCHEMA.md) · **ગુજરાતી**

> **બિનસત્તાવાર સામુદાયિક પ્રોજેક્ટ. DeepSeek સાથે સંલગ્ન નથી, તેના દ્વારા સમર્થિત નથી કે પ્રાયોજિત નથી.**
> DeepSeek નામો અને ચિહ્નો તેમના સંબંધિત માલિકના છે.

આ [`schemas/plugin.schema.yaml`](../../schemas/plugin.schema.yaml) માટે ફિલ્ડ-બાય-ફિલ્ડ સંદર્ભ છે,
જે પબ્લિક JSON સ્કીમા (draft 2020-12) છે અને `catalog/plugins/` હેઠળની દરેક ફાઇલે તેને સંતોષવું જ પડે છે.
સ્કીમા ફાઇલ પોતે જ સત્યનો સ્રોત છે; જ્યારે આ પેજ અને સ્કીમા વચ્ચે મતભેદ હોય, ત્યારે
સ્કીમા લાગુ પડે છે.

વેલિડેશનના બે સ્તરો લાગુ પડે છે. પબ્લિક સ્કીમા બાઉન્ડેડ *સેફ શેપ્સ* લાગુ કરે છે (એવા પેટર્ન અને
લંબાઈ જે ઓપ્શન જેવા કે અમર્યાદિત મૂલ્યોને નકારે છે). તેની ઉપર, `catalog validate` ફરજિયાત
સિમેન્ટિક પાર્સર્સ લાગુ કરે છે: વર્ઝન માટે ચોક્કસ SemVer, ઇન્ટિગ્રિટી મૂલ્યો માટે SHA-512 SRI,
લાઇસન્સ માટે SPDX એક્સપ્રેશન પાર્સિંગ, અને ડુપ્લિકેટ-કી નકાર. કોઈ મૂલ્ય સ્કીમા પેટર્ન સાથે
મેચ થાય અને છતાં સિમેન્ટિક રીતે નકારવામાં આવે તે શક્ય છે.

ટોચ-સ્તરના નિયમો: પ્રવેશ એક જ YAML ઑબ્જેક્ટ છે, `additionalProperties: false`
(અજાણ્યાં ફીલ્ડ નકારવામાં આવે છે), અને નીચેનાં બધાં ફીલ્ડ ફરજિયાત છે — માત્ર `media` સિવાય,
જે એકમાત્ર વૈકલ્પિક ફીલ્ડ છે.

## ટોપ-લેવલ ફિલ્ડ્સ

| ફિલ્ડ           | પ્રકાર | જરૂરી | સારાંશ                                                          |
| ----------------- | ------- | :------: | ------------------------------------------------------------- |
| `schemaVersion`   | const   |   હા    | બરાબર `1` જ હોવું જોઈએ                                        |
| `id`              | string  |   હા    | લોઅરકેસ kebab-case એન્ટ્રી ID; ફાઇલનામ સાથે મેચ થવું જોઈએ      |
| `name`            | string  |   હા    | ડિસ્પ્લે નેમ, 1–120 અક્ષરો                                     |
| `description`     | object  |   હા    | ક્યુરેટ કરેલ અંગ્રેજી સારાંશ અને તેનો પુરાવો પાથ                 |
| `unofficial`      | const   |   હા    | બરાબર `true` જ હોવું જોઈએ                                     |
| `kind`            | enum    |   હા    | કેનોનિકલ આર્ટિફેક્ટ ડિસ્ક્રિમિનેટર                              |
| `primaryCategory` | enum    |   હા    | એક જ પ્રાથમિક ક્ષમતા શ્રેણી                                     |
| `tags`            | array   |   હા    | અનન્ય લોઅરકેસ kebab-case ટૅગ્સ (ખાલી હોઈ શકે)                |
| `source`          | object  |   હા    | મૂળ રિપોઝિટરી, નોડ ID, સબપાથ અને પિન કરેલ કમિટ                |
| `creator`         | object  |   હા    | ક્રિએટરનું જાહેર GitHub હેન્ડલ                                  |
| `package`         | object  |   હા    | કેનોનિકલ ઇન્સ્ટોલ ડિસ્ક્રિપ્ટર (npm **અથવા** સોર્સ)              |
| `dsh`             | object  |   હા    | DSH પ્રોફાઇલ્સ અને નેટિવ-ઇન્ટિગ્રેશન પુરાવો પાથ                  |
| `repositoryScope` | enum    |   હા    | `dedicated` અથવા `monorepo`                                    |
| `popularity`      | object  |   હા    | સ્ટાર્સ પોલિસી અને સ્ટાર ગણતરી (સ્કોપ પર શરતી)                  |
| `license`         | object  |   હા    | અપસ્ટ્રીમ SPDX લાઇસન્સ એક્સપ્રેશન                               |
| `verification`    | object  |   હા    | વેરિફિકેશન સ્ટેટસ, ચેક સમય, ઓળખ અને સ્મોક ટેસ્ટ               |
| `provenance`      | object  |   હા    | જાહેર Discussion/comment URLs અથવા `null`                       |
| `media`           | array   |    ના    | વધુમાં વધુ 6 સ્ક્રીનશોટ/વિડિયો, દરેક URL `source.commit` પર પિન |

### `schemaVersion`

સ્થિર `1`. પબ્લિક સ્કીમા વર્ઝન 1 ઓળખાવે છે; બીજું કોઈપણ મૂલ્ય અમાન્ય છે.

### `id`

`^[a-z0-9]+(?:-[a-z0-9]+)*$` સાથે મેચ થતી સ્ટ્રિંગ — લોઅરકેસ kebab-case, શરૂઆત/અંતે કે
બમણા હાઇફન્સ નહીં. [CONTRIBUTING.md](../../CONTRIBUTING.md) મુજબ, એન્ટ્રી ફાઇલનું નામ
`catalog/plugins/<id>.yaml` સમાન મૂલ્ય સાથે હોવું જોઈએ; વેલિડેટર મેલ ન ખાય તો નકારે છે
(`id-filename-mismatch`). ID ક્રિએટરના નેમસ્પેસથી પણ શરૂ થવું જોઈએ:
`creator.github` હેન્ડલ લોઅરકેસમાં, `[a-z0-9]` બહારના અક્ષરોની દરેક હાર એક જ
`-` માં સંકોચાયેલી, અને પછી `-` (`id-creator-prefix`).

### `name`

ફ્રી-ફોર્મ ડિસ્પ્લે નેમ, `minLength: 1`, `maxLength: 120`.

### `description`

બરાબર બે જરૂરી પ્રોપર્ટીઝ ધરાવતું ઓબ્જેક્ટ (બીજી કોઈ મંજૂર નથી):

| પ્રોપર્ટી     | પ્રકાર  | નિયમો                                                                 |
| -------------- | ------ | --------------------------------------------------------------------- |
| `en`           | string | અંગ્રેજી સારાંશ, 20–320 અક્ષરો                                          |
| `evidencePath` | string | રિપોઝિટરી-રિલેટિવ પાથ પેટર્ન; શરૂઆતમાં `/` નહીં, બેકસ્લેશ નહીં, `.`/`..` સેગમેન્ટ નહીં |

અંગ્રેજી સારાંશ `evidencePath` પર જેવો અસ્તિત્વમાં છે તેવા `source.commit` પરની ફાઇલમાંથી
ક્યુરેટ થયેલો હોવો જોઈએ — બીજા કેટલોગમાંથી કોપી કરેલો નહીં.

### `unofficial`

સ્થિર `true`. લિસ્ટિંગ બિનસત્તાવાર છે તેવું મશીન-વાંચી શકાય તેવું માર્કર.

### `kind`

**એકમાત્ર** આર્ટિફેક્ટ-પ્રકાર ડિસ્ક્રિમિનેટર (બીજું કોઈ ઇન્ટિગ્રેશન-કાઇન્ડ ફિલ્ડ અસ્તિત્વમાં નથી). તેમાંનું એક:

`plugin` · `plugin-family` · `skin-theme` · `skill` · `preset-profile` · `client-interface` ·
`bridge-adapter` · `ecosystem-project`

અર્થ અને રેન્કિંગ પરિણામો [docs/CATEGORIES.md](../../docs/CATEGORIES.md) માં વ્યાખ્યાયિત છે.

### `primaryCategory`

ચૌદ ક્ષમતા શ્રેણીઓમાંનું એક:

`user-interface-dashboards` · `memory-rag` · `search-research` · `coding-developer-tools` ·
`browser-automation` · `vision-audio-multimodal` · `sessions-productivity` ·
`security-permissions-approvals` · `diagnostics-observability` · `models-providers-routing` ·
`messaging-notifications` · `data-external-services` · `entertainment-customization` · `finance-trading`

ડિસ્પ્લે લેબલ્સ અને પસંદગી માર્ગદર્શન [docs/CATEGORIES.md](../../docs/CATEGORIES.md) માં છે.

### `tags`

અનન્ય સ્ટ્રિંગ્સનો એરે, દરેક `^[a-z0-9]+(?:-[a-z0-9]+)*$` સાથે મેચ થતી (લોઅરકેસ kebab-case).
સ્કીમા કોઈ લઘુત્તમ ગણતરી લાદતું નથી.

### `source`

બરાબર ચાર જરૂરી પ્રોપર્ટીઝ ધરાવતું ઓબ્જેક્ટ:

| પ્રોપર્ટી         | પ્રકાર          | નિયમો                                                                  |
| ------------------ | -------------- | ---------------------------------------------------------------------- |
| `repository`       | string         | `https://github.com/<owner>/<repo>` URL; owner GitHub યુઝરનેમ નિયમોને અનુસરે છે, રિપોઝિટરી નામ 1–100 અક્ષરો, `.`/`..` ન હોઈ શકે કે `.git` પર પૂરું થતું નથી |
| `repositoryNodeId` | string         | અપરિવર્તનીય GitHub રિપોઝિટરી નોડ ID, ખાલી નહીં                       |
| `subpath`          | string અથવા null | રિપોઝિટરીની અંદર પ્લગિન સબપાથ (`evidencePath` જેવો જ સેફ રિલેટિવ-પાથ પેટર્ન), અથવા રિપોઝિટરી-રૂટ પ્લગિન માટે `null` |
| `commit`           | string         | પૂરું 40-અક્ષરનું હેક્ઝાડેસિમલ કમિટ OID                                |

કેટલોગ વેલિડેશને `repositoryNodeId` ઉકેલવું જ પડે અને રિપોઝિટરી URL મેલ ન ખાય તો નકારવું જ પડે — તે
ઉકેલ મેન્ટેનર-બાજુનો ગેટ છે, લોકલ સ્ટ્રક્ચરલ ચેકનો ભાગ નથી.

### `creator`

એક જ જરૂરી પ્રોપર્ટી ધરાવતું ઓબ્જેક્ટ:

| પ્રોપર્ટી | પ્રકાર  | નિયમો                                           |
| -------- | ------ | ------------------------------------------------- |
| `github` | string | GitHub યુઝરનેમ (1–39 અક્ષરો, GitHub હેન્ડલ નિયમો) |

જાહેર પ્રોફાઇલ URL હંમેશા `https://github.com/<handle>` તરીકે ડિરાઇવ થાય છે; બીજું કોઈ પ્રોફાઇલ
ફિલ્ડ સંગ્રહાતું નથી, તેથી બંને ક્યારેય અલગ પડી શકે નહીં.

### `package`

કેનોનિકલ ઇન્સ્ટોલ ડિસ્ક્રિપ્ટર. તે ડેટા છે, ક્યારેય શેલ કમાન્ડ નથી, અને બે શેપમાંથી બરાબર એક લે છે
(`oneOf`):

**npm પેકેજ** — જરૂરી `ecosystem`, `name`, `version`; વૈકલ્પિક `integrity`:

| પ્રોપર્ટી  | પ્રકાર | નિયમો                                                                      |
| ----------- | ----- | -------------------------------------------------------------------------- |
| `ecosystem` | const | `npm`                                                                      |
| `name`      | string | npm પેકેજ નેમ શેપ (વૈકલ્પિક રીતે સ્કોપ્ડ), મહત્તમ 214 અક્ષરો                 |
| `version`   | string | ચોક્કસ `x.y.z` વર્ઝન શેપ (વૈકલ્પિક પ્રિરિલીઝ/બિલ્ડ); રેન્જ નકારવામાં આવે છે. સિમેન્ટિક સ્તર વધારામાં પાર્સ કરી શકાય તેવું, ચોક્કસ SemVer જરૂરી બનાવે છે |
| `integrity` | string | વૈકલ્પિક `sha512-…` SRI શેપ, 8–256 અક્ષરો. સિમેન્ટિક સ્તરે તેને માન્ય SHA-512 SRI તરીકે પાર્સ કરવું જ પડે |

**સોર્સ ઇન્સ્ટોલ** — ફક્ત જરૂરી `ecosystem`:

| પ્રોપર્ટી  | પ્રકાર | નિયમો    |
| ----------- | ----- | -------- |
| `ecosystem` | const | `source` |

સોર્સ ડિસ્ક્રિપ્ટર જાણીજોઈને બીજું કંઈ સંગ્રહતું નથી: રિપોઝિટરી, કમિટ અને સબપાથ
`source` પરથી ડિરાઇવ થાય છે, તેથી મ્યુટેબલ મૂલ્યો ક્યારેય ડુપ્લિકેટ થતા નથી.

### `dsh`

નેટિવ DSH ઇન્ટિગ્રેશન પુરાવો:

| પ્રોપર્ટી     | પ્રકાર  | નિયમો                                                          |
| -------------- | ------ | -------------------------------------------------------------- |
| `profiles`     | array  | ઓછામાં ઓછું એક અનન્ય પ્રોફાઇલ નામ જે `^[A-Za-z0-9][A-Za-z0-9._-]*$` સાથે મેચ થાય |
| `evidencePath` | string | `source.commit` પર DSH ઇન્ટિગ્રેશન પુરાવા માટે સેફ રિલેટિવ પાથ |

### `repositoryScope`

કાં તો `dedicated` (રિપોઝિટરી સ્ટાર્સ આ ચોક્કસ પ્લગિનના છે) અથવા `monorepo` (પ્લગિન
વ્યાપક પ્રોજેક્ટની અંદર સબપાથ કે પેકેજ છે). આ મૂલ્ય નીચેના શરતી પોપ્યુલેરિટી
નિયમોને ચલાવે છે.

### `popularity`

| પ્રોપર્ટી   | પ્રકાર           | નિયમો                                                |
| ------------ | --------------- | ---------------------------------------------------- |
| `starsPolicy`| enum            | `exact-repository` અથવા `undefined-parent-repository` |
| `stars`      | integer અથવા null | બિન-નકારાત્મક પૂર્ણાંક, અથવા `null`                    |

શરતી નિયમો (સ્કીમાના `allOf` બ્લોક્સ દ્વારા લાગુ):

- `repositoryScope: monorepo` `starsPolicy: undefined-parent-repository` અને
  `stars: null` **ફરજિયાત** કરે છે. પેરેન્ટ-પ્રોજેક્ટના સ્ટાર્સ ક્યારેય મોનોરેપો પ્લગિનને આપવામાં આવતા નથી.
- `repositoryScope: dedicated` `starsPolicy: exact-repository` અને પૂર્ણાંક
  `stars >= 0` **ફરજિયાત** કરે છે.

આ મૂલ્યો રેન્કિંગ પ્રિડિકેટને કેવી રીતે ખવડાવે છે તે [docs/RANKING.md](../../docs/RANKING.md) માં જુઓ.

### `license`

| પ્રોપર્ટી | પ્રકાર  | નિયમો                                                          |
| -------- | ------ | -------------------------------------------------------------- |
| `spdx`   | string | SPDX એક્સપ્રેશન શેપ, 2–256 અક્ષરો, શરૂઆતમાં હાઇફન નહીં          |

સ્કીમા ફક્ત સેફ અક્ષર-શેપ લાગુ કરે છે; કેટલોગ વેલિડેશને મૂલ્યને સાચા SPDX એક્સપ્રેશન પાર્સર વડે
પાર્સ અને નોર્મલાઇઝ કરવું જ પડે. પિન કરેલા કમિટ પર પુરાવારૂપ સંપૂર્ણ અપસ્ટ્રીમ એક્સપ્રેશન રેકોર્ડ કરો
(ઉદાહરણ તરીકે `Apache-2.0` અથવા `MIT OR GPL-3.0-only`).

### `verification`

વેરિફિકેશન `source.commit` પર લાગુ પડે છે. ચાર જરૂરી પ્રોપર્ટીઝ ધરાવતું ઓબ્જેક્ટ:

| પ્રોપર્ટી           | પ્રકાર          | નિયમો                                                  |
| -------------------- | -------------- | ------------------------------------------------------ |
| `status`             | enum           | `eligible` · `verified` · `stale` · `unavailable` · `archived` · `quarantined` |
| `checkedAt`          | string         | ચેકનો `date-time` ફોર્મેટમાં ટાઇમસ્ટેમ્પ                    |
| `repositoryIdentity` | const          | `resolved` જ હોવું જોઈએ                                |
| `smokeTest`          | object અથવા null | સ્મોક-ટેસ્ટ રેકોર્ડ, અથવા કોઈ લાયક ટેસ્ટ ન હોય ત્યારે `null` |

હાજર હોય ત્યારે, `smokeTest` આવશ્યક બનાવે છે:

| પ્રોપર્ટી      | પ્રકાર  | નિયમો                                                             |
| --------------- | ------ | ----------------------------------------------------------------- |
| `installTarget` | const  | `canonical-install-descriptor` — મ્યુટેબલ મૂલ્યો ડુપ્લિકેટ કર્યા વિના `package` કે પિન કરેલા સોર્સનો સંદર્ભ લે છે |
| `check`         | object | જરૂરી `name` (પેકેજ-નેમ શેપ) અને `version` (ચોક્કસ વર્ઝન શેપ)      |
| `result`        | const  | `passed` — નિષ્ફળ સ્મોક ટેસ્ટ સ્મોક ટેસ્ટ તરીકે રેકોર્ડ થતો નથી   |

શરતી નિયમ: `status: verified` નલ્લ ન હોય તેવું `smokeTest` ઓબ્જેક્ટ **જરૂરી** બનાવે છે. રિવ્યુ કરી
શકાય તેવા સ્મોક પુરાવા વિનાની એન્ટ્રીઓ `status: eligible` અને `smokeTest: null` વાપરે છે. કોઈ સ્ટેટસ
સમર્થન કે સુરક્ષા પ્રમાણપત્ર નથી — [docs/RANKING.md](../../docs/RANKING.md) જુઓ.

### `provenance`

જાહેર પ્રોવેનન્સ લિંક્સ, દરેક URI અથવા `null`:

| પ્રોપર્ટી   | પ્રકાર         | નિયમો                                            |
| ------------ | ------------- | ------------------------------------------------ |
| `discussion` | string અથવા null | અસ્તિત્વમાં હોય ત્યારે જાહેર Discussion URL      |
| `comment`    | string અથવા null | અસ્તિત્વમાં હોય ત્યારે જાહેર કોમેન્ટ URL          |

### `media`

એકમાત્ર વૈકલ્પિક ફીલ્ડ. વધુમાં વધુ **6** આઇટમની એરે, જેમાં દરેક પ્લગઇનનો એક સ્ક્રીનશોટ અથવા એક ટૂંકો વિડિયો વર્ણવે છે:

| ગુણધર્મ | પ્રકાર | નિયમો |
| -------- | ------ | ----- |
| `kind`   | enum   | `screenshot` અથવા `video` |
| `url`    | string | અપરિવર્તનીય GitHub URL, વધુમાં વધુ 2048 અક્ષર (નીચે જુઓ) |
| `alt`    | string | વૈકલ્પિક લખાણ, 1–120 અક્ષર |

અહીંનું URL `source.commit` જેટલું જ અપરિવર્તનીય હોવું જોઈએ. શાખાનું નામ ધરાવતો
`raw.githubusercontent.com` પાથ (`.../main/docs/shot.png`) એ શાખા આજે જે ધરાવે છે તે બતાવે છે,
એટલે શાખા ખસે તે દિવસે પ્રવેશ સમીક્ષા વગરની છબી પ્રકાશિત કરી દેશે. બે જ સ્વરૂપ સ્વીકાર્ય છે:

- `https://raw.githubusercontent.com/<owner>/<repo>/<commit>/<path>` — કમિટ પર પિન કરેલો raw પાથ;
- `https://github.com/<owner>/<repo>/assets/…` — GitHub નું સામગ્રી-આધારિત અપલોડ URL, `video` આઇટમ માટે.

સ્કીમા માત્ર સુરક્ષિત સ્વરૂપ લાગુ કરે છે (હોસ્ટ, 40 અક્ષરનો હેક્સાડેસિમલ સંદર્ભ, મર્યાદિત લંબાઈ).
બાકીનું `catalog validate` અર્થની દૃષ્ટિએ લાગુ કરે છે: URL એ **પ્રવેશના પોતાના** રિપોઝિટરીમાં
**પ્રવેશના પોતાના** `source.commit` ને પિન કરવું જોઈએ, અને શાખાનું URL
`media[n].url must pin the entry commit, not a branch` સાથે નકારાય છે.

બતાવવા જેવું કંઈ ન હોય ત્યારે ફીલ્ડ સંપૂર્ણપણે છોડી દો — `media: []` એ "કોઈ સ્ક્રીનશોટ નથી" કહેવાની
માન્ય રીત નથી. આ ફીલ્ડ ઉમેરણરૂપ છે: તે અસ્તિત્વમાં આવ્યા પહેલાં પ્રકાશિત પ્રવેશો માન્ય રહે છે, અને
તેને અવગણનાર ઉપભોક્તા દરેક પ્રવેશ પહેલાંની જેમ જ વાંચે છે.

## `kind: skill` પ્રવેશો

સ્કીમા વર્ઝન 1 `kind: skill` માટે બીજો, સ્વ-સમાવિષ્ટ પ્રવેશ કરાર પણ વ્યાખ્યાયિત કરે છે, જે
[`schemas/skill.schema.yaml`](../../schemas/skill.schema.yaml) તરીકે પ્રકાશિત છે (SKL-01 ફેઝ 0).
તે ઉપરના પ્લગિન સ્કીમાને ક્યારેય સ્પર્શતો નથી: `kind: plugin` વાળા પ્રવેશો પહેલાંની જેમ જ
ચોક્કસ રીતે માન્ય થતા રહે છે, અને સ્કિલ સ્કીમા ફાઇલ સ્કિલ પ્રવેશો માટે એ જ રીતે સત્યનો સ્રોત છે
જે રીતે પ્લગિન સ્કીમા પ્લગિન પ્રવેશો માટે છે.

સ્કિલ ઇન્સ્ટોલ થતી નથી, હાર્નેસ તેને **લોડ** કરે છે, તેથી ફક્ત-પ્લગિન માટેના ઇન્સ્ટોલ
ડિસ્ક્રિપ્ટર્સ (`package`, `dsh`) સ્કિલ પ્રવેશ પર અસ્તિત્વમાં નથી અને તેમની જગ્યાએ `usage` +
`compat` આવે છે. સ્કિલ ઘણી વાર એવા રિપોઝિટરીના સબડિરેક્ટરીમાં પણ રહે છે જે ઘણી સ્કિલ્સ હોસ્ટ
કરે છે, તેથી ઓળખ અને ડિડ્યુપ `source.repository` + `source.subpath` છે, ફક્ત રિપોઝિટરી નહીં.
સ્કિલ પ્રવેશ કોઈ `media` ગેલેરી સ્વીકારતો નથી: સ્કિલ એ ટેક્સ્ટ છે જે હાર્નેસ લોડ કરે છે, તેથી
સ્ક્રીનશોટ લેવા જેવું કંઈ નથી (`additionalProperties: false` જ તેને લાગુ કરે છે).

આ ફિલ્ડ્સ ઉપર પ્લગિન પ્રવેશો માટે દસ્તાવેજિત સ્વરૂપ અને નિયમો બરાબર જાળવી રાખે છે:
`schemaVersion`, `id`, `name`, `description`, `unofficial`, `primaryCategory`, `tags`,
`source`, `creator`, `repositoryScope`, `license`, `provenance`. `triggers` સિવાય દરેક ફિલ્ડ
જરૂરી છે — તે એકમાત્ર વૈકલ્પિક સ્કિલ ફિલ્ડ છે.

### સ્કિલ-વિશિષ્ટ ફિલ્ડ્સ

| ફિલ્ડ                | પ્રકાર | જરૂરી | નિયમો                                                        |
| -------------------- | ------ | :------: | ----------------------------------------------------------- |
| `kind`               | const  |   હા    | બરાબર `skill` જ હોવું જોઈએ                                    |
| `skillScope`         | enum   |   હા    | `repository` (આખું રિપોઝિટરી **જ** સ્કિલ છે) અથવા `subdirectory` (સ્કિલ `source.subpath` પર રહે છે) |
| `triggers`           | array  |    ના    | સ્કિલ ક્યારે સક્રિય થાય છે — તે ટેક્સ્ટ જે વપરાશકર્તા લોડ કરતાં પહેલાં મૂલવે છે. ઓછામાં ઓછી 1 અનન્ય સ્ટ્રિંગ, દરેક 3–200 અક્ષરો; કંઈ ન હોય ત્યારે ફિલ્ડ સંપૂર્ણપણે છોડી દો (`triggers: []` અમાન્ય છે) |
| `usage.load`         | string |   હા    | હાર્નેસ સ્કિલ કેવી રીતે લોડ કરે છે, 1–200 અક્ષરો; સ્કિલ લોડ થાય છે, ક્યારેય ઇન્સ્ટોલ થતી નથી |
| `usage.evidencePath` | string |   હા    | `source.commit` પરના લોડ પુરાવા સુધીનો સુરક્ષિત સાપેક્ષ પાથ (`description.evidencePath` જેવો જ પેટર્ન) |
| `compat.harnessMin`  | string |   હા    | લઘુતમ હાર્નેસ વર્ઝન જેની સામે સ્કિલ ચકાસાઈ હતી; ચોક્કસ `x.y.z` સ્વરૂપ (વૈકલ્પિક prerelease/build), મહત્તમ 64 અક્ષરો. સિમેન્ટિક લેયર વધારામાં પાર્સ થઈ શકે તેવું, ચોક્કસ SemVer માગે છે |

શરતી નિયમો (સ્કિલ સ્કીમાના `allOf` બ્લોક્સ દ્વારા લાગુ):

- `skillScope: subdirectory` `source.subpath` ને સુરક્ષિત સાપેક્ષ પાથ સ્ટ્રિંગ હોવા માટે
  **ફરજ પાડે છે** — સબડિરેક્ટરીમાં હોસ્ટ થયેલી સ્કિલે તે સબડિરેક્ટરી પિન કરવી જ જોઈએ.
- `skillScope: repository` `source.subpath: null` **ફરજ પાડે છે** — આખા-રિપોઝિટરીની સ્કિલે
  subpath જાહેર કરવો ન જોઈએ.

`verification` પ્લગિન સ્વરૂપ જાળવે છે (`status`, `checkedAt`, `repositoryIdentity`,
`smokeTest`), પણ `smokeTest` બરાબર `null` જ હોવું જોઈએ: સ્કિલ પાસે ઇન્સ્ટોલ સ્મોક ટેસ્ટ નથી,
અને કન્ટેન્ટ રિવ્યૂ જ પ્રવેશ દ્વાર છે. સ્કિલ સ્કીમામાં `status: verified` → `smokeTest`
શરત નથી અને `repositoryScope` → `popularity` શરતો પણ નથી; તે જોડાણો ફક્ત પ્લગિન-સ્કીમાના
નિયમો છે.

### સ્કિલ્સ માટે સિમેન્ટિક લેયર

સ્કીમાની ઉપર, કેટલોગ વેલિડેશન જ્યાં ફિલ્ડ્સ અસ્તિત્વમાં હોય ત્યાં પ્લગિન્સ માટેના જ ફરજિયાત
સિમેન્ટિક પાર્સર્સ લાગુ કરે છે: `license.spdx` માન્ય SPDX અભિવ્યક્તિ તરીકે પાર્સ થવું જોઈએ
(`invalid-spdx`), અને `compat.harnessMin` ચોક્કસ SemVer હોવું જોઈએ (`invalid-semver`).
`invalid-sri` કેસ નથી — સ્કિલ પાસે `package.integrity` નથી.

### સ્કિલ ઓળખ અને ડિડ્યુપ

સ્કિલની કેનોનિકલ કી `skill:<source.repositoryNodeId>:<normalized subpath>` છે. subpath ફક્ત
ઓળખના હેતુઓ માટે નોર્મલાઇઝ થાય છે: બેકસ્લેશ `/` બને છે, ખાલી અને `.` સેગમેન્ટ્સ કાઢી નખાય
છે, અને ખાલી પરિણામ (અથવા `subpath: null`) `.` બને છે — આખું રિપોઝિટરી. NUL બાઇટ્સ કે `..`
સેગમેન્ટ્સ ધરાવતો subpath નકારાય છે, ક્યારેય "સાફ" થતો નથી. એક જ રિપોઝિટરીની બે સ્કિલ્સ બે
પ્રવેશો છે; એ જ રિપોઝિટરી + subpath બે વાર એ ટકરાવ છે.
