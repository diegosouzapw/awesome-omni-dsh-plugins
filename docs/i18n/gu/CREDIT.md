# ક્રિએટર ક્રેડિટ અને પુલ રિક્વેસ્ટ અગ્રતા

કેટલોગ સ્વતંત્ર DSH કામને તેના ક્રિએટર્સ પાસેથી માલિકી લીધા વિના શોધી શકાય તેવું બનાવવા
અસ્તિત્વમાં છે. પબ્લિક એન્ટ્રીઝ મૂળ રિપોઝિટરી અને અપરિવર્તનીય સોર્સ કમિટ ટાંકે છે.

## એ જ પ્લગિન માટે અગ્રતા

<!-- creator-first:direct-pr-supersedes-curation-and-automation -->

1. પ્લગિન ક્રિએટર અથવા માલિકી ધરાવતી સંસ્થા દ્વારા ખોલવામાં આવેલ પુલ રિક્વેસ્ટ.
2. ક્રિએટર દ્વારા સ્પષ્ટપણે મંજૂર કરાયેલ અથવા કો-ઓથર કરાયેલ સામુદાયિક પુલ રિક્વેસ્ટ.
3. અસ્તિત્વમાં હોય તેવો માન્ય સામુદાયિક પુલ રિક્વેસ્ટ.
4. કેટલોગ ઓટોમેશન પુલ રિક્વેસ્ટ.
5. પબ્લિક પુલ રિક્વેસ્ટ વિનાનો ખાનગી ઉમેદવાર.

ક્રિએટરનો સીધો પુલ રિક્વેસ્ટ હંમેશા પસંદગીનો હોય છે અને એ જ કેનોનિકલ પ્લગિન માટે કોઈપણ ખુલ્લા
સામુદાયિક ક્યુરેશન કે ઓટોમેશન પુલ રિક્વેસ્ટને બદલી નાખે છે, ભલે કયો પહેલા ખોલવામાં આવ્યો હોય
કે વધુ આગળ વધ્યો હોય. ક્રિએટરનો પુલ રિક્વેસ્ટ રિવ્યૂ વાહન બની જાય છે; તેમની બ્રાન્ચ ક્યારેય
ઓવરરાઇટ, ફોર્સ-પુશ કે ક્યુરેટેડ પુલ રિક્વેસ્ટમાં ટ્રાન્સપ્લાન્ટ થતી નથી. જો ક્યુરેટેડ એન્ટ્રી પહેલેથી
મર્જ થઈ ગઈ હોય, તો ઇતિહાસ અકબંધ રહે છે અને ક્રિએટર નવા યોગદાનમાં તેનો દાવો કે સુધારો કરી શકે છે.

## પબ્લિક એટ્રિબ્યુશન

દરેક કેટલોગ એન્ટ્રી ક્રિએટરનું જાહેર GitHub હેન્ડલ, મૂળ રિપોઝિટરી, રિપોઝિટરી
નોડ ID, પ્લગિન સબપાથ અને પૂરું પિન કરેલ કમિટ ધરાવે છે. જાહેર ક્રિએટર પ્રોફાઇલ બીજી ઓળખ
તરીકે સંગ્રહવાને બદલે એક જ હેન્ડલ પરથી ડિરાઇવ થાય છે. મેન્ટેનરનો અલગ પ્રોવેનન્સ
ગેટ નોડ ID ઉકેલે છે અને રિપોઝિટરી URL મેલ ન ખાય તો નકારે છે. પુલ રિક્વેસ્ટ વર્ણનમાં
`Created by @handle` લખવું જોઈએ અને સોર્સ રિપોઝિટરી તથા સોર્સ કમિટ મેટાડેટા સામેલ કરવા જોઈએ.

જે વ્યક્તિ Discussion પર પોસ્ટ કે કોમેન્ટ કરે છે તે આપોઆપ ક્રિએટર ગણવામાં આવતી નથી.
માલિકી રિપોઝિટરી માલિક કે ઓર્ગેનાઇઝેશન, પેકેજ ઓથરશિપ, મેનિફેસ્ટ
મેટાડેટા કે ચોક્કસ પિન કરેલ સોર્સ ઇતિહાસ દ્વારા સમર્થિત હોવી જોઈએ.

## Git ઓળખ

<!-- creator-first:source-bound-git-identity -->

કમિટ ઓથરશિપ અને પુલ રિક્વેસ્ટ ઓથરશિપ અલગ છે. ક્રિએટર-ઉદ્ભવ પુલ રિક્વેસ્ટ
ક્રિએટરને પુલ રિક્વેસ્ટ ઓથર તરીકે રાખે છે, અને તેમના કમિટ્સ ઓથરશિપ સ્વાભાવિક રીતે જાળવે છે. મેન્ટેનર
અથવા ઓટોમેશન એકાઉન્ટ કમિટર અથવા ચકાસાયેલ કો-ઓથર તરીકે દેખાઈ શકે છે, પરંતુ ક્રિએટરની
ઓથરશિપને બદલી શકે નહીં.

ક્યુરેટેડ કમિટ માટે, ક્રિએટરને Git ઓથર તરીકે વાપરો અથવા `Co-authored-by` ટ્રેલર ફક્ત
ત્યારે જ ઉમેરો જ્યારે ચોક્કસ ઓળખ સોર્સ-બાઉન્ડ અને જાહેરમાં ચકાસી શકાય તેવી હોય, જેમ કે
મૂળ રિપોઝિટરીમાં ક્રિએટરના કમિટ સાથે પહેલેથી જોડાયેલી ઓળખ. ક્યારેય ઇમેઇલનો અંદાજ ન લગાવો, નોરિપ્લાય
સરનામું બનાવટી ન બનાવો કે અધિકૃત પબ્લિક સ્ત્રોતની બહાર મળેલું ખાનગી સરનામું વાપરો.

જ્યારે ચકાસાયેલી Git ઓળખ ઉપલબ્ધ ન હોય, ત્યારે ક્યુરેટર અથવા ઓટોમેશન એકાઉન્ટ કમિટ લખે છે
અને તેને બદલે સ્પષ્ટ દૃશ્યમાન ક્રેડિટ આપે છે: `Created by @handle`, તેને મળતું જાહેર પ્રોફાઇલ અને
એન્ટ્રી તથા પુલ રિક્વેસ્ટમાં મૂળ રિપોઝિટરીની લિંક. દૃશ્યમાન YAML એટ્રિબ્યુશન હંમેશા
Git ઓળખ મેપિંગથી સ્વતંત્ર રીતે જરૂરી છે. પછીથી આવેલો ક્રિએટરનો સીધો પુલ રિક્વેસ્ટ ખુલ્લા
ક્યુરેટેડ પુલ રિક્વેસ્ટને તેનો કૃત્રિમ ઇતિહાસ વારસામાં લેવાને બદલે બદલી નાખે છે.

## આદરપૂર્ણ ક્રિએટર ઉલ્લેખ

ક્યુરેટેડ પુલ રિક્વેસ્ટ તેના વર્ણનમાં મૂળ રિપોઝિટરી લિંકની બાજુમાં એક આદરપૂર્ણ જાહેર
`@creator` ઉલ્લેખ વાપરે છે. તે રિવ્યૂ અથવા બદલાઈ જાય તેવા સીધા પુલ રિક્વેસ્ટ માટે આમંત્રિત કરી શકે છે.
ઉલ્લેખનું પુનરાવર્તન ન કરો, પ્રમોશનલ ઇશ્યુ ન ખોલો, ક્રોસ-પોસ્ટ ન કરો કે અયાચિત ડાયરેક્ટ મેસેજ ન મોકલો.

## કેટલોગ લાઇસન્સ વિરુદ્ધ અપસ્ટ્રીમ લાઇસન્સ

કેટલોગ ફેક્ટ્સ અને એડિટોરિયલ YAML મેટાડેટા CC0-1.0 હેઠળ સમર્પિત છે. તે સમર્પણ
અપસ્ટ્રીમ પ્લગિનનું લાઇસન્સ બદલતું નથી. અપસ્ટ્રીમ કોડ, દસ્તાવેજીકરણ, સ્ક્રીનશોટ્સ, લોગો અને અન્ય
સર્જનાત્મક સામગ્રી તેમના મૂળ લાઇસન્સ અને માલિકોને આધીન જ રહે છે.
