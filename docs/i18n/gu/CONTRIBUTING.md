# યોગદાન

> 🌐 [English](../../CONTRIBUTING.md) · [Português (Brasil)](../pt-BR/CONTRIBUTING.md) · [中文（简体）](../zh-CN/CONTRIBUTING.md) · **ગુજરાતી**

> **બિનસત્તાવાર સામુદાયિક પ્રોજેક્ટ. DeepSeek સાથે સંલગ્ન, સમર્થિત કે પ્રાયોજિત નથી.**
> DeepSeek નામો અને ચિહ્નો તેમના સંબંધિત માલિકોના છે.

કેટલોગ સુધારવા બદલ આભાર. યોગદાનમાં સર્જકને પ્રાધાન્ય આપવામાં આવે છે: મૂળ રિપોઝિટરીના પુરાવાનો ઉપયોગ કરો,
એટ્રિબ્યુશન જાળવો અને દરેક પ્લગઇનને સ્વતંત્ર રીતે સમીક્ષા કરી શકાય તેવું રાખો. કેટલોગ ડિઝાઇન દ્વારા ખાલી શરૂ થાય
છે; કોઈપણ એન્ટ્રીને તેના પોતાના સમીક્ષા કરાયેલા પુલ રિક્વેસ્ટ વિના સ્વીકારવામાં આવતી નથી.

## સર્જકથી શરૂઆત કરો

પ્લગઇન સર્જક અથવા માલિકી ધરાવતી સંસ્થા દ્વારા સીધો ખોલવામાં આવેલો પુલ રિક્વેસ્ટ હંમેશા પસંદ કરવામાં આવે છે.
જો સર્જક યોગદાન આપવા તૈયાર હોય, તો ક્યુરેટર અથવા ઓટોમેશન બ્રાન્ચમાં તેમનું કામ ફરીથી બનાવવાને બદલે તેમની
બ્રાન્ચ અને પુલ રિક્વેસ્ટનો ઉપયોગ કરો.

જ્યારે તે એવા સર્જકને મદદ કરે છે જેણે હજુ સુધી પુલ રિક્વેસ્ટ ખોલ્યો નથી, ત્યારે સામુદાયિક ક્યુરેશનનું સ્વાગત છે.
તે પછીના સર્જકના સીધા યોગદાન પર માલિકી કે અગ્રતા સ્થાપિત કરતું નથી.

## એક પ્લગઇન દીઠ એક બ્રાન્ચ અને પુલ રિક્વેસ્ટ

એક પ્લગઇન માટે એક સમર્પિત બ્રાન્ચ બનાવો અને તે બ્રાન્ચમાંથી એક પુલ રિક્વેસ્ટ ખોલો. બ્રાન્ચ અને પુલ રિક્વેસ્ટે
`catalog/plugins/` હેઠળ બરાબર એક YAML ફાઇલ બનાવવી અથવા બદલવી જોઈએ. તે બ્રાન્ચ કે પુલ રિક્વેસ્ટમાં
પ્લગિન્સ, ડોક્યુમેન્ટેશન ક્લીનઅપ, જનરેટેડ ઇન્ડેક્સ કે અસંબંધિત મેન્ટેનન્સ ભેગું ન કરો.

એન્ટ્રી ID અને ફાઇલનામ સમાન લોઅરકેસ kebab-case મૂલ્ય હોવા જોઈએ. મેન્ટેનર્સ દરેક પ્લગઇન પુલ રિક્વેસ્ટની
વ્યક્તિગત રીતે સમીક્ષા કરે છે અને મર્જ કરે છે; બહુવિધ પ્લગિન્સ ધરાવતો બેચ વિભાજિત કે આંશિક રીતે મર્જ કરવામાં
આવતો નથી.

## મૂળ સ્રોતનું નિરાકરણ કરો

દરેક જાહેર ફિલ્ડ પિન કરેલા કમિટ પર મૂળ સર્જકની રિપોઝિટરી, પેકેજ, મેનિફેસ્ટ, README, લાયસન્સ કે રિલીઝમાંથી
પુનર્નિર્માણ થવું જોઈએ. બીજા કેટલોગ કે એગ્રિગેટરના પ્રોસ, કેટેગરી અસાઇનમેન્ટ, સ્ક્રીનશોટ્સ, રેન્કિંગ, બેજ કે
જનરેટેડ મેટાડેટા કોપી ન કરો. કોઈ છત્ર પ્રોજેક્ટ, માર્કેટપ્લેસ, યાદી કે એગ્રિગેટરમાં મળેલી લિંક ફક્ત એક લીડ છે,
પુરાવો નથી અને પ્લગિનનો સ્રોત નથી.

કોઈ છત્ર, એગ્રિગેટર, માર્કેટપ્લેસ, ઇન્સ્ટોલર કેટલોગ કે યાદીને ક્યારેય કેટલોગ એન્ટ્રી તરીકે સબમિટ ન કરો, ભલે તે
સ્વતંત્ર રીતે ઇન્સ્ટોલ કરી શકાય તેવું હોય. તેનો ઉપયોગ ફક્ત લીડ તરીકે કરો અને દરેક સ્વતંત્ર રીતે ઇન્સ્ટોલ કરી
શકાય તેવા ચાઇલ્ડ પ્લગિનને તેના વાસ્તવિક સર્જક અને મૂળ રિપોઝિટરી સુધી ઉકેલો. સર્જકના વાસ્તવિક મોનોરેપોમાં
રહેલું પ્લગિન તેના ચોક્કસ સબપાથમાંથી સબમિટ કરી શકાય છે, પરંતુ તેણે નીચે આપેલી મોનોરેપો સ્ટાર્સ પોલિસીનું
પાલન કરવું જોઈએ.

## જરૂરી પુરાવો

પુલ રિક્વેસ્ટમાં નીચેનું બધું પ્રદાન કરો:

- મૂળ રિપોઝિટરીની કેનોનિકલ પબ્લિક URL અને તેનું અપરિવર્તનીય રિપોઝિટરી નોડ ID. મેન્ટેનર્સ અલગ પ્રોવેનન્સ
  ગેટમાં નોડ ID ઉકેલે છે અને URL મેળ ન ખાય તો નકારે છે.
- સર્જકનું જાહેર GitHub હેન્ડલ અને તેને મળતું જાહેર પ્રોફાઇલ URL. YAML હેન્ડલ એકવાર સંગ્રહે છે; પ્રોફાઇલ
  URL `https://github.com/<handle>` તરીકે ડિરાઇવ કરવામાં આવે છે.
- પૂરું 40-અક્ષરનું સોર્સ કમિટ OID અને પ્લગિનનો ચોક્કસ સબપાથ, અથવા રિપોઝિટરી-રૂટ પ્લગિન માટે `null`.
- એક બાઉન્ડેડ અંગ્રેજી વર્ણન અને તે પિન કરેલા કમિટ પર તેનો પુરાવો પાથ.
- આર્ટિફેક્ટ `kind`, પ્રાથમિક કેટેગરી અને [docs/CATEGORIES.md](../../docs/CATEGORIES.md) માંથી
  પસંદ કરેલા ટૅગ્સ.
- પિન કરેલા કમિટ પર પુરાવારૂપ સંપૂર્ણ upstream SPDX લાયસન્સ એક્સપ્રેશન.
- npm ના ચોક્કસ વર્ઝન પર પિન કરેલો, અથવા સોર્સ રિપોઝિટરી, પૂરું કમિટ અને સબપાથ પર પિન કરેલો કેનોનિકલ
  ઇન્સ્ટોલ ડિસ્ક્રિપ્ટર. ડિસ્ક્રિપ્ટર ડેટા છે, ક્યારેય શેલ કમાન્ડ નથી.
- નેટિવ DSH ઇન્ટિગ્રેશન પુરાવો અને પિન કરેલા કમિટ પર તેનો પાથ.
- તે ચોક્કસ આર્ટિફેક્ટ પિન માટે હાલના, બિન-સંવેદનશીલ સ્મોક પુરાવો, અથવા સ્પષ્ટ મૂલ્ય `not run`. કેટલોગ
  યોગદાન તૈયાર કરવા માટે ફક્ત પ્લગિન ઇન્સ્ટોલ ન કરો કે `preinstall`, `install`, `postinstall`, `prepare`
  કે અન્ય પેકેજ/પ્લગિન લાઇફસાઇકલ કોડ એક્ઝિક્યુટ ન કરો.
- સમર્પિત રિપોઝિટરી માટે, તે ચોક્કસ રિપોઝિટરી માટે ચકાસી શકાય તેવી સ્ટાર ગણતરી, જાહેર સ્રોત અને ચકાસણી
  સમય સાથે. મોનોરેપો પ્લગિન માટે, નીચે આપેલી ફરજિયાત null પોલિસીનો ઉપયોગ કરો.
- અસ્તિત્વમાં હોય ત્યારે જાહેર Discussion કે કોમેન્ટ પ્રોવેનન્સ; અન્યથા `null` વાપરો.
- મશીન-વાંચી શકાય તેવું `unofficial: true` મૂલ્ય.

જો કોઈ લાયક સ્મોક ટેસ્ટ પહેલેથી અસ્તિત્વમાં ન હોય, તો `verification.status: eligible` અને
`verification.smokeTest: null` વાપરો. `verified` નો ઉપયોગ ફક્ત ત્યારે જ કરો જ્યારે ચોક્કસ પિન માટે
સમીક્ષા કરી શકાય તેવો સ્મોક પુરાવો અસ્તિત્વમાં હોય. કોઈપણ સ્થિતિ સમર્થન કે સુરક્ષા પ્રમાણપત્ર નથી.

ક્યારેય ક્રેડેન્શિયલ્સ, કૂકીઝ, ખાનગી ઇમેઇલ સરનામાં, અપ્રકાશિત સોર્સ કે અન્ય ગુપ્ત માહિતી સબમિટ ન કરો.

## YAML અને સ્કીમા નિયમો

`catalog/plugins/<plugin-id>.yaml` બનાવો અને તેને
[`schemas/plugin.schema.yaml`](../../schemas/plugin.schema.yaml) સામે વેલિડેટ કરો. `id` ફાઇલના
બેઝનેમ જેવું જ હોવું જોઈએ અને તમારા નેમસ્પેસથી શરૂ થવું જોઈએ: તમારું `creator.github` હેન્ડલ લોઅરકેસમાં
(`[a-z0-9]` બહારના અક્ષરોની કોઈપણ હાર એક જ `-` બની જાય છે) અને પછી `-`, ઉદાહરણ તરીકે
`some-creator-my-plugin` હેન્ડલ માટે `Some-Creator`. કેટલોગ વેલિડેશન બંને લાગુ કરે છે. સ્કીમા ફિલ્ડ
નામો અને માન્ય મૂલ્યો માટે સત્યનો સ્રોત છે; [docs/CATEGORIES.md](../../docs/CATEGORIES.md) એક જ
આર્ટિફેક્ટ kind, પ્રાથમિક કેટેગરી, ટૅગ્સ અને રિપોઝિટરી સ્કોપ કેવી રીતે પસંદ કરવા તે વ્યાખ્યાયિત કરે છે.

npm ડિસ્ક્રિપ્ટરમાં માન્ય પેકેજ નામ અને ચોક્કસ વર્ઝન હોવું જોઈએ. જાહેર સ્કીમા ઓપ્શન જેવા અને
અમર્યાદિત મૂલ્યોને નકારે છે પરંતુ SemVer કે SRI ને ફરીથી લાગુ કરતું નથી: કેટલોગ વેલિડેશને વર્ઝન પાર્સ
કરવું જોઈએ, ચોક્કસ SemVer જરૂરી બનાવવું જોઈએ અને કોઈપણ ઇન્ટિગ્રિટી મૂલ્યને માન્ય SHA-512 SRI તરીકે
પાર્સ કરવું જોઈએ. સોર્સ ડિસ્ક્રિપ્ટર `source.repository`, `source.commit` અને `source.subpath` સાથે
બંધાયેલો છે, જે મ્યુટેબલ સોર્સ મૂલ્યોની ડુપ્લિકેશન કર્યા વગર.

ઇન્સ્ટોલર્સે આર્ગ્યુમેન્ટ એરેનો ઉપયોગ કરવો જોઈએ, શેલ એક્ઝિક્યુશન બંધ કરવું જોઈએ અને ઇન્વોક કરેલો
કમાન્ડ સપોર્ટ કરે ત્યાં કેટલોગ-પ્રદાન કરેલા પોઝિશનલ મૂલ્યો પહેલાં ઓપ્શન ટર્મિનેટર મૂકવો જોઈએ. સબમિશન
વેલિડેશને ઇન્સ્ટોલર કે પ્લગિન લાઇફસાઇકલ ઇન્વોક ન કરવું જોઈએ.

સ્કીમા વેલિડેટ કરે છે, SPDX એક્સપ્રેશન પાર્સ કરે છે, ચોક્કસ SemVer અને માન્ય SHA-512 SRI જરૂરી બનાવે
છે, અને ડુપ્લિકેટ ID તથા કેનોનિકલ રિપોઝિટરી-નોડ-પ્લસ-સબપાથ કીને નકારે છે. તે GitHub સાથે સંપર્ક કરતું
નથી, રિપોઝિટરી ઓળખ ઉકેલતું નથી કે પિન કરેલા કમિટ પર પુરાવા પાથનું નિરીક્ષણ કરતું નથી.

<!-- maintainer-gate:repository-origin-and-pinned-evidence -->

એન્ટ્રી `eligible` સુધી પહોંચે તે પહેલાં, મેન્ટેનર્સ અલગથી કેનોનિકલ રિપોઝિટરી અને નોડ ID ઉકેલે છે,
સર્જકને મૂળ સ્રોત સાથે બાંધે છે, અને `source.commit` પર જાહેર કરેલા વર્ણન, લાયસન્સ, DSH ઇન્ટિગ્રેશન
અને સ્મોક પુરાવાનું નિરીક્ષણ કરે છે. લોકલ ગ્રીન વેલિડેશન પરિણામ પ્રોવેનન્સ કે ઓરિજિન પુરાવો નથી.

## રિપોઝિટરી સ્ટાર્સ

ફક્ત ચોક્કસ સમર્પિત પ્લગિન રિપોઝિટરીની ચકાસી શકાય તેવી સ્ટાર્સ જ રેકોર્ડ કરી શકાય છે. પેરેન્ટ પ્રોજેક્ટની
સ્ટાર્સ ક્યારેય વ્યાપક મોનોરેપોમાં સંગ્રહાયેલા પ્લગિનને આપવામાં આવવી જોઈએ નહીં. મોનોરેપો એન્ટ્રી
ફંક્શનલ કેટલોગ સેક્શન્સ માટે લાયક રહે છે પરંતુ તેણે જાહેર કરવું આવશ્યક છે:

```yaml
repositoryScope: monorepo
popularity:
  starsPolicy: undefined-parent-repository
  stars: null
```

સમર્પિત એન્ટ્રી `repositoryScope: dedicated`, `starsPolicy: exact-repository` અને તે જ રિપોઝિટરી પર
જોવા મળેલી બિન-નકારાત્મક સ્ટાર ગણતરીનો ઉપયોગ કરે છે. લોકપ્રિયતાનો ડેટા સબમિટ કરતાં પહેલાં
[docs/RANKING.md](../../docs/RANKING.md) વાંચો.

## સર્જકની અગ્રતા અને આદરપૂર્ણ સંપર્ક

એક જ કેનોનિકલ પ્લગિન માટે, અગ્રતા આ પ્રમાણે છે:

1. સર્જક અથવા માલિકી ધરાવતી સંસ્થા દ્વારા ખોલવામાં આવેલો પુલ રિક્વેસ્ટ.
2. સર્જક દ્વારા સ્પષ્ટપણે મંજૂર કરાયેલો સામુદાયિક પુલ રિક્વેસ્ટ.
3. અસ્તિત્વમાં હોય તેવો માન્ય સામુદાયિક ક્યુરેશન પુલ રિક્વેસ્ટ.
4. કેટલોગ ઓટોમેશન પુલ રિક્વેસ્ટ.

સર્જકનો સીધો પુલ રિક્વેસ્ટ કોઈપણ ખુલ્લા ક્યુરેશન કે ઓટોમેશન પુલ રિક્વેસ્ટને બદલી નાખે છે, ભલે કયો પહેલા
ખોલવામાં આવ્યો હોય કે વધુ આગળ વધ્યો હોય. સર્જકનો પુલ રિક્વેસ્ટ સમીક્ષા વાહન બની જાય છે; મેન્ટેનર્સ
સર્જકની બ્રાન્ચ પર ફોર્સ-પુશ કરતા નથી કે તેમનું કામ ક્યુરેટેડ પુલ રિક્વેસ્ટમાં ટ્રાન્સપ્લાન્ટ કરતા નથી. જો
ક્યુરેટેડ એન્ટ્રી પહેલેથી મર્જ થઈ ગઈ હોય, તો જાહેર ઇતિહાસ ફરીથી લખવામાં આવતો નથી. સર્જક ક્લેમ કે
કરેક્શન રિક્વેસ્ટનો ઉપયોગ કરી શકે છે અને પછી સીધો ફોલો-અપ પુલ રિક્વેસ્ટ યોગદાન આપી શકે છે.

ક્યુરેટેડ પુલ રિક્વેસ્ટે તેના વર્ણનમાં એક આદરપૂર્ણ જાહેર `@creator` ઉલ્લેખ વાપરવો જોઈએ, મૂળ રિપોઝિટરીની
લિંકની બાજુમાં, સર્જકને તેની સમીક્ષા કરવા કે તેને સીધા પુલ રિક્વેસ્ટથી બદલવા આમંત્રિત કરીને. ઉલ્લેખનું
પુનરાવર્તન ન કરો, પ્રમોશનલ ઇશ્યુ ન ખોલો, ક્રોસ-પોસ્ટ ન કરો, અયાચિત ડાયરેક્ટ મેસેજ ન મોકલો કે અન્ય
રીતે સર્જકને સ્પામ ન કરો.

<!-- creator-first:source-bound-git-identity -->

સર્જક-લેખિત પુલ રિક્વેસ્ટ્સ અને કમિટ્સ સ્વાભાવિક રીતે સર્જકનું ક્રેડિટ જાળવે છે. ક્યુરેટેડ કમિટ્સ ફક્ત
સોર્સ-બાઉન્ડ, જાહેરમાં ચકાસી શકાય તેવી ઓળખ સાથે જ સર્જકની Git ઓથરશિપ કે `Co-authored-by` ટ્રેલરનો
ઉપયોગ કરી શકે છે. ક્યારેય ઇમેઇલ શોધો કે અંદાજ ન લગાવો. જ્યારે કોઈ ચકાસાયેલી Git ઓળખ ઉપલબ્ધ ન હોય,
ત્યારે ક્યુરેટર કમિટ લેખે છે અને YAML તથા પુલ રિક્વેસ્ટમાં મૂળ રિપોઝિટરી લિંક સાથે સ્પષ્ટ `Created by @handle` ક્રેડિટ આપે છે. મેન્ટેનર કે ઓટોમેશન એકાઉન્ટ કમિટર કે ચકાસાયેલ કો-ઓથર બની શકે છે, પરંતુ સર્જકની
ઓથરશિપને બદલી શકે નહીં. સંપૂર્ણ પોલિસી માટે [docs/CREDIT.md](../../docs/CREDIT.md) જુઓ.

## વેલિડેશન કમાન્ડ્સ અને ઉપલબ્ધતા

npm CLI `omni-dsh-plugins@1.0.1` તરીકે પ્રકાશિત થયેલ છે, તેથી નીચેના કમાન્ડ્સ આજે `npx`
દ્વારા ઉપલબ્ધ છે. તેમને બરાબર લખેલા છે તે પ્રમાણે વાપરો; યોગદાનકર્તાઓએ વિકલ્પ કમાન્ડ્સ શોધવા ન જોઈએ.

આ કમાન્ડ્સ રિપોઝિટરીના રૂટમાંથી ચલાવો:

```bash
npx omni-dsh-plugins catalog validate --catalog .
npx omni-dsh-plugins catalog docs-check .
npx omni-dsh-plugins catalog github-forms-check .
```

`catalog validate` ફક્ત ઉપર વર્ણવેલા લોકલ YAML, સ્કીમા, SPDX, ચોક્કસ SemVer, SHA-512 SRI અને
ડુપ્લિકેટ ચેક કરે છે, અને ઇરાદાપૂર્વક ખાલી કેટલોગ સ્વીકારે છે. તે રિમોટ રિપોઝિટરી ઓળખ કે પિન કરેલા
સોર્સ પુરાવાનું સાબિતી આપતું નથી. અન્ય કમાન્ડ્સ જરૂરી જાહેર ડોક્યુમેન્ટેશન અને સ્ટ્રક્ચર્ડ GitHub
ઇશ્યુ ફોર્મ્સ ચકાસે છે. આ કમાન્ડ્સ સ્થાનિક રીતે પાસ કરવાથી પુરાવાની જરૂરિયાતો ઢીલી થતી નથી; મર્જ
પહેલાં મેન્ટેનર્સ હજુ પણ દરેક અનુરૂપ રિલીઝ ગેટ લાગુ કરે છે.

## સમીક્ષા ગેટ્સ, ટકરાવ અને મર્જ

મર્જ કરતાં પહેલાં મેન્ટેનર્સ વર્તમાન પુલ રિક્વેસ્ટ કમિટ પર દરેક ગેટ લાગુ કરે છે:

1. **સ્કોપ:** એક સમર્પિત બ્રાન્ચ, એક પ્લગિન YAML ફાઇલ અને કોઈ અસંબંધિત ફેરફારો નહીં.
2. **મૂળ ઓળખ:** સર્જક, કેનોનિકલ રિપોઝિટરી, નોડ ID, પૂરું કમિટ અને સબપાથ સંમત થાય છે.
3. **સ્કીમા અને પુરાવો:** YAML, કેટેગરીઓ, SPDX, ઇન્સ્ટોલ પિન, DSH પુરાવો અને સ્મોક સ્થિતિ પ્લગિન
   લાઇફસાઇકલ કોડ એક્ઝિક્યુટ કર્યા વગર આંતરિક રીતે સુસંગત છે.
4. **લોકપ્રિયતા:** સમર્પિત સ્ટાર્સ ચોક્કસ રિપોઝિટરી પર ચકાસી શકાય તેવી છે, અથવા મોનોરેપો સ્ટાર્સ
   `null` સાથે `undefined-parent-repository` છે.
5. **ડોક્યુમેન્ટેશન અને ફોર્મ્સ:** જાહેર ડોક્સ, Markdown ફેન્સ અને સ્ટ્રક્ચર્ડ ફોર્મ્સ માન્ય રહે છે.
6. **ટકરાવ અને ડિડુપ્લિકેશન:** કોઈ મર્જ થયેલી એન્ટ્રી કે ખુલ્લો પુલ રિક્વેસ્ટ સમાન કેનોનિકલ પ્લગિનનું
   પ્રતિનિધિત્વ કરતો નથી.

અલગ નામો કે ID ડુપ્લિકેટ પ્લગિનને અલગ બનાવતા નથી. સમાન રિપોઝિટરી નોડ ID અને સબપાથ, સમાન
કેનોનિકલ પેકેજ, અથવા બીજા સાબિત રીતે સમાન ઇન્સ્ટોલ ટાર્ગેટને ટકરાવ તરીકે ગણો. મર્જ પહેલાં એલિયાસ
અને હરીફ પુલ રિક્વેસ્ટ્સ ઉકેલો. સર્જકનો સીધો પુલ રિક્વેસ્ટ ક્યુરેશન કે ઓટોમેશન સાથેના ટકરાવમાં જીતે
છે; અન્યથા મેન્ટેનર્સ એક સમીક્ષા વાહન પસંદ કરે છે અને બંનેને મર્જ કરવાને બદલે ડુપ્લિકેટ્સ બંધ કરે છે
અથવા રીડાયરેક્ટ કરે છે.

બધા ગેટ્સ પાસ થયા પછી ફક્ત મેન્ટેનર જ પ્લગિન મર્જ કરે છે. દરેક સ્વીકૃત પ્લગિન વ્યક્તિગત રીતે મર્જ થાય
છે; વેલિડેશન, ક્યુરેશન કે ઓટોમેશન સ્વયંસંચાલિત કે બેચ મર્જ સૂચવતા નથી.

- [ ] આ યોગદાન તૈયાર કરવા મેં પ્લગિન કે પેકેજ લાઇફસાઇકલ કોડ એક્ઝિક્યુટ કર્યો નથી.
- [ ] સમર્પિત સ્ટાર્સ ચકાસી શકાય તેવી છે, અથવા મોનોરેપો સ્ટાર્સ ફરજિયાત null પોલિસી વાપરે છે.
- [ ] મેં એ જ કેનોનિકલ પ્લગિન માટે અસ્તિત્વમાં હોય એવી એન્ટ્રી અને ખુલ્લા પુલ રિક્વેસ્ટ માટે તપાસ કરી છે.
- [ ] એન્ટ્રી સ્પષ્ટપણે બિનસત્તાવાર છે અને તેમાં કોઈ ગુપ્ત માહિતી કે ખાનગી અંગત ડેટા નથી.

રહે છે; ખાલી લોકેલ ડોક્યુમેન્ટ્સ કે ઓટોમેટિક બલ્ક ટ્રાન્સલેશન ઉમેરશો નહીં.
