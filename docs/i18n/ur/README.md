ویب سائٹ نجی ماخذ سے برقرار رکھی جاتی ہے۔ CLI یہیں [`cli/`](../../cli) کے تحت رہتا ہے، اور یہ ریپوزٹری عوامی کیٹلاگ ڈیٹا، اسکیما اور وہ پالیسیاں فراہم کرتی ہے جو یہ دونوں استعمال کرتے ہیں۔

### آج CLI استعمال کریں

ورژن 1.0.1 صرف پڑھنے کے لیے ڈسکوری اور توثیق کمانڈز کے ساتھ ساتھ رضامندی سے مشروط انسٹال کمانڈز فراہم کرتا ہے۔ فلیگز، exit codes اور کوڈ ایگزیکیوشن رضامندی گیٹ سمیت مکمل کمانڈ ریفرنس [docs/CLI.md](../../docs/CLI.md) میں ہے۔

| کمانڈ | یہ کیا کرتا ہے | کیا یہ آپ کے سسٹم کو چھوتا ہے؟ |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | کیٹلاگ YAML، اسکیما اور مقامی سیمنٹکس کی توثیق کریں | نہیں — صرف پڑھنے کے لیے |
| `search <query...>` | عوامی کیٹلاگ فیلڈز کو مقامی طور پر تلاش کریں | نہیں — صرف پڑھنے کے لیے |
| `info <id>` | ایک عوامی کیٹلاگ اندراج دکھائیں | نہیں — صرف پڑھنے کے لیے |
| `list` | پروفائلز میں ترمیم کیے بغیر کیٹلاگ کے زیرِ انتظام انسٹالز کی فہرست دیں | نہیں — صرف پڑھنے کے لیے |
| `doctor` | صرف پڑھنے کے لیے Node، DSH، مقامی Windows پالیسی اور کیٹلاگ کی تشخیص | نہیں — صرف پڑھنے کے لیے |
| `add <id> --profile <name> --dry-run` | بغیر فائلوں یا سب پروسیسز کے تصدیق شدہ انسٹال پلان دکھائیں | نہیں — dry-run |
| `add <id> --profile <name> --allow-code-execution` | سرکاری DSH وفد کے ذریعے انسٹال کریں | ہاں — صرف واضح رضامندی فلیگ کے ساتھ |

```bash
# Validate the catalog in this repository (what CI runs):
npx omni-dsh-plugins catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx omni-dsh-plugins add <plugin-id> --profile default --dry-run
```

میوٹیٹنگ کمانڈز (`add`، `update`، `remove`) کبھی بھی پلگ ان lifecycle کوڈ ایگزیکیوٹ نہیں کرتیں جب تک آپ `--allow-code-execution` پاس نہ کریں۔ نیٹو Windows پر یہ میوٹیشنز v1.0.1 میں غیر فعال ہیں؛ WSL استعمال کریں۔ صرف پڑھنے کے لیے اور dry-run کمانڈز ہر جگہ کام کرتی ہیں۔

## 🔍 پلگ ان کیٹلاگ میں کیسے داخل ہوتا ہے

![پلگ ان کیٹلاگ میں کیسے داخل ہوتا ہے](../../docs/diagrams/catalog-flow-dark.svg#gh-dark-mode-only)
![پلگ ان کیٹلاگ میں کیسے داخل ہوتا ہے](../../docs/diagrams/catalog-flow-light.svg#gh-light-mode-only)

1. **ایک پلگ ان، ایک برانچ، ایک pull request۔** PR بالکل ایک YAML فائل `catalog/plugins/` کے تحت شامل یا تبدیل کرتی ہے۔
2. **تخلیق کار کو ترجیح۔** پلگ ان کے تخلیق کار یا مالک تنظیم کی طرف سے کھولی گئی PR ہمیشہ اسی پلگ ان کے لیے کمیونٹی کیوریشن یا آٹومیشن پر فوقیت رکھتی ہے — دیکھیں [docs/CREDIT.md](../../docs/CREDIT.md)۔
3. **اصل ماخذ سے ثبوت۔** ہر فیلڈ تخلیق کار کی ریپوزٹری سے ایک پن شدہ 40-حرفی کمٹ پر دوبارہ تعمیر کی جاتی ہے: تفصیل، لائسنس، DSH انٹیگریشن، انسٹال ڈسکرپٹر، ستارے۔
4. **مقامی توثیق۔** `catalog validate` ساخت اور مقامی سیمنٹکس چیک کرتا ہے؛ یہ وہی چیک ہے جو `catalog-validation` CI جاب PR پر چلاتی ہے۔
5. **مینٹینر گیٹس۔** ضم کرنے سے پہلے، مینٹینرز الگ سے ریپوزٹری کی شناخت، تخلیق کار بائنڈنگ اور پن شدہ ثبوت کی تصدیق کرتے ہیں۔ ایک سبز مقامی توثیق ضروری ہے، مگر کبھی کافی نہیں۔

مکمل معاہدہ — درکار ثبوت، YAML قواعد، ستاروں کی پالیسی، تصادم کا انتظام اور جائزہ گیٹس — [CONTRIBUTING.md](../../CONTRIBUTING.md) میں ہے۔ فیصلے کیسے اور کس کے ذریعے کیے جاتے ہیں یہ [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md) میں ہے۔

## 📄 ایک اندراج کی ساخت

ہر اندراج ایک YAML فائل ہے جس کا نام اس کے ID کے مطابق رکھا گیا ہے۔ نیچے دی گئی مثال موجودہ اسکیما کے خلاف توثیق شدہ ہے (فیلڈ بہ فیلڈ ریفرنس [docs/SCHEMA.md](../../docs/SCHEMA.md) میں):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

اسکیما کے ذریعے نافذ کردہ اہم invariants:

- `unofficial: true` اور `schemaVersion: 1` مستقل ہیں۔
- ایک مونوریپو پلگ ان کو لازمی طور پر `stars: null` استعمال کرنا چاہیے — پیرنٹ پروجیکٹ کے ستارے کبھی وراثت میں نہیں ملتے۔
- انسٹال ڈسکرپٹر یا تو ایک exact-version npm پیکج ہے یا خود پن شدہ سورس؛ یہ ڈیٹا ہے، کبھی shell کمانڈ نہیں۔
- `verified` حیثیت کے لیے جائزہ لینے کے قابل smoke-test ثبوت درکار ہے؛ ورنہ اندراج `smokeTest: null` کے ساتھ `eligible` ہوتا ہے۔

## 🗂 یہاں کیا شامل ہوتا ہے

یہ ریپوزٹری DeepSeek Harness (DSH) کے لیے آزادانہ طور پر شائع شدہ انٹیگریشنز کیٹلاگ کرتی ہے، بشمول نیٹو پلگ انز، پلگ ان فیملیز، تھیمز، اسکلز، کلائنٹس اور برجز۔ آرٹیفیکٹ اقسام، صلاحیت کے زمرے اور انٹرفیس ٹیگز [docs/CATEGORIES.md](../../docs/CATEGORIES.md) میں بیان کیے گئے ہیں۔

ہر عوامی ریکارڈ `catalog/plugins/` کے تحت ایک YAML فائل ہے اور اسے `schemas/plugin.schema.yaml` کے خلاف توثیق شدہ ہونا چاہیے۔ فہرست کا مطلب ہے کہ دستاویزی اہلیت یا توثیق چیکس مکمل ہو چکے ہیں؛ یہ کوئی سیکیورٹی سرٹیفیکیشن یا DeepSeek کی توثیق نہیں ہے۔

## 🏅 درجہ بندی اور توثیق

صرف مخصوص، نیٹو، اہل یا توثیق شدہ پلگ ان ریپوزٹریز جن کے ستارے اسی عین ریپوزٹری سے تعلق رکھتے ہوں، ستاروں کی درجہ بندی میں شامل ہو سکتی ہیں۔ وسیع تر مونوریپوز کے اندر رکھی گئی انٹیگریشنز قابلِ دریافت رہتی ہیں مگر `stars: null` استعمال کرتی ہیں اور کبھی پیرنٹ پروجیکٹ کے ستارے وراثت میں نہیں لیتیں۔ مکمل پیش شرط کے لیے [docs/RANKING.md](../../docs/RANKING.md) دیکھیں۔

عوامی توثیق کی حالتیں ساختی اہلیت کو انسٹالیشن smoke test سے ممتاز کرتی ہیں۔ کوئی بھی حالت مطلق تحفظ کی نمائندگی نہیں کرتی۔ استعمال سے پہلے پلگ ان کی ریپوزٹری، پن شدہ کمٹ، لائسنس اور انسٹالیشن رویے کا جائزہ لیں۔

## 🤝 حصہ ڈالیں یا کسی اندراج کا دعویٰ کریں

pull request کھولنے سے پہلے [CONTRIBUTING.md](../../CONTRIBUTING.md) پڑھیں۔ ایک pull request کو بالکل ایک پلگ ان اندراج شامل یا تبدیل کرنا چاہیے اور کسی دوسرے کیٹلاگ کے بجائے اصل تخلیق کار کی ریپوزٹری کا حوالہ دینا چاہیے۔ تخلیق کار کی تصنیف کردہ pull requests خودکار کیٹلاگ pull requests پر فوقیت رکھتی ہیں۔

تخلیق کار کے دعووں، اصلاحات اور ہٹانے کے لیے منظم issue فارمز دستیاب ہیں۔ کبھی بھی اسناد، نجی رابطے کی تفصیلات یا دیگر خفیہ معلومات جمع نہ کروائیں۔
