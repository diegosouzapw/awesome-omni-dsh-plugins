# تخلیق کار کا کریڈٹ اور Pull Request کی فوقیت

> 🌐 [English](../../CREDIT.md) · [Português (Brasil)](../pt-BR/CREDIT.md) · [中文（简体）](../zh-CN/CREDIT.md) · **اردو**

کیٹلاگ اس لیے موجود ہے کہ آزادانہ DSH کام کو اپنے تخلیق کاروں سے ملکیت لیے بغیر قابلِ دریافت بنایا جائے۔ عوامی اندراجات اصل ریپوزٹری اور ایک ناقابلِ تبدیل سورس کمٹ کا حوالہ دیتی ہیں۔

## ایک ہی پلگ ان کے لیے فوقیت

<!-- creator-first:direct-pr-supersedes-curation-and-automation -->

1. پلگ ان کے تخلیق کار یا مالک تنظیم کی طرف سے کھولی گئی pull request۔
2. ایک کمیونٹی pull request جسے تخلیق کار نے واضح طور پر منظور یا مشترکہ طور پر تصنیف کیا ہو۔
3. ایک موجودہ درست کمیونٹی pull request۔
4. ایک کیٹلاگ آٹومیشن pull request۔
5. کوئی نجی امیدوار بغیر کسی عوامی pull request کے۔

ایک براہِ راست تخلیق کار pull request ہمیشہ ترجیحی ہوتی ہے اور ایک ہی معیاری پلگ ان کے لیے کسی بھی کھلی کمیونٹی کیوریشن یا آٹومیشن pull request پر فوقیت رکھتی ہے، چاہے کوئی بھی پہلے کھولی گئی ہو یا زیادہ آگے بڑھی ہو۔ تخلیق کار کی pull request جائزہ کی گاڑی بن جاتی ہے؛ ان کی برانچ کبھی overwrite، force-push یا کیوریٹ شدہ pull request میں منتقل نہیں کی جاتی۔ اگر ایک کیوریٹ شدہ اندراج پہلے ہی ضم ہو چکی ہے، تاریخ برقرار رہتی ہے اور تخلیق کار ایک نئی شراکت میں اس کا دعویٰ یا اصلاح کر سکتا ہے۔

## عوامی انتساب

ہر کیٹلاگ اندراج تخلیق کار کا عوامی GitHub ہینڈل، اصل ریپوزٹری، repository node ID، پلگ ان subpath اور مکمل پن شدہ کمٹ رکھتی ہے۔ عوامی تخلیق کار پروفائل واحد ہینڈل سے اخذ کیا جاتا ہے بجائے اس کے کہ دوسری شناخت کے طور پر محفوظ ہو۔ علیحدہ مینٹینر provenance گیٹ node ID حل کرتا ہے اور ریپوزٹری URL کے عدم مطابقت کو مسترد کرتا ہے۔ Pull request کی تفصیل میں `Created by @handle` لکھا جانا چاہیے اور سورس ریپوزٹری اور سورس کمٹ میٹا ڈیٹا شامل ہونا چاہیے۔

جو شخص کسی Discussion پر پوسٹ یا comment کرتا ہے اسے خودکار طور پر تخلیق کار نہیں سمجھا جاتا۔ ملکیت کو ریپوزٹری کے مالک یا تنظیم، پیکج کی تصنیف، مینی فیسٹ میٹا ڈیٹا یا عین پن شدہ سورس تاریخ کی حمایت حاصل ہونی چاہیے۔

## Git شناخت

<!-- creator-first:source-bound-git-identity -->

کمٹ کی تصنیف اور pull request کی تصنیف الگ ہیں۔ ایک تخلیق کار-پیدا کردہ pull request تخلیق کار کو pull request مصنف کے طور پر رکھتی ہے، اور ان کی commits قدرتی طور پر تصنیف محفوظ رکھتی ہیں۔ ایک مینٹینر یا آٹومیشن اکاؤنٹ committer یا تصدیق شدہ co-author کے طور پر ظاہر ہو سکتا ہے، مگر اسے تخلیق کار کی تصنیف کی جگہ نہیں لینی چاہیے۔

ایک کیوریٹ شدہ commit کے لیے، تخلیق کار کو Git مصنف کے طور پر استعمال کریں یا `Co-authored-by` trailer صرف تب شامل کریں جب عین شناخت سورس سے منسلک اور عوامی طور پر قابلِ تصدیق ہو، جیسے کوئی شناخت جو پہلے ہی اصل ریپوزٹری میں تخلیق کار کی commit سے منسلک ہو۔ کبھی بھی ای میل اندازہ نہ لگائیں، noreply پتہ ایجاد نہ کریں، یا کسی مجاز عوامی سورس سے باہر ملنے والا نجی پتہ استعمال نہ کریں۔

جب کوئی تصدیق شدہ Git شناخت دستیاب نہ ہو، تو کیوریٹر یا آٹومیشن اکاؤنٹ commit کا مصنف بنتا ہے اور اس کے بجائے واضح قابلِ نظر کریڈٹ دیتا ہے: `Created by @handle`، مطابقت رکھنے والا عوامی پروفائل اور اندراج اور pull request میں اصل ریپوزٹری کا لنک۔ قابلِ نظر YAML انتساب ہمیشہ درکار ہے چاہے Git شناخت mapping کچھ بھی ہو۔ ایک بعد کی براہِ راست تخلیق کار pull request کھلی کیوریٹ شدہ pull request کی مصنوعی تاریخ کو وراثت میں لینے کے بجائے اسے بدل دیتی ہے۔

## باعزت تخلیق کار کا ذکر

ایک کیوریٹ شدہ pull request اپنی تفصیل میں، اصل ریپوزٹری لنک کے ساتھ، ایک باعزت عوامی `@creator` ذکر استعمال کرتی ہے۔ یہ جائزہ یا کسی متبادل براہِ راست pull request کی دعوت دے سکتی ہے۔ ذکر کو دہرائیں نہیں، پرومیشنل issues نہ کھولیں، cross-post نہ کریں یا غیر مطلوبہ براہِ راست پیغامات نہ بھیجیں۔

## کیٹلاگ لائسنس بمقابلہ اپ اسٹریم لائسنس

کیٹلاگ حقائق اور ایڈیٹوریل YAML میٹا ڈیٹا CC0-1.0 کے تحت وقف کیے گئے ہیں۔ یہ وقف اپ اسٹریم پلگ ان کے لائسنس کو تبدیل نہیں کرتا۔ اپ اسٹریم کوڈ، دستاویزات، اسکرین شاٹس، لوگو اور دیگر تخلیقی مواد اپنے اصل لائسنسز اور مالکان کے تابع رہتے ہیں۔
