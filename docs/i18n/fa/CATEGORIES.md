# دسته‌های کاتالوگ

> 🌐 [English](../../CATEGORIES.md) · [Português (Brasil)](../pt-BR/CATEGORIES.md) · [中文（简体）](../zh-CN/CATEGORIES.md) · **فارسی**

هر ورودی کاتالوگ یک `kind` مصنوع، یک دستهٔ اصلی قابلیت و صفر یا چند برچسب دارد. دستهٔ اصلی جایی
که ورودی ظاهر می‌شود را تعیین می‌کند؛ برچسب‌ها جستجوی میان‌دسته‌ای را بدون تکرار ورودی فراهم
می‌کنند.

## انواع مصنوع

<!-- catalog-policy:aggregators-never-entries -->

| مقدار | معنی | به‌عنوان افزونه با ستاره رتبه‌بندی می‌شود |
|---|---|---:|
| `plugin` | بستهٔ بومیِ قابل‌نصب DSH | فقط زمانی که هر شرط رتبه‌بندی برآورده شود |
| `plugin-family` | ریپازیتوری حاوی چندین افزونهٔ DSH | خیر؛ بخش جداگانه |
| `skin-theme` | پوستهٔ رابط کاربری یا تم بصریِ DSH | خیر؛ بخش جداگانه |
| `skill` | مهارت عامل با پشتیبانی DSH | خیر |
| `preset-profile` | پروفایل یا پیش‌تنظیم DSH | خیر |
| `client-interface` | کلاینت دسکتاپ، TUI، ویرایشگر یا از راه دور | خیر |
| `bridge-adapter` | یکپارچگی از محصول دیگری به DSH | خیر |
| `ecosystem-project` | پروژهٔ گسترده‌تر حاوی یک یکپارچگی DSH | خیر |

یک ریپازیتوری چتری، جمع‌کننده، بازار، کاتالوگ نصب‌کننده یا فهرست هرگز ورودی کاتالوگ نیست، حتی
وقتی خودِ جمع‌کننده قابل‌نصب باشد. آن فقط می‌تواند به‌عنوان سرنخ استفاده شود. هر سرنخ را تا یک
مصنوع فرزندِ به‌طور مستقل قابل‌نصب دنبال کنید و سازندهٔ واقعی، ریپازیتوری اصلی، بسته و زیرمسیر
منبع آن مصنوع را پیش از ارسالش حل کنید. یک مونوریپوی واقعیِ سازنده می‌تواند ریپازیتوری اصلی برای
یک افزونهٔ فرزند باشد، اما فرزند باید از همان زیرمسیر دقیق و سیاست ستاره‌های مونوریپو استفاده
کند.

فیلد `kind` تمایزدهندهٔ قانونیِ مصنوعِ DSH است. هیچ نوع یکپارچگیِ جداگانه‌ای وجود ندارد: `plugin`
از قبل یعنی یک بستهٔ بومیِ DSH، در حالی که `ecosystem-project` از قبل یعنی یک پروژهٔ گسترده‌تر با
یکپارچگی DSH. این از جفت‌های طبقه‌بندیِ متناقض جلوگیری می‌کند.

## دسته‌های اصلی قابلیت

| مقدار | برچسب نمایشی |
|---|---|
| `user-interface-dashboards` | رابط کاربری و داشبوردها |
| `memory-rag` | حافظه و RAG |
| `search-research` | جستجو و پژوهش |
| `coding-developer-tools` | کدنویسی و ابزارهای توسعه‌دهنده |
| `browser-automation` | مرورگر و خودکارسازی |
| `vision-audio-multimodal` | بینایی، صدا و چندوجهی |
| `sessions-productivity` | نشست‌ها و بهره‌وری |
| `security-permissions-approvals` | امنیت، مجوزها و تأییدها |
| `diagnostics-observability` | تشخیص و رصدپذیری |
| `models-providers-routing` | مدل‌ها، ارائه‌دهندگان و مسیریابی |
| `messaging-notifications` | پیام‌رسانی و اعلان‌ها |
| `data-external-services` | داده و سرویس‌های خارجی |
| `entertainment-customization` | سرگرمی و سفارشی‌سازی |

دسته‌ای را انتخاب کنید که بهترین بازتاب‌دهندهٔ کار اصلی افزونه باشد، نه دسته‌ای که بیشترین
احتمال افزایش دیده‌شدن را دارد.

## برچسب‌های رابط

برچسب‌های رابط استاندارد شامل `web-ui`، `sidebar`، `settings`، `tui`، `cli`، `desktop`،
`mobile`، `remote`، `editor`، `headless` و `theme` هستند. برچسب‌های قابلیتِ اضافیِ
kebab-case با حروف کوچک وقتی شاهد قابل‌مشاهده در منبع اصلیِ پین‌شده را توصیف کنند مجاز هستند.

## دامنهٔ ریپازیتوری

فقط زمانی از `dedicated` استفاده کنید که ستاره‌های ریپازیتوری متعلق به همان افزونهٔ کاتالوگ‌شدهٔ
دقیق باشند. وقتی افزونه زیرمسیر یا بسته‌ای درون یک پروژهٔ گسترده‌تر است، از `monorepo` استفاده
کنید. یک ورودی مونوریپو باید از `popularity.starsPolicy: undefined-parent-repository` و
`popularity.stars: null` استفاده کند.
