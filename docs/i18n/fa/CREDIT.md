# اعتبار سازنده و اولویت Pull Request

> 🌐 [English](../../docs/CREDIT.md) · **فارسی**

کاتالوگ برای قابل‌کشف کردن کار مستقل DSH، بدون گرفتن مالکیت از سازندگانش وجود دارد. ورودی‌های
عمومی به ریپازیتوری اصلی و یک کامیت منبع ثابت استناد می‌کنند.

## اولویت برای همان افزونه

<!-- creator-first:direct-pr-supersedes-curation-and-automation -->

1. یک pull request باز‌شده توسط سازندهٔ افزونه یا سازمان مالک.
2. یک pull request جامعه که صراحتاً توسط سازنده تأیید یا هم‌تألیف شده.
3. یک pull request معتبر و موجودِ ویرایش جامعه.
4. یک pull request خودکارسازی کاتالوگ.
5. یک نامزد خصوصی بدون pull request عمومی.

یک pull request مستقیم از سازنده همیشه ترجیح داده می‌شود و جایگزین هر pull request باز ویرایش
جامعه یا خودکارسازی برای همان افزونهٔ قانونی می‌شود، صرف نظر از اینکه کدام‌یک اول باز شده یا
پیشرفته‌تر است. pull request سازنده به وسیلهٔ بازبینی تبدیل می‌شود؛ شاخهٔ او هرگز بازنویسی،
force-push یا به pull request ویرایش‌شده منتقل نمی‌شود. اگر یک ورودی ویرایش‌شده از قبل ادغام
شده، تاریخچه دست‌نخورده باقی می‌ماند و سازنده می‌تواند آن را در یک مشارکت جدید ادعا یا اصلاح کند.

## اعتباردهی عمومی

هر ورودی کاتالوگ هندل عمومی GitHub سازنده، ریپازیتوری اصلی، شناسهٔ گرهٔ ریپازیتوری، زیرمسیر
افزونه و کامیت کاملِ پین‌شده را حمل می‌کند. پروفایل عمومی سازنده از تک هندل استخراج می‌شود
به‌جای آنکه به‌عنوان یک هویت دوم ذخیره شود. دروازهٔ منشأ جداگانهٔ نگهدارنده شناسهٔ گره را حل
می‌کند و ناهماهنگی URL ریپازیتوری را رد می‌کند. توضیحات pull request باید بگویند
`Created by @handle` و شامل ابردادهٔ ریپازیتوری منبع و کامیت منبع باشند.

شخصی که در یک Discussion پست یا کامنت می‌گذارد به‌طور خودکار به‌عنوان سازنده در نظر گرفته
نمی‌شود. مالکیت باید توسط مالک ریپازیتوری یا سازمان، تألیف بسته، ابردادهٔ مانیفست یا تاریخچهٔ
منبع پین‌شدهٔ دقیق پشتیبانی شود.

## هویت Git

<!-- creator-first:source-bound-git-identity -->

تألیف کامیت و تألیف pull request جداگانه‌اند. یک pull request که منشأش از سازنده است سازنده را
به‌عنوان مؤلف pull request نگه می‌دارد، و کامیت‌های او تألیف را به‌طور طبیعی حفظ می‌کنند. یک
نگهدارنده یا حساب خودکارسازی می‌تواند به‌عنوان committer یا هم‌مؤلف تأییدشده ظاهر شود، اما
نباید جایگزین تألیف سازنده شود.

برای یک کامیت ویرایش‌شده، از سازنده به‌عنوان مؤلف Git استفاده کنید یا فقط زمانی که هویت دقیق
مقید به منبع و به‌صورت عمومی قابل‌تأیید باشد یک تریلر `Co-authored-by` اضافه کنید، مانند
هویتی که از قبل به کامیت سازنده در ریپازیتوری اصلی متصل است. هرگز ایمیلی را حدس نزنید، آدرس
noreply جعل نکنید یا از آدرس خصوصیِ پیداشده خارج از منبع عمومیِ مجاز استفاده نکنید.

وقتی هویت Git تأییدشده در دسترس نیست، حساب ویرایشگر یا خودکارسازی کامیت را تألیف می‌کند و
در عوض اعتبار صریح و قابل‌مشاهده می‌دهد: `Created by @handle`، پروفایل عمومی متناظر و لینکی به
ریپازیتوری اصلی در ورودی و pull request. اعتباردهی قابل‌مشاهدهٔ YAML همیشه مستقل از نگاشت هویت
Git الزامی است. یک pull request مستقیم از سازنده بعداً به‌جای به‌ارث‌بردن تاریخچهٔ مصنوعی، یک
pull request ویرایش‌شدهٔ باز را جایگزین می‌کند.

## اشارهٔ محترمانه به سازنده

یک pull request ویرایش‌شده از یک اشارهٔ عمومی محترمانهٔ `@creator` در توضیحاتش، کنار لینک
ریپازیتوری اصلی، استفاده می‌کند. می‌تواند به بازبینی یا یک pull request مستقیم جایگزین دعوت
کند. اشاره را تکرار نکنید، issue تبلیغاتی باز نکنید، cross-post نکنید یا پیام مستقیم ناخواسته
نفرستید.

## مجوز کاتالوگ در برابر مجوز بالادستی

حقایق کاتالوگ و ابردادهٔ ویرایشیِ YAML تحت CC0-1.0 وقف شده‌اند. این وقف مجوز افزونهٔ بالادستی را
تغییر نمی‌دهد. کد بالادستی، مستندات، اسکرین‌شات‌ها، لوگوها و سایر مواد خلاقانه همچنان تابع
مجوزها و مالکان اصلی خود هستند.
