# หมวดหมู่แคตตาล็อก

> 🌐 [English](../../docs/CATEGORIES.md) · **ไทย (th)**

> **โปรเจกต์ชุมชนที่ไม่เป็นทางการ ไม่มีส่วนเกี่ยวข้อง ไม่ได้รับการรับรอง และไม่ได้รับการสนับสนุนจาก DeepSeek**
> ชื่อและเครื่องหมายการค้าของ DeepSeek เป็นของเจ้าของแต่ละราย

รายการแคตตาล็อกแต่ละรายการมี artifact kind หนึ่งอย่าง หมวดหมู่ความสามารถหลักหนึ่งอย่าง และแท็กศูนย์อย่างขึ้นไป
หมวดหมู่หลักกำหนดว่ารายการจะปรากฏที่ไหน ส่วนแท็กให้การค้นหาข้ามหมวดหมู่โดยไม่ต้องทำสำเนารายการซ้ำ

## Artifact kinds

<!-- catalog-policy:aggregators-never-entries -->

| ค่า | ความหมาย | จัดอันดับด้วยดาวในฐานะปลั๊กอินหรือไม่ |
|---|---|---:|
| `plugin` | ชุด DSH แบบเนทีฟที่ติดตั้งได้ | เฉพาะเมื่อผ่านเงื่อนไขการจัดอันดับทุกข้อ |
| `plugin-family` | รีโพซิทอรีที่บรรจุปลั๊กอิน DSH หลายตัว | ไม่ใช่; มีส่วนแยกต่างหาก |
| `skin-theme` | สกินหรือธีมภาพของ UI ของ DSH | ไม่ใช่; มีส่วนแยกต่างหาก |
| `skill` | สกิลของเอเจนต์ที่รองรับ DSH | ไม่ใช่ |
| `preset-profile` | โปรไฟล์หรือพรีเซ็ตของ DSH | ไม่ใช่ |
| `client-interface` | ไคลเอนต์เดสก์ท็อป, TUI, เอดิเตอร์ หรือรีโมต | ไม่ใช่ |
| `bridge-adapter` | การผสานรวมจากผลิตภัณฑ์อื่นเข้าสู่ DSH | ไม่ใช่ |
| `ecosystem-project` | โปรเจกต์ที่กว้างกว่าซึ่งบรรจุการผสานรวมกับ DSH | ไม่ใช่ |

รีโพซิทอรีร่ม (umbrella), aggregator, มาร์เก็ตเพลส แคตตาล็อกตัวติดตั้ง หรือรายชื่อ ไม่ถือเป็นรายการในแคตตาล็อก
เด็ดขาด แม้ว่าตัว aggregator เองจะติดตั้งได้ก็ตาม มันอาจถูกใช้เป็นเพียงเบาะแสเท่านั้น ให้ตามเบาะแสแต่ละอันไปยัง
ผลงานลูกที่ติดตั้งได้อย่างอิสระ และสืบหาผู้สร้างจริง รีโพซิทอรีดั้งเดิม แพ็กเกจ และ source subpath ของผลงานนั้น
ก่อนส่งเข้าแคตตาล็อก monorepo แท้จริงของผู้สร้างอาจเป็นรีโพซิทอรีดั้งเดิมสำหรับปลั๊กอินลูกได้ แต่ปลั๊กอินลูกต้อง
ใช้ subpath ที่แน่นอนนั้นและนโยบายดาวของ monorepo

ฟิลด์ `kind` คือตัวจำแนกผลงาน DSH ตามมาตรฐาน ไม่มีฟิลด์ประเภทการเชื่อมต่อแยกต่างหาก:
`plugin` มีความหมายว่าเป็นชุด DSH แบบเนทีฟอยู่แล้ว ในขณะที่ `ecosystem-project` มีความหมายว่าเป็นโปรเจกต์ที่
กว้างกว่าซึ่งมีการเชื่อมต่อ DSH อยู่แล้ว สิ่งนี้ป้องกันคู่การจัดประเภทที่ขัดแย้งกันเอง

## หมวดหมู่ความสามารถหลัก

| ค่า | ป้ายชื่อที่แสดงผล |
|---|---|
| `user-interface-dashboards` | หน้าจอผู้ใช้และแดชบอร์ด |
| `memory-rag` | หน่วยความจำและ RAG |
| `search-research` | การค้นหาและการวิจัย |
| `coding-developer-tools` | การเขียนโค้ดและเครื่องมือนักพัฒนา |
| `browser-automation` | เบราว์เซอร์และระบบอัตโนมัติ |
| `vision-audio-multimodal` | การมองเห็น เสียง และมัลติโมดัล |
| `sessions-productivity` | เซสชันและประสิทธิภาพการทำงาน |
| `security-permissions-approvals` | ความปลอดภัย สิทธิ์ และการอนุมัติ |
| `diagnostics-observability` | การวินิจฉัยและการสังเกตการณ์ |
| `models-providers-routing` | โมเดล ผู้ให้บริการ และการกำหนดเส้นทาง |
| `messaging-notifications` | การส่งข้อความและการแจ้งเตือน |
| `data-external-services` | ข้อมูลและบริการภายนอก |
| `entertainment-customization` | ความบันเทิงและการปรับแต่ง |

เลือกหมวดหมู่ที่สื่อถึงหน้าที่หลักของปลั๊กอินได้ดีที่สุด ไม่ใช่หมวดหมู่ที่มีแนวโน้มจะเพิ่มการมองเห็นมากที่สุด

## แท็กอินเทอร์เฟซ

แท็กอินเทอร์เฟซมาตรฐาน ได้แก่ `web-ui`, `sidebar`, `settings`, `tui`, `cli`, `desktop`, `mobile`, `remote`,
`editor`, `headless` และ `theme` แท็กความสามารถแบบ lowercase kebab-case เพิ่มเติมสามารถใช้ได้เมื่ออธิบาย
หลักฐานที่มองเห็นได้ในซอร์สดั้งเดิมที่ตรึงไว้

## ขอบเขตรีโพซิทอรี

ใช้ `dedicated` เฉพาะเมื่อดาวของรีโพซิทอรีเป็นของปลั๊กอินที่ลงแคตตาล็อกนี้จริง ๆ ใช้ `monorepo` เมื่อปลั๊กอิน
เป็น subpath หรือแพ็กเกจภายในโปรเจกต์ที่ใหญ่กว่า รายการใน monorepo ต้องใช้
`popularity.starsPolicy: undefined-parent-repository` และ `popularity.stars: null`
