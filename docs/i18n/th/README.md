## 🚀 ติดตั้ง CLI

```bash
npx omni-dsh-plugins --help
```

แพ็กเกจนี้เผยแพร่ในชื่อ `omni-dsh-plugins@1.0.1` และคำสั่งด้านบนคือวิธีเรียกใช้มาตรฐานในปัจจุบัน
ไม่มีสคริปต์ตัวติดตั้งใด ๆ ที่โฮสต์ไว้ที่นี่

### ใช้งาน CLI วันนี้

เวอร์ชัน 1.0.1 มาพร้อมคำสั่งค้นพบและตรวจสอบแบบอ่านอย่างเดียว รวมถึงคำสั่งติดตั้งที่ต้องได้รับความยินยอมก่อน
คู่มืออ้างอิงคำสั่งฉบับเต็ม รวมทั้งแฟล็ก รหัสออก และขั้นตอนขอความยินยอมก่อนรันโค้ด อยู่ที่ [docs/CLI.md](../../docs/CLI.md)

| คำสั่ง                        | สิ่งที่ทำได้                                                        | มีผลต่อระบบของคุณหรือไม่?                    |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | ตรวจสอบ YAML ของแคตตาล็อก สคีมา และความหมายเชิงตรรกะภายในเครื่อง                   | ไม่ — อ่านอย่างเดียว                          |
| `search <query...>`            | ค้นหาฟิลด์แคตตาล็อกสาธารณะภายในเครื่อง                                | ไม่ — อ่านอย่างเดียว                          |
| `info <id>`                    | แสดงรายการแคตตาล็อกสาธารณะหนึ่งรายการ                                       | ไม่ — อ่านอย่างเดียว                          |
| `list`                         | แสดงรายการที่ติดตั้งซึ่งจัดการโดยแคตตาล็อก โดยไม่แก้ไขโปรไฟล์            | ไม่ — อ่านอย่างเดียว                          |
| `doctor`                       | ตรวจวินิจฉัย Node, DSH, นโยบาย Windows แบบเนทีฟ และแคตตาล็อกแบบอ่านอย่างเดียว  | ไม่ — อ่านอย่างเดียว                          |
| `add <id> --profile <name> --dry-run` | แสดงแผนการติดตั้งที่ตรวจสอบแล้ว โดยไม่มีไฟล์หรือซับโพรเซสใด ๆ | ไม่ — โหมดจำลอง                            |
| `add <id> --profile <name> --allow-code-execution` | ติดตั้งผ่านการมอบหมายอย่างเป็นทางการของ DSH        | ใช่ — เฉพาะเมื่อส่งแฟล็กยินยอมอย่างชัดแจ้งเท่านั้น   |

```bash
# Validate the catalog in this repository (what CI runs):
npx omni-dsh-plugins catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx omni-dsh-plugins add <plugin-id> --profile default --dry-run
```

คำสั่งที่เปลี่ยนแปลงสถานะ (`add`, `update`, `remove`) จะไม่รันโค้ดวงจรชีวิตของปลั๊กอินเลย เว้นแต่คุณจะส่งแฟล็ก
`--allow-code-execution` บน Windows แบบเนทีฟ การเปลี่ยนแปลงเหล่านี้ถูกปิดใช้งานใน v1.0.1 — ให้ใช้ WSL แทน
ส่วนคำสั่งอ่านอย่างเดียวและโหมดจำลองใช้งานได้ทุกที่

2. **ผู้สร้างมาก่อน** PR ที่เปิดโดยผู้สร้างปลั๊กอินเองหรือองค์กรเจ้าของ จะมีความสำคัญเหนือกว่าการจัดทำโดยชุมชนหรือ
   ระบบอัตโนมัติสำหรับปลั๊กอินเดียวกันเสมอ — ดู [docs/CREDIT.md](../../docs/CREDIT.md)
3. **หลักฐานจากแหล่งต้นทาง** ทุกฟิลด์ถูกสร้างขึ้นใหม่จากรีโพซิทอรีของผู้สร้าง ณ คอมมิต 40 ตัวอักษรที่ตรึงไว้: คำอธิบาย
   ใบอนุญาต การเชื่อมต่อกับ DSH ตัวระบุการติดตั้ง จำนวนดาว
4. **การตรวจสอบภายในเครื่อง** `catalog validate` จะตรวจสอบโครงสร้างและความหมายเชิงตรรกะภายในเครื่อง ซึ่งเป็นการตรวจ
   แบบเดียวกับที่งาน CI `catalog-validation` รันบน PR
5. **ด่านตรวจของผู้ดูแล** ก่อนผสาน ผู้ดูแลจะตรวจสอบตัวตนของรีโพซิทอรี การผูกกับผู้สร้าง และหลักฐานที่ตรึงไว้แยกต่างหาก
   การตรวจสอบภายในเครื่องที่ผ่านเป็นเงื่อนไขจำเป็น แต่ไม่เคยเพียงพอในตัวเอง

ข้อตกลงฉบับเต็ม — หลักฐานที่ต้องใช้ กฎ YAML นโยบายเรื่องดาว การจัดการความขัดแย้ง และด่านตรวจการรีวิว — อยู่ที่
[CONTRIBUTING.md](../../CONTRIBUTING.md) ส่วนวิธีการตัดสินใจและผู้มีอำนาจตัดสินใจ อยู่ที่
[docs/GOVERNANCE.md](../../docs/GOVERNANCE.md)

## 📄 โครงสร้างของรายการหนึ่งรายการ

แต่ละรายการคือไฟล์ YAML หนึ่งไฟล์ที่ตั้งชื่อตาม ID ของมัน ตัวอย่างด้านล่างนี้ผ่านการตรวจสอบตามสคีมาปัจจุบัน
(คู่มืออ้างอิงแบบรายฟิลด์อยู่ที่ [docs/SCHEMA.md](../../docs/SCHEMA.md)):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

ค่าคงที่สำคัญที่สคีมาบังคับใช้:

- `unofficial: true` และ `schemaVersion: 1` เป็นค่าคงที่ตายตัว
- ปลั๊กอินที่อยู่ใน monorepo ต้องใช้ `stars: null` — ไม่มีการรับช่วงดาวจากโปรเจกต์แม่ไม่ว่ากรณีใด
- ตัวระบุการติดตั้งต้องเป็นแพ็กเกจ npm ที่ระบุเวอร์ชันแน่นอน หรือซอร์สที่ตรึงไว้เองเท่านั้น มันคือข้อมูล ไม่ใช่คำสั่งเชลล์
  เด็ดขาด
- สถานะ `verified` ต้องมีหลักฐานการทดสอบเบื้องต้น (smoke test) ที่สามารถรีวิวได้ มิฉะนั้นรายการจะอยู่ในสถานะ `eligible`
  พร้อม `smokeTest: null`

## 🗂 สิ่งที่เก็บรวบรวมไว้ที่นี่

รีโพซิทอรีนี้รวบรวมส่วนขยายที่เผยแพร่อย่างอิสระสำหรับ DeepSeek Harness (DSH) ซึ่งรวมถึงปลั๊กอินแบบเนทีฟ กลุ่มปลั๊กอิน
ธีม สกิล ไคลเอนต์ และสะพานเชื่อม ประเภทของผลงาน หมวดหมู่ความสามารถ และแท็กอินเทอร์เฟซ ถูกกำหนดไว้ใน
[docs/CATEGORIES.md](../../docs/CATEGORIES.md)

แต่ละระเบียนสาธารณะคือไฟล์ YAML หนึ่งไฟล์ภายใต้ `catalog/plugins/` และต้องผ่านการตรวจสอบตาม `schemas/plugin.schema.yaml`
การอยู่ในรายการหมายความว่าผ่านการตรวจสอบความมีสิทธิ์หรือการยืนยันตามที่ระบุไว้ในเอกสารแล้วเท่านั้น ไม่ใช่การรับรอง
ด้านความปลอดภัยหรือการรับรองจาก DeepSeek

## 🏅 การจัดอันดับและการยืนยัน

เฉพาะรีโพซิทอรีปลั๊กอินที่อุทิศให้เฉพาะ เป็นแบบเนทีฟ มีสิทธิ์ หรือได้รับการยืนยัน และมีดาวที่เป็นของรีโพซิทอรีนั้นจริง ๆ
เท่านั้นที่จะเข้าอยู่ในการจัดอันดับดาวได้ ส่วนขยายที่จัดเก็บอยู่ใน monorepo ที่ใหญ่กว่านั้นยังคงค้นพบได้ แต่ใช้ `stars: null`
และไม่รับช่วงดาวจากโปรเจกต์แม่เลย ดูหลักเกณฑ์ฉบับเต็มได้ที่ [docs/RANKING.md](../../docs/RANKING.md)

สถานะการยืนยันสาธารณะแยกความแตกต่างระหว่างสิทธิ์เชิงโครงสร้างกับการทดสอบเบื้องต้นของการติดตั้ง ไม่มีสถานะใดหมายถึงความ
ปลอดภัยแบบสมบูรณ์ โปรดตรวจสอบรีโพซิทอรี คอมมิตที่ตรึงไว้ ใบอนุญาต และพฤติกรรมการติดตั้งของปลั๊กอินก่อนใช้งานเสมอ

หรือความลับอื่นใดเด็ดขาด
