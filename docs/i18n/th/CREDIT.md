# การให้เครดิตผู้สร้างและลำดับความสำคัญของพูลรีเควสต์

> 🌐 [English](../../CREDIT.md) · [Português (Brasil)](../pt-BR/CREDIT.md) · [中文（简体）](../zh-CN/CREDIT.md) · **ไทย**

> **โปรเจกต์ชุมชนที่ไม่เป็นทางการ ไม่มีส่วนเกี่ยวข้อง ไม่ได้รับการรับรอง และไม่ได้รับการสนับสนุนจาก DeepSeek**
> ชื่อและเครื่องหมายการค้าของ DeepSeek เป็นของเจ้าของแต่ละราย

แคตตาล็อกนี้มีอยู่เพื่อทำให้ผลงาน DSH ที่เป็นอิสระค้นพบได้ โดยไม่ยึดความเป็นเจ้าของไปจากผู้สร้างของมัน รายการ
สาธารณะอ้างอิงรีโพซิทอรีดั้งเดิมและคอมมิตต้นทางที่ไม่เปลี่ยนแปลง

## ลำดับความสำคัญสำหรับปลั๊กอินเดียวกัน

<!-- creator-first:direct-pr-supersedes-curation-and-automation -->

1. พูลรีเควสต์ที่เปิดโดยผู้สร้างปลั๊กอินหรือองค์กรเจ้าของ
2. พูลรีเควสต์จากชุมชนที่ได้รับการอนุมัติหรือร่วมเขียนอย่างชัดแจ้งโดยผู้สร้าง
3. พูลรีเควสต์จากชุมชนที่ถูกต้องและมีอยู่แล้ว
4. พูลรีเควสต์จากระบบอัตโนมัติของแคตตาล็อก
5. ผู้สมัครส่วนตัวที่ไม่มีพูลรีเควสต์สาธารณะ

พูลรีเควสต์โดยตรงจากผู้สร้างได้รับความสำคัญเป็นอันดับแรกเสมอ และมีความสำคัญเหนือกว่าพูลรีเควสต์การจัดทำโดยชุมชน
หรือระบบอัตโนมัติที่เปิดอยู่สำหรับปลั๊กอินเดียวกัน ไม่ว่าฉบับใดจะเปิดก่อนหรือคืบหน้าไปมากกว่ากัน พูลรีเควสต์ของ
ผู้สร้างจะกลายเป็นช่องทางการรีวิว แบรนช์ของพวกเขาจะไม่มีวันถูกเขียนทับ, force-push หรือย้ายไปยังพูลรีเควสต์ที่
จัดทำไว้ หากรายการที่จัดทำแล้วถูกผสานไปแล้ว ประวัติจะยังคงอยู่ครบถ้วน และผู้สร้างสามารถขอเป็นเจ้าของหรือแก้ไข
มันได้ในการมีส่วนร่วมใหม่

## การให้เครดิตสาธารณะ

รายการแคตตาล็อกทุกรายการมีแฮนเดิล GitHub สาธารณะของผู้สร้าง รีโพซิทอรีดั้งเดิม node ID ของรีโพซิทอรี subpath
ของปลั๊กอิน และคอมมิตเต็มที่ตรึงไว้ โปรไฟล์สาธารณะของผู้สร้างถูกอนุมานมาจากแฮนเดิลเดียว แทนที่จะถูกเก็บเป็นตัวตน
ที่สอง ด่านตรวจแหล่งที่มาแยกต่างหากของผู้ดูแลจะแก้ไข node ID และปฏิเสธความไม่ตรงกันของ URL รีโพซิทอรี
คำอธิบายพูลรีเควสต์ควรระบุว่า `Created by @handle` และรวมเมทาดาทารีโพซิทอรีต้นทางและคอมมิตต้นทางไว้ด้วย

บุคคลที่โพสต์หรือคอมเมนต์ใน Discussion จะไม่ถูกถือว่าเป็นผู้สร้างโดยอัตโนมัติ ความเป็นเจ้าของต้องได้รับการรองรับ
โดยเจ้าของรีโพซิทอรีหรือองค์กร ความเป็นผู้เขียนแพ็กเกจ เมทาดาทาใน manifest หรือประวัติซอร์สที่ตรึงไว้แน่นอน

## ตัวตนบน Git

<!-- creator-first:source-bound-git-identity -->

ความเป็นผู้เขียนคอมมิตและความเป็นผู้เขียนพูลรีเควสต์แยกจากกัน พูลรีเควสต์ที่ริเริ่มโดยผู้สร้างจะให้ผู้สร้างเป็น
ผู้เขียนพูลรีเควสต์ และคอมมิตของพวกเขาจะรักษาความเป็นผู้เขียนไว้ตามธรรมชาติ บัญชีผู้ดูแลหรือระบบอัตโนมัติอาจ
ปรากฏเป็น committer หรือผู้ร่วมเขียนที่ยืนยันแล้วได้ แต่ต้องไม่แทนที่ความเป็นผู้เขียนของผู้สร้าง

สำหรับคอมมิตที่จัดทำโดยชุมชน ให้ใช้ผู้สร้างเป็น Git author หรือเพิ่ม trailer `Co-authored-by` ได้เฉพาะเมื่อ
ตัวตนที่แน่นอนนั้นผูกกับแหล่งที่มาและตรวจสอบได้สาธารณะ เช่นตัวตนที่ผูกอยู่กับคอมมิตของผู้สร้างในรีโพซิทอรีดั้งเดิม
อยู่แล้ว ห้ามคาดเดาอีเมล สร้างที่อยู่ noreply ขึ้นเอง หรือใช้ที่อยู่ส่วนตัวที่พบนอกแหล่งที่มาสาธารณะที่ได้รับ
อนุญาตเด็ดขาด

เมื่อไม่มีตัวตน Git ที่ยืนยันแล้ว บัญชีผู้จัดทำหรือระบบอัตโนมัติจะเป็นผู้เขียนคอมมิตและให้เครดิตที่มองเห็นได้
อย่างชัดแจ้งแทน: `Created by @handle`, โปรไฟล์สาธารณะที่ตรงกัน และลิงก์ไปยังรีโพซิทอรีดั้งเดิมในรายการและพูล
รีเควสต์ การให้เครดิตแบบมองเห็นได้ใน YAML จำเป็นเสมอไม่ว่าการจับคู่ตัวตน Git จะเป็นอย่างไร พูลรีเควสต์โดยตรง
จากผู้สร้างในภายหลังจะแทนที่พูลรีเควสต์ที่จัดทำไว้ซึ่งเปิดอยู่ แทนที่จะสืบทอดประวัติสังเคราะห์ของมัน

## การกล่าวถึงผู้สร้างอย่างสุภาพ

พูลรีเควสต์ที่จัดทำโดยชุมชนใช้การกล่าวถึง `@creator` แบบสุภาพสาธารณะเพียงหนึ่งครั้งในคำอธิบาย คู่กับลิงก์
รีโพซิทอรีดั้งเดิม มันสามารถเชิญชวนให้รีวิวหรือแทนที่ด้วยพูลรีเควสต์โดยตรงได้ อย่ากล่าวถึงซ้ำ อย่าเปิด issue
เชิงส่งเสริม อย่าโพสต์ข้ามแพลตฟอร์ม หรือส่งข้อความส่วนตัวโดยไม่ได้รับการร้องขอ

## ใบอนุญาตแคตตาล็อกเทียบกับใบอนุญาตต้นทาง

ข้อมูลข้อเท็จจริงของแคตตาล็อกและเมทาดาทา YAML เชิงบรรณาธิการถูกอุทิศไว้ภายใต้ CC0-1.0 การอุทิศนี้ไม่ได้เปลี่ยน
ใบอนุญาตของปลั๊กอินต้นทาง โค้ด เอกสารประกอบ ภาพหน้าจอ โลโก้ และเนื้อหาสร้างสรรค์อื่น ๆ ต้นทางยังคงอยู่ภายใต้
ใบอนุญาตและเจ้าของดั้งเดิมของพวกเขา
