# คู่มืออ้างอิง CLI — `omni-dsh-plugins@1.0.1`

> 🌐 [English](../../docs/CLI.md) · **ไทย (th)**

> **โปรเจกต์ชุมชนที่ไม่เป็นทางการ ไม่มีส่วนเกี่ยวข้อง ไม่ได้รับการรับรอง และไม่ได้รับการสนับสนุนจาก DeepSeek**
> ชื่อและเครื่องหมายการค้าของ DeepSeek เป็นของเจ้าของแต่ละราย

หน้านี้บันทึกพฤติกรรมของ CLI ที่เผยแพร่แล้วตามที่มันทำงานจริงในเวอร์ชัน `1.0.1` เป๊ะ ๆ ทุก synopsis และแฟล็ก
ด้านล่างมาจากผลลัพธ์ `--help` ของคำสั่งที่เผยแพร่จริงเอง ไม่มีสิ่งใดในหน้านี้อธิบายพฤติกรรมที่ยังไม่เผยแพร่ CLI
นี้ถูกพัฒนาในรีโพซิทอรีนี้ภายใต้ [`cli/`](../../cli) และเผยแพร่ไปยัง npm ในชื่อ
[`omni-dsh-plugins`](https://www.npmjs.com/package/omni-dsh-plugins) พร้อม provenance attestation ที่ผูก
แต่ละบิลด์เข้ากับคอมมิตและ workflow run ที่สร้างมันขึ้นมา

```bash
npx omni-dsh-plugins --help
```

## หลักการออกแบบใน v1.0.1

- **อ่านอย่างเดียวโดยค่าเริ่มต้น** `catalog`, `search`, `info`, `list` และ `doctor` จะไม่แก้ไขโปรไฟล์ เขียน
  ไฟล์ หรือสั่งรันโค้ดของปลั๊กอินเลย
- **ด่านตรวจความยินยอมสำหรับการรันโค้ด** `add`, `update` และ `remove` จะปฏิเสธการรันโค้ดวงจรชีวิตของ DSH/pnpm
  เว้นแต่คุณจะส่ง `--allow-code-execution` หากไม่ส่ง ให้ใช้ `--dry-run` เพื่อดูแผนที่ตรวจสอบแล้ว
- **นโยบาย Windows แบบเนทีฟ** `add`/`update`/`remove` แบบ Windows เนทีฟที่มีการรันโค้ดถูกปิดใช้งานใน v1.0.1
  ให้ใช้ WSL แทน โหมดจำลอง (dry-run) และคำสั่งอ่านอย่างเดียวยังคงใช้งานได้ และเครื่องหมายการกู้คืนของ Windows
  เนทีฟต้องกู้คืนด้วยตนเองตามที่ระบุไว้ในเอกสาร
- **อินพุตที่ตรึงไว้** อินพุตของแคตตาล็อกสามารถเป็นไดเรกทอรีภายในเครื่อง ไฟล์ snapshot หรือ URL snapshot
  สาธารณะที่ตรึงไว้ โดยสามารถล็อกไปยัง revision ที่แน่นอน 40 ตัวอักษรได้ตามต้องการ

## ออปชันร่วม

ออปชันเหล่านี้ปรากฏในคำสั่งที่ใช้แคตตาล็อก (`catalog validate`, `search`, `info`, `add`, `update`, `remove`,
`doctor`):

| ออปชัน                    | ความหมาย                                                            |
| ------------------------- | ------------------------------------------------------------------ |
| `--catalog <path-or-url>` | ไดเรกทอรีแคตตาล็อกภายในเครื่อง ไฟล์ snapshot หรือ URL snapshot สาธารณะที่ตรึงไว้ |
| `--revision <sha>`        | revision ของ snapshot ที่แน่นอน 40 ตัวอักษร                               |
| `--json`                  | แสดงผลลัพธ์เป็น JSON ที่คงที่                                            |

ออปชันร่วมทั่วไป: `-V, --version` แสดงเวอร์ชันของ CLI; `-h, --help` แสดงวิธีใช้สำหรับคำสั่งใด ๆ
(`dsh-plugins help [command]` ก็ใช้ได้เช่นกัน)

## รหัสออก (exit codes)

CLI ใช้รหัสออกของโปรเซสตามธรรมเนียม:

| รหัสออก | ความหมาย                                                                    |
| --------: | -------------------------------------------------------------------------- |
| `0`       | สำเร็จ (รวมถึงผลลัพธ์ "ว่างเปล่าแต่ถูกต้อง" เช่นแคตตาล็อกที่ไม่มีรายการ)     |
| `1`       | ล้มเหลว: ข้อผิดพลาดจากการตรวจสอบ ไม่พบรายการ ขาดออปชันที่จำเป็น หรือการตรวจวินิจฉัยรายงานข้อผิดพลาด |

ตัวอย่างที่พบใน v1.0.1: `catalog validate` บนแคตตาล็อกว่างที่ถูกต้องจะออกด้วย `0` พร้อมข้อความ
`0 entries valid; catalog is empty`; `info <unknown-id>` ออกด้วย `1` พร้อมข้อความ `Plugin not found`;
`doctor` ออกด้วย `1` เมื่อการตรวจสอบใด ๆ (เช่นไม่พบไฟล์ปฏิบัติการ `dsh`) รายงานข้อผิดพลาด

## คำสั่ง

### `catalog` — ตรวจสอบพื้นผิวแคตตาล็อกสาธารณะ

```text
dsh-plugins catalog validate [--catalog <path-or-url>] [--revision <sha>] [--json]
dsh-plugins catalog docs-check [root]
dsh-plugins catalog github-forms-check [root]
```

- **`catalog validate`** — ตรวจสอบ YAML และความหมายเชิงตรรกะของแคตตาล็อก: การ parse YAML แบบปลอดภัย สคีมา
  สาธารณะ การ parse นิพจน์ SPDX, SemVer ที่แน่นอน, SHA-512 SRI และการปฏิเสธ ID ซ้ำ / คีย์ node-รีโพซิทอรีบวก
  subpath ที่ซ้ำกัน มันเป็นการตรวจสอบภายในเครื่องและอ่านอย่างเดียว: มันไม่ติดต่อ GitHub ไม่ตรวจสอบตัวตนของ
  รีโพซิทอรี หรือตรวจสอบหลักฐาน ณ คอมมิตที่ตรึงไว้ นี่คือคำสั่งเดียวกับที่งาน CI `catalog-validation` รันบน
  พูลรีเควสต์ของแคตตาล็อกทุกฉบับ
- **`catalog docs-check [root]`** — ตรวจสอบว่าเอกสารแคตตาล็อกสาธารณะที่จำเป็นมีอยู่จริง และ Markdown fences
  จับคู่กันถูกต้อง
- **`catalog github-forms-check [root]`** — ตรวจสอบแบบฟอร์ม issue สาธารณะของ GitHub ที่มีโครงสร้าง (การขอเป็น
  เจ้าของ การแก้ไข การนำออก)

```bash
# From the repository root:
npx omni-dsh-plugins catalog validate --catalog .
npx omni-dsh-plugins catalog docs-check .
npx omni-dsh-plugins catalog github-forms-check .
```

### `search` — ค้นหาฟิลด์แคตตาล็อกสาธารณะภายในเครื่อง

```text
dsh-plugins search [options] <query...>
```

ค้นหาฟิลด์แคตตาล็อกสาธารณะภายในเครื่องเทียบกับอินพุตแคตตาล็อกที่เลือกไว้ แสดงผลรายการที่ตรงกัน หรือ
`No plugins found.` (ออกด้วยรหัส `0`) เมื่อไม่มีอะไรตรงกัน

```bash
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins search notes markdown --catalog . --json
```

### `discover` — ค้นหาปลั๊กอินนอกเหนือจากแคตตาล็อก

```text
dsh-plugins discover [options] <query...>
```

> `discover` มาพร้อมกับ `1.0.0` ซึ่งเป็นรีลีสแรกภายใต้ชื่อแพ็กเกจนี้

ค้นหาในแคตตาล็อกที่คัดสรรไว้ก่อน จากนั้น — เว้นแต่จะระบุ `--offline` — จะค้นหาใน topic `dsh-plugin` ของ
GitHub แบบสด ๆ ด้วย ดังนั้นปลั๊กอินที่ยังไม่ถูกส่งเข้าแคตตาล็อกก็ยังคงค้นพบได้ ผลลัพธ์จากแคตตาล็อกมีหลักฐานที่
แคตตาล็อกเก็บไว้ (คอมมิตที่ตรึงไว้ ผู้สร้าง ใบอนุญาต) ส่วนผลลัพธ์จากชุมชนไม่มีหลักฐานใด ๆ เลยและถูกระบุไว้เช่นนั้น
เพราะไม่มีสิ่งใดเกี่ยวกับผลลัพธ์เหล่านั้นถูกรีวิวมาก่อน

`--limit <n>` จำกัดจำนวนผลลัพธ์ต่อระดับ (ค่าเริ่มต้น `8`) `--json` แสดงผลรูปแบบเครื่องอ่านที่คงที่ ซึ่งไม่เคย
ถูกแปลเป็นภาษาท้องถิ่น

```bash
npx omni-dsh-plugins discover memory --catalog .
npx omni-dsh-plugins discover vision --offline --catalog . --json
```

### `info` — แสดงรายการแคตตาล็อกสาธารณะหนึ่งรายการ

```text
dsh-plugins info [options] <id>
```

แสดงรายการแคตตาล็อกสาธารณะหนึ่งรายการตาม ID ปลั๊กอินมาตรฐาน ออกด้วยรหัส `1` พร้อม
`Plugin not found: <id>` เมื่อไม่พบ ID นั้นในแคตตาล็อก

```bash
npx omni-dsh-plugins info example-notes-search --catalog .
```

### `add` — เพิ่มปลั๊กอินในแคตตาล็อกหนึ่งตัวผ่านการมอบหมายอย่างเป็นทางการของ DSH

```text
dsh-plugins add [options] <id>
```

| ออปชัน                   | ความหมาย                                                            |
| ------------------------ | ------------------------------------------------------------------ |
| `--profile <name>`       | โปรไฟล์ DSH ที่จะเปลี่ยนแปลง (จำเป็นในทางปฏิบัติ คำสั่งจะแจ้งข้อผิดพลาดหากไม่ระบุ) |
| `--dry-run`              | แสดงแผนที่ตรวจสอบแล้วโดยไม่มีไฟล์หรือซับโพรเซสใด ๆ                       |
| `--allow-code-execution` | ยินยอมให้รันโค้ดวงจรชีวิตของ DSH/pnpm (Windows เนทีฟถูกปิดใช้งาน ให้ใช้ WSL) |
| `--catalog` / `--revision` / `--json` | ออปชันร่วมด้านบน                                  |

ความหมายของ dry-run ในเวอร์ชันนี้: คำสั่งจะแก้ไขและตรวจสอบแผนสำหรับรายการที่ตรึงไว้แล้วแสดงผล โดยไม่สร้างไฟล์
และไม่สั่งรันซับโพรเซสใด ๆ การติดตั้งจริงจะมอบหมายให้เครื่องมือ DSH อย่างเป็นทางการ และจะดำเนินการต่อก็ต่อเมื่อ
มี `--allow-code-execution` เท่านั้น

```bash
# Preview only — nothing is written, nothing executes:
npx omni-dsh-plugins add example-notes-search --profile default --dry-run

# Real install — explicit consent to lifecycle code:
npx omni-dsh-plugins add example-notes-search --profile default --allow-code-execution
```

### `update` — อัปเดตปลั๊กอินในแคตตาล็อกหนึ่งตัวผ่านการมอบหมายอย่างเป็นทางการของ DSH

```text
dsh-plugins update [options] <id>
```

มีออปชันและความหมายของความยินยอมเหมือนกับ `add`: `--profile <name>`, `--dry-run`,
`--allow-code-execution` รวมถึงออปชันร่วมของแคตตาล็อกด้วย

### `remove` — ถอดปลั๊กอินที่จัดการโดยแคตตาล็อกหนึ่งตัวผ่านการมอบหมายอย่างเป็นทางการของ DSH

```text
dsh-plugins remove [options] <id>
```

มีออปชันและความหมายของความยินยอมเหมือนกับ `add` มีเพียงการติดตั้งที่จัดการโดยแคตตาล็อกเท่านั้นที่จะถูกถอดออก

### `recover` — กู้คืนการเปลี่ยนแปลง POSIX ที่ค้างอยู่

```text
dsh-plugins recover
```

กู้คืนการเปลี่ยนแปลง POSIX ที่ค้างอยู่หลังจาก `add`/`update`/`remove` ถูกขัดจังหวะ หากไม่มีรายการค้างอยู่
มันจะแสดง `No mutation recovery is pending.` และออกด้วยรหัส `0` การกู้คืนบน Windows เนทีฟยังคงต้องทำด้วยตนเอง
ตามนโยบายที่ระบุไว้ในเอกสาร

### `list` — แสดงรายการที่จัดการโดยแคตตาล็อก

```text
dsh-plugins list [--profile <name>] [--json]
```

แสดงรายการที่จัดการโดยแคตตาล็อกโดยไม่แก้ไขโปรไฟล์ `--profile <name>` กรองตามโปรไฟล์ DSH หากไม่มีรายการที่
ติดตั้ง มันจะแสดง `No catalog-managed plugins installed.` และออกด้วยรหัส `0`

### `doctor` — การตรวจวินิจฉัยแบบอ่านอย่างเดียว

```text
dsh-plugins doctor [--catalog <path-or-url>] [--revision <sha>] [--json]
```

รันการตรวจวินิจฉัย Node, DSH, นโยบาย Windows เนทีฟ และแคตตาล็อกแบบอ่านอย่างเดียว การตรวจสอบแต่ละอย่างจะรายงาน
`ok` หรือ `error`; หากมี `error` ใด ๆ รหัสออกโดยรวมจะเป็น `1` ตัวอย่างผลลัพธ์บนเครื่องที่ไม่มีไฟล์ปฏิบัติการ
`dsh`:

```text
node [ok]: Node 24.16.0 is supported
dsh [error]: dsh executable was not found
catalog [ok]: catalog is valid and empty
```

## สิ่งที่การตรวจสอบภายในเครื่องไม่พิสูจน์

การรัน `catalog validate` แล้วผ่านยืนยันได้เพียงโครงสร้างและความหมายเชิงตรรกะภายในเครื่องเท่านั้น มันไม่พิสูจน์
ตัวตนของรีโพซิทอรีระยะไกล ความเป็นเจ้าของของผู้สร้าง หรือหลักฐาน ณ คอมมิตที่ตรึงไว้ — ผู้ดูแลจะใช้ด่านตรวจแหล่ง
ที่มาแยกต่างหากเหล่านั้นก่อนการผสานใด ๆ ตามที่อธิบายไว้ใน [CONTRIBUTING.md](../../CONTRIBUTING.md) และ
[docs/GOVERNANCE.md](../../docs/GOVERNANCE.md)
