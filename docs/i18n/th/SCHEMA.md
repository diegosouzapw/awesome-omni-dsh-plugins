# คู่มืออ้างอิงสคีมารายการแคตตาล็อก

> 🌐 [English](../../SCHEMA.md) · [Português (Brasil)](../pt-BR/SCHEMA.md) · [中文（简体）](../zh-CN/SCHEMA.md) · **ไทย**

> **โปรเจกต์ชุมชนที่ไม่เป็นทางการ ไม่มีส่วนเกี่ยวข้อง ไม่ได้รับการรับรอง และไม่ได้รับการสนับสนุนจาก DeepSeek**
> ชื่อและเครื่องหมายการค้าของ DeepSeek เป็นของเจ้าของแต่ละราย

นี่คือคู่มืออ้างอิงแบบรายฟิลด์สำหรับ [`schemas/plugin.schema.yaml`](../../schemas/plugin.schema.yaml)
ซึ่งเป็น JSON Schema สาธารณะ (draft 2020-12) ที่ทุกไฟล์ภายใต้ `catalog/plugins/` ต้องตรวจสอบผ่าน ไฟล์สคีมา
นั้นเองคือแหล่งข้อมูลจริง เมื่อหน้านี้กับสคีมาขัดแย้งกัน ให้ยึดตามสคีมา

การตรวจสอบมีสองชั้น สคีมาสาธารณะบังคับใช้ *รูปแบบที่ปลอดภัย* ที่มีขอบเขต (แพตเทิร์นและความยาวที่ปฏิเสธค่าที่
คล้ายตัวเลือกหรือไม่มีขอบเขต) นอกเหนือจากนั้น `catalog validate` ยังใช้ตัวแยกวิเคราะห์เชิงความหมายที่บังคับ:
SemVer ที่แน่นอนสำหรับเวอร์ชัน, SHA-512 SRI สำหรับค่า integrity, การ parse นิพจน์ SPDX สำหรับใบอนุญาต และการ
ปฏิเสธคีย์ที่ซ้ำกัน ค่าหนึ่งอาจตรงกับแพตเทิร์นของสคีมาแต่ยังคงถูกปฏิเสธในเชิงความหมายได้

กฎระดับบนสุด: รายการคืออ็อบเจกต์ YAML เดียว `additionalProperties: false` (ฟิลด์ที่ไม่รู้จักจะถูกปฏิเสธ) และ
ฟิลด์ **ทั้งหมด** ต่อไปนี้จำเป็นต้องมี

## ฟิลด์ระดับบนสุด

| ฟิลด์             | ชนิด    | จำเป็น | สรุป                                                       |
| ----------------- | ------- | :------: | ------------------------------------------------------------- |
| `schemaVersion`   | const   |   ใช่    | ต้องเป็น `1` เท่านั้น                                           |
| `id`              | string  |   ใช่    | ID รายการแบบ lowercase kebab-case ต้องตรงกับชื่อไฟล์        |
| `name`            | string  |   ใช่    | ชื่อที่แสดงผล ความยาว 1–120 ตัวอักษร                                |
| `description`     | object  |   ใช่    | บทสรุปภาษาอังกฤษที่คัดสรรมาพร้อมเส้นทางหลักฐาน                |
| `unofficial`      | const   |   ใช่    | ต้องเป็น `true` เท่านั้น                                        |
| `kind`            | enum    |   ใช่    | ตัวจำแนกประเภทผลงานตามมาตรฐาน                              |
| `primaryCategory` | enum    |   ใช่    | หมวดหมู่ความสามารถหลักเพียงหนึ่งเดียว                            |
| `tags`            | array   |   ใช่    | แท็กแบบ lowercase kebab-case ที่ไม่ซ้ำกัน (อาจว่างเปล่าได้)               |
| `source`          | object  |   ใช่    | รีโพซิทอรีดั้งเดิม node ID, subpath และคอมมิตที่ตรึงไว้       |
| `creator`         | object  |   ใช่    | แฮนเดิล GitHub สาธารณะของผู้สร้าง                            |
| `package`         | object  |   ใช่    | ตัวระบุการติดตั้งมาตรฐาน (npm **หรือ** source)              |
| `dsh`             | object  |   ใช่    | โปรไฟล์ DSH และเส้นทางหลักฐานการเชื่อมต่อแบบเนทีฟ             |
| `repositoryScope` | enum    |   ใช่    | `dedicated` หรือ `monorepo`                                     |
| `popularity`      | object  |   ใช่    | นโยบายดาวและจำนวนดาว (ขึ้นอยู่กับเงื่อนไข)            |
| `license`         | object  |   ใช่    | นิพจน์ใบอนุญาต SPDX ต้นทาง                                |
| `verification`    | object  |   ใช่    | สถานะการยืนยัน เวลาตรวจสอบ ตัวตน และการทดสอบเบื้องต้น      |
| `provenance`      | object  |   ใช่    | URL ของ Discussion/คอมเมนต์สาธารณะ หรือ `null`                      |

### `schemaVersion`

ค่าคงที่ `1` ระบุสคีมาสาธารณะเวอร์ชัน 1 ค่าอื่นใดถือว่าไม่ถูกต้อง

### `id`

สตริงที่ตรงกับ `^[a-z0-9]+(?:-[a-z0-9]+)*$` — lowercase kebab-case ไม่มีขีดกลางนำหน้า/ตามท้าย หรือขีดกลาง
ซ้อนกัน ตาม [CONTRIBUTING.md](../../CONTRIBUTING.md) ไฟล์รายการต้องตั้งชื่อ `catalog/plugins/<id>.yaml`
ด้วยค่าเดียวกันเป๊ะ ๆ ตัวตรวจสอบจะปฏิเสธความไม่ตรงกัน (`id-filename-mismatch`) ID ต้องขึ้นต้นด้วยเนมสเปซของ
ผู้สร้างด้วย: แฮนเดิล `creator.github` ที่แปลงเป็นตัวพิมพ์เล็ก โดยอักขระที่ต่อเนื่องกันนอกช่วง `[a-z0-9]`
ถูกยุบเป็น `-` ตัวเดียว ตามด้วย `-` (`id-creator-prefix`)

### `name`

ชื่อที่แสดงผลแบบอิสระ `minLength: 1`, `maxLength: 120`

### `description`

อ็อบเจกต์ที่มีคุณสมบัติที่จำเป็นสองอย่างพอดี (ไม่อนุญาตอย่างอื่น):

| คุณสมบัติ       | ชนิด   | กฎ                                                                 |
| -------------- | ------ | --------------------------------------------------------------------- |
| `en`           | string | บทสรุปภาษาอังกฤษ ความยาว 20–320 ตัวอักษร                                    |
| `evidencePath` | string | แพตเทิร์นเส้นทางแบบสัมพัทธ์ในรีโพซิทอรี ไม่มี `/` นำหน้า ไม่มีแบ็กสแลช ไม่มีส่วน `.`/`..` |

บทสรุปภาษาอังกฤษต้องคัดสรรจากไฟล์ที่ `evidencePath` ตามที่มีอยู่จริง ณ `source.commit` — ห้ามคัดลอกมาจาก
แคตตาล็อกอื่น

### `unofficial`

ค่าคงที่ `true` เครื่องหมายที่เครื่องอ่านได้ว่ารายการนี้ไม่เป็นทางการ

### `kind`

ตัวจำแนก**เพียงตัวเดียว**สำหรับประเภทผลงาน (ไม่มีฟิลด์ประเภทการเชื่อมต่อที่สองอยู่เลย) ค่าหนึ่งใน:

`plugin` · `plugin-family` · `skin-theme` · `skill` · `preset-profile` · `client-interface` ·
`bridge-adapter` · `ecosystem-project`

ความหมายและผลกระทบต่อการจัดอันดับถูกกำหนดไว้ใน [docs/CATEGORIES.md](../../docs/CATEGORIES.md)

### `primaryCategory`

หนึ่งในสิบสามหมวดหมู่ความสามารถ:

`user-interface-dashboards` · `memory-rag` · `search-research` · `coding-developer-tools` ·
`browser-automation` · `vision-audio-multimodal` · `sessions-productivity` ·
`security-permissions-approvals` · `diagnostics-observability` · `models-providers-routing` ·
`messaging-notifications` · `data-external-services` · `entertainment-customization`

ป้ายชื่อที่แสดงผลและแนวทางการเลือกอยู่ใน [docs/CATEGORIES.md](../../docs/CATEGORIES.md)

### `tags`

อาร์เรย์ของสตริงที่ไม่ซ้ำกัน แต่ละตัวตรงกับ `^[a-z0-9]+(?:-[a-z0-9]+)*$` (lowercase kebab-case) สคีมาไม่ได้
กำหนดจำนวนขั้นต่ำ

### `source`

อ็อบเจกต์ที่มีคุณสมบัติที่จำเป็นสี่อย่างพอดี:

| คุณสมบัติ           | ชนิด           | กฎ                                                                  |
| ------------------ | -------------- | ---------------------------------------------------------------------- |
| `repository`       | string         | URL รูปแบบ `https://github.com/<owner>/<repo>`; owner เป็นไปตามกฎชื่อผู้ใช้ GitHub, ชื่อ repo ยาว 1–100 ตัวอักษร ต้องไม่เป็น `.`/`..` หรือลงท้ายด้วย `.git` |
| `repositoryNodeId` | string         | node ID ของรีโพซิทอรี GitHub ที่ไม่เปลี่ยนแปลง ต้องไม่ว่างเปล่า                         |
| `subpath`          | string หรือ null | subpath ของปลั๊กอินภายในรีโพซิทอรี (ใช้แพตเทิร์นเส้นทางสัมพัทธ์แบบปลอดภัยเดียวกับ `evidencePath`) หรือ `null` สำหรับปลั๊กอินที่รากของรีโพซิทอรี |
| `commit`           | string         | OID คอมมิตแบบเลขฐานสิบหกเต็ม 40 ตัวอักษร                               |

การตรวจสอบแคตตาล็อกต้องแก้ไข `repositoryNodeId` และปฏิเสธความไม่ตรงกันของ URL รีโพซิทอรี — การแก้ไขนั้นเป็น
ด่านตรวจฝั่งผู้ดูแล ไม่ใช่ส่วนหนึ่งของการตรวจสอบโครงสร้างภายในเครื่อง

### `creator`

อ็อบเจกต์ที่มีคุณสมบัติที่จำเป็นเพียงหนึ่งอย่าง:

| คุณสมบัติ | ชนิด   | กฎ                                             |
| -------- | ------ | ------------------------------------------------- |
| `github` | string | ชื่อผู้ใช้ GitHub (ยาว 1–39 ตัวอักษร ตามกฎแฮนเดิลของ GitHub) |

URL โปรไฟล์สาธารณะถูกสร้างขึ้นจาก `https://github.com/<handle>` เสมอ ไม่มีการเก็บฟิลด์โปรไฟล์ที่สอง ดังนั้น
ทั้งสองจึงไม่มีทางแตกต่างกันได้

### `package`

ตัวระบุการติดตั้งมาตรฐาน มันคือข้อมูล ไม่ใช่คำสั่งเชลล์ และมีได้เพียงหนึ่งในสองรูปแบบเท่านั้น (`oneOf`):

**แพ็กเกจ npm** — จำเป็นต้องมี `ecosystem`, `name`, `version`; `integrity` เป็นตัวเลือก:

| คุณสมบัติ    | ชนิด  | กฎ                                                                      |
| ----------- | ----- | --------------------------------------------------------------------------- |
| `ecosystem` | const | `npm`                                                                      |
| `name`      | string | รูปแบบชื่อแพ็กเกจ npm (สามารถมี scope ได้) ยาวสูงสุด 214 ตัวอักษร                 |
| `version`   | string | รูปแบบเวอร์ชัน `x.y.z` ที่แน่นอน (มี prerelease/build เป็นตัวเลือก); ช่วงเวอร์ชัน (range) ถูกปฏิเสธ ชั้นความหมายยังกำหนดให้ต้องเป็น SemVer ที่แน่นอนและ parse ได้เพิ่มเติมด้วย |
| `integrity` | string | รูปแบบ SRI `sha512-…` เป็นตัวเลือก ยาว 8–256 ตัวอักษร ชั้นความหมายต้อง parse เป็น SHA-512 SRI ที่ถูกต้อง |

**การติดตั้งแบบ source** — จำเป็นต้องมี `ecosystem` เท่านั้น:

| คุณสมบัติ    | ชนิด  | กฎ    |
| ----------- | ----- | -------- |
| `ecosystem` | const | `source` |

ตัวระบุแบบ source จงใจไม่เก็บอย่างอื่นเลย: รีโพซิทอรี คอมมิต และ subpath ถูกอนุมานมาจาก `source` ดังนั้นค่า
ต้นทางที่เปลี่ยนแปลงได้จึงไม่ถูกทำซ้ำ

### `dsh`

หลักฐานการเชื่อมต่อ DSH แบบเนทีฟ:

| คุณสมบัติ       | ชนิด   | กฎ                                                          |
| -------------- | ------ | -------------------------------------------------------------- |
| `profiles`     | array  | ชื่อโปรไฟล์ที่ไม่ซ้ำกันอย่างน้อยหนึ่งชื่อ ตรงกับ `^[A-Za-z0-9][A-Za-z0-9._-]*$` |
| `evidencePath` | string | เส้นทางสัมพัทธ์แบบปลอดภัยไปยังหลักฐานการเชื่อมต่อ DSH ณ `source.commit` |

### `repositoryScope`

`dedicated` (ดาวของรีโพซิทอรีเป็นของปลั๊กอินนี้จริง) หรือ `monorepo` (ปลั๊กอินเป็น subpath หรือแพ็กเกจภายใน
โปรเจกต์ที่ใหญ่กว่า) ค่านี้ขับเคลื่อนกฎความนิยมแบบมีเงื่อนไขด้านล่าง

### `popularity`

| คุณสมบัติ     | ชนิด            | กฎ                                                |
| ------------ | --------------- | ---------------------------------------------------- |
| `starsPolicy`| enum            | `exact-repository` หรือ `undefined-parent-repository`  |
| `stars`      | integer หรือ null | จำนวนเต็มที่ไม่ติดลบ หรือ `null`                      |

กฎแบบมีเงื่อนไข (บังคับใช้โดยบล็อก `allOf` ของสคีมา):

- `repositoryScope: monorepo` **บังคับ** ให้เป็น `starsPolicy: undefined-parent-repository` และ
  `stars: null` ดาวของโปรเจกต์แม่จะไม่ถูกนำมาระบุให้กับปลั๊กอินใน monorepo เด็ดขาด
- `repositoryScope: dedicated` **บังคับ** ให้เป็น `starsPolicy: exact-repository` และ `stars >= 0` แบบ
  จำนวนเต็ม

ดู [docs/RANKING.md](../../docs/RANKING.md) สำหรับวิธีที่ค่าเหล่านี้ป้อนเข้าสู่หลักเกณฑ์การจัดอันดับ

### `license`

| คุณสมบัติ | ชนิด   | กฎ                                                          |
| -------- | ------ | -------------------------------------------------------------- |
| `spdx`   | string | รูปแบบนิพจน์ SPDX ยาว 2–256 ตัวอักษร ไม่มีขีดกลางนำหน้า          |

สคีมาบังคับใช้เฉพาะรูปแบบอักขระที่ปลอดภัยเท่านั้น การตรวจสอบแคตตาล็อกต้อง parse และทำให้ค่าอยู่ในรูปแบบมาตรฐาน
ด้วยตัว parse นิพจน์ SPDX จริง บันทึกนิพจน์ต้นทางฉบับสมบูรณ์ที่มีหลักฐาน ณ คอมมิตที่ตรึงไว้ (เช่น `Apache-2.0`
หรือ `MIT OR GPL-3.0-only`)

### `verification`

การยืนยันใช้กับ `source.commit` อ็อบเจกต์ที่มีคุณสมบัติที่จำเป็นสี่อย่าง:

| คุณสมบัติ             | ชนิด           | กฎ                                                  |
| -------------------- | -------------- | ------------------------------------------------------ |
| `status`             | enum           | `eligible` · `verified` · `stale` · `unavailable` · `archived` · `quarantined` |
| `checkedAt`          | string         | timestamp รูปแบบ `date-time` ของการตรวจสอบ           |
| `repositoryIdentity` | const          | ต้องเป็น `resolved`                                     |
| `smokeTest`          | object หรือ null | บันทึกการทดสอบเบื้องต้น หรือ `null` เมื่อไม่มีการทดสอบที่เข้าเงื่อนไข |

เมื่อมีอยู่ `smokeTest` ต้องมี:

| คุณสมบัติ        | ชนิด   | กฎ                                                             |
| --------------- | ------ | ----------------------------------------------------------------- |
| `installTarget` | const  | `canonical-install-descriptor` — อ้างอิงถึง `package` หรือ source ที่ตรึงไว้โดยไม่ทำซ้ำค่าที่เปลี่ยนแปลงได้ |
| `check`         | object | ต้องมี `name` (รูปแบบชื่อแพ็กเกจ) และ `version` (รูปแบบเวอร์ชันที่แน่นอน) |
| `result`        | const  | `passed` — การทดสอบเบื้องต้นที่ล้มเหลวจะไม่ถูกบันทึกเป็นการทดสอบเบื้องต้น    |

กฎแบบมีเงื่อนไข: `status: verified` **ต้อง**มีอ็อบเจกต์ `smokeTest` ที่ไม่ใช่ null รายการที่ไม่มีหลักฐานการ
ทดสอบเบื้องต้นที่รีวิวได้ใช้ `status: eligible` และ `smokeTest: null` ไม่มีสถานะใดเป็นการรับรองหรือใบรับรอง
ด้านความปลอดภัย — ดู [docs/RANKING.md](../../docs/RANKING.md)

### `provenance`

ลิงก์แหล่งที่มาสาธารณะ แต่ละอันเป็น URI หรือ `null`:

| คุณสมบัติ     | ชนิด          | กฎ                                            |
| ------------ | ------------- | ------------------------------------------------ |
| `discussion` | string หรือ null | URL ของ Discussion สาธารณะเมื่อมีอยู่            |
| `comment`    | string หรือ null | URL ของคอมเมนต์สาธารณะเมื่อมีอยู่               |

## สิ่งที่สคีมาไม่ตรวจสอบ

สคีมาตั้งใจให้เป็นการตรวจสอบเชิงโครงสร้างและภายในเครื่องเท่านั้น มัน**ไม่**ตรวจสอบว่ารีโพซิทอรีมีอยู่จริง ว่า
node ID ตรงกับ URL ว่าเส้นทางหลักฐานมีอยู่จริง ณ คอมมิตที่ตรึงไว้ ว่าจำนวนดาวถูกต้อง หรือว่าผู้สร้างเป็นเจ้าของ
ซอร์สจริง การตรวจสอบเหล่านั้นเป็นหน้าที่ของด่านตรวจรีวิวของผู้ดูแลที่อธิบายไว้ใน
[CONTRIBUTING.md](../../CONTRIBUTING.md) และ [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md)
