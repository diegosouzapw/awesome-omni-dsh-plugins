Acest repository este sursa publică de adevăr pentru catalog. Fiecare intrare este un fișier YAML
sub `catalog/plugins/`, validat față de o schemă JSON publicată, adăugat printr-un pull request
revizuit individual și mereu creditat creatorului original al pluginului. Nimic din catalog nu
este generat dintr-un alt catalog sau listă: fiecare intrare este reconstruită din repository-ul
creatorului original, la un commit fixat.

Site-ul este întreținut dintr-o sursă privată. CLI-ul se află aici, sub [`cli/`](../../cli), iar
acest repository poartă datele publice ale catalogului, schema și politicile pe care ambele le
consumă.

**681 de pluginuri integrate.** Fiecare plugin intră printr-un pull request revizuit individual,

explicită.

## 🚀 Instalează CLI-ul

```bash
npx omni-dsh-plugins --help
```

Pachetul este publicat ca `omni-dsh-plugins@1.0.1`, iar comanda de mai sus este
invocarea canonică actuală; niciun script de instalare nu este găzduit aici.

### Folosește CLI-ul astăzi

Versiunea 1.0.1 oferă comenzi de descoperire și validare read-only, plus comenzi de instalare
condiționate de consimțământ. Referința completă de comenzi, inclusiv flagurile, codurile de
ieșire și poarta de consimțământ pentru execuția de cod, se află în
[docs/CLI.md](../../docs/CLI.md).

| Comandă                        | Ce face                                                              | Atinge sistemul tău?                    |
| ------------------------------ | ---------------------------------------------------------------------| ---------------------------------------- |
| `catalog validate --catalog .` | Validează YAML-ul catalogului, schema și semantica locală            | Nu — doar citire                         |
| `search <query...>`            | Caută local în câmpurile publice ale catalogului                     | Nu — doar citire                         |
| `info <id>`                    | Afișează o intrare publică din catalog                               | Nu — doar citire                         |
| `list`                         | Listează instalările gestionate de catalog, fără a modifica profiluri | Nu — doar citire                        |
| `doctor`                       | Diagnostice read-only pentru Node, DSH, politica nativă Windows și catalog | Nu — doar citire                    |
| `add <id> --profile <name> --dry-run` | Arată planul de instalare verificat, fără fișiere sau subprocese | Nu — simulare (dry-run)             |
| `add <id> --profile <name> --allow-code-execution` | Instalează prin delegarea oficială DSH               | Da — doar cu flagul explicit de consimțământ |

```bash
# Validate the catalog in this repository (what CI runs):
npx omni-dsh-plugins catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx omni-dsh-plugins add <plugin-id> --profile default --dry-run
```

Comenzile care modifică starea (`add`, `update`, `remove`) nu execută niciodată codul de ciclu de
viață al pluginului decât dacă adaugi `--allow-code-execution`. Pe Windows nativ, aceste mutații
sunt dezactivate în v1.0.1; folosește WSL. Comenzile read-only și dry-run funcționează peste tot.

## 🔍 Cum intră un plugin în catalog

![Cum intră un plugin în catalog](../../docs/diagrams/catalog-flow-dark.svg#gh-dark-mode-only)
![Cum intră un plugin în catalog](../../docs/diagrams/catalog-flow-light.svg#gh-light-mode-only)

1. **Un plugin, o ramură, un pull request.** PR-ul adaugă sau modifică exact un fișier YAML sub
   `catalog/plugins/`.
2. **Creatorul are prioritate.** Un PR deschis de creatorul pluginului sau de organizația care îl
   deține are întotdeauna prioritate față de curatoria comunitară sau automatizare, pentru
   același plugin — vezi [docs/CREDIT.md](../../docs/CREDIT.md).
3. **Dovezi din sursa originală.** Fiecare câmp este reconstruit din repository-ul creatorului, la
   un commit fixat de 40 de caractere: descriere, licență, integrare DSH, descriptor de instalare,
   stele.
4. **Validare locală.** `catalog validate` verifică structura și semantica locală; este exact
   verificarea pe care o rulează job-ul CI `catalog-validation` pe PR.
5. **Porți ale întreținătorilor.** Înainte de merge, întreținătorii verifică separat identitatea
   repository-ului, legătura cu creatorul și dovezile fixate. O validare locală verde este
   necesară, dar niciodată suficientă.

Contractul complet — dovezile necesare, regulile YAML, politica privind stelele, gestionarea
coliziunilor și porțile de review — se află în [CONTRIBUTING.md](../../CONTRIBUTING.md). Modul în
care se iau deciziile și de către cine este descris în
[docs/GOVERNANCE.md](../../docs/GOVERNANCE.md).

## 📄 Anatomia unei intrări

Fiecare intrare este un fișier YAML numit după ID-ul său. Exemplul de mai jos validează față de
schema actuală (referință câmp cu câmp în [docs/SCHEMA.md](../../docs/SCHEMA.md)):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

Invarianți-cheie impuși de schemă:

- `unofficial: true` și `schemaVersion: 1` sunt constante.
- Un plugin dintr-un monorepo trebuie să folosească `stars: null` — stelele proiectului-părinte nu
  sunt niciodată moștenite.
- Descriptorul de instalare este fie un pachet npm cu versiune exactă, fie sursa fixată propriu-zisă;
  este date, niciodată o comandă shell.
- Statusul `verified` necesită dovezi de smoke-test revizuibile; altfel intrarea este `eligible`
  cu `smokeTest: null`.

## 🗂 Ce se catalogează aici

Acest repository catalogează integrări publicate independent pentru DeepSeek Harness (DSH),
inclusiv pluginuri native, familii de pluginuri, teme, skill-uri, clienți și punți. Tipurile de
artefact, categoriile de capabilități și tag-urile de interfață sunt definite în
[docs/CATEGORIES.md](../../docs/CATEGORIES.md).

Fiecare înregistrare publică este un fișier YAML sub `catalog/plugins/` și trebuie să valideze
față de `schemas/plugin.schema.yaml`. O listare înseamnă că verificările documentate de
eligibilitate sau de verificare au fost finalizate; nu este o certificare de securitate și nici
o susținere din partea DeepSeek.

## 🏅 Clasament și verificare

Doar repository-urile de pluginuri dedicate, native, eligibile sau verificate, ale căror stele
aparțin exact acelui repository, pot intra într-un clasament după stele. Integrările stocate în
interiorul unor monorepo-uri mai largi rămân descoperibile, dar folosesc `stars: null` și nu
moștenesc niciodată stelele proiectului-părinte. Vezi [docs/RANKING.md](../../docs/RANKING.md)
pentru predicatul complet.

Stările publice de verificare disting eligibilitatea structurală de un smoke-test de instalare.
Nicio stare nu reprezintă siguranță absolută. Analizează repository-ul unui plugin, commit-ul
fixat, licența și comportamentul de instalare înainte de a-l folosi.

## 🤝 Contribuie sau revendică o intrare

Citește [CONTRIBUTING.md](../../CONTRIBUTING.md) înainte de a deschide un pull request. Un pull
request trebuie să adauge sau să modifice exact o intrare de plugin și trebuie să citeze
repository-ul creatorului original, nu un alt catalog. Pull request-urile create de creator au
prioritate față de pull request-urile automate ale catalogului.

Sunt disponibile formulare de issue structurate pentru revendicări de creator, corecturi și
eliminări. Nu trimite niciodată credențiale, date de contact private sau alte secrete.
