本儲存庫是這份目錄的公開真實來源。每一筆項目都是 `catalog/plugins/` 底下的一個 YAML 檔案,依已發佈的 JSON Schema 驗證,
透過一次單獨審查的提取請求加入,並始終掛名外掛的原始創作者。目錄中沒有任何內容是從其他目錄或清單產生的:每個項目都是根據
創作者原始儲存庫在固定提交處重新建構而成。

網站與 CLI 皆維護於私有原始碼;本儲存庫承載它們所使用的公開目錄資料、結構描述與政策。

**已合併 160 個外掛。** 每個外掛皆透過一次單獨審查的提取請求逐一納入,來自原始創作者儲存庫,並附帶固定的來源提交與明確
掛名。

## 🚀 安裝 CLI

```bash
npx @diegosouza.pw/dsh-plugins --help
```

這個具作用域的套件以 `@diegosouza.pw/dsh-plugins@0.1.0` 發佈,上方指令是目前的標準呼叫方式;本儲存庫不代管任何安裝
指令碼。

### 立即使用 CLI

0.1.0 版本提供唯讀的探索與驗證指令,以及需經同意方可執行的安裝指令。完整的指令參考(包含旗標、結束代碼與程式碼執行同意
機制)請見 [docs/CLI.md](../../docs/CLI.md)。

| 指令                        | 功能說明                                                        | 是否會變更你的系統?                    |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | 驗證目錄 YAML、結構描述與本地語義                   | 否——唯讀                          |
| `search <query...>`            | 在本地搜尋公開目錄欄位                                | 否——唯讀                          |
| `info <id>`                    | 顯示一筆公開目錄項目                                       | 否——唯讀                          |
| `list`                         | 列出由目錄管理的已安裝項目,不修改設定檔            | 否——唯讀                          |
| `doctor`                       | 對 Node、DSH、原生 Windows 政策與目錄進行唯讀診斷  | 否——唯讀                          |
| `add <id> --profile <name> --dry-run` | 顯示已驗證的安裝計畫,不寫入檔案也不啟動子程序 | 否——試跑模式                            |
| `add <id> --profile <name> --allow-code-execution` | 透過官方 DSH 委派機制安裝        | 是——僅在明確傳入同意旗標時   |

```bash
# Validate the catalog in this repository (what CI runs):
npx @diegosouza.pw/dsh-plugins@0.1.0 catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx @diegosouza.pw/dsh-plugins@0.1.0 search memory --catalog .
npx @diegosouza.pw/dsh-plugins@0.1.0 info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx @diegosouza.pw/dsh-plugins@0.1.0 add <plugin-id> --profile default --dry-run
```

會變更狀態的指令(`add`、`update`、`remove`)在未傳入 `--allow-code-execution` 時,絕不會執行外掛生命週期程式碼。在原生
Windows 上,v0.1.0 中這些變更操作已被停用;請改用 WSL。唯讀與試跑模式指令在任何環境下皆可使用。

## 🔍 外掛如何進入目錄

![外掛如何進入目錄](../../docs/diagrams/catalog-flow-dark.svg#gh-dark-mode-only)
![外掛如何進入目錄](../../docs/diagrams/catalog-flow-light.svg#gh-light-mode-only)

1. **一個外掛,一個分支,一個提取請求。** 該 PR 只新增或修改 `catalog/plugins/` 底下的一個 YAML 檔案。
2. **創作者優先。** 由外掛創作者本人或所屬組織發起的 PR,針對同一外掛永遠優先於社群整理或自動化提交——參見
   [docs/CREDIT.md](../../docs/CREDIT.md)。
3. **證據來自原始來源。** 每個欄位皆根據創作者儲存庫在固定的 40 位元提交雜湊處重新建構而成:描述、授權條款、DSH 整合
   方式、安裝描述子、星標數。
4. **本地驗證。** `catalog validate` 會檢查結構與本地語義;這與 `catalog-validation` CI 工作在 PR 上執行的檢查完全
   相同。
5. **維護者關卡。** 合併前,維護者會另行核實儲存庫身分、創作者綁定與固定證據。本地驗證通過是必要條件,但絕非充分條件。

完整的貢獻規範——所需證據、YAML 規則、星標政策、衝突處理與審查關卡——請見 [CONTRIBUTING.md](../../CONTRIBUTING.md)。決策
如何制定、由誰制定,請見 [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md)。

## 📄 項目結構剖析

每個項目都是以其 ID 命名的一個 YAML 檔案。下方範例可通過目前結構描述的驗證(逐欄位參考請見
[docs/SCHEMA.md](../../docs/SCHEMA.md)):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

結構描述強制要求的關鍵不變量:

- `unofficial: true` 與 `schemaVersion: 1` 為固定常數。
- 位於 monorepo 中的外掛必須使用 `stars: null`——絕不繼承母專案的星標。
- 安裝描述子只能是精確版本的 npm 套件,或固定的來源本身;它是資料,絕非殼層指令。
- `verified` 狀態需要可供審查的煙霧測試證據;否則項目狀態為 `eligible`,且 `smokeTest: null`。

## 🗂 本儲存庫收錄什麼

本儲存庫收錄為 DeepSeek Harness(DSH)獨立發佈的各類整合,包括原生外掛、外掛家族、佈景主題、技能、用戶端與橋接程式。
產物種類、能力分類與介面標籤定義請見 [docs/CATEGORIES.md](../../docs/CATEGORIES.md)。

每筆公開紀錄都是 `catalog/plugins/` 底下的一個 YAML 檔案,且必須通過 `schemas/plugin.schema.yaml` 的驗證。收錄代表
已完成文件規定的資格或驗證檢查;這並非安全認證,也不代表 DeepSeek 的背書。

## 🏅 排名與驗證

只有專屬的、原生的、符合資格或已驗證的外掛儲存庫,且星標確實屬於該儲存庫本身,才能進入星標排名。存放在較大
monorepo 中的整合仍可被發現,但使用 `stars: null`,絕不繼承母專案的星標。完整判定原則請見
[docs/RANKING.md](../../docs/RANKING.md)。

公開的驗證狀態用於區分結構性資格與安裝煙霧測試。任何狀態皆不代表絕對安全。使用前請自行審查外掛的儲存庫、固定提交、
授權條款與安裝行為。

## 🤝 貢獻或認領項目

發起提取請求前,請先閱讀 [CONTRIBUTING.md](../../CONTRIBUTING.md)。一個提取請求只能新增或修改一個外掛項目,且必須引用
原始創作者儲存庫,而非其他目錄。由創作者本人提交的提取請求優先於自動化目錄提交。

創作者認領、更正與移除均可透過結構化的 issue 表單提交。切勿提交憑證、私人聯絡方式或其他機密資訊。
