# Вказівка авторства та пріоритет pull request

> 🌐 [English](../../CREDIT.md) · [Português (Brasil)](../pt-BR/CREDIT.md) · [中文（简体）](../zh-CN/CREDIT.md) · **Українська**

Каталог існує, щоб робити незалежну роботу над DSH помітною, не забираючи в авторів власність на
неї. Публічні записи посилаються на оригінальний репозиторій і незмінний коміт джерела.

## Пріоритет для того самого плагіна

<!-- creator-first:direct-pr-supersedes-curation-and-automation -->

1. Pull request, відкритий автором плагіна або організацією-власником.
2. Громадський pull request, явно схвалений автором або створений у співавторстві з ним.
3. Наявний чинний громадський pull request.
4. Pull request автоматизації каталогу.
5. Приватний кандидат без публічного pull request.

Прямий pull request автора завжди переважний і має пріоритет над будь-яким відкритим громадським
кураторським або автоматизованим pull request для того самого канонічного плагіна, незалежно від
того, який відкрито раніше або який просунувся далі. Pull request автора стає засобом рев'ю; його
гілку ніколи не перезаписують, не роблять у неї force-push і не переносять її вміст у кураторський
pull request. Якщо кураторський запис уже злито, історія залишається недоторканною, і автор може
заявити права на нього або виправити його новим внеском.

## Публічна атрибуція

Кожен запис каталогу містить публічний GitHub-хендл автора, оригінальний репозиторій, вузловий ID
репозиторію, субшлях плагіна та повний закріплений коміт. Публічний профіль автора виводиться з
єдиного хендла, а не зберігається як друга ідентичність. Окремий шлюз походження мейнтейнерів
розв'язує вузловий ID і відхиляє невідповідність URL репозиторію. Описи pull request мають
містити `Created by @handle` та метадані репозиторію джерела і коміта джерела.

Людина, яка публікує допис чи коментує в Discussion, автоматично не вважається автором. Власність
має підтверджуватися власником репозиторію або організацією, авторством пакета, метаданими
маніфесту або точною історією закріпленого джерела.

## Ідентичність у Git

<!-- creator-first:source-bound-git-identity -->

Авторство комітів і авторство pull request — різні речі. Pull request, створений автором,
залишає автора автором pull request, а його коміти природно зберігають авторство. Обліковий запис
мейнтейнера чи автоматизації може фігурувати як комітер або перевірений співавтор, але не повинен
замінювати авторство автора.

Для кураторського коміта використовуйте автора як автора Git або додавайте трейлер `Co-authored-by`
лише тоді, коли точна ідентичність прив'язана до джерела і публічно перевірювана, — наприклад,
ідентичність, уже прикріплена до коміта автора в оригінальному репозиторії. Ніколи не вгадуйте
електронну адресу, не вигадуйте адресу типу noreply та не використовуйте приватну адресу, знайдену
поза авторизованим публічним джерелом.

Коли перевіреної ідентичності в Git немає, автором коміта стає куратор або обліковий запис
автоматизації, а натомість надається явна видима вказівка авторства: `Created by @handle`,
відповідний публічний профіль і посилання на оригінальний репозиторій у записі та в pull request.
Видима атрибуція в YAML обов'язкова завжди, незалежно від зіставлення ідентичності в Git. Пізніший
прямий pull request автора замінює відкритий кураторський pull request, а не успадковує його
синтетичну історію.

## Поважна згадка автора

Кураторський pull request використовує одну поважну публічну згадку `@автора` в описі, поруч із
посиланням на оригінальний репозиторій. Вона може запрошувати до рев'ю або до прямого замісного
pull request. Не повторюйте згадку, не відкривайте промоційні issue, не робіть кроспостів і не
надсилайте небажаних прямих повідомлень.

## Ліцензія каталогу та ліцензія висхідного джерела

Факти каталогу та редакційні YAML-метадані передано в суспільне надбання за CC0-1.0. Ця передача
не змінює ліцензію висхідного плагіна. Вихідний код, документація, скриншоти, логотипи та інші
творчі матеріали висхідного джерела залишаються під дією своїх оригінальних ліцензій і власників.
