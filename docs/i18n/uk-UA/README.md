## Коротко про головне

| Розділ     | Що це                                                       | Де                                                                    |
| ----------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **Сайт** | Готовий вебкаталог із пошуком і рейтингом                 | [dsh-plugins.omniroute.online](https://dsh-plugins.omniroute.online)     |
| **Каталог** | Один YAML-файл на плагін, єдине джерело істини             | [`catalog/plugins/`](../../catalog/plugins)                                    |
| **Схема**  | Публічна JSON Schema (draft 2020-12), за якою перевіряється кожен запис | [`schemas/plugin.schema.yaml`](../../schemas/plugin.schema.yaml)               |
| **CLI**     | Пошук, перегляд, перевірка та встановлення з каталогу           | [`omni-dsh-plugins`](https://www.npmjs.com/package/omni-dsh-plugins) |
| **Машиночитані фіди** | `catalog.json` + `catalog.snapshot.json` для інструментів           | [catalog.json](https://dsh-plugins.omniroute.online/catalog.json) · [catalog.snapshot.json](https://dsh-plugins.omniroute.online/catalog.snapshot.json) |

Цей репозиторій — публічне джерело істини для каталогу. Кожен запис — це один YAML-файл
у `catalog/plugins/`, перевірений за опублікованою JSON Schema, доданий через окремо
розглянутий pull request і завжди з вказівкою оригінального автора плагіна.
Нічого в каталозі не згенеровано з іншого каталогу чи списку: кожен запис відтворено
із репозиторію оригінального автора на закріпленому коміті.

Сайт розробляється в закритому вихідному коді. CLI перебуває тут, у цьому репозиторії, у
[`cli/`](../../cli), і саме цей репозиторій містить публічні дані каталогу, схему та політики,
які використовують обидва.

## 🚀 Встановлення CLI

```bash
npx omni-dsh-plugins --help
```

Пакет опубліковано як `omni-dsh-plugins@1.0.1`, і наведена вище команда
сьогодні є канонічним способом виклику; скрипт встановлення тут не розміщено.

### Можливості CLI вже зараз

Версія 1.0.1 включає команди пошуку й валідації лише для читання, а також команди встановлення,
що потребують явної згоди. Повний довідник команд — із прапорцями, кодами завершення та шлюзом
згоди на виконання коду — у [docs/CLI.md](../../docs/CLI.md).

| Команда                        | Що робить                                                        | Впливає на систему?                    |
| ------------------------------ | ------------------------------------------------------------------- | --------------------------------------- |
| `catalog validate --catalog .` | Перевіряє YAML каталогу, схему та локальну семантику                   | Ні — лише читання                          |
| `search <query...>`            | Шукає за публічними полями каталогу локально                                | Ні — лише читання                          |
| `info <id>`                    | Показує один публічний запис каталогу                                       | Ні — лише читання                          |
| `list`                         | Показує встановлення, керовані каталогом, не змінюючи профілі            | Ні — лише читання                          |
| `doctor`                       | Діагностика Node, DSH, політики нативного Windows і каталогу лише для читання  | Ні — лише читання                          |
| `add <id> --profile <name> --dry-run` | Показує перевірений план встановлення без файлів і підпроцесів | Ні — тестовий прогін                            |
| `add <id> --profile <name> --allow-code-execution` | Встановлює через офіційне делегування DSH        | Так — лише з явним прапорцем згоди   |

```bash
# Validate the catalog in this repository (what CI runs):
npx omni-dsh-plugins catalog validate --catalog .

# Search and inspect locally, without installing anything:
npx omni-dsh-plugins search memory --catalog .
npx omni-dsh-plugins info <plugin-id> --catalog .

# Preview an install plan; nothing is written and no subprocess runs:
npx omni-dsh-plugins add <plugin-id> --profile default --dry-run
```

Змінювальні команди (`add`, `update`, `remove`) ніколи не виконують код життєвого циклу плагіна,
якщо не передано прапорець `--allow-code-execution`. У нативному Windows ці змінювальні команди
вимкнено у v1.0.1; використовуйте WSL. Команди лише для читання й тестового прогону працюють усюди.

## 🔍 Як плагін потрапляє до каталогу

![Як плагін потрапляє до каталогу](../../docs/diagrams/catalog-flow-dark.svg#gh-dark-mode-only)
![Як плагін потрапляє до каталогу](../../docs/diagrams/catalog-flow-light.svg#gh-light-mode-only)

1. **Один плагін, одна гілка, один pull request.** PR додає або змінює рівно один YAML-файл
   у `catalog/plugins/`.
2. **Пріоритет автора.** PR, відкритий автором плагіна або організацією-власником, завжди має
   пріоритет над кураторством спільноти чи автоматизацією для того самого плагіна — див.
   [docs/CREDIT.md](../../docs/CREDIT.md).
3. **Докази з першоджерела.** Кожне поле відтворюється з репозиторію автора на закріпленому
   40-символьному коміті: опис, ліцензія, інтеграція з DSH, дескриптор встановлення, зірки.
4. **Локальна перевірка.** `catalog validate` перевіряє структуру та локальну семантику — це та
   сама перевірка, яку запускає завдання CI `catalog-validation` для PR.
5. **Перевірки мейнтейнерів.** Перед злиттям мейнтейнери окремо перевіряють ідентичність
   репозиторію, прив'язку автора та закріплені докази. Успішна локальна перевірка необхідна,
   але ніколи не достатня.

Повний контракт — необхідні докази, правила YAML, політика зірок, обробка колізій
і перевірки під час рев'ю — міститься в [CONTRIBUTING.md](../../CONTRIBUTING.md). Про те, як і ким
ухвалюються рішення, — у [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md).

## 📄 Анатомія запису

Кожен запис — це один YAML-файл, названий за його ID. Приклад нижче проходить перевірку за
поточною схемою (поатрибутний довідник — у [docs/SCHEMA.md](../../docs/SCHEMA.md)):

```yaml
schemaVersion: 1
id: example-notes-search
name: Example Notes Search
description:
  en: >-
    Searches a local Markdown notes folder from DSH sessions and returns
    matching snippets with file paths.
  evidencePath: README.md
unofficial: true
kind: plugin
primaryCategory: search-research
tags:
  - search
  - notes
  - cli
source:
  repository: https://github.com/example-creator/example-notes-search
  repositoryNodeId: R_kgDOExample01
  subpath: null
  commit: 0123456789abcdef0123456789abcdef01234567
creator:
  github: example-creator
package:
  ecosystem: npm
  name: example-notes-search
  version: 1.4.2
dsh:
  profiles:
    - default
  evidencePath: dsh-plugin.json
repositoryScope: dedicated
popularity:
  starsPolicy: exact-repository
  stars: 128
license:
  spdx: MIT
verification:
  status: eligible
  checkedAt: "2026-08-18T12:00:00Z"
  repositoryIdentity: resolved
  smokeTest: null
provenance:
  discussion: null
  comment: null
```

Ключові інваріанти, які забезпечує схема:

- `unofficial: true` і `schemaVersion: 1` — константи.
- Плагін із монорепозиторію повинен використовувати `stars: null` — зірки батьківського проєкту ніколи не успадковуються.
- Дескриптор встановлення — це або npm-пакет із точною версією, або сам закріплений вихідний
  код; це дані, а не команда shell.
- Статус `verified` вимагає перевірюваних доказів smoke-тесту; інакше запис має статус
  `eligible` з `smokeTest: null`.

## 🗂 Що тут публікується

Цей репозиторій каталогізує незалежно опубліковані інтеграції для DeepSeek Harness (DSH),
включно з нативними плагінами, родинами плагінів, темами, навичками, клієнтами й мостами. Види
артефактів, категорії можливостей і теги інтерфейсів визначені в [docs/CATEGORIES.md](../../docs/CATEGORIES.md).

Кожен публічний запис — це один YAML-файл у `catalog/plugins/`, який повинен проходити
перевірку за `schemas/plugin.schema.yaml`. Наявність запису означає, що документовані
перевірки відповідності або верифікації було виконано; це не сертифікація безпеки і не
схвалення з боку DeepSeek.

## 🏅 Рейтинг і верифікація

До рейтингу за зірками можуть потрапити лише виділені, нативні, допущені або верифіковані
репозиторії плагінів, чиї зірки належать саме цьому репозиторію. Інтеграції, що зберігаються
всередині більших монорепозиторіїв, залишаються доступними для пошуку, але використовують
`stars: null` і ніколи не успадковують зірки батьківського проєкту. Повне правило — у
[docs/RANKING.md](../../docs/RANKING.md).

Публічні статуси верифікації відрізняють структурну відповідність від smoke-тесту встановлення.
Жоден статус не означає абсолютну безпеку. Перед використанням плагіна вивчіть його
репозиторій, закріплений коміт, ліцензію та поведінку під час встановлення.

оригінального автора, а не на інший каталог. Pull request-и, авторами яких є творці плагінів,
мають пріоритет над автоматизованими pull request-ами каталогу.

Для заявлення авторських прав, виправлень і видалення записів доступні структуровані форми
issue. Ніколи не надсилайте облікові дані, приватні контактні дані чи інші секрети.
