# Довідник схеми запису каталогу

> 🌐 [English](../../SCHEMA.md) · [Português (Brasil)](../pt-BR/SCHEMA.md) · [中文（简体）](../zh-CN/SCHEMA.md) · **Українська**

> **Неофіційний проєкт спільноти. Не пов'язаний із DeepSeek, не схвалений і не спонсорований компанією DeepSeek.**
> Назви та товарні знаки DeepSeek належать їхньому власнику.

Це поатрибутний довідник для [`schemas/plugin.schema.yaml`](../../schemas/plugin.schema.yaml) —
публічної JSON Schema (draft 2020-12), якій має відповідати кожен файл у `catalog/plugins/`.
Сам файл схеми є джерелом істини; коли ця сторінка і схема розходяться, схема має пріоритет.

Застосовуються два рівні перевірки. Публічна схема забезпечує обмежені *безпечні форми* (патерни
та довжини, що відхиляють опцієподібні чи необмежені значення). Поверх неї `catalog validate`
застосовує обов'язкові семантичні парсери: точний SemVer для версій, SHA-512 SRI для значень
цілісності, парсинг виразів SPDX для ліцензій і відхилення дублікатів ключів. Значення може
відповідати патерну схеми, але все одно бути відхиленим семантично.

Правила верхнього рівня: запис — це один об'єкт YAML, `additionalProperties: false` (невідомі
поля відхиляються), і **всі** наведені нижче поля є обов'язковими.

## Поля верхнього рівня

| Поле             | Тип    | Обов'язкове | Коротко                                                       |
| ----------------- | ------- | :------: | ------------------------------------------------------------- |
| `schemaVersion`   | const   |   так    | Має бути рівно `1`                                           |
| `id`              | string  |   так    | ID запису в kebab-case малими літерами; має збігатися з іменем файлу        |
| `name`            | string  |   так    | Назва для відображення, 1–120 символів                                |
| `description`     | object  |   так    | Кураторський опис англійською та шлях до його доказу                |
| `unofficial`      | const   |   так    | Має бути рівно `true`                                        |
| `kind`            | enum    |   так    | Канонічний розрізнювач типу артефакту                              |
| `primaryCategory` | enum    |   так    | Одна основна категорія можливостей                            |
| `tags`            | array   |   так    | Унікальні теги в kebab-case малими літерами (можуть бути порожніми)               |
| `source`          | object  |   так    | Оригінальний репозиторій, вузловий ID, субшлях і закріплений коміт       |
| `creator`         | object  |   так    | Публічний GitHub-хендл автора                                |
| `package`         | object  |   так    | Канонічний інсталяційний дескриптор (npm **або** джерело)              |
| `dsh`             | object  |   так    | Профілі DSH і шлях до доказу нативної інтеграції             |
| `repositoryScope` | enum    |   так    | `dedicated` або `monorepo`                                     |
| `popularity`      | object  |   так    | Політика зірок і кількість зірок (залежно від області)            |
| `license`         | object  |   так    | Вираз ліцензії SPDX висхідного джерела                              |
| `verification`    | object  |   так    | Статус верифікації, час перевірки, ідентичність і smoke-тест      |
| `provenance`      | object  |   так    | Публічні URL Discussion/коментаря або `null`                      |

### `schemaVersion`

Константа `1`. Позначає версію 1 публічної схеми; будь-яке інше значення недійсне.

### `id`

Рядок, що відповідає `^[a-z0-9]+(?:-[a-z0-9]+)*$` — kebab-case малими літерами, без дефісів на
початку/в кінці чи подвійних. Відповідно до [CONTRIBUTING.md](../../CONTRIBUTING.md), файл запису
має мати назву `catalog/plugins/<id>.yaml` з ідентичним значенням; валідатор відхиляє
невідповідність (`id-filename-mismatch`). ID також має починатися з простору імен автора: хендл
`creator.github` малими літерами, де кожна послідовність символів поза `[a-z0-9]` згортається в
один `-`, із наступним `-` (`id-creator-prefix`).

### `name`

Довільна назва для відображення, `minLength: 1`, `maxLength: 120`.

### `description`

Об'єкт із рівно двома обов'язковими властивостями (інші не дозволені):

| Властивість    | Тип   | Правила                                                                 |
| -------------- | ------ | --------------------------------------------------------------------- |
| `en`           | string | Опис англійською, 20–320 символів                                    |
| `evidencePath` | string | Патерн відносного шляху в репозиторії; без `/` на початку, без зворотних слешів, без сегментів `.`/`..` |

Опис англійською має бути кураторським із файлу за `evidencePath` таким, яким він існує на
`source.commit` — а не скопійованим з іншого каталогу.

### `unofficial`

Константа `true`. Машиночитний маркер того, що запис неофіційний.

### `kind`

**Єдиний** розрізнювач типу артефакту (другого поля типу інтеграції не існує). Одне з:

`plugin` · `plugin-family` · `skin-theme` · `skill` · `preset-profile` · `client-interface` ·
`bridge-adapter` · `ecosystem-project`

Значення та наслідки для ранжування визначені в [docs/CATEGORIES.md](../../docs/CATEGORIES.md).

### `primaryCategory`

Одна з тринадцяти категорій можливостей:

`user-interface-dashboards` · `memory-rag` · `search-research` · `coding-developer-tools` ·
`browser-automation` · `vision-audio-multimodal` · `sessions-productivity` ·
`security-permissions-approvals` · `diagnostics-observability` · `models-providers-routing` ·
`messaging-notifications` · `data-external-services` · `entertainment-customization`

Мітки для відображення та поради щодо вибору — у [docs/CATEGORIES.md](../../docs/CATEGORIES.md).

### `tags`

Масив унікальних рядків, кожен з яких відповідає `^[a-z0-9]+(?:-[a-z0-9]+)*$` (kebab-case малими
літерами). Мінімальна кількість схемою не встановлена.

### `source`

Об'єкт із рівно чотирма обов'язковими властивостями:

| Властивість        | Тип           | Правила                                                                  |
| ------------------ | -------------- | ---------------------------------------------------------------------- |
| `repository`       | string         | URL `https://github.com/<owner>/<repo>`; власник відповідає правилам імен користувачів GitHub, назва репозиторію 1–100 символів, не може бути `.`/`..` і не може закінчуватися на `.git` |
| `repositoryNodeId` | string         | Незмінний вузловий ID репозиторію на GitHub, непорожній                         |
| `subpath`          | string або null | Субшлях плагіна в репозиторії (той самий безпечний патерн відносного шляху, що й `evidencePath`), або `null` для плагіна в корені репозиторію |
| `commit`           | string         | Повний 40-символьний шістнадцятковий OID коміта                               |

Валідація каталогу має розв'язати `repositoryNodeId` і відхилити невідповідність URL репозиторію —
це розв'язання є шлюзом на боці мейнтейнерів, а не частиною локальної структурної перевірки.

### `creator`

Об'єкт з однією обов'язковою властивістю:

| Властивість | Тип   | Правила                                             |
| -------- | ------ | ------------------------------------------------- |
| `github` | string | Ім'я користувача GitHub (1–39 символів, правила хендлів GitHub) |

Публічна URL профілю завжди виводиться як `https://github.com/<handle>`; друге поле профілю не
зберігається, тож вони ніколи не можуть розійтися.

### `package`

Канонічний інсталяційний дескриптор. Це дані, а не команда shell, і він має рівно одну з двох
форм (`oneOf`):

**npm-пакет** — обов'язкові `ecosystem`, `name`, `version`; необов'язкове `integrity`:

| Властивість | Тип  | Правила                                                                      |
| ----------- | ----- | -------------------------------------------------------------------------- |
| `ecosystem` | const | `npm`                                                                      |
| `name`      | string | Форма назви npm-пакета (за потреби зі scope), максимум 214 символів                 |
| `version`   | string | Форма точної версії `x.y.z` (необов'язкові prerelease/build); діапазони відхиляються. Семантичний рівень додатково вимагає розбірний, точний SemVer |
| `integrity` | string | Необов'язкова форма `sha512-…` SRI, 8–256 символів. Семантичний рівень має розпарсити його як коректний SHA-512 SRI |

**встановлення з джерела** — обов'язкове лише `ecosystem`:

| Властивість | Тип  | Правила    |
| ----------- | ----- | -------- |
| `ecosystem` | const | `source` |

Дескриптор джерела навмисно не зберігає нічого більше: репозиторій, коміт і субшлях виводяться з
`source`, тож змінні значення ніколи не дублюються.

### `dsh`

Доказ нативної інтеграції з DSH:

| Властивість    | Тип   | Правила                                                          |
| -------------- | ------ | -------------------------------------------------------------- |
| `profiles`     | array  | Принаймні одне унікальне ім'я профілю, що відповідає `^[A-Za-z0-9][A-Za-z0-9._-]*$` |
| `evidencePath` | string | Безпечний відносний шлях до доказу інтеграції з DSH на `source.commit` |

### `repositoryScope`

Або `dedicated` (зірки репозиторію належать саме цьому плагіну), або `monorepo` (плагін є
субшляхом або пакетом у ширшому проєкті). Це значення керує наведеними нижче умовними правилами
популярності.

### `popularity`

| Властивість  | Тип            | Правила                                                |
| ------------ | --------------- | ---------------------------------------------------- |
| `starsPolicy`| enum            | `exact-repository` або `undefined-parent-repository`  |
| `stars`      | integer або null | Невід'ємне ціле, або `null`                      |

Умовні правила (забезпечуються блоками `allOf` схеми):

- `repositoryScope: monorepo` **вимагає** `starsPolicy: undefined-parent-repository` і
  `stars: null`. Зірки батьківського проєкту ніколи не приписуються плагіну з монорепозиторію.
- `repositoryScope: dedicated` **вимагає** `starsPolicy: exact-repository` і ціле
  `stars >= 0`.

Див. [docs/RANKING.md](../../docs/RANKING.md), щоб дізнатися, як ці значення живлять правило
ранжування.

### `license`

| Властивість | Тип   | Правила                                                          |
| -------- | ------ | -------------------------------------------------------------- |
| `spdx`   | string | Форма виразу SPDX, 2–256 символів, без дефіса на початку          |

Схема забезпечує лише безпечну форму символів; валідація каталогу має розпарсити та нормалізувати
значення справжнім парсером виразів SPDX. Записуйте повний висхідний вираз, підтверджений на
закріпленому коміті (наприклад `Apache-2.0` або `MIT OR GPL-3.0-only`).

### `verification`

Верифікація застосовується до `source.commit`. Об'єкт із чотирма обов'язковими властивостями:

| Властивість          | Тип           | Правила                                                  |
| -------------------- | -------------- | ------------------------------------------------------ |
| `status`             | enum           | `eligible` · `verified` · `stale` · `unavailable` · `archived` · `quarantined` |
| `checkedAt`          | string         | Мітка часу перевірки у форматі `date-time`           |
| `repositoryIdentity` | const          | Має бути `resolved`                                     |
| `smokeTest`          | object або null | Запис smoke-тесту, або `null`, якщо відповідного тесту не існує |

Якщо присутній, `smokeTest` вимагає:

| Властивість     | Тип   | Правила                                                             |
| --------------- | ------ | ----------------------------------------------------------------- |
| `installTarget` | const  | `canonical-install-descriptor` — посилається на `package` або закріплене джерело без дублювання змінних значень |
| `check`         | object | Обов'язкові `name` (форма назви пакета) і `version` (форма точної версії) |
| `result`        | const  | `passed` — невдалий smoke-тест не записується як smoke-тест    |

Умовне правило: `status: verified` **вимагає** ненульового об'єкта `smokeTest`. Записи без
перевірюваного доказу smoke використовують `status: eligible` і `smokeTest: null`. Жоден статус не
є схваленням або сертифікацією безпеки — див. [docs/RANKING.md](../../docs/RANKING.md).

### `provenance`

Публічні посилання походження, кожне — URI або `null`:

| Властивість  | Тип          | Правила                                            |
| ------------ | ------------- | ------------------------------------------------ |
| `discussion` | string або null | Публічна URL Discussion, якщо вона існує            |
| `comment`    | string або null | Публічна URL коментаря, якщо він існує               |

## Чого схема не перевіряє

Схема навмисно локальна та структурна. Вона **не** перевіряє, що репозиторій існує, що вузловий
ID відповідає URL, що шляхи доказів існують на закріпленому коміті, що кількість зірок точна чи
що автор володіє джерелом. Ці перевірки належать до перевіркових шлюзів мейнтейнерів, описаних у
[CONTRIBUTING.md](../../CONTRIBUTING.md) і [docs/GOVERNANCE.md](../../docs/GOVERNANCE.md).
